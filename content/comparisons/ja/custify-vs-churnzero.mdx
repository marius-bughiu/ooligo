[Custify](/ja/tools/custify/) と [ChurnZero](/ja/tools/churnzero/) は同じ買い手を奪い合っています。health score とライフサイクル自動化を求めつつ、コストと導入の重さから Gainsight を既に除外した mid-market の B2B SaaS Customer Success チームです。どちらも同じ CS プラットフォームの形で動きます。利用イベント、課金、サポートのシグナルを health score に流し込み、それが playbook を発火させる構造です。違いは Gainsight 比較よりも狭く、2 つに集約されます。AI 支援と、自分で組む柔軟な health score モデル(Custify)を重視するか、それとも同梱された in-app engagement とやや成熟した playbook 面(ChurnZero)を重視するか。もう 1 つの決め手は持ち込むデータです。どちらも背後にある製品イベントのパイプ次第で価値が決まります。

## Custify が勝つ領域

- **分析だけでなく設定作業までこなす AI。** Custify は AI-native ですが、ChurnZero はそうではありません。CustifyAI は顧客メールから churn リスクのトーンを検知し、アカウントの要約を生成し、そして最も重要な点として、onboarding 中に初期の health score と playbook を下書きしてくれるため、白紙から設定する必要がありません。初めて CS プラットフォームを立ち上げる小規模チームにとって、これは展開で最も時間のかかる部分を短縮します。
- **自分で制御できる health score モデル。** Custify の数式エディタはこのカテゴリで最も扱いやすい部類です。製品イベント、NPS/CSAT、チケット量、契約額、ログインの新しさからスコアを組み立て、各入力の重みを自分で設定します。ChurnZero も health を的確に算出しますが、Custify のエディタは RevOps を持たない CSM リーダーが認定 admin なしで実際に運用できるものです。
- **より小規模で軽いタッチのチームへの適合。** Custify は SMB/mid-market 帯の 3-20 CSM を狙っています。CS 組織が mid-market の小さい側にあり、製品の利用データが主要な churn シグナルであれば、Custify の軽いフットプリントは、5-30 CSM 帯以上に寄る ChurnZero よりもあなたの実態に素直に合致します。

## ChurnZero が勝つ領域

- **in-app engagement が同梱されている。** ChurnZero は walk-through、in-app サーベイ、NPS プロンプトをプラットフォーム内に備えており、Pendo や WalkMe の別契約は不要です。Custify は health score とライフサイクル playbook に注力していますが、in-app engagement レイヤーは同梱しません。同じ health データに紐づく in-app ガイドで機能採用を促したいなら、ChurnZero は 1 つの契約でそれを提供します。Custify では別ツールを後付けすることになります。
- **より実績のある mid-market の導入基盤。** ChurnZero は pricing-value の強さと 5-30 CSM 帯での厚い実績により、ooligo score がやや高い(7.6 対 7.4)です。$10-150M ARR でリスクの低い、参照先の多い選択を求める CS リーダーにとって、ChurnZero はより安全な default です。
- **pricing の方向性がより見える。** ChurnZero は Custify よりも価格の方向性を多く公開しています。Custify は完全に見積もりのみで、公開された self-serve tier はありません。結局は営業との会話に至りますが、ChurnZero の mid-market 帯は通話前に妥当性を確認しやすいです。

## pricing の実態

どちらも見積もり制、年間コミット、営業審査があり、クレジットカードでのサインアップはできません。ChurnZero の mid-market 展開(10-30 CSM)は $25K-$70K/年に収まり、enterprise は $80K-$200K+ です。価格は CSM 単位に加え、in-app engagement を大規模に使う場合は product-MAU 課金です。Custify は見積もり制で確定した公開価格はありません。第三者のリスティングは小規模チーム向けに最大 ~$899/月 という数字を挙げていますが、これらは古く方向性を示すだけで見積もりではありません。価格は管理するアカウント数と seat に応じて増えます。同等の mid-market スコープでは両者は同じ広い帯に収まるため、ここで価格が決め手になることはまれです。構造的な違いは、ChurnZero の per-MAU 要素は高 engagement の製品で驚きを生みうる一方、Custify のアカウント数ベースは tier を過小に見積もると契約途中の再交渉を招いて不利になる点です。

## 導入の手間

ChurnZero の go-live の中央値は 4-8 週間で、ベンダーの onboarding が含まれ、パートタイムの CS ops リソースで維持できます。Custify も四半期ではなく週単位という同様の期間を狙い、CustifyAI が自動生成するスコアと playbook が設定工程の時間を削ります。ただしどちらも、本当のプロジェクトは UI ではなく data plumbing です。health score と ChurnZero の in-app walk-through は、製品イベントがきれいに流れるまで(Segment、Mixpanel、または直接 API 経由)休眠状態です。どちらのプラットフォームも意味を持つ前に、イベントを計装するエンジニアリング時間を見込んでください。両者共通のガードはこうです。まず計装の整った health 次元を 1 つ立ち上げ、既に churn したと分かっているアカウントに対して検証し、それから拡張します。

## 結論

- **Custify を選ぶ**のは、より小規模な mid-market の CS チーム(3-20 CSM)で、製品の利用データが主要な churn シグナルであり、AI に初期の health score と playbook を下書きさせたく、同梱の in-app engagement レイヤーを必要としない場合です。
- **ChurnZero を選ぶ**のは、in-app engagement(walk-through、サーベイ、NPS)を health score と同じプラットフォームに同梱したく、$10-150M ARR で 5-30 CSM のチームを持ち、AI-native の設定ツールよりも、参照先が多く価格がより見える mid-market の選択を重視する場合です。
- **どちらも選ばない**のは、CSM が 5 名未満、または product-market fit より前の場合です。その規模では CRM の共有ビューと CSM が管理するスプレッドシートが正しいツールです。30 アカウント以上で再検討してください。そして深い NRR/GRR の予測、複数製品の entitlement、専任 admin が必要なら、どちらも手狭になります。それは [Gainsight](/ja/tools/gainsight/) の話です。

上記の条件なしに選ぶなら、ChurnZero を選んでください。同梱の in-app engagement と幅広い mid-market 実績が、最もリスクの低い default にしています。AI 支援の設定と自分で組む health モデルが in-app レイヤーよりも重要で、かつチームが ChurnZero の重い面が過剰になるほど小さいときに、Custify へ切り替えてください。
