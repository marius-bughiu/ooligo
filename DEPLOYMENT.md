# Deployment

ooligo deploys to Cloudflare Pages via GitHub Actions on every push to `main`. The workflow ([`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml)) builds the Astro site and uploads the `dist/` directory directly via Wrangler — no git connector, no Cloudflare-side build step. The build environment is fully under our control.

## Architecture

```
push to main
  └─▶ GitHub Actions (.github/workflows/deploy.yml)
        ├─ npm ci
        ├─ npm run validate:config
        ├─ npm run typecheck (pipeline)
        ├─ npm run build  (Astro → apps/web/dist)
        └─ wrangler pages deploy apps/web/dist --project-name=ooligo
              └─▶ Cloudflare Pages → ooligo.pages.dev (and custom domain)
```

## One-time setup (do this once, on the Cloudflare account)

### 1. Create the Cloudflare account (if needed)

[dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) — free tier is sufficient for Pages.

### 2. Get the Account ID

Cloudflare Dashboard → home → right sidebar shows **Account ID** (a 32-character hex string). Copy it.

### 3. Create an API token

Cloudflare Dashboard → **My Profile** → **API Tokens** → **Create Token** → **Custom token**.

- **Name:** `ooligo-pages-deploy`
- **Permissions:**
  - `Account` → `Cloudflare Pages` → `Edit`
- **Account Resources:** `Include` → your account
- **TTL:** leave default (no expiry) or set as preferred
- Continue → review → **Create token**
- Copy the token immediately (you won't see it again)

### 4. Create the Pages project

Optional — Wrangler will create it on first deploy if it doesn't exist. To pre-create:

```bash
npx wrangler pages project create ooligo --production-branch=main
```

Or via dashboard: **Workers & Pages** → **Create application** → **Pages** → **Direct Upload** → name it `ooligo` → production branch `main`.

### 5. Add GitHub secrets

In `marius-bughiu/ooligo` repository: **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.

| Secret name | Value |
|---|---|
| `CLOUDFLARE_API_TOKEN` | the token from step 3 |
| `CLOUDFLARE_ACCOUNT_ID` | the account ID from step 2 |

### 6. Trigger a deploy

Push any commit to `main` (or run the workflow manually: **Actions** → **Deploy** → **Run workflow**). The workflow will:

1. Build the site
2. Upload `apps/web/dist/` directly to Cloudflare Pages
3. Output the deployment URL in the workflow summary

The site will be live at:

- **`https://ooligo.pages.dev`** — production
- **`https://<commit-hash>.ooligo.pages.dev`** — per-deployment preview (auto-generated by Cloudflare)

## Custom domain (when ready)

Once you own `ooligo.com` (or any apex/subdomain):

1. Cloudflare Dashboard → **Workers & Pages** → `ooligo` → **Custom domains** → **Set up a custom domain**
2. Enter the domain; Cloudflare will guide you through DNS records (typically a CNAME or `pages.dev` flatten record)
3. Update [`deploy.yml`](./.github/workflows/deploy.yml) — change `PUBLIC_SITE_URL` from `https://ooligo.pages.dev` to `https://ooligo.com`
4. Commit + push; the next deploy uses the new canonical URL in `<link rel="canonical">`, hreflang tags, sitemap, OG tags

Until the custom domain is set up, the site uses `ooligo.pages.dev` as its canonical URL.

## Manual deploy (for emergencies)

You can deploy from your local machine without GitHub Actions:

```bash
# one-time
export CLOUDFLARE_API_TOKEN=<token>
export CLOUDFLARE_ACCOUNT_ID=<account-id>

# every deploy
npm ci
npm run build
npx wrangler pages deploy apps/web/dist --project-name=ooligo --branch=main
```

## Rollback

Cloudflare Pages keeps every deployment. To roll back:

- Dashboard → **Workers & Pages** → `ooligo` → **Deployments** → find the good deployment → ⋯ → **Rollback to this deployment**

Or push a revert commit; the next deploy supersedes the bad one.

## Cost

Free tier covers:
- 500 builds/month (we hit this only with very high commit volume)
- 100 custom domain SSL certs
- Unlimited bandwidth and requests on Pages
- 1 build at a time (we serialize via the `concurrency` block in the workflow)

Once we exceed free tier (unlikely in year 1), Workers Paid plan is $5/mo and lifts most limits.

## Troubleshooting

**Workflow fails at "Deploy to Cloudflare Pages" step with `Authentication error`** → API token is missing, expired, or lacks `Cloudflare Pages: Edit` permission.

**Workflow fails with `project not found`** → either pre-create the project (see step 4 above) or ensure the API token has account-scope (not zone-scope only).

**Pages dev URL shows 404 after first deploy** → wait ~30 seconds for DNS propagation; first-time project setup takes a moment.

**Custom domain shows `Error 526`** → SSL not yet provisioned. Cloudflare auto-issues SSL within minutes; check the **Custom domains** tab for status.

**Wrangler version drift** → `cloudflare/wrangler-action@v3` pins to the latest stable Wrangler. To pin a specific version, add `wranglerVersion: '3.x.y'` under `with:` in the workflow.
