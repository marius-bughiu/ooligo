## 概要

kapa.ai は、自社コンテンツから製品に関する技術的な質問に回答するマネージド型の検索拡張生成（RAG）サービスです。対象はドキュメントサイト、API 仕様、PDF、GitHub、コミュニティフォーラム、Zendesk のチケット、そして Confluence や Notion などの社内 Wiki です。ソースを指定すると、kapa がクロールして同期を保ち、出典付きの回答を既製のチャネルから提供します。ドキュメント上の「Ask AI」ウィジェット、チケット作成前に回答するサポートフォームのデフレクター、Slack と Discord のボット、解決済みチケットから返信案を作成する Zendesk アプリ、そしてサポートエンジニアやソリューションエンジニア向けの社内アシスタントです。開発者向けには Chat API、Retrieval API、Agent SDK、ホスト型 MCP サーバーを提供しており、顧客が Claude Code、Cursor、Codex で使うコーディングエージェントからドキュメントを直接検索できます。

同社は Y Combinator の Summer 2023 バッチ出身で、Emil Soerensen（CEO）と Finn Bauer（CTO）が創業し、2024年10月に $3.2M の資金調達を発表しました。YC のプロフィールではチームは 22 名です。導入企業は 200 社以上とされ、公表されている顧客には OpenAI、Docker、monday.com、Nokia、Logitech、Raspberry Pi が含まれます。2026年半ばに「AI ドキュメントアシスタント」から「エージェントが動くためのナレッジレイヤー」へとポジショニングを変えており、Retrieval API と MCP サーバーはその流れから生まれたものです。

## Customer Success のスタックで選ばれる理由

- **技術コンテンツに対する回答品質こそが製品です。** kapa の仕事は 1 つだけです。出典付きの根拠ある回答を返し、ソースが質問をカバーしていなければ回答を断ります。G2 のレビュー（5 点満点中 4.9、約 40 件と少ないサンプル）や独立したレビュー記事では、回答の正確さと「わかりません」と答えるガードレールが真っ先に挙げられています。チケットの中身が「この SDK の呼び出しはなぜタイムアウトするのか」であれば、ワークフローの幅広さよりもこちらが重要です。
- **チケット化の後ではなく、質問した瞬間に問い合わせを減らします。** ドキュメントのウィジェットとサポートフォームのデフレクターが、チケットになる前に質問を受け止め、すり抜けたチケットは Zendesk アプリが担当者を支援します。ベンダー公表の事例では Raspberry Pi で 88% のセルフサービス率、Nokia で 300k 件超の回答実績とされていますが、これは予測ではなく上限値として扱ってください。
- **ドキュメントチームはギャップレポートを得られます。** 会話分析がドキュメントで答えられなかった質問を可視化するため、アシスタントはテクニカルライターのバックログとしても機能します。このループこそが、サポートだけでなく DevRel やドキュメントチームが契約のオーナーになる主な理由です。

## 価格の実態

kapa は有料プランの価格を公開していません。料金ページは 3 段階です。14 日間の無料トライアル（インデックス 1 つ、クロール 5,000 ページ、回答 1,000 件、クレジットカード不要、終了後はワークスペースが一時停止）、**Growth**（プラットフォーム料金に月間のコミット回答数を加えたもので、継続同期、ゼロデータ保持、PII マスキング、ギャップレポートを含む）、**Enterprise**（SSO、SCIM、ロールベースのアクセス制御、EU または米国でのホスティング、SLA）です。

実際の支払額については、Vendr の購買データ（30 件の契約）で年間の中央値が約 $24,600、範囲はおおよそ $12,000 から $83,000 です。年間契約で、下限が月額約 $1,000、中央値が月額約 $2,000 と読み替えてください。最大のコスト変数は、コミット量を超えた回答に対する**超過料金**です。Vendr の購入者は質問量の予測が難しいと報告しており、交渉すると kapa は超過料金（約 20% 減）とプラットフォーム料金（約 30% 減）の両方で譲歩したとしています。

## 最適な利用者

開発者ツール、API、ハードウェア、B2B SaaS 企業のサポート、DevRel、ドキュメント責任者で、質問の答えがドキュメント、仕様、過去のチケットにあり、RAG パイプラインを自前で構築・運用せずに、ドキュメント、Slack または Discord のコミュニティ、Zendesk にマネージド型アシスタントを数週間で展開したいチームです。

注文状況、返金、アカウント変更が中心の EC や消費者向けサポートチームには向きません。kapa は質問に答えるツールであり、バックエンドでアクションを実行したりチケットをクローズしたりはしません。

## 注意点

- **回答単位の課金で、超過料金が不透明です。** リリース、互換性を壊す変更、コミュニティでの急増によって、回答数がコミット量を大きく超えることがあります。**対策：** 1,000 回答あたりの超過料金と年間上限を発注書に明記させ、コミット量は推測ではなく、チケットとコミュニティの実際の質問量 3 か月分から算出してください。
- **質問応答レイヤーであり、ヘルプデスクのエージェントではありません。** Zendesk アプリは人が送信するための返信案を作成するだけで、チケットを自律的に解決したりルーティングしたりはしません。**対策：** 自律解決が目的なら、[Intercom](/ja/tools/intercom/) Fin のような解決単位課金のエージェントと比較し、kapa の範囲は問い合わせ削減と担当者支援に限定してください。
- **品質の上限はドキュメントで決まります。** 古いドキュメントや欠けたドキュメントからは、自信を持った回答拒否や薄い回答しか出てきません。**対策：** ギャップレポートにドキュメント担当者を割り当てて週次でレビューし、契約前に、Vendr の購入者が勧めるとおり、実際の難しい質問 200 件で 3 週間のパイロットを実施してください。
- **アクセス制限付きコンテンツには権限の複製が必要です。** ドキュメントの一部がログインやプランの階層で制限されている場合、そのアクセスルールを設定に複製しない限りアシスタントは制限を守りません。**対策：** 制限付きコンテンツと公開コンテンツを別々のインデックスに分け、リリース前に未ログインのユーザーでテストしてください。
- **小規模なベンダーです。** 公表済みの調達額 $3.2M、約 22 名のチームは、サポートエージェントのプラットフォームと比べると小規模です。**対策：** SOC 2 Type II レポートを請求し、データエクスポートの条件を確認したうえで、回答レイヤーを差し替えられるようにドキュメントを正本として維持してください。

## 代替ツール

[Intercom](/ja/tools/intercom/) Fin と [Zendesk](/ja/tools/zendesk/) の AI エージェントは AI サポートの市場シェアのリーダーです。すでに契約しているヘルプデスク内で、種類の混ざったチケットキューを解決単位の課金で処理したいならこちらを選んでください。[Sierra](/ja/tools/sierra/) と [Decagon](/ja/tools/decagon/) は最も急成長している新興勢力で、アクションを実行する大量処理のエージェントを個別見積もりのエンタープライズ価格で導入する場合に向いています。[Inkeep](/ja/tools/inkeep/) は技術ドキュメント領域で最も近い直接の競合です。エージェントを自社の TypeScript リポジトリで定義したい場合や、質問応答だけでなくバックグラウンドの自動化エージェントが必要な場合に選んでください。[eesel AI](/ja/tools/eesel-ai/) は、回答の元が Zendesk や Freshdesk 内の過去チケットにあるチーム向けの、より安価でヘルプデスク中心の選択肢です。ドキュメントプラットフォームにすでにアシスタントが付属しており（Mintlify、Fern）、質問量が少ないならそこから始め、回答品質や複数チャネルへの対応がボトルネックになった時点で kapa を導入してください。製品が技術的で、ドキュメントに基づく回答の正確さが決め手となる指標であり、自前で構築するのではなくマネージドで使いたいなら kapa.ai を選んでください。
