相手方の NDA または MSA を `.docx` 形式で受け取り、自社のレッド/イエロー/グリーンのプレイブックに対して各条項を分類し、事前に作成されたフォールバックライブラリから修正案を提案し、プレイブック外のものを弁護士にフラグを立てる Claude スキルです。追跡変更付きの Word 文書と、社内チームがディールチャンネルに貼り付けられる 1 ページの逸脱サマリーを出力します。プレイブックを一度設定するだけで、その後は受信するすべての契約書に実行できます。

## 使用するタイミング

受信した NDA、MSA、DPA、注文書、またはベンダー契約が届いて、弁護士がファイルを開く前にポリシーに根拠を置いたファーストパスのリドラインが欲しい場合にこのスキルを使用します。取引ごとの時間節約が複合される場合、つまり一般的に [contract review SOP](/ja/learn/contract-review-sop/) の Tier 2〜3 レベルで月 30 件以上の受信契約書を扱う法務 Ops チームで、経済的に機能します。それ以下のボリュームでは、プレイブックメンテナンスのオーバーヘッドが節約を超えます。

このスキルは、文書化されたプレイブックがすでにあることを前提とします（スキルが期待する構造については [NDA プレイブック](/ja/learn/nda-playbook/)と [MSA リドライニングルーブリック](/ja/learn/msa-redlining-rubric/)を参照）。プレイブックがまだ存在しない場合は先に構築してください — スキルはポリシーを増幅しますが、発明しません。

## 使用しないタイミング

- **最終承認または相手方へのリドラインの返送。** スキルは提案します。名前が付いた人間の弁護士がすべての変更を承認してから送信します。出力は先行スタートであり、サインオフではありません。
- **信頼できるソーステンプレートとしての自社の契約書への編集。** テンプレートの変更はプレイブックの更新です — 将来のすべての実行が新しい立場を取り込むよう `references/1-playbook-template.md` を直接編集してください。「更新するために」スキルを自社のテンプレートに実行しないでください。
- **高度にカスタムな書類。** M&A の最終合意書、複雑な IP の権利譲渡、規制産業のサイドレター — プレイブックはこれらをエンコードできません。スキルはすべての条項をポリシー外としてフラグし、それをしながらトークンを消費します。
- **最終ラウンドの交渉ドラフト。** 3 回目のターンまでに、リドラインはプレイブックが予測できない取引固有の譲歩です。スキルは開始ポジション専用です。
- **非 Tier-A AI ベンダーを経由する特権的な作業成果物。** 会社の AI ポリシーがスキルが呼び出すモデルを除外している場合は、ポリシーを緩めるのではなく人間の弁護士にエスカレートしてください。特権はスピードの価値に見合いません。

## セットアップ

1. **バンドルを配置する。** `apps/web/public/artifacts/contract-redline-claude-skill/` の内容を Claude Code のスキルディレクトリ（`~/.claude/skills/contract-redline/`）またはClause.ai プロジェクトにフォルダをアップロードします。スキルは渡された契約書を分類してリドラインする 1 つのエントリーポイントを公開します。
2. **テンプレートを置き換える。** バンドルには `references/` に 3 つのテンプレートファイルが付属しています。最初の実行前にそれぞれを自社の実際のコンテンツに置き換えます：
   - `references/1-playbook-template.md` — 条項タイプごとのレッド/イエロー/グリーンのポジション。
   - `references/2-fallback-positions.md` — スキルが逐語的に代入する弁護士承認済みの差し込み段落（言い換えなし）。
   - `references/3-escalation-criteria.md` — 条項が提案されたリドラインを取得する代わりに人間にルーティングされるタイミングを決定するルール。重要なことに、法的作業成果物に対して許可する AI ベンダーをリストアップする場所でもあります — スキルはそうでなければ実行を拒否します。
3. **既知の契約書でテストする。** すでに手動でリドラインした契約書に対して実行し、出力を比較します。スキルのポジションが適切でない箇所ではプレイブックを調整し、文言がぎこちない箇所ではフォールバックポジションの段落を調整します。2〜3 回のイテレーションで良いベースラインに到達します。
4. **インテークに接続する。** [Ironclad](/ja/tools/ironclad/) のインテークまたはメールで新しい契約書が届いた際、担当レビュアーが `.docx` をスキルに渡し、約 60 秒でリドラインされた出力を受け取ります。レビュアーは Word で `.docx` を開き、追跡変更を確認し（各変更には、一致したプレイブックのセクション ID を引用した Word コメントが付いています）、自身のレビュー後にのみ相手方に返送します。

## スキルの実際の動作

スキルは 4 つのサブタスクを順番に実行します。各ステップが前のステップのコンテキストに依存するため、並列化されていません。完全な方法と設計上の根拠は `apps/web/public/artifacts/contract-redline-claude-skill/SKILL.md` にあります。簡単に説明すると：

1. **契約書のタイプを分類する。** NDA（相互 / 一方向）、MSA、DPA、注文書、ベンダー契約、または「その他」。「その他」の場合、停止して単一のエスカレーションブロックを出力します。スキルはプレイブックが対応していない契約書タイプのリドラインを試みません — これが最も一般的なサイレントドリフトの失敗モードです。
2. **条項ごとの分類。** 見出しで契約書を分割します（番号付きセクション解析にフォールバック）。各条項について、条項タイプのヒューリスティックでプレイブックエントリに一致させ、`green`（許容可能）、`yellow`（フォールバック代入）、`red`（必須書き直し）、`out-of-playbook`（エスカレート）として分類します。すべての分類は、レビュアーが数秒で決定を監査できるよう、出力の一致したプレイブックセクション ID を引用します。
3. **リドライン提案。** すべての yellow 条項について、`references/2-fallback-positions.md` から対応するフォールバック段落を逐語的に貼り付けます。すべての red 条項について、必須の段落を貼り付けます。事前に作成された段落を使う理由（自由形式の書き直しではなく）：弁護士がすでにこの言葉を審査しています。自由形式の書き直しは毎回の実行で新しい文言を導入し、レビュアーが各フォールバックをゼロから読み直すことを強制します — 時間節約が無効になります。
4. **エスカレーションフラグ付け。** すべてのプレイブック外の条項と、`references/3-escalation-criteria.md` のルールに一致するすべての条項は、リドラインの代わりにエスカレーションブロックを受け取ります。スキルは推測しません。

## コストの実態

契約書あたりのトークンコストは長さと条項数によって異なります。具体的な数字：

- **典型的な NDA（3〜5 ページ、~2K ワード）。** 入力 ~6K トークン（契約書 + プレイブック + フォールバックライブラリ + エスカレーション基準）、出力 ~4K トークン（条項ごとの根拠 + サマリー）。Claude Sonnet 4.5 の価格（入力 3 USD/MTok、出力 15 USD/MTok）で、契約書あたり約 0.08 USD。
- **典型的な MSA（15〜25 ページ、~10K ワード）。** 入力 ~14K トークン、出力 ~10K トークン。契約書あたり約 0.20 USD。
- **100 件の月次実行コスト（NDA 50 件 + MSA 50 件）。** トークンコストで約 14 USD — 人間の時間節約と比較して桁違いに小さい（時間あたり 90 USD のパラリーガルが担う業務は完全に負担すると ~640 件のスキルコストをカバーします）。

実際のコストはプレイブックのメンテナンスです。弁護士は `references/1-playbook-template.md` と `references/2-fallback-positions.md` を最新の状態に保つ必要があります。四半期ごとに両方を更新するためにシニア弁護士の 2 時間を予算として確保し、エスカレーションパターンをトリアージして繰り返し発生するプレイブック外の条項をプレイブックに折り込むために四半期ごとに 1 時間を確保してください。

## 成功の指標

2 つの指標を一緒に見ることで、スキルが価値を生んでいるかがわかります：

- **ファーストパスリドラインのサイクルタイムの削減。** ベースライン：契約書のインテークから「人間のレビューの準備ができたファーストパスリドライン」までの中央時間。目標：中央値を 60〜75% 削減します。ファーストパスリドラインに 90 分のベースラインを持つチームは、25〜35 分に着地するべきです（スキルが 60 秒で出力し、残りは人間のレビューに費やす）。
- **人間のレビューのためにフラグされた条項の %。** 目標範囲：契約書あたりの条項の 15〜25%。10% 未満はプレイブックが寛容すぎることを意味します（スキルはイエローゾーンの言語をグリーンとしてゴム印を押しています）— ルーブリックを厳しくしてください。35% 超はプレイブックが十分な条項タイプをカバーしていないことを意味します — 拡張してください。

稼働から 30 日以内にサイクルタイム指標が改善しない場合、ボトルネックはリドラインではなく人間のレビューのステップです。一般的な原因：レビュアーが根拠の文字列を信頼せず、ゼロから各条項を読み直します。修正方法：根拠の文字列がプレイブックのセクション ID を引用するようにし（スキルはデフォルトでそうします）、レビュアーが ID をスキャンするようにトレーニングします。

## 代替案との比較

決定はこのスキルとベンダー組み込みの専門家との間にあります：

- **[LawGeex](/ja/tools/lawgeex/) または [BlackBoiler](/ja/tools/blackboiler/)と比較して。** これらは数百万件の契約書に対して事前トレーニングされたモデルを持つベンダー SaaS 製品です。Tier 1 の NDA（標準プレイブックに対する自動承認）と迅速なデプロイメントに優れています。ベンダーがまだ見ていない珍しいポジションがプレイブックにある場合、トークンレベルの透明性が重要な場合（スキルはプレイブックセクション ID を引用します。ベンダーはモデルの信頼度を引用します）、価格面（ベンダーのシートは月 500〜2K USD に対してスキルのトークンコストは契約書あたり ~0.20 USD にパラリーガル時間の償却を加えたもの）では劣ります。
- **[Ironclad AI Assist](/ja/tools/ironclad/) または [Spellbook](/ja/tools/spellbook/)と比較して。** それぞれ CLM / Word に組み込まれています。すでに使用しているツール内での UX が優れています。ベンダーの根拠は部分的にベンダーの汎用トレーニングであるため、特定のプレイブックを強制する力が弱いです。ゼロデプロイの労力が欲しく、セクション ID への引用の監査可能性が必要でない場合はこれらを選択してください。
- **手動パラリーガル主導のリドラインと比較して。** ほとんどの会社での現状。珍しい条項での品質が高い（人間は珍しい言語でよりパターンマッチが優れています）、契約書あたりのコストははるかに高く、ターンアラウンドが遅い。スキルはパラリーガルの代替品ではありません — パラリーガルの時間をタイピングから判断にシフトします。

Claude スキルのスイートスポットは、社内チームが AI にファーストパスを行ってほしいが、すべての出力に人間のレビューを期待し、すべてのリドラインが文書化されたプレイブックのポジションに遡ることを要求する高ボリュームの中程度のリスクの契約書です。リドラインの背後にプレイブックのエントリーを指し示せない場合、リドラインは送信されません。

## 注意事項

- **サイレントなプレイブックのドリフト。** 数ヶ月古いプレイブックは古いポジションから自信に満ちたリドラインを生成します。ガード：すべての出力はサマリーヘッダーにプレイブックの `last_reviewed` 日付を書きます。レビュアーはその日付が 90 日以上前の出力を拒否し、プレイブックを再実行前に更新します。
- **ヒューリスティックの不一致により見逃された新規条項。** 見出しは似て聞こえます：「non-solicitation」対「non-compete」、「Limitation of Liability」対「Cap on Damages」。ガード：すべての条項の分類は出力の一致したプレイブックセクション ID を引用します。レビュアーは引用された ID をスキャンして、リドラインが送付される前に不一致を修正します。引用なしでは、レビュアーはスキルが不一致だったかどうかを判断できません。
- **非 Tier-A ベンダーを通じた特権漏洩。** 相手方のドラフトには弁護士とクライアント間の特権コンテキストが含まれています（特に DPA とサイドレターで）。ガード：スキルは設定されたモデルが `references/3-escalation-criteria.md` の先頭にある許可ベンダーリストに表示されない場合、実行を拒否します。強制的な前提条件であり、CLI フラグでバイパスできません。
- **プレイブックの品質がすべてです。** 漠然とした プレイブックは漠然としたリドラインを生成します。`references/2-fallback-positions.md` の具体的なフォールバック言語を持ち、`references/1-playbook-template.md` の抽象的な原則だけでなく、ポジションを明示的にコード化してください。
- **法的レビューの代替品ではありません。** すべてのリドライン出力は相手方に返却される前に人間がレビューします。スキルはドラフトの時間を節約しますが、判断の呼びかけではありません。
