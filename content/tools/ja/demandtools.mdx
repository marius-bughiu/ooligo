## 概要

DemandTools は Validity が提供する [Salesforce](/ja/tools/salesforce/) 向けのデータ品質ツールキットです。ダウンロード型のアプリ（Windows 版に加え、2021 年の V リリース以降は Mac 版もあります）で、管理者が Salesforce の認証情報でログインし、重複の検出とマージ、エクスポートを経由しない項目の一括更新、既存データと照合しながらのレコードのインポートとエクスポート、Assess モジュールによるデータ品質のスコアリングを行います。スケジューラーを使えば、保存したシナリオを無人で実行できます。メール検証（Validity Engage を基盤とする機能）と変更通知も含まれており、サードパーティのガイドによれば、入力時点で重複をブロックする Validity の Salesforce ネイティブアプリ DupeBlocker も DemandTools のサブスクリプションに含まれます。製品の歴史は 2000 年にさかのぼり、G2 では 284 件のレビューで 5 点満点中 4.6 の評価です。

DemandTools でないもの：マルチ CRM ツール、エンリッチメントのデータソース、AI 製品のいずれでもありません。対応するのは Salesforce のみで、空の項目をサードパーティのデータで埋めることはせず、Validity の製品ページにも AI 機能の記載はありません。Validity が 2026 年に打ち出している MCP コネクターはメール製品 Validity Engage のもので、DemandTools のものではありません。

## RevOps チームが導入する理由

Salesforce の重複ルールは入力時にレコードをブロックまたはフラグ付けしますが、すでに溜まったバックログは片付けません。標準のマージ機能は一度に 3 件までで、しかも手作業です。DemandTools は大規模な組織を担当する管理者のためにこのギャップを埋めます。任意の項目の組み合わせによる照合ルール（誤った項目に入った電話番号のような項目間の比較を含む）、マスターレコードのルール、取引先責任者と取引先のリレーションのマージ、スケジュール実行できる一括マージがそろっています。

典型的なユースケースは次のとおりです。テリトリーの再設計を前に、300 ライセンスの組織の Salesforce 管理者が、孤立した 40,000 件のリードを変換し、正規化したドメインと会社名で既存の取引先にひも付け、長年のリストインポートで生まれた重複した取引先責任者をマージし、そのうえでバックログが再発しないよう週次の重複排除をスケジュール設定します。

## 料金

Validity は価格表を公開していません。2026-10-24 に Vendr のマーケットプレイスデータと公開情報で確認した内容です。

- **ライセンスの単位。** DemandTools の利用者数ではなく、Salesforce 組織のライセンス数で課金されます。つまり、200 ユーザーの組織で 2 人の管理者だけが使う場合も 200 ライセンス分を支払います。
- **DemandTools フル版。** Vendr の掲載価格は 1 ライセンスあたり年 $132（月約 $11）です。交渉後価格の中央値は、50 ライセンスで年 $4,825（定価 $6,600 から 27% 引き）、200 ライセンスで $16,764（$26,400 から 36% 引き）です。Vendr によれば、200 ライセンス以上では 40-55% の割引が見られます。
- **DemandTools Elements**（重複排除に特化したエディション）：Vendr によれば 25 ライセンスで $801 で、G2 と Capterra が示す 1 ライセンスあたり月 $2.67 と一致します。
- **変更点。** 2025 年 12 月、Validity のカスタマーサクセス・ディレクターが同社のコミュニティフォーラムで、Web ストアのプランを廃止し Enterprise プランに移行することを認めました。カードによるセルフサービス購入は事実上なくなっており、営業からの見積もりと年間（または 1-3 年）契約を前提にしてください。

## 最適なケース

- 100-2,000 ライセンスの組織で、数十万件規模の重複と標準化のバックログを抱え、市場で最も細かい重複排除とマージのルールを求め、デスクトップアプリの運用に抵抗がない Salesforce 管理者または RevOps リーダー
- 移行の前、買収後の組織統合の前、あるいはテリトリーとルーティングの再設計の前に Salesforce 組織をクリーンアップするチーム
- 向かないケース：HubSpot 中心のチーム、15,000 件のレコードしかない 20 ライセンスの組織（Salesforce 標準のルールと半日の作業で足ります）、本当の課題が空の項目であるチーム

## 代替ツールと選ぶべき条件

- **Salesforce の重複ルールと一致ルール**：無料で、すでに組織にあります。バックログが小さいならこちらを選びます。一括マージ、スケジュール実行、項目間の照合が必要なら DemandTools を選びます。
- **Plauti Deduplicate**（旧 Duplicate Check）：Salesforce の中でネイティブに動作し、無料エディションがあります。有料プランは Plauti 自身の 2023 年の比較記事で年 $588 からとされていました。データを組織の外に一切出せない場合や、ライセンス数のせいで DemandTools が高くつく場合に選びます。
- **Cloudingo**：Salesforce の重複排除を長く手がけるもう一つの専門ベンダーで、サードパーティの情報ではエントリー価格が年 $2,500-$10,000 とされています。デスクトップへのインストールより Web アプリを好むなら選びます。
- **[Insycle](/ja/tools/insycle/)**：レコード数による課金で、ユーザー数は無制限、HubSpot と Salesforce に対応します。HubSpot 中心の組織や、ライセンスは多いがレコードは少ない組織ならこちらです。50 ライセンス・80,000 レコードの場合、DemandTools は年約 $4,800-$6,600、Insycle Growth は $1,440 です。
- **[Openprise](/ja/tools/openprise/)** または **[ZoomInfo](/ja/tools/zoominfo/) Operations**（旧 RingLead）：データ品質の課題がマーケティングオートメーション、CRM、ルーティングにまたがり、数万ドル規模の予算がある場合に選びます。Salesforce ネイティブの取引先階層が必要なら [Traction Complete](/ja/tools/traction-complete/)、本当の課題がルーティングなら [LeanData](/ja/tools/leandata/) を選びます。
- **Salesforce API に対して動くエージェント**：このカテゴリーで最も急速に伸びているアプローチです。[Salesforce データクリーンアップ スキル](/ja/workflows/salesforce-data-cleanup-skill/)は、トークン代だけで Claude Code から照合ルールとマージ計画を作成します。技術に強い管理者が行う単発のクリーンアップにはこちらを選び、スケジュール化され監査可能なデータ衛生管理には DemandTools を残してください。

## 注意点

- **現在のプランが更新できない可能性があります。** Web ストアのプランが廃止されたため、セルフサービスの顧客は更新時に同等のプランが見つからないことがあります。対策：今すぐ更新日を確認し、90 日前に Enterprise の見積もりを依頼し、上記の Vendr の中央値を交渉に持ち込んでください。
- **ライセンス課金は、大規模で利用の少ない組織に不利です。** ツールを操作するのが 1-2 人の管理者でも、Salesforce の全ライセンス分を支払います。対策：契約前に Insycle のレコード課金と Plauti のネイティブアプリの価格で試算し、ライセンス数は契約期間とは切り離して交渉してください。
- **一括マージは元に戻しにくい作業です。** Salesforce はマージを取り消せません。マージで消えたレコードはごみ箱に入りますが、復元しても関連する活動は戻りません。対策：一括実行の前に対象オブジェクトを必ずエクスポートし、50 グループに絞ったサンプルでシナリオをテストし、残ったマスターレコードを目視で確認してください。
- **実行のたびに Salesforce の API 割り当てを消費します。** DemandTools は Salesforce API を通じて動作するため、大規模なスケジュール実行は組織の 1 日あたりの上限を連携ツールと奪い合います。対策：大きなジョブは夜間にスケジュールし、専用の連携ユーザーで実行し、最初のフル実行の後に Salesforce の設定画面で API 使用量を確認してください。

これらのツールを取り巻く運用モデル（データ衛生の責任者、最初に標準化すべき項目、実行頻度）については [CRM ハイジーン](/ja/learn/crm-hygiene/)を参照してください。
