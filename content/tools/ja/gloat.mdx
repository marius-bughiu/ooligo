## 概要

Gloat は大企業向けの社内タレントマーケットプレイスを販売しています。職務履歴、システム上の活動、本人が申告した関心から構築したスキルグラフを使い、従業員と社内の機会 — 正社員ポジション、短期プロジェクト、ギグ、メンターシップ — をマッチングします。この製品は今も存在し、今も主力です。プラットフォームページは配下に 7 つのモジュールを挙げています。Learning、Projects（**Mosaic** による業務の分解とマッチング）、Mentorships and Networking、Positions、Internal Hiring、My Team、Skills Landscape です。

変わったのは外側です。**2026 年 3 月 31 日**、Gloat は **Agentic HR Platform** として再ローンチし、サイトは同社をタレントマーケットプレイスのベンダーではなく「the AI-native system of action for workforce orchestration」と説明するようになりました。その下のエンジンが **Loomra** で、9 年分の企業データの上に構築されたワークフォース・コンテキスト・エンジンです。ナレッジグラフ、セマンティック埋め込み、スキルの推論とクラスタリング、キャリア軌跡のモデリング、企業規模のマッチングを組み合わせています。Gloat は人員再配置、キャリア開発、社内タレントソーシング、サクセッションプランニング、workforce planning、学習とリスキリングの各用途にプリビルトのエージェントを提供し、トランザクション型、ワークフロー型、戦略型に分類しています。

**2026 年 4 月 27 日**、これらのエージェントが Microsoft の中に入りました。Gloat Copilot Agent と Teams アプリが Microsoft Agent Store と Microsoft Marketplace に掲載され、従業員は Gloat を開かずに Teams のスレッドから再配置やキャリア異動について質問できます。Loomra は既存の HR システムを置き換えるのではなく、そこに接続します。

Gloat を最後に評価したのが社内モビリティのモジュールとしてなら、それは今やより広い製品の中の 1 ユースケースです。プラットフォームページ上の規模は、**エンタープライズ顧客 100 社以上、カバー対象従業員 500 万人、112 か国**。Mastercard、MetLife、Seagate、Telstra、Estée Lauder、Unilever、Schneider Electric、HSBC が公開名として挙がっています。

## Recruiting スタックに入る理由

**スキルグラフが資産であり、それは積み上がります。** プロジェクトへのアサイン、ポジション異動、学習の修了がすべてグラフを豊かにします。2 年間の利用が生むマッチング精度を、導入初日のシステムは再現できません。これは両刃で、注意点の項に再登場します。

**今の購買トリガーはキャリア開発ではなく再配置です。** エージェント一覧の先頭は人員再配置とサクセッションプランニングです。外部の採用枠を凍結した企業もポジションは埋める必要があり、Gloat の主張は「候補者はすでに給与台帳に載っている」というものです。これは recruiting 予算の会話であり、だからこそこのエントリは L&D ではなく recruiting のスタックに置かれています。

**配信はポータルではなく Teams と Copilot 経由です。** 社内マーケットプレイスは利用されないことで死にます。Microsoft Agent Store への掲載は、接点を従業員がすでにいる場所へ移します。

**API はドキュメント化済み、MCP サーバーはなし。** `developer.gloat.com` が API リファレンス — Candidacy API、Company API、Authorization API、Skills Foundation、Job Architecture、Talent Marketplace — を認証ガイドとともに公開しています。Gloat の MCP サーバーは存在しません。現時点のエージェントアクセスは Gloat 自身のエージェントと Copilot への掲載を通じたものであり、Claude を向ける先のサーバーではありません。要件が「自社のアシスタントがスキルグラフを照会する」であれば、それは REST API に対する開発です。

## 価格の実態

見積のみで、2026 年 9 月 4 日に確認済みです。`gloat.com/talk-to-us/` は金額もプラン名もティアも公開していません。デモ申込フォームであり、記載は「Fill out the form and our team will be in touch shortly.」だけです。規模を問わずセルフサーブの入口はありません。

以下の数値はすべて第三者の購買データとレビューからの三角測量です。交渉の材料に使い、定価として引用し返さないでください。

- **従業員あたり。** 概ね **1 人あたり月 $5-10**。アクティブシートではなく総従業員数に対して課金されます。ログインの有無にかかわらず全人員分を支払うため、ここが効いてくる数字です。
- **契約金額に直すと。** 従業員 5,000 人でおよそ **年 $300,000-$600,000**、20,000 人で **年 $1.2M-$2.4M**。1,500 人規模の導入は **年 $90,000-$180,000** 前後で、これが Gloat が商談に入る実務上の下限です。
- **導入費は別枠です。** エンタープライズのロールアウトは **6-12 か月**かかり、統合と教育のコストはライセンスの外側です。明示的に予算化してください。ビジネスケースが崩れるのはたいていここです。
- **年間のエンタープライズ契約**で個別見積、最大規模の導入にはボリュームティアがあります。

この製品について最も重要な構造的事実は価格モデルです。総従業員数に対する 1 人あたり課金は、利用率が低くても請求額は下がらず、下がるのはリターンだけ、ということを意味します。

## 最適な対象

**従業員およそ 10,000 人超のグローバル企業**の CHRO または Talent 責任者で、社内モビリティが担当者の決まった予算付きプログラムであり、圧力の源が求人票の量ではなく再配置である場合。Gloat が明確に勝つ限定条件は、Workday、SuccessFactors、Oracle HCM 上に載った多国籍の人員構成で、経営陣が従業員とマネージャーに、単一のスキルグラフに対して、新しいポータルを立ち上げずに Teams や Copilot からキャリアと配置の質問をさせたい場合です。

## 向かない対象

従業員およそ 5,000 人未満の企業です。1 人あたり課金と 6-12 か月のロールアウトを合わせると、この規模での社内異動 1 件あたりのコストは代替手段の価格を上回り、グラフに載る人数もチェンジマネジメントに見合うマッチングを生むには少なすぎます。5,000 人未満なら、すでに運用している [ATS](/ja/tools/ashby/) 内での社内公募にマネージャー推薦のプロセスを足せば、ここで得られるモビリティのほとんどは取れます。プログラムの持ち主がいない場合も誤った購入です。この経済性は従業員がスキルを自己申告し、マネージャーがプロジェクトにタグを付けることを前提としており、持ち主のいないマーケットプレイスは静かになりながら全従業員分を請求し続けます。

## 代替案との比較

- **[Workday](/ja/tools/workday/)** — 命題が「ベンダーを減らす」で、Workday がすでに人事システムの正となっている場合に選びます。自社のタレントマーケットプレイスとエージェント層が、どのみち締結する契約の中に入ってくるからです。Gloat のエージェント型ローンチに対する Josh Bersin の読みは構造的な問題を名指ししています。ServiceNow のアカウントは既定で ServiceNow へ、Workday のアカウントは Workday の Sana へ、Oracle のアカウントは Oracle の agent studio へ流れる、というものです。Gloat を選ぶのは、HCM 内蔵のマーケットプレイスが定着テストにすでに落ちている場合、あるいは人員が複数の HCM にまたがっていて、その上に単一のグラフが必要な場合 — Workday 自身の製品では扱えないケースです。
- **[Eightfold AI](/ja/tools/eightfold/)** — 同じスキルグラフが社内モビリティと同じ厳しさで外部ソーシングも支える必要がある場合に選びます。Eightfold のグラフは 10 億件超の公開プロフィールで学習しているため外部候補者のマッチングで強く、Gloat のグラフは自社の人員で学習しているため社内で強くなります。ロードマップが採用と再配置を 1 枚の talent intelligence 層で賄うものなら、Eightfold のほうが広く覆います。すでにいる人を動かすことが目的なら、Gloat のほうが効く場所で正確です。
- **[Beamery](/ja/tools/beamery/)** — 生きている競合脅威であり、最も新しく再確認すべき相手です。Beamery は talent CRM から Workforce Intelligence Suite へ立ち位置を移し、Ray というエージェント型のコンサルタントを載せました。社内モビリティは別ライセンスのモジュールではなく、そのスイート内の再配置ユースケースになっています。Gloat が主張しているのと同じ土俵に、候補者リレーション側から入ってきた形です。採用部門が予算を持ち、CRM とキャリアサイトが一緒に付いてくるなら Beamery を、HR が予算を持ち社内供給が問題のすべてなら Gloat を選びます。
- **HCM ベンダー自身の agent studio** — Oracle Agent Studio、SAP Joule Studio、Moveworks 買収後の ServiceNow、Microsoft Copilot Studio — がこのカテゴリで最も速く動く新規参入で、しかもバンドルで来ます。ただし 9 年分の人員データで学習したワークフォース・コンテキスト・エンジンを出しているところはなく、そこが Gloat の実際の防御線です。Bersin は、他の HCM ベンダーがそうしたシステムを構築したという認識はない、と述べています。この主張は鵜呑みにせず検証してください。同じ再配置の質問 3 本を、同じ評価期間内に Gloat と自社の HCM ベンダーのエージェントの両方にぶつけることです。

## 注意点

- **総従業員数に対する 1 人あたり課金は、コストを利用率から切り離します。** 20,000 人分の契約は、従業員の 2% が使っても 40% が使っても同額です。**ガード:** 署名前にビジネスケースへ利用率の下限 — 契約が回収できる月次アクティブ従業員数 — を書き込み、3 年間フラットのコミットを受け入れる代わりに、その数字に対する中間時点の料率見直しを交渉してください。
- **スキルグラフは参加がなければ劣化します。** マッチング精度は従業員のスキル自己申告とマネージャーのプロジェクトタグ付けに依存します。参加率が低いと悪いマッチングが出て、それがさらに参加率を下げます。**ガード:** 自己申告に頼るのではなく、ローンチ前に HCM のジョブアーキテクチャとシステム上の活動からグラフを初期投入し、プロフィール充足率は年次レビューではなく初週から週次指標として計測してください。
- **6-12 か月のロールアウトはスポンサーより長生きします。** チェンジマネジメント、統合、スキルデータの整備は 2〜3 回の計画サイクルにまたがり、社内モビリティのプログラムはその期間内に役員スポンサーを失います。**ガード:** 最初の本番稼働が 90 日以内に単一の事業部門で立つよう契約を段階化し、全社展開はその部門の再配置実績を条件にしてください。
- **エージェント型への転換は 5 か月前、マーケットプレイスは 9 年もの。** Loomra は 2026 年 3 月 31 日、Copilot への掲載は 4 月下旬です。マーケットプレイスには数年前まで遡るエンタープライズ事例がありますが、エージェントにはありません。**ガード:** マーケットプレイスではなくエージェントを本番運用している実名のリファレンス顧客を求め、トライアルは購入予定のエージェントそのものに絞ってください。エージェント側の証拠が薄ければ、マーケットプレイスは別建てで見積らせます。
- **MCP サーバーがないということは、エージェントアクセスは Gloat のエージェントが Gloat の画面上で動くことを指します。** 自社のアシスタントにスキルグラフを推論させる計画なら、それは有効化するコネクタではなく REST API に対する統合作業です。**ガード:** 開発を予算化する前に Candidacy API と Company API のスコープが想定するクエリを満たすか確認し、API アクセスを契約書に明記させてください。エンタープライズ HR プラットフォームがこれを上位ティアの裏に置いた例はすでにあります。
