## What it is

OpenCode is an MIT-licensed coding agent that works with any model provider. You describe a task, and it reads the repository, edits files, runs shell commands and reports back, the same loop as [Claude Code](/en/tools/claude-code/) or [OpenAI Codex](/en/tools/openai-codex/). The difference is that the agent is not tied to one lab: it connects to more than 200 providers, including the Anthropic, OpenAI and Google APIs, [OpenRouter](/en/tools/openrouter/), a self-hosted gateway such as [LiteLLM](/en/tools/litellm/), or local models.

It is built in the open by Anomaly, the company behind the project. The GitHub repository (anomalyco/opencode) had about 228,000 stars and more than 1,000 contributors when we checked on 22 November 2026; the "22M+ developers every month" figure on the homepage is the vendor's own and unaudited.

OpenCode 2.0, announced in mid-October 2026, made the client/server split the default. One local server runs the agent loop, and clients attach to it: a terminal UI that works over SSH, a desktop app for macOS, Windows and Linux (still labeled beta), mobile apps in early access, and an SDK. Version 2.0 also added background tasks and hot-reloaded skills and plugins.

## Why ops teams look at it

The RevOps or legal-ops engineer who writes CRM sync scripts and custom MCP servers usually ends up on whatever agent comes with the company's AI vendor. OpenCode appeals for three reasons:

- **No single-vendor lock.** The same agent, config and skills run against Claude, GPT, Gemini or a cheap open model. If the company switches its main AI contract, the engineering workflow does not move.
- **Existing seats work.** You can sign in with a ChatGPT Plus or Pro subscription or a [GitHub Copilot](/en/tools/github-copilot/) seat, so the agent can ride on spend you already have. Claude Pro and Max logins are not supported: OpenCode removed them in early 2026 after legal requests from Anthropic, so Claude models require an API key or the Console.
- **Central policy for a free tool.** Admins can push a system config file (`/etc/opencode/opencode.json` on Linux, `/Library/Application Support/opencode/opencode.json` on macOS or via MDM, `%ProgramData%\opencode\opencode.json` on Windows) that outranks user and project settings, restricting providers, tools and MCP servers.

## Pricing reality

The agent itself costs nothing. You pay for the model, in one of four ways:

- **Bring your own** — API keys from any provider, or a ChatGPT or Copilot login. $0 extra.
- **OpenCode Go** — a subscription for a curated set of 32 models, mostly open-weight (Kimi, GLM, Qwen, DeepSeek) plus a few closed ones. Go is $10/month, Go Plus $40/month, and Go Teams $20 per member per month with a two-member minimum. Each plan's allowance is set in dollars per model, and no more than 20% of it can be spent in any five-hour window or 50% in a week.
- **Console (pay-as-you-go)** — prepaid credits billed per token, with a processing fee of 4.6% + $0.31 on each credit purchase and no other markup. Workspaces carry per-member budgets.
- **Enterprise** — custom pricing, adding SSO (Okta, Entra ID, Google Workspace, any OIDC or SAML 2.0 provider), SCIM, budgets and policy controls.

The real number depends on the model, not the plan. On the Console, Claude Opus 5.5 costs $4 input / $20 output per million tokens; GLM 5.3, discounted, costs $0.56 / $1.76, roughly 7–11 times cheaper per token. Teams that route routine work (refactors, test fixes, config edits) to an open model and keep a frontier model for hard tasks get most of OpenCode's savings. Teams that run everything on Opus pay roughly what they would pay through the API anyway.

## Best for

RevOps engineers, GTM engineers and legal-ops or recruiting-ops technologists at companies that either refuse to tie their engineering workflow to one AI lab or already pay for ChatGPT or Copilot seats and want a capable terminal agent on top. The scoped case where it wins: a small ops engineering team (two to ten people) standardizing on one agent under a managed config, with provider keys held by the company and the expensive model reserved for the tasks that need it. On a Go Teams plan, that costs $240 per person per year before overflow usage.

## Not for

Teams that want a single throat to choke for both the agent and the model, with a signed DPA covering the whole chain. With bring-your-own keys, OpenCode is the client and each provider holds your data under its own terms; that is clean for engineers and awkward for procurement. It is also not for people who do not review diffs. The default permissions let the agent act without asking (see below), so a non-engineer belongs in a tool with tighter rails.

## Versus the alternatives

- **[Claude Code](/en/tools/claude-code/)** — the largest coding agent by revenue, included in Claude plans from $20/month. Pick it when Claude is the model you would use anyway and you want routines, Code Review and one vendor contract. OpenCode cannot use a Claude subscription, so running Claude through OpenCode means paying API rates.
- **[GitHub Copilot](/en/tools/github-copilot/)** — the largest installed base by seats, at $19 (Business) or $39 (Enterprise) per user per month. Pick it when the need is inline completion for many developers inside GitHub Enterprise. Many teams use both: the Copilot seat signs in to OpenCode.
- **[OpenAI Codex](/en/tools/openai-codex/)** — the fastest-growing entrant, included in ChatGPT plans. Pick it when the company has standardized on ChatGPT Business and wants OpenAI's own agent with OpenAI's admin and compliance features. If engineers prefer OpenCode's interface, the same ChatGPT login works there.
- **[Cursor](/en/tools/cursor/)** — pick it when the engineer wants to steer edits visually in an IDE rather than delegate from a terminal.

## Is it safe to standardize on?

On 17 October 2026, OpenCode disclosed that attackers had broken into an older system overnight and reached provider API keys stored in OpenCode Console workspaces, affecting 1.4% of Console users. TechCrunch reported charges in the hundreds of dollars on individual accounts and some above $1,000. Anthropic and Google blocked the exposed keys, OpenAI restored access and refunded its API customers, and OpenCode said refunds were underway. Its co-founder said the open-source CLI and app were not affected. As of 22 November 2026, OpenCode had not published how the attackers got in or how the keys were stored.

Our read: the local agent is a reasonable standard under a managed config; storing company provider keys in the Console is not, until a root-cause report exists.

## Watch-outs

- **The default policy allows almost everything.** Under the V2 permission model, every agent starts from an allow-all rule; only reading `.env` files asks first, and edits outside the project folder proceed without a prompt. Guard: ship a system-level `opencode.json` that sets `ask` or `deny` for `shell`, `external_directory` and any MCP tool that writes to the CRM. Policy actions in the managed config need version 2.2.3 or later, so enforce a minimum version.
- **Hosted key storage is the attack surface.** The October breach hit keys parked in the Console, not laptops. Guard: keep provider keys in your own secret manager or behind a gateway such as LiteLLM, issue each engineer a scoped key with a monthly spend cap at the provider, and revoke keys through SCIM when someone leaves.
- **Free and some paid models retain or train on data.** Retention varies by model: most open models served through Go are zero-retention, OpenAI, Anthropic and xAI models keep data 30 days, Google up to 55 days, and some free models may use prompts for training. Guard: set `OPENCODE_DISABLE_FREE_MODELS=1` or block the free tier in the managed config, and allowlist only providers your DPA covers.
- **Release churn after 2.0.** Users in the Hacker News launch thread reported that the npm package did not yet install 2.0 and hit postinstall errors. Guard: pin the version in your install script, let one engineer run a new release for a week before the team upgrades, and allowlist plugins through policy instead of letting each user install their own.
