## 概要

Inkeep は、Customer Experience チームとサポートチーム向けのエージェントプラットフォームです。構築方法は 2 つあります。サポートやコンテンツ担当者向けのドラッグ＆ドロップのビジュアルビルダーと、エンジニア向けの TypeScript SDK です。両者は双方向に同期するため、キャンバス上で編集したエージェントはコードの変更として現れ、その逆も成り立ちます。もともとは開発者ツール企業向けの、ドキュメントに基づく「AI に質問」ウィジェットから始まった会社で、現在は 3 種類のエージェントを提供しています。ドキュメントやヘルプセンターを参照する顧客向けアシスタント、Slack や Zendesk の中で CRM と請求システムの文脈を取り込んでサポート担当者に回答する社内コワーカー型エージェント、そしてイベントをトリガーにナレッジベースの更新、チケット作成、CRM レコードの書き込みを行うバックグラウンドの自動化エージェントです。エージェントは MCP 経由でツールを呼び出し、A2A API で相互に連携し、確認可能な OpenTelemetry トレースを出力します。

フレームワークは GitHub 上で `inkeep/agents` として、Elastic License 2.0 と Inkeep 独自の補足条項のもとで公開されており、Vercel または Docker でセルフホストできます。会社はサンフランシスコ拠点で、Y Combinator の W23 バッチに属し、Nick Gomez（CEO）と Robert Tran（CTO）が創業しました。2025 年 9 月に Khosla Ventures、GreatPoint Ventures、Y Combinator がリードする $13M のシードラウンドを調達しています。本番利用の顧客として Anthropic、Midjourney、Clay、PostHog、Pinecone、Postman、Clerk が名前を挙げられています。

## Customer Success スタックで採用される理由

- **エージェントを自社で所有し、バージョン管理できます。** クローズドなサポートエージェント（[Intercom](/ja/tools/intercom/) Fin、[Sierra](/ja/tools/sierra/)、[Decagon](/ja/tools/decagon/)）は、エージェントの定義をベンダー側に保持します。Inkeep ではエージェントは自社リポジトリ内の TypeScript プロジェクトです。コードレビューを通り、サポート責任者がキャンバス上でプロンプトを変更すればきれいな差分になり、フレームワークのコードが公開されているためベンダーが撤退しても残ります。
- **技術系プロダクト向けに作られています。** ドキュメント、GitHub、コミュニティのスレッドに基づく出典付き回答がこの会社の出発点で、顧客リストが開発者ツールの一覧のように見えるのはそのためです。チケットが「なぜこの API 呼び出しは 403 を返すのか」という種類なら、マクロで学習したヘルプデスク組み込みのボットより Inkeep の方が課題に近い位置にいます。
- **サポートの流れ全体を 1 つのプラットフォームで扱えます。** 同じビルダーで、公開ドキュメントアシスタント、[Zendesk](/ja/tools/zendesk/) のサイドバーで担当者を支援するコパイロット（根拠のある返信を下書きし、1 クリックでチケットに適用）、[Slack](/ja/tools/slack/) チャンネル内のエージェントをカバーします。3 つのベンダーではなく、1 つのナレッジ設定を保守すれば済みます。

## 料金の実態

Inkeep は定価を公開していません。選択肢は 2 つです。

- **オープンソース、ライセンス料 $0。** ビジュアルビルダー、SDK、MCP ツール、オブザーバビリティ、UI コンポーネントライブラリをセルフホストで使えます。支払うのはホスティング、データベース、選んだプロバイダーの LLM トークン、そして運用するエンジニアのコストです。サポートはコミュニティのみです。
- **Enterprise、個別見積もり。** マネージドホスティング、ドキュメントとヘルプセンターを対象とするマネージド RAG 検索レイヤー、Slack とサポートプラットフォームとの連携、PII 除去とデータ管理機能、SSO とユーザー管理、専任の forward-deployed エンジニアが加わります。Inkeep は想定利用量に基づいて見積もるとしており、無料のクラウドプランはなく、30 日間のデモ用サンドボックスのみです。

実務上の意味はこうです。以前のドキュメントアシスタントのセルフサーブプラン（第三者のディレクトリでは月額 $150〜$500 と掲載）はすでになく、forward-deployed エンジニア付きのモデルはクレジットカードで買うものではなく年間の Enterprise 契約です。比較対象となるマネージド型ドキュメントアシスタントの kapa.ai は月額約 $250 から始まり、年間契約では月額 $500 を超えます。Inkeep Enterprise はこの価格帯より上で予算を組み、解決件数課金のベンダーと比べる前に、会話量ごとの内訳付きで見積もりを取ってください。

## 最適な利用者

開発者ツールや API を提供する従業員約 50〜1,000 人の企業で、TypeScript プロジェクトを担当できるエンジニアがいるサポート責任者や developer experience 責任者です。ドキュメント Q&A、Zendesk や Slack での担当者支援、ナレッジベースの保守を 1 つのエージェントレイヤーでまかない、そのエージェントを自社リポジトリでバージョン管理したいチームに向いています。

エンジニアリングの時間がなく、チケットが消費者向けや EC（注文状況、返金、返品）中心のサポートチームには向きません。解決件数課金のヘルプデスク組み込みエージェントの方が早く稼働でき、解決したときだけ課金されます。

## 注意点

- **「オープンソース」はソース公開型の意味です。** ELv2 は、ソフトウェアをホスト型またはマネージド型のサービスとして第三者に提供すること、およびライセンスキーを回避することを禁じており、Inkeep はさらに補足条項を上乗せしています。**対策:** 顧客向けプロダクトをこの上に構築する前に、ライセンスと補足条項を法務に確認させ、デプロイするバージョンを固定してください。
- **セルフホストでは運用負荷が自社に移ります。** 稼働率、アップグレード、MCP 認証情報のシークレット管理、LLM 費用がチームの仕事になり、マネージド RAG 検索とサポートプラットフォーム連携は Enterprise の機能です。**対策:** セルフホストのコストをホスティング＋トークン＋運用に必要なエンジニアリング工数として算出し、$0 ではなくその合計を Enterprise の見積もりと比較してください。
- **料金が不透明で比較しにくいです。** 公開料金がないため、Fin や Zendesk と解決 1 件あたりの計算ができません。**対策:** 現在の月間ボリュームでの会話 1 件あたりの価格として見積もりを出してもらい、超過料金と更新時の値上げ上限を書面で確保してください。
- **シード段階のベンダーです。** 調達額 $13M は Sierra や Decagon と比べると小規模です。**対策:** Inkeep の Trust Center から最新の SOC 2 レポートを取り寄せ、ドキュメントとヘルプセンターを正本として維持し、エージェントレイヤーを置き換え可能にしておいてください。

## 代替ツール

[Intercom](/ja/tools/intercom/) Fin は AI サポートエージェントの市場シェア首位で、解決 1 件あたり約 $0.99 です。クローズドなエージェントを数日で稼働させたく、定義をベンダーが持つことを受け入れられるなら選んでください。[Zendesk](/ja/tools/zendesk/) 純正の AI エージェントはもう一方の既存大手で、すでに Suite を契約していてベンダーを 1 社にまとめたい場合に選びます。[Sierra](/ja/tools/sierra/) は最も急成長している新興勢力で、音声や深いバックエンド操作を伴う大量処理・個別価格の Enterprise 導入なら Sierra（または [Decagon](/ja/tools/decagon/)）を選んでください。用途がドキュメント Q&A だけでエージェントを構築しないなら、kapa.ai がより絞り込まれたマネージドの選択肢です。サポート向けのエージェントプラットフォームではなく汎用の自動化が必要なら、[n8n](/ja/tools/n8n/) や [Relevance AI](/ja/tools/relevance-ai/) の方が幅広いワークフローに対応します。プロダクトが技術系で、回答がドキュメントの中にあり、エージェントを自社で管理するコードに置きたいなら Inkeep を選んでください。
