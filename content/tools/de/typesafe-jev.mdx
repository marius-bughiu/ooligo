## Was es ist

Jev ist ein Modell von TypeSafe AI, das typisierte Fragen beantwortet, statt Text zu schreiben. Sie senden einen `state` (eine E-Mail, einen CRM-Datensatz, eine Vertragsklausel, als Text oder JSON) und eine oder mehrere benannte Fragen, und Jev liefert strukturierte Antworten: einen `choice` aus bis zu 255 von Ihnen definierten Optionen, einen `score` auf einer Skala mit bis zu 10 Stufen oder einen `noul`, eine Wahrscheinlichkeit von 0 bis 1, dass eine Aussage zutrifft. Choice- und Score-Antworten enthalten zusätzlich die vollständige Wahrscheinlichkeitsverteilung und einen `confidence`-Wert. Es gibt keine Prosa zu parsen und kein fehlerhaftes JSON, das erneut angefragt werden muss.

TypeSafe kam im September 2026 aus dem Stealth-Modus und gab am 9. Oktober 2026 eine Finanzierungsrunde über 870 Mio. US-Dollar bei einer Bewertung von 7,5 Mrd. US-Dollar bekannt, angeführt von Andreessen Horowitz, mit Sequoia und DCVC. Auf typesafe.ai ist das Produkt weiterhin als Early Access gekennzeichnet. Der Zugang läuft über einen einzigen REST-Endpoint (`POST https://api.typesafe.ai/v1/systemone`) sowie SDKs für Python und JavaScript. Die Dokumentation nennt keinen nativen Connector für Zapier, Make oder n8n; in diesen Tools rufen Sie Jev über einen HTTP-Request-Schritt auf.

## Wo es in die Ops-Automatisierung passt

Jev ist für die Entscheidung innerhalb einer Automatisierung gedacht, nicht für die Automatisierung selbst. Die konkreten Use Cases, in denen es seinen Platz verdient:

- **Ticket-Triage.** Ein einziger Aufruf fragt „Welche Queue?“ (choice), „Wie dringend?“ (score) und „Ist das eine Erstattungsanfrage?“ (noul) zum selben Ticket. TypeSafe wertet die Fragen parallel aus, eine zusätzliche Frage verändert die Latenz also kaum.
- **Vorprüfungen beim Lead-Routing.** Klassifizieren Sie ein Inbound-Formular oder eine Antwort nach Segment, Absicht und „Bestandskunde?“, bevor Ihr Router einen Owner zuweist.
- **Freigabestufen.** Spesen-Vorabfreigabe, Triage am Discount-Desk oder „Weicht diese Klausel von unserem Playbook ab?“ als Ja/Nein mit angehängter Wahrscheinlichkeit.
- **Freigabe von Tool-Aufrufen in Agents.** Fragen Sie Jev, ob die vorgeschlagene Aktion eines Agents zur Anfrage des Nutzers passt, bevor sie ausgeführt wird.

Das Muster, das TypeSafe dokumentiert, ist konfidenzgesteuertes Routing: oberhalb eines hohen Schwellenwerts automatisch handeln, im mittleren Band eine Bestätigung einholen und alles unterhalb von etwa 0,5 an einen Menschen geben.

## Preisrealität

Jev 1.13 und Jev 1.14 kosten jeweils 0,042 US-Dollar pro Million Input-Tokens, Output-Tokens sind kostenlos (Modellseite von TypeSafe, geprüft am 21. Oktober 2026). Eine Lizenz pro Nutzer bietet TypeSafe nicht an. Enterprise-Pläne bringen höhere Rate Limits und Zero Data Retention über den Vertrieb.

Bei Ops-Volumen ist die Rechnung ein Rundungsfehler. 100.000 Tickets pro Monat mit je etwa 1.500 Input-Tokens ergeben 150 Mio. Tokens, also rund 6,30 US-Dollar. Dasselbe Volumen kostet über die Decisions API von OpenAI (0,10 US-Dollar pro Million Input, keine Output-Gebühr) rund 15 US-Dollar. Mit einem allgemeinen Modell wie GPT-6 Luna über die Responses API sind es rund 17,50 US-Dollar, sobald Sie etwa 50 Output-Tokens pro Antwort bezahlen. Der Preis entscheidet diesen Kauf nicht. Entscheidend sind die Genauigkeit auf Ihren eigenen Labels und die Frage, ob die Konfidenzwerte auf Ihren Daten etwas aussagen.

## Am besten geeignet für

Einen Engineer in RevOps, Support Ops oder Legal Ops, der Triage oder Routing bereits über n8n, einen eigenen Service oder ein Agent-Framework betreibt und Geld oder Latenz für ein LLM ausgibt, nur um ein Label pro Datensatz zu erzeugen. Der Gewinn: Geschwindigkeit, nahezu keine Kosten und eine Wahrscheinlichkeit, auf die Sie Schwellenwerte setzen können.

**Nicht geeignet** für ein Team ohne jemanden, der eine API aufrufen und ein gelabeltes Testset pflegen kann, oder für einen Workflow, in dem die Entscheidung mehrstufiges Schlussfolgern, Arithmetik oder Datumslogik erfordert.

## Im Vergleich zu den Alternativen

**Die Decisions API von OpenAI** ist der direkte Wettbewerber und die Standardwahl, wenn Sie bereits auf OpenAI laufen. Sie ging am 6. Oktober 2026 auf `gpt-6-luna` in die Public Beta, mit denselben drei Fragetypen (predicate, choice, score), zu 0,10 US-Dollar pro Million Input-Tokens. Wählen Sie sie, wenn Sie ZDR, HIPAA-Eignung oder EU-Datenresidenz sofort und ohne Vertriebsgespräch brauchen oder nur einen Lieferantenvertrag wollen. Wählen Sie Jev, wenn Input-Kosten oder Latenz bei sehr hohem Volumen die Engstelle sind und Jev in Ihrer eigenen Evaluierung besser abschneidet als Luna. Mindestens ein Kommentator im HN-Thread zur Finanzierungsrunde berichtete genau das aus Produktions-Evals.

**Ein allgemeines LLM mit strukturierten Outputs (Modelle von [Claude](/de/tools/claude/), [ChatGPT](/de/tools/chatgpt/))** ist das, was die meisten Teams heute einsetzen. Bleiben Sie dabei, wenn die Entscheidung mehrstufiges Schlussfolgern braucht oder wenn Sie den Erklärungstext neben dem Label für einen Audit-Trail wollen.

**Die native Triage in Ihrem Helpdesk oder Router ([Zendesk](/de/tools/zendesk/), [Intercom](/de/tools/intercom/), [LeanData](/de/tools/leandata/))** ist die richtige Wahl, wenn die eingebaute KI oder die Regeln des Anbieters Ihre Kategorien bereits abdecken. Ein zusätzlicher Modellaufruf bringt dann eine Abhängigkeit ohne Gewinn.

## Worauf Sie achten sollten

- **„Confidence“ ist keine kalibrierte Genauigkeit.** Die Dokumentation von TypeSafe definiert sie selbst als Kennzahl dafür, wie stark die Wahrscheinlichkeitsverteilung konzentriert ist, nicht als gemessene Trefferquote. Kommentatoren auf HN bestritten die Kalibrierungsaussagen, und einige fanden allgemeine LLMs bei fachlichen Business-Labels genauer. Absicherung: Lassen Sie 200 bis 500 historische Datensätze mit bekanntem Ergebnis durch Jev laufen, tragen Sie die Genauigkeit pro Konfidenzband auf und setzen Sie jeden Schwellenwert anhand dieses Diagramms, Frage für Frage.
- **Dokumentierte blinde Flecken.** Die Notizen von TypeSafe zu Jev 1.13 nennen eine Bevorzugung der ersten Option bei Choice-Fragen, schwache Verarbeitung von Zahlen, Datumsangaben und doppelten Verneinungen sowie sinkende Genauigkeit, wenn der State irrelevante Details enthält. Absicherung: Berechnen Sie Datumswerte, Beträge und SLAs vor dem Aufruf im Code, kürzen Sie den State auf die relevanten Felder und mischen Sie die Reihenfolge der Optionen oder nutzen Sie das dokumentierte Self-Consistency-Muster bei Entscheidungen mit hohem Risiko.
- **Der State wird nicht als feindlich behandelt.** Laut denselben Notizen können eingeschleuste Anweisungen im Input die Antworten verändern, trotz des Marketing-Slogans „zero hallucinations“. Absicherung: Lassen Sie nie eine Jev-Antwort allein eine Erstattung, eine Löschung oder eine vertragliche Aktion auf Basis von Kundentext auslösen; verlangen Sie oberhalb einer Kostenschwelle eine zweite Prüfung oder einen Menschen.
- **Anbieter im Early Access, wandernde Aliase.** `jev-latest` und `jev-preview` zeigen bei neuen Releases auf andere Versionen, und die Dokumentation nennt keine Deprecation-Policy. Absicherung: Pinnen Sie `jev-1.13.0` (oder die Version, die Sie validiert haben), lassen Sie Ihr Eval-Set vor jedem Versionswechsel erneut laufen und kapseln Sie den Modellaufruf in einer einzigen Funktion, damit Sie an einem Nachmittag auf den Endpoint von OpenAI wechseln können.
