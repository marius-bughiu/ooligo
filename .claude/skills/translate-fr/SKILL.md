# translate-fr

Translate one item from `fr_TRANSLATION_QUEUE.md` into French, then commit and push to `main`. Fully autonomous — invoking this skill is the user's consent for that single page.

## How this skill is wired

- **Source of work**: `fr_TRANSLATION_QUEUE.md` at the repo root (regenerated by `npm run queue:translations`).
- **Staleness signal**: each translated MDX carries `source_sha256` — SHA-256 of the EN source's body. When the EN body changes, the hash drifts and the queue marks the page stale.
- **Autonomy**: this skill commits and pushes to `main` without asking. Do not invoke it if you don't want that to happen.

## The autonomous one-page workflow

Execute these steps in order. Stop at the first failure (don't push broken builds).

1. **Read the queue.** Read `fr_TRANSLATION_QUEUE.md`. If the body says "Queue empty — all content translated and current.", print one line ("FR queue is empty.") and exit.

2. **Pick the next item.** Take the **first** unchecked checklist item under the **first non-empty** collection section. Note `source` and `target` paths from the item's bullet lines, and whether the status is `missing` or `stale`.

3. **Read the EN source.** Read the full file at `source`. Use `gray-matter` semantics in your head: everything between the two `---` fences is frontmatter; everything after is the body.

4. **Translate the body** into French, applying the rules in this skill (glossary + register sections below). Translate the markdown body only. Frontmatter values are not translated except where noted in step 5.

5. **Compute the EN body hash.** Run `npm run hash:en --workspace=packages/pipeline -- <source>` and capture stdout. The single line printed is the SHA-256 of the EN file's body. You will paste this into the target's frontmatter in the next step.

6. **Write the target MDX** at `target`. Frontmatter rules:
   - Copy these fields verbatim from EN: `slug`, `canonical_slug`, `verticals`, and **all entity-specific fields** (`name`, `category`, `subcategories`, `pricing_model`, `pricing_starts_at`, `pricing_url`, `website`, `ai_native`, `mcp_available`, `api_available`, `integrations`, `ooligo_score`, `ooligo_score_breakdown`, `last_reviewed`, `last_refreshed`, `affiliate_link`, etc.). These are structural data, not translatable display strings.
   - Set `locale: fr`.
   - Set `ai_generated: true`, `ai_translated: true`.
   - Set `translated_from: en/<basename of source>.mdx`.
   - Set `translated_at` to now in ISO-8601 UTC with seconds precision (e.g. `"2026-05-02T22:58:47Z"`).
   - Set `translation_model: claude-opus-4-7`.
   - Set `source_sha256: "<hash from step 5>"`.
   - If the target already exists (stale case), overwrite it.

7. **Validate the build.** Run `npm run validate` and `npm run build`. If either fails, fix the translation file and retry. Never proceed with a failing build.

8. **Regenerate the queue.** Run `npm run queue:translations --workspace=packages/pipeline -- --locale=fr` (the workspace form is required — npm doesn't forward `--` args through the root passthrough). Confirm the item you just translated no longer appears in `fr_TRANSLATION_QUEUE.md`.

9. **Commit and push.** Stage exactly: the new/updated target file, `fr_TRANSLATION_QUEUE.md`. Commit with message `content(<collection>/fr): translate <slug>` (e.g. `content(tools/fr): translate claude-skills`). Include the `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>` trailer. Then `git push origin main`.

10. **Report.** One sentence: which slug was translated, status before (missing/stale), commit SHA.

### Fixed translations (anglicisms standard in French tech)

```
lead       → lead
pipeline   → pipeline
outbound   → outbound
inbound    → inbound
stack      → stack
workflow   → workflow
prompt     → prompt
agent      → agent
skill      → skill   (when referring to Claude Skills specifically)
email      → email   (don't force "courriel")
upload     → upload  (don't force "téléversement")
```

### Regional register — Metropolitan French, formal "vous"

- Default to **"vous"** (formal you) — standard for B2B audience.
- Metropolitan French (France) — not Quebec. Avoid Quebec-only vocabulary ("courriel", "téléversement", "fin de semaine") unless the EN explicitly demands it.
- Anglicisms standard in French tech writing: **email**, **workflow**, **pipeline**, **agent**, **lead** stay in English. The Académie's preferred neologisms ("courriel", "fluence") feel forced in tech contexts.
- Use French typographic conventions: non-breaking space before `: ; ! ?` and inside « » quotes.
- Audience: French-speaking B2B operators across France, Belgium, Switzerland, Luxembourg, Quebec (readers comfortable with Metropolitan French).
- Keep the original voice: confident, opinionated, structured. We rank, we recommend, we say what's bad. Don't soften into G2-style hedging.

### Quality bar

**Translate; don't re-author.** The FR variant says the same things the EN variant says — same opinions, same recommendations, same product judgments. If the EN entry says "Apollo is the right pick under $10M ARR," the FR entry says the same. Never inject locale-specific opinions or restructure the argument.

If you spot a factual error in the EN source while translating, **stop and surface it** in your final report — don't silently "fix" it in the translation. The fix belongs in the EN source as a separate change.
