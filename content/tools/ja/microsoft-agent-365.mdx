## これは何か

Microsoft Agent 365 は、Microsoft テナント内の AI エージェントを統括するコントロールプレーンです。組織内のすべてのエージェントをレジストリで管理し、Entra Agent ID によって一つひとつに ID を与え、それらのエージェントが何に接続しているかをマッピングし、Conditional Access、Purview、Defender が従業員に対してすでに効いているのと同じように、自律的に動くソフトウェアに対しても効くための接続点を提供します。一般提供は **2026年5月1日** に開始され、同じ日に Microsoft は Entra 管理センターにあった独立した Entra Agent Registry のブレードを廃止してここに統合しました。コントロールプレーンは 2 つではなく 1 つになります。

何よりも先に直しておくべき誤解があります。**Agent 365 はエージェントを作りませんし、実行もしません。** 作るのは Copilot Studio と Microsoft Foundry です。Agent 365 は作られたものを統治します。エージェントが欲しいという理由でこれを買うのは、このカテゴリで最も高くつく読み違いです。本当に必要だったライセンスは、その下にあるベースのスイートだからです。

## ops チームがここにたどり着く理由

きっかけがセキュリティ要件であることはほとんどありません。きっかけは、CRM や ATS、契約リポジトリに書き込めるエージェントが何個あるのかと誰かが尋ね、その場の誰も答えられない瞬間です。エージェントは部門ごとに 1 つずつ増えていきます。RevOps のリーダーがルーティングのエージェントを組み、リクルーターがスクリーニングのフローをつなぎ、legal ops が intake のトリアージを立ち上げる。そしてそのどれもが、作った本人として認証されます。一覧はなく、オーナーの列もなく、トークンを借りた人間とは別の監査対象も存在しません。

Agent 365 はその問いにインベントリで答えます。レジストリの対象は、Microsoft 製のエージェント、Copilot Studio と Foundry で作られたエージェント、Agent 365 向けに設定済みで提供されるパートナー製エージェント（提供開始時点で Genspark、Zensai、Egnyte、Zendesk）、そしてローンチリストに載る agent factory 由来のエージェント、すなわち Kasisto、Kore、[n8n](/ja/tools/n8n/) です。n8n 上で作られたエージェントには Entra Agent ID が自動で払い出され、自前の ID 設計をしなくても管理センターに現れます。動く自動化を統治された自動化に変える経路としては、これが最も安価です。

## 価格の実態

- スタンドアロンで **1 ユーザーあたり月額 15.00 USD**、年額払い。
- **Microsoft 365 E7（1 ユーザーあたり月額 99 USD）にバンドル** されています。2026年5月1日に投入された Frontier Suite で、E5、Copilot、Agent 365 をまとめたものです。
- **E5 には含まれません。** 2026年6月の Product Terms では、前提条件として Microsoft 365 E5、Microsoft 365 Business Premium、または Defender + Purview Suite Frontline Worker の組み合わせが必要です。

15 USD はアドオンであって入口価格ではありません。実際の価格帯は、すでに何を持っているかで完全に変わります。

- **すでに E5 を導入済み、200 席の場合：** 15 USD × 200 = 現在の支払いに加えて **年間 36,000 USD**。
- **Business Premium の場合、200 席：** 22 USD + 15 USD = 1 ユーザーあたり月額 37 USD、総額 **年間 88,800 USD**。
- **前提条件を満たすベースが何もない場合、200 席：** E5 の 60 USD に 15 USD を足して 1 ユーザーあたり月額 75 USD、**年間 180,000 USD**。ここまで来ると買っているのはセキュリティスイートであり、エージェントガバナンスはその付随物です。その場合は購買判断をスイートの側で行うべきです。

多くの予算が読み違えるのは単位です。Agent 365 は **エージェント単位ではなく人間のユーザー単位** でライセンスされます。1 ライセンスで、その人が管理・スポンサー・所有するエージェント、およびその人のために働くエージェントのすべてがカバーされます。40 個目のエージェントは無料です。201 人目の従業員は月額 15 USD です。コストは人員数に連動し、リスクはエージェント数に連動します。そして請求書に載るのは、その 2 本の曲線のうち片方だけです。

実行は別の請求書になります。エージェントの構築と実行は Copilot Studio（25,000 クレジットあたり月額 200 USD のキャパシティパック、または従量課金で 1 クレジット 0.01 USD）か、Azure 請求書上の Microsoft Foundry を通じて課金されます。エージェントが作業できる管理環境である Windows 365 for Agents は、従量課金で VM 1 時間あたり 0.40 USD、米国のみ、プレビュー段階です。

## こんなチームに向く

**すでに E5 または Business Premium を契約している Microsoft 中心の企業** の IT または ops のリーダーで、記録システムへの書き込み権限を持つすべてのエージェントについてオーナーを明示したインベントリを作る必要があり、Conditional Access と Purview のポリシーを、エージェントが成りすます人間ではなくエージェント自身に効かせたい場合です。文句なしに勝つ限定的なケースは、Copilot Studio、Teams、n8n でエージェントが動いていて、それぞれを誰が承認したのかを問うコンプライアンスレビューが控えている ops 組織です。

## 向かないケース

Microsoft のスイートを土台に持たないまま、[n8n](/ja/tools/n8n/) やワークフロービルダーで 2〜3 個のエージェントを動かしている 5〜30 人のチームです。前提条件のライセンス連鎖のほうがエージェントより高くつきますし、同じ統制、つまりエージェントごとのオーナー、書き込みに対する承認ゲート、実行ログは、[AI エージェント ops スタック](/ja/stacks/ai-agent-ops-stack/) からライセンス費用の何分の一かで手に入ります。重要なエージェントが人間の操作する [Claude](/ja/tools/claude/) や [ChatGPT](/ja/tools/chatgpt/) のセッションである場合も、これは誤った買い物です。どちらもパートナーリストに載っておらず、レジストリにも現れず、統治するならそれぞれの管理コンソールで行うしかありません。

## 代替との比較

- **Okta for AI Agents** — 2026年4月30日に一般提供が開始されました。エージェントのレジストリ、静的な API キーの代わりに使う短命な認証情報、SIEM に送られるエージェントのアクティビティログ、そしてアプリ境界をまたぐエージェントのためのオープンプロトコルである Cross App Access（XAA）を備えます。ID 基盤がすでに Okta 中心で、重要なエージェントが Microsoft 以外の SaaS 上で動作するなら Okta を選んでください。Microsoft のコントロールプレーンは自社テナントの内側で最も強く、その外側では最も薄くなります。
- **Salesforce Agentforce** — 統治すべきエージェントが Salesforce の中に住み、Salesforce のデータに対して動作するなら、こちらを選んでください。レコードの隣に座るガバナンスは、そこへフェデレートするガバナンスより立証が容易です。Salesforce 中心のレベニュー組織なら、他社の管理センターにレジストリのエントリを 1 行持つよりも、ネイティブの統制のほうが遠くまで行けます。
- **Token Security** と独立系の非人間 ID プラットフォーム — 本当の問題が、企業として承認済みのエージェント台帳ではなく認証情報の氾濫（サービスアカウント、API キー、OAuth 付与）であるなら、こちらを選んでください。ただし契約前にこの領域の再編を確認してください。Cisco は 2026年5月に Astrix を買収し、SailPoint は 2026年6月29日に Entro の買収を完了し、Cyera は 2026年7月28日に Oasis に関する LOI を締結しました。独立系はこの市場で縮小している側です。

## 注意点

- **面白いシナリオはまだプレビューです。** 自律エージェントと non-OBO エージェント、つまりサインイン済みユーザーの代理ではなく自身のアクセス権で動作するエージェントはパブリックプレビューのままで、GA までは課金されません。ops チームが無人で動かしたいものの大半はここに含まれます。**ガード：** コンプライアンスの説明は GA 済みの機能だけを根拠に書き、プレビューのカバレッジは、なくても出荷できる加速材として扱ってください。監査日を確約する前に、プレビュー一覧を必ず確認し直してください。
- **ユーザー単位の価格はエージェントの増殖を隠します。** エージェントが 12 個から 60 個に増えても請求書は動かないため、予算のシグナルは一度も鳴りません。**ガード：** 毎月、レジストリを実名のオーナー一覧と突き合わせ、オーナーのないものは廃止してください。このレビューはポリシー文書の一文ではなく、担当者を割り当てたカレンダー上の予定にしてください。
- **前提条件の連鎖こそが本当の見積もりです。**「1 ユーザーあたり 15 USD」という見積もりは、正確ではあっても不完全です。エージェント向けの Conditional Access は下限として M365 E3 を必要とし、エージェント向けの Identity Protection は E5 を必要とし、脅威ハンティングは別途 Defender for Cloud Apps のライセンスを必要とします。**ガード：** 承認の前に連鎖全体、つまりベースのスイートにアドオン、さらに約束しようとしている個々の統制の裏にあるセキュリティ SKU まで見積もり、統制と SKU の対応関係をリセラーから書面で入手してください。
- **ポータルにエクスポート履歴もスナップショット差分もありません。** 今日時点のレジストリは見られますが、四半期を通じてどう変わったかを監査人に示すのは自分の仕事です。**ガード：** 初日から、Graph API 経由で毎月レジストリを自社のストレージに取り込んでください。差分が必要になる最初の 1 回は、それを再現できない最初の 1 回でもあります。
