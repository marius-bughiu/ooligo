## 概要

Linear は、ソフトウェアチーム向けに設計された、明確な思想を持つプロジェクト管理ツールです。キーボード操作を前提とし、イシュー、プロジェクト、サイクル、ロードマップというデータモデルを備えています。オプスチームが社内施策に採用してきた理由は単純で、[Notion](/ja/tools/notion/) のデータベースより構造を強制し、Jira より儀式が少ないからです。

2026 年に 2 つの変化があり、どちらも購買判断に効きます。まず有料プランの改称と価格改定です。Standard と Plus は廃止され、年額請求で **Basic が $10、Business が $16**（ユーザーあたり月額）に置き換わりました。次に、Linear は製品をエージェントのホストに変えました。Linear Agent が 2026-03-24 にパブリックベータ、前払い AI クレジットを使う coding sessions が 2026-06-11、Loops が 2026-07-20 に登場しています。Linear を「API 付きの高速なイシュートラッカー」と説明していたこのページの旧版は、もはや製品の全体像ではありません。

## オプススタックに登場する理由

- **速度そのものが機能です。** 100 ミリ秒を下回る操作レスポンスと、あらゆる画面で使えるコマンドパレット。UX の細部に聞こえて、実際にはプロセスの変化として働きます。オプスチームは、そうでなければ登録しなかったイシューを登録するようになります。
- **既定で構造化されています。** サイクル、ステータス、優先度、ラベル、プロジェクトが最初から揃っています。スプレッドシート 3 枚に散らばるはずだった RevOps の施策が、状態遷移を持つ 1 つのオブジェクトモデルに収まります。
- **Linear Asks。** Slack で立った社内リクエストが、担当者とステータスを持つ Linear のイシューになります。今は DM で受付を回しているオプスチームにとって、これが Business プランで最も価値のある要素であり、エンジニアリング以外のチームが Linear を買う理由です。
- **ワークスペースのメンバーとしてのエージェント。** Linear Agent はイシューに割り当て、プロジェクトに追加し、コメントでメンションできます。トリアージ、ワークスペースに関する質問への回答、プロジェクト更新のドラフト、フォローアップ作業の起票を行います。Free を含む全プランで利用でき、クレジットも消費しません。
- **自社製の MCP サーバー。** `https://mcp.linear.app/mcp` でホストされ、読み取り専用エンドポイントは `https://mcp.linear.app/mcp/readonly` です。Claude、Cursor、VS Code、Windsurf、Zed が直接接続するため、外部エージェントは連携を自作せずにイシューを読み書きできます。このカテゴリで保守された自社サーバーを出しているツールはごく少数です。

## 料金

2026-09-08 に `linear.app/pricing` で検証しました。以下のユーザー単価はすべて年額請求です。月額請求は高くなるため、別途明記します。

- **Free** — $0。**250 イシュー、2 チーム**が上限で、メンバー数は無制限、アップロードは 10 MB まで。エージェントプラットフォーム、Linear Agent、API/Webhook アクセスを含みます。
- **Basic** — **年額 $10/ユーザー/月、月額 $12/ユーザー/月。** イシュー無制限、5 チーム、ファイルアップロード無制限、管理者ロール。
- **Business** — **年額 $16/ユーザー/月、月額 $18/ユーザー/月。** チーム無制限、プライベートチーム、ゲスト、Triage Intelligence、Code Intelligence、Loops、Linear Insights、Linear Asks、Zendesk と Intercom の連携。MCP アクセスはこのプランに載ります。
- **Enterprise** — 個別見積もり、年額請求のみ。SAML と SCIM、詳細な管理者制御、移行支援、請求書・発注書での支払い。

旧数値に対する訂正が 2 点あります。Basic は Standard を置き換え、入口価格は **$8 から $10 へ、25% の上昇**。Business は Plus を置き換え、**$14 から $16 へ、14% の上昇**です。年額請求は有料 2 プランとも 1 席あたり年 $24 の節約になります。

**見落とされるのは AI クレジットの行です。** どのプランにも含まれていません。クレジットは別途購入し、購入から 12 か月で失効します。必要になるのは coding sessions と Loops で、Linear Agent 自体には不要です。coding sessions はモデルのトークンをプロバイダー公表レートでマークアップなしに課金し、加えてサンドボックス実行時間が **20 分ブロックあたり $0.25** かかります。coding session を伴わない Loop の 1 回の実行は、典型的に **$0.07–$0.20** です。有料プランのワークスペースには 2026-06-11 のローンチ時に、有効ユーザー 1 人あたり $20 相当のプロモーション枠が付与されました。これは 1 回限りの付与であり、毎期の枠ではありません。

Business を使う 25 人のオプスチームの実勢レンジは、席料で **年 $4,800**、これに Loops の消費が乗ります。トリアージされた各イシューで loop が発火し、月 200 イシューなら、クレジットは **年 $170–$480** 前後に着地します。クレジットは別行で予算化してください。サブスクリプションの請求書には現れません。

## 適している相手

エンジニアリングがすでに Linear で動いており、オプスチームが 2 つ目のツールではなく 1 つのイシューモデルを求めている企業の、RevOps および Talent の責任者です。Business プラン単体を正当化する限定的なケースはこれです。Slack の DM 受付を Linear Asks に置き換え、社内リクエストに担当者、ステータス、そして報告できるサイクルタイムの数字を持たせること。

エンジニアリングが Jira にいてオプスが Linear を望む場合、論拠は弱くなります。拡張ではなくツールの追加であり、ツール間の受け渡しは手作業のまま残ります。

## 代替候補との比較

- **Jira** — シェア首位。カスタムフィールド、プロジェクトごとのカスタムワークフロー、そして Linear が意図的にモデル化を拒む承認フローが必要なら Jira です。Jira はあなたのプロセスに合わせて曲がり、Linear は自分のやり方の採用を求めます。Atlassian のエージェント層は [Atlassian Rovo](/ja/tools/atlassian-rovo/) で $5/ユーザー/月、既存の Jira 資産に AI を載せる最も安い手段です。
- **Asana または Monday.com** — マーケティング、財務、法務が主要ユーザーなら、このどちらかです。Linear のモデルはイシュー、サイクル、リリースを前提にしており、キャンペーンとカレンダーで計画するチームは 1 四半期で離脱します。
- **[Notion](/ja/tools/notion/)** — 隣接領域で最も成長が速い参入者で、現在はエージェントとデータベースを 1 つの面として売っています。仕事の実体がドキュメントで、その上に軽い追跡が乗る程度なら Notion です。ただしサイクルタイム、スループット、報告可能な状態遷移が必要になった時点で、Notion のデータベースは仕事の代わりにあなたが保守する対象になります。切り分けの詳細は [Notion vs Linear](/ja/comparisons/notion-vs-linear/) の比較で扱っています。
- **[Productboard](/ja/tools/productboard/)** — 仕事が違います。ロードマップと顧客インプットの優先度づけで Linear の上に位置し、多くのチームは選ばずに両方を運用しています。
- **Free のまま使う** — オプスチームのイシューが累計 250 未満で、2 チーム以内に収まるなら、無料プランにエージェントと API が含まれています。アップグレードはイシュー上限が効いてきてからで、それ以前は不要です。

## 注意点

- **AI クレジットは別売りで、失効します。** Loops と coding sessions にはどのプランにも同梱枠がなく、未使用クレジットは 12 か月で失効します。*ガード:* プロモーション枠で Loops を 1 か月回し、実行あたりの実コストを $0.07–$0.20 のレンジと突き合わせて測り、1 年分を前払いするのではなく、その実測値に対してクレジットを購入してください。
- **MCP と Asks は Basic ではなく Business です。** オプスチームが実際に Linear を買う理由になる 2 つの機能が $16 のプランにあるため、この用途の実質的な入口価格は $10 ではなく $16 です。*ガード:* パイロットは最初から Business で見積もってください。Basic のパイロットは、運用しない製品を検証することになります。
- **思想は機能であり税でもあります。** Linear は仕事を 1 通りにしかモデル化せず、例外を吸収するための設定を足しません。*ガード:* 展開前に、Linear がモデル化しないチームのワークフローを 2 つ名指しし、それがどこに置かれるかを決めてください。文書化された例外は問題ありませんが、後から発見された例外はスプレッドシート上の影の運用になります。
- **カスタムフィールドとビューは依然として Jira に劣ります。** 改善はしていますが、レポーティングがプロジェクトごとのカスタムスキーマに依存しているなら天井に当たります。*ガード:* 必須の 3 本のレポートは移行後ではなく、トライアル中に作ってください。
- **無料プランの上限はイシュー数であって人数ではありません。** 活動中のオプスチームにとって 250 イシューは低い天井で、メンバー無制限が Free を実際より広く見せます。*ガード:* Free を恒常的なプランとして扱う前に、月間のイシュー量を見積もってください。大半のオプスチームは 1 四半期で 250 を超えます。
- **Loops は Linear 自身のオブジェクトモデルでしか発火しません。** 受信メール、カレンダーの変更、CRM のフィールド更新といった外部トリガーでは Loop は始まりません。*ガード:* 自動化を Linear の外から始める必要があるなら、前段に [Zapier](/ja/tools/zapier/) か Webhook を置き、そこから Linear のイベントを作らせてください。
