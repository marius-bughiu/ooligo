## 何であるか

Composio はエージェントの下に位置する認証とツール呼び出しのレイヤーであり、エージェント本体ではありません。1,000 を超える連携先 — Gmail、[Slack](/ja/tools/slack/)、GitHub、[Notion](/ja/tools/notion/)、[HubSpot](/ja/tools/hubspot/)、[Salesforce](/ja/tools/salesforce/)、[Linear](/ja/tools/linear/) — に向けるだけで、OAuth の一連の手続き、トークンの保管、リフレッシュ、サンドボックス実行を引き受けるため、エージェント側のコードが認証情報に触れることは一度もありません。Python と TypeScript の SDK を提供し、Anthropic、OpenAI、Vercel AI SDK、OpenAI Agents SDK 向けのフレームワークパッケージ、`v3.1` の REST API、そして [Claude](/ja/tools/claude/) Desktop や [Cursor](/ja/tools/cursor/) が直接つなげる Sessions 経由のホスト型 MCP エンドポイントを備えます。

同社は Lightspeed がリードする 2,500 万ドルのシリーズ A を調達し、400 万ドルのシードを含めて総額 2,900 万ドル、2026 年 5 月 31 日時点の従業員数は 71 名です。SOC 2 と ISO 27001:2022 を取得しており、顧客ロゴとして Glean、Zoom、AWS、Google、Wix、ClickFunnels を掲げています。

## 実際に取り除く問題

エージェントのツールアクセスを自前で作るとは、ベンダーごとに OAuth クライアントを登録し、リフレッシュトークンを保管し、ベンダー各社の有効期限の扱いに対応し、モデルが呼び出せるツールスキーマを書き、それをアプリの数だけ繰り返すということです。ベンダーの認証仕様は自社ではなくベンダーの都合で変わるため、恒久的な保守コストとして残り続けます。

Composio はこれを 1 回の接続呼び出しにまとめます。Sessions は事前に用意した auth config を要求せず実行時にエンドユーザーを認証し、ツールは 1 つずつ配線するのではなく意図に基づいて選択されます。5 つ以上の SaaS に書き込む社内エージェントを立ち上げるチームにとって、この領域で動くツール呼び出しに最短で到達できる選択肢です。アーキテクチャ上もっとも近い競合である Arcade.dev は自社製 MCP サーバーが約 80 なのに対し、Composio のカタログは約 1,000 です。

## 価格の実像

新しい価格は 2026 年 8 月 15 日以降の登録に適用されます。

- **Free** — 月 10 万ツール呼び出し、月 5 万トリガーイベント、接続アカウント無制限、チームメンバー 3 名、ログ保持 7 日。ハードキャップで、上限に達すると利用が停止し、課金は一切発生しません。
- **Pro** — 月 29 ドルに月次の利用クレジットが含まれ、以降はツール呼び出し 1 件あたり 0.0003 ドル、トリガーイベント 1 件あたり 0.003 ドル。メンバー無制限、ログ保持 30 日、閲覧専用のダッシュボードロール付き。アドオンは IP 許可リスト、1 件 0.0003 ドルの BAA、1 件 0.0001 ドルのゼロデータ保持です。
- **Enterprise** — コミット数量に基づく個別見積もり。KMS プロキシ、SSO/SCIM、より高い API レート制限、MSA/DPA/SLA はこの階層です。

実際の価格帯はこうです。試作は無料で済み、月 50 万呼び出しの本番エージェントで月 150 ドル前後、月 200 万呼び出しで月 600 ドル前後になります。1 呼び出しあたり 0.0003 ドルで、これは Arcade.dev が含みの 2,000 実行を使い切った後の 0.01 ドルに対して 33 倍の開きがあり、Zapier MCP のプラン内単価である約 0.069 ドルに対しても同様です。Zapier の MCP 呼び出しは 1 件で 2 タスクを消費し、月 69 ドルの Team プランに含まれるのは 2,000 タスクだからです。認証済みツール呼び出し 1 件あたりの価格で、Composio はこの領域で 2 桁安く、それが最大の購入理由です。

**コストの落とし穴はツール呼び出しではなくトリガーイベントです。** 単価はツール呼び出しの 10 倍で、流量の多い受信トレイに対するポーリング型トリガーは、エージェントがそのイベントに反応するかどうかに関係なく課金されます。

## 最適な相手

5 つ以上の SaaS に対して認証済みの*書き込み*アクセスを必要とする社内エージェントを、ベンダーごとに OAuth サービスを作る予算が出ない期限のなかで構築する AI プラットフォームエンジニア、または ops エンジニアリングの責任者です。明確に勝てる限定条件は、Slack と Linear を読み、HubSpot や Salesforce に高い呼び出し量で書き込むエージェントを出す RevOps や Customer Success のチームです。

## 向かない相手

「リフレッシュトークンを保持しているのは誰か」への答えが「自社」でなければならない案件を、Free や Pro の予算でやろうとする場合です。KMS プロキシによる認証情報の保管は Enterprise にあります。Legal Ops が契約書リポジトリを、Recruiting が候補者の個人データを持つ ATS をつなぎ、セキュリティレビューが顧客管理鍵を要求するなら、セルフサーブの階層はその問いに答えません。Enterprise を買うか、別のものを自社ホストしてください。非エンジニア向けのレイヤーでもありません。これは SDK と API であって、キャンバスではありません。

## 代替候補との比較

- **[Zapier](/ja/tools/zapier/) MCP** — 9,000 を超えるアプリを擁し、導入規模でこのカテゴリの首位を大きく引き離しています。Free を含む全 Zapier プランに標準で含まれます。すでに社内で Zapier に支払っており、エージェントの量が月 1,000 ツール呼び出し程度に収まり、設定する人がエンジニアではなく ops のジェネラリストである場合に選んでください。量が増えた瞬間に成立しなくなります。タスク課金は Composio の 1 呼び出し単価のおよそ 230 倍だからです。
- **Arcade.dev** — この領域でもっとも成長の速い新規参入であり、Composio の中心的な弱点に対する構造的な答えです。呼び出し時点のユーザー単位 OAuth とアクション単位の権限の積集合をとる方式なので、実際に使われるトークンは単一のプラットフォーム鍵ではなく、要求を出したエンドユーザーのものになります。監査要件が「この書き込みをどの人間が承認したかを証明すること」である場合、あるいはプラットフォーム認証情報 1 つの漏洩が許容できない影響範囲になる場合に選んでください。その代償はカタログの幅と価格です。
- **[n8n](/ja/tools/n8n/)** — データレジデンシーやセキュリティレビューが、そもそも第三者にトークンを保持させることを禁じている場合に選んでください。自社ホストは認証情報の保管を自社インフラに戻します。その代わり、Composio を買って消したはずの認証保守を引き受けることになります。

どれも合わない場合、正直な代替案は、本当に重要な 3 つのアプリに対して直接 API クライアントを書き、このレイヤーを飛ばすことです。連携先が 5 つ程度を下回るなら、ゲートウェイは余分な負荷です。

## 注意点

- **Composio はあなたの OAuth トークンを保持しており、その保管庫はすでに侵害されています。** 2026 年 5 月 21 日、同社は攻撃者が約 5,241 件の API キーと 5,001 件の GitHub OAuth トークン、さらに少数の Jira、Slack、HubSpot、Linear、Notion、Google Calendar のトークンと 12 件の Gmail トークンを窃取したインシデントを公表しました。初期侵入経路は Composio 従業員の Gmail OAuth トークンの侵害で、攻撃者は受信トレイへのアクセスを得たうえで、マジックリンクのログインメールを傍受し、顧客の機密情報を保持する本番システムに到達しました。GitHub のトークンは予防的に失効されました。対策は次のとおりです。Composio の共有開発者アプリを使わずベンダーごとに自社の OAuth クライアントを登録し、失効をサポート依頼ではなく自社の操作にしてください。各接続をエージェントに必要な最小限の権限に絞り、GitHub、Salesforce、契約書や個人データのリポジトリに対する書き込みスコープは Free と Pro から完全に外してください。書き込み可能な接続は Enterprise の KMS プロキシの背後に置いてください。そしてローテーションの手順書は、次の公表の後ではなく本番投入の前に書いてください。
- **ログ保持期間は、インシデントを調査するのに必要な期間より短いです。** Free で 7 日、Pro で 30 日です。認証情報のインシデントは発生から数週間後に発覚するのが通例で、今回も誰かが気づく前に従業員の受信トレイ経由で本番に到達していました。対策は、初日から日次ジョブで Composio のログを自社の SIEM やオブジェクトストレージに書き出し、製品内のログ画面は監査記録ではなくデバッグ用の利便機能として扱うことです。
- **Free 階層は上限で課金する代わりに停止します。** クレジットカードにとっては正しい既定動作ですが、本番エージェントにとっては誤りです。10 万ツール呼び出しで実行の途中で止まり、急増を吸収する超過枠がありません。対策は、本番を Free で動かさないこと。Pro に移り、明示的な支出上限を設定して、障害の形を静かな停止ではなく上限つきの請求にしてください。
- **既存顧客は借り物の価格で走っています。** 2026 年 8 月 15 日より前のアカウントは 2026 年 12 月 31 日まで従来プランのままです。対策は、1 月にそれと出会うのではなく、いま現行の呼び出し単価とトリガー単価で月額を再計算し、その差額を来年の予算に入れておくことです。
