## 概要

Amazon Redshift は AWS のクラウドデータウェアハウスで、2 つの形態で提供されています。**プロビジョニング型**のクラスターは自分でサイズを決めて時間単位で支払う RA3 ノード上で動き、ストレージは Redshift Managed Storage として別途課金されます。**Redshift Serverless** はクエリの実行中だけ Redshift Processing Units（RPU）単位でコンピューティングを課金し、ベース容量は 4〜512 RPU（一部のリージョンでは 1,024 まで）の範囲で設定します。どちらもウェアハウスに加え、Spectrum 経由で S3 上のデータもクエリできます。2026 年 8 月 31 日からは Apache Iceberg v3 テーブルの読み書きにも対応しました。データレイクを長期保存先とし、ウェアハウスを複数あるエンジンの 1 つとして使う場合に重要です。

オペレーションチームにとって重要な 2026 年の変化は、エージェントからのアクセスです。2026 年 8 月 27 日、AWS は Redshift を **Agent Toolkit for AWS** と統合しました。AWS MCP Server と Redshift 用のスキル群（SQL 構文、メタデータ探索、データロード、マテリアライズドビュー、移行プレイブック）を、Claude Code、Kiro、Cursor 向けの `aws-data-analytics` プラグインとしてまとめたものです。プロビジョニング型クラスターと Serverless ワークグループの両方で動き、追加料金はかかりません。これとは別に、AWS は SQL を読み取り専用モードで実行し、危険なステートメントを検証で弾くオープンソースの Redshift MCP サーバーも公開しています。コンソール内では、Query Editor v2 の Amazon Q 生成 SQL が 2024 年 9 月から GA で、管理者が有効にすれば自然言語の質問を SQL に変換します。

## オペレーションチームがここにたどり着く理由

RevOps のために Redshift を選ぶ人はほとんどいません。引き継ぐのです。エンジニアリングが何年も前に AWS に標準化し、プロダクトデータはすでにそこにあります。本当の問いはこうです。*うちは Snowflake ではなく Redshift だ。ウェアハウスネイティブの GTM ツールや報酬計算ツールは使えるのか。エージェントに安全にクエリさせられるのか。*

おおむね使えます。[Hightouch](/ja/tools/hightouch/) は Redshift から同期し、[Fivetran](/ja/tools/fivetran/) はそこへデータをロードし、[Sigma](/ja/tools/sigma/) はライブでクエリし、[Everstage](/ja/tools/everstage/) と [Fullcast](/ja/tools/fullcast/) はどちらもネイティブコネクターとして対応しています。2024 年 12 月から GA の zero-ETL 統合は、パイプラインツールなしで Salesforce などの SaaS アプリケーションを Redshift に複製します。課金は AWS Glue 経由なので、ソースが少ないチームなら Fivetran が不要な場合もあります。具体的な使い方の例：CS チームが MCP サーバー経由で Claude Code に「$50,000 を超える更新案件のうち、週次アクティブユーザーが減っているのはどれか」と尋ね、同じウェアハウス内のプロダクトテレメトリーと Salesforce データから直接答えを得ます。

## 価格の実態

ユーザー単位の価格はありません。US East（N. Virginia）の定価は次のとおりです。

- **Serverless：** RPU 時間あたり $0.375。秒単位課金で最低 60 秒なので、下限の 4 RPU は稼働中 1 時間あたり $1.50 です。Serverless の新規ユーザーには 90 日で失効する $300 のクレジットが付与されます。Serverless Reservations を使うと、1 年契約で最大 24%、3 年契約で最大 45% 料金が下がります。
- **プロビジョニング型：** ra3.xlplus がノード時間あたり $1.086、ra3.4xlarge が $3.26。これにマネージドストレージが GB 月あたり $0.024 かかります。各クラスターは 1 日 1 時間分の Concurrency Scaling を無料で得られ、最大 30 時間まで繰り越せます。
- **Spectrum：** S3 でスキャンした TB あたり $5。

試算例：ベース 8 RPU の Serverless で動く RevOps 用ウェアハウスが、営業日ごとに約 4 時間稼働し、500 GB を保持するケース。コンピューティングは月約 $264（1 時間 $3 × 4 時間 × 22 日）、ストレージは月約 $12 です。**月額およそ $280、年間約 $3,300 です。** 同じワークロードを 2 台の ra3.xlplus ノードで常時稼働させると、オンデマンドで月約 $1,590 かかります。小規模なオペレーション用途に Serverless が向いているのはこのためです。

## 最適な用途

**プロダクトデータがすでに AWS にある企業の、RevOps または CS のアナリティクス責任者**で、移行プロジェクトなしに、ウェアハウスネイティブのアクティベーション、報酬計算、BI ツールをその上で使いたい人。セキュリティレビューのために顧客データを AWS のアカウントとリージョン内に留める必要があり、コーディングエージェントにサードパーティのサービス経由ではなく IAM の下でウェアハウスをクエリさせたいチームにも合います。

## 向いていないケース

AWS への縛りがない状態で、最初のウェアハウスを選ぶ企業。Snowflake と BigQuery のほうが GTM エコシステムが大きく、独自の対話型アナリティクス層も持っています。Redshift の AI の強みは主に MCP 経由のエージェントアクセスで、ビジネスユーザー向けのチャット製品ではありません。主な問いが「そもそもウェアハウスと CDP のどちらが必要か」なら、[データウェアハウス vs CDP](/ja/learn/data-warehouse-vs-cdp/) から始めてください。

## 代替ツールとの比較

- **[Snowflake](/ja/tools/snowflake/)**：GTM 領域のシェアリーダーで、あらゆるリバース ETL・報酬計算ベンダーの標準接続先です。特定のクラウドに縛られておらず、ウェアハウス上でビジネスユーザー向けに CoWork 型のチャットを使いたいなら選んでください。
- **[Google BigQuery](/ja/tools/google-bigquery/)**：もう一方のシェアリーダーです。会社が Google Cloud や Workspace で動いており、クラスターなしの TiB 単位オンデマンド料金を使いたいなら選んでください。
- **[Databricks](/ja/tools/databricks/)**：最も急成長している新興勢力です。2026 年 8 月の報道では、データウェアハウス事業の年間換算売上が 15 億ドルを超え、前年比 100% 以上伸びたとされています。データサイエンスと ML がすでにレイクハウス上で動いており、同じデータで Genie を使いたいなら選んでください。
- **データがすでにあるなら Redshift に留まる。** 動いているウェアハウスを、少し良い GTM コネクターのために移行しても、エンジニアリングの 1 四半期に見合うことはまずありません。

## 注意点

- **Serverless はデフォルトで大きなベース容量を提案します。** コンソールの初期値は 128 RPU で、クエリ実行中は 1 時間 $48 です。**対策：** オペレーション用途ではベースを 8 RPU に設定し、1 日あたりの RPU 時間に使用量制限をかけ、上限到達前にアラートが鳴るようにします。
- **BI ツールと同期が Serverless を起こし続けます。** 5 分ごとに更新されるダッシュボードや 1 時間ごとのリバース ETL 同期は、1 日中コンピューティング料金を発生させます。**対策：** 同期を少数のバッチ枠にまとめ、Sigma が読むモデルをマテリアライズし、最初の 1 か月はワークグループ別の RPU 使用量を毎週確認します。
- **エージェントの書き込み権限は IAM ポリシー 1 つで開いてしまいます。** AWS MCP Server は、渡されたユーザーとして認証済みの AWS API 呼び出しを実行します。**対策：** エージェントには専用の IAM ロールとデータベースユーザーを割り当て、モデル化済みスキーマへの SELECT 権限のみを付与し、アドホックな質問にはオープンソースの Redshift MCP サーバーの読み取り専用モードを使います。
- **Python UDF は廃止されました。** サポートは 2026 年 6 月 30 日をもって終了しましたが、古い dbt パッケージやチュートリアルはまだ使っています。**対策：** モデル内の `LANGUAGE plpythonu` を検索し、それを含むパッケージに依存する前に、該当関数を Lambda UDF に移植します。
- **ライトバック系ツールは大きめのノードを求めます。** Sigma は Redshift 上の入力テーブルに ra3.4xlarge 以上を推奨しています。**対策：** アプリを組む前に、トライアル中に Serverless または実際のノードサイズでライトバックを検証します。
