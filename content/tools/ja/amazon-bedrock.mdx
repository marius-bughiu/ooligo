## 概要

Amazon Bedrock は、自社の AWS アカウントの中から基盤モデルを呼び出すための AWS のマネージドサービスで、2025 年以降は 1 つの名前の下に 2 つの製品があります。狭い意味での **Bedrock** はモデル層です。Claude（Fable、Opus、Sonnet、Haiku）、OpenAI の GPT-5.5 と GPT-5.4（2026 年 6 月 1 日から Bedrock で一般提供）、Amazon Nova、gpt-oss、Llama、Mistral、そして多数のオープンウェイトモデルが、すべて IAM、CloudTrail、自社の VPC の背後にあります。その周りに Guardrails（コンテンツ、PII、グラウンディングのフィルター）、Knowledge Bases（マネージド RAG）、バッチ推論と階層別推論があります。**Bedrock AgentCore** はエージェント層です。エージェントのセッションごとに専用の microVM で実行する Runtime、API や Lambda 関数を MCP ツールに変える Gateway、さらに Memory、Identity、Policy、Observability、Evaluations、マネージドの Browser と Code Interpreter で構成されます。

2026 年は重心が AgentCore に移りました。2026 年 4 月 22 日に**マネージドハーネス**がプレビューになりました。モデル、システムプロンプト、ツールを宣言するだけで、AWS がエージェントのループを実行し、オーケストレーションのコードは不要です。物足りなくなったら Strands のコードとしてエクスポートできます。同じリリースで、Infrastructure as Code でデプロイする AgentCore CLI と、コーディングアシスタント向けの AgentCore skills も出ました。8 月 27 日には AgentCore に US West（N. California）と Asia Pacific（Hyderabad）が加わりました。一方、元の Bedrock Agents は **Bedrock Agents Classic** に改称され、2026 年 7 月 30 日に新規顧客の受け付けを終了しました。AWS 自身が、これらのワークロードを AgentCore に移行するよう推奨しています。

## オペレーションチームがここにたどり着く理由

問いはほぼ毎回同じです。*セキュリティチームはモデルを自社の AWS テナント内で動かせと言っている。Bedrock と AgentCore で足りるのか、それとも Dust、Glean、Copilot Studio がまだ必要なのか。* 前半には Bedrock がはっきり答えます。Bedrock 上の Claude は、オペレーターアクセスのない AWS 管理のインフラで動き（Anthropic の社員は推論スタックに到達できません）、プロンプトはモデルの学習に使われず、すべての呼び出しが自社アカウントの CloudTrail に記録されます。利用額は既存の AWS のコミットメントにも算入され、多くの場合それが予算承認の決め手になります。

後半には答えません。Bedrock は作る人のためのプラットフォームです。Knowledge Bases は S3、SharePoint、Confluence、Salesforce を取り込めますが、従業員向けのチャットアプリも、社内ツール全体でユーザーごとの権限を尊重する検索も、RevOps マネージャーが操作できる管理コンソールもありません。オペレーションで真価を発揮するのは、エンジニアが責任を持つケースです。S3 に届いた契約書を分類して条項データを抽出する Legal Ops 向けの契約受付パイプライン。Gateway のツール経由で Salesforce を読み、修正案をレビューキューに書き込むパイプライン衛生エージェント。応募をルーブリックで採点し、候補者データを EU 内に保持しなければならない Recruiting のスクリーニング。サポートでの [Amazon Connect](/ja/tools/amazon-connect/) の背後にある AI 層です。

## 価格の実態

席単位の価格はありません。モデルはトークン単位、それ以外はすべてユニット単位で支払い、AWS アカウントに請求されます。

- **Claude Sonnet 5.5：入力 100 万トークンあたり 2 USD、出力 100 万トークンあたり 10 USD**（グローバルエンドポイント）。Anthropic の定価と同じです。Opus 5.5 は 4/20 USD、Haiku 5.5 は 100,000 トークンまでのプロンプトで 0.10/0.50 USD です。
- **リージョナルエンドポイントは 10% 高くなります。** データレジデンシーのために推論を 1 つのリージョンや地域（US、EU、JP、AU の推論プロファイル）に固定すると、トークン料金に 10% が上乗せされます。Sonnet 5.5 は 2.20/11 USD になります。
- **待てるなら割引：** バッチ推論は対応モデルでオンデマンドより 50% 安く、Flex 階層は 50% 引き、Priority は 75% の割増です。
- **Guardrails：** コンテンツフィルターまたは拒否トピックはテキスト 1,000 ユニットあたり 0.15 USD、機密情報（PII）フィルターは 0.10 USD です。
- **AgentCore：** Runtime は vCPU 時間あたり 0.0895 USD、GB 時間あたり 0.00945 USD で秒単位課金。Gateway はツール呼び出し 1,000 回あたり 0.005 USD。長期 Memory は月 1,000 レコードあたり 0.75 USD に加え、取得 1,000 回あたり 0.50 USD。マネージドハーネス、CLI、skills は追加料金なしです。Observability は CloudWatch として課金されます。

試算の目安です。社内の RevOps エージェントが**月 3,000 セッション**を処理し、各セッションが Sonnet 5.5 で入力約 20,000、出力約 1,500 トークン、EU に固定した場合。トークン：グローバル料金で約 165 USD、リージョナルの割増込みで約 182 USD。Runtime：セッションごとに 1 vCPU と 2 GB を 5 分間確保すると多めに見積もって約 27 USD。Gateway、Guardrails、Memory を合わせて 10 USD 未満。**合計：月約 215 USD、年約 2,600 USD。** AWS の請求額は小さいほうの数字です。本当のコストはエージェントを構築し、評価し、保守するエンジニアであり、だからこそ 50 人規模のオペレーションチームには席単位の製品のほうが得になることが多いのです。

## 最適な用途

**すでに AWS に標準化している企業のプラットフォームチームまたは RevOps エンジニアリングチーム**で、構築に責任を持つエンジニアが少なくとも 1 人おり、データを AWS アカウントとリージョン内に留める必要があるエージェントや文書パイプラインを求めている場合です。大量のバックオフィス処理（抽出、分類、エンリッチメント、スコアリング）ではっきり勝ちます。この規模では、Haiku や Sonnet のトークン課金が席単位や会話単位の価格より 1 桁安くなるからです。

## 向いていないケース

来週から従業員に社内ナレッジとチャットさせたいオペレーションチームです。Bedrock にはユーザーインターフェースも、Slack、Drive、SharePoint を横断する権限対応の検索も、エンジニア以外のための管理コンソールもありません。その用途には [Dust](/ja/tools/dust/)、[Glean](/ja/tools/glean/)、[Langdock](/ja/tools/langdock/) を買い、セキュリティチームが求めるなら Bedrock のモデルに接続してください。エージェントが Teams にある Microsoft 365 の会社にも不向きです。そこでは [Copilot Studio](/ja/tools/microsoft-copilot-studio/) が ID と配布を追加の手間なく提供します。

## 代替ツールとの比較

- **Microsoft Foundry（Azure）**：ハイパースケーラーのモデルプラットフォームで、Bedrock と並ぶシェアリーダーです。ID とデータが Entra と Azure にある場合や、エージェントを [Copilot Studio](/ja/tools/microsoft-copilot-studio/) 経由で Teams に届ける場合はこちらを選んでください。2026 年 6 月以降、OpenAI を独占できる利点はなくなりました。GPT-5.5 は Bedrock でも動きます。
- **Google Cloud Vertex AI**：3 つ目のハイパースケーラーの選択肢です。データウェアハウスが BigQuery で、会社が Google Workspace で動いており、最初に使いたいモデルが [Gemini](/ja/tools/gemini/) ならこちらです。
- **Claude Platform on AWS**：最も新しい参入者で、機能面の進みが最も速い選択肢です。Anthropic が運用し、AWS Marketplace 経由で請求され、通常は Claude の新機能に即日アクセスできます。Agent Skills、コード実行、Files API、Claude Managed Agents も含まれ、これらはどれも Bedrock 上の Claude では使えません。Claude のエージェント機能をフルに使いたく、Anthropic をデータ処理者として受け入れられるならこちらです。要件が文字どおり「AWS が運用し、ベンダーは一切見ない」なら Bedrock を選んでください。
- **[Dust](/ja/tools/dust/) / [Langdock](/ja/tools/langdock/) / [Glean](/ja/tools/glean/)**：買い手がエンジニアではなくオペレーションのリーダーで、必要なのがパイプラインではなくコネクタと権限を備えたアシスタントであれば、こちらを選んでください。Bedrock と競合するというより補完する関係です。

## 注意点

- **Bedrock 上の Claude は Claude API の完全版ではありません。** Bedrock 版の Claude には、Files API、サーバー側の Web 検索とコード実行、Agent Skills、MCP コネクタ、Message Batches エンドポイント、Claude Managed Agents がありません。**対策：** 採用を決める前に、設計が依存する Claude の機能をすべて書き出し、Anthropic の Bedrock 機能表と照合してください。Skills や Managed Agents が含まれるなら、代わりに Claude Platform on AWS を評価してください。
- **データレジデンシーはデフォルトではなく設定です。** グローバルエンドポイントは最も安く、容量のある任意のリージョンにリクエストを振り分けます。**対策：** EU のデータや規制対象データには、リージョナルエンドポイントか地域別の推論プロファイルだけを呼び出し、10% の割増を予算に組み込み、グローバル推論プロファイルの ARN を拒否する IAM ポリシーで強制してください。
- **Bedrock Agents Classic は行き止まりです。** 2026 年 7 月 30 日から新規顧客を受け付けておらず、それ以前に書かれたチュートリアルはいまだにこれを教えています。**対策：** 新しいエージェントは AgentCore だけで構築し、既存の Classic エージェントは拡張せずに移行計画に載せてください。
- **マネージドハーネスはまだプレビューです。** 4 つのリージョン（N. Virginia、Oregon、Frankfurt、Sydney）で動き、一般提供の約束の対象外です。**対策：** プロトタイプに使い、その後オーケストレーションを Strands のコードとしてエクスポートし、顧客向けの何かが依存する前に AgentCore Runtime にデプロイしてください。
- **コストが 5 つのメーターに分散します。** トークン、Runtime、Gateway、Memory、CloudWatch が別々に課金されるため、1 つのエージェントにいくらかかっているかを示す画面がありません。**対策：** すべての AgentCore リソースと推論プロファイルにエージェント名のタグを付け、そのタグをコスト配分タグとして有効化し、エージェントごとに予測の 120% で AWS Budgets のアラートを設定してください。
