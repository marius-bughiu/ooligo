[SAP SuccessFactors Recruiting](/ja/tools/successfactors-recruiting/) を運用しているなら、あなたはベンダー自身がすでに後継製品を指名した、めずらしい買い手です。2026年3月3日、SAP は HCM スイート内の talent acquisition の主力製品として SmartRecruiters for SAP SuccessFactors をリリースし、既存の Recruiting モジュールを同社が Core Stability Phase と呼ぶ状態に移しました。これはロードマップ上の決定であって、立ち退き通告ではありません。この違いこそがこのページの中身です。

## Core Stability Phase が実際に課す義務

期限という意味では、何もありません。SAP は SuccessFactors Recruiting の提供終了日を公表しておらず、移行を支援する SAP 専門パートナーも2026年8月時点で同じことを言っています。SuccessFactors プレジデントの Daniel Beck は2025年10月に CIO に対し、顧客には移行完了まで3〜5年あると述べ、SAP は2026年 Q1 末までに移行の提供開始を知らせるとしました。誰もあなたの requisition を止めたりはしません。

強制力は崖ではなく、兵糧攻めです。Core Stability Phase とはロードマップのない保守を意味し、1H 2026 リリースがその中身を示しています。候補者のステータス変更で発火する OnChange ビジネスルール、Hired 到達時の requisition 自動クローズ、Career Site Builder のスタイル設定、そして SuccessFactors のキャリアサイト上に埋め込まれた SmartRecruiters の Winston チャット。後継製品が現職製品の内側で出荷されているわけです。

2025年9月11日に18億ドルの SmartRecruiters 買収を完了して以降、SAP が発表した recruiting 機能はすべて向こう側に着地しています。2026年6月リリースの Winston Match は、候補者自身が確認または入力したプロフィールデータでスコアリングし、そのデータが欠けているときだけ履歴書パースにフォールバックします。この機能があなたのモジュールに来ることはありません。つまり残留のコストは停止ではなく、競合の recruiter がエージェントを手にする一方で、バグ修正しか届かないシステムの上で採用を回し続けることです。

## SmartRecruiters — SAP が資金を投じている経路

[SmartRecruiters](/ja/tools/smartrecruiters/) との統合は3つのフェーズで製品化されており、SAP は各フェーズの内容を公表しています。フェーズ1（H1 2026）は IAS 経由の single sign-on、両システムをまたぐ recruiter 向け UI、そして SuccessFactors から SmartRecruiters への基礎的な組織データの自動連携を提供します。フェーズ2（同じく H1 2026）は Employee Central と Onboarding への候補者から入社者への変換を自動化し、SAP SuccessFactors Story Reports との統合を加え、そして移行の順序を決める最重要点として、両システムの並行稼働をサポートします。フェーズ3（H2 2026 以降）は Winston Chat を Joule に接続し、BTP による拡張性を開きます。

移行ツールは実在し、2026年6月に前進しました。Migration Hub は準備状況レポートを渡すのではなく、移行そのものを実行するようになりました。フィールドマッピングを確認・確定すると、job フィールドと application フィールドを設定ごと SmartRecruiters へ移行し、Application、Candidate プロフィール、Offer の各設定をデータ型の不一致や picklist の変更について解析し、対象となる single-select フィールド定義を Integration Sync に直接送ります。同じリリースでは、マスターデータ同期と Position-to-Job マッピングのために SmartRecruiters 設定内に SuccessFactors Connectivity Hub が追加されました。

価格。Vendr の2026年取引データでは、SmartRecruiters の支出中央値は年間 $33,507、契約の大半は $15,250 から $51,561 の範囲に収まります。ミッドマーケットの買い手は recruiter 1席あたり年間 $5,000〜$10,000 に着地します。設定、統合、データ移行のプロフェッショナルサービスは別見積もりで、ミッドマーケットで $10,000〜$50,000、グローバル企業では $100,000 を超えます。

**ここへ移るのは:** Employee Central を運用していて、Recruiting の設定が標準に近く、TA 組織で最も大きい不満が recruiter の使い勝手であるときです。これがデフォルトであり、そうあるべきです。

**移らないのは:** 離れたい理由が SAP そのものであるときです。SAP 傘下の後継製品への移行は UX の不満には答えますが、ベンダー戦略の問いには答えません。

## Workday

人事のシステム・オブ・レコードも俎上に載っている場合にだけ意味を持つ選択肢です。[Workday](/ja/tools/workday/) Recruiting は、いま Employee Central があなたのために保持している従業員レコード、ポジション予算、組織図と同じものの上で動き、SAP に同等品のないエージェントを2つ加えます。sourcing と screening を担う HiredScore ベースの Recruiting Agent と、会話型の応募と自己日程調整を担う Paradox ベースの Candidate Experience Agent で、いずれも Workday の Agent System of Record に登録されます。

Vendr の2026年データでは、Workday の支出中央値は367件の購入で年間 $50,865、範囲は $19,522 から $549,949 です。この数字はプラットフォーム全体を指し、Recruiting モジュール単体ではありません。同モジュールは従業員単位、ユーザー単位、パッケージによっては requisition 単位や採用1件単位の add-on として課金されます。

**ここへ移るのは:** recruiting とは無関係の理由で、SAP から Workday への HCM 評価がすでに走っているときです。SuccessFactors のコアの上に Workday Recruiting を後付けするのは両者の悪いところ取りで、単体 ATS に企業スイートの価格を払ったうえ、入社データの受け渡しを手作業で作り直すことになります。

## Greenhouse

問題が人事レコードとの近さではなく採用の質であるときの選択肢です。[Greenhouse](/ja/tools/greenhouse/) は structured hiring の作法——スコアカード、インタビューキット、source-of-hire レポート——を確立し、450以上の認定統合により、sourcing、アセスメント、バックグラウンドチェックのどのベンダーもまず Greenhouse 向けに作ります。プランは Core、Plus、Pro です。

Vendr の2026年データでは、Greenhouse の支出中央値は868件の購入で年間 $26,611、範囲は $10,222 から $75,001 です。各分布の中央同士で比べると SmartRecruiters の中央値より約21%低い一方、席単位ではミッドマーケットの買い手で $6,000〜$12,000 と高く、導入は $15,000〜$150,000 超で見積もられます。Greenhouse は中央値の契約では安く、recruiter 1人あたりでは高い。どちらを体感するかは、支出を押し上げているのが席数なのか範囲なのかで決まります。

**ここへ移るのは:** hiring manager のフィードバックが構造化されておらず、面接ループがチームごとにばらばらで、「どのソースが最良の採用を生んだか」に ATS から答えられないときです。Greenhouse はこれを直し、SmartRecruiters は直しません。

**移らないのは:** 現場職や多国籍オペレーションで大量採用をしているときです。Greenhouse は熟慮型のホワイトカラー採用向けに作られており、その外側では急速に手薄になります。

## iCIMS

人事のシステム・オブ・レコードに触れずに ATS を入れ替える方法です。[iCIMS](/ja/tools/icims/) は SuccessFactors との統合を維持しており、Employee Central を従業員レコードとして残したまま、複数事業部・複数国の採用向けに作られたプラットフォームへ recruiting だけを差し替えられる、ここで唯一の選択肢です。OFCCP に沿ったレポートも備えます。Vendr のデータセットでは iCIMS の平均契約額は年間 $20,781、観測された範囲は $14,500 から $635,000 と4製品で最も広く、これは iCIMS が Recruit、Attract、Engage、Video Studio、Onboard を別モジュールとして販売しているためです。

**ここへ移るのは:** 規制業種またはマルチブランドの企業で、SuccessFactors HCM への投資は維持され、SmartRecruiters への反対理由が製品適合ではなく集中リスクであるときです。企業向けと structured hiring の軸については [iCIMS vs Greenhouse](/ja/vs/icims-vs-greenhouse/) を参照してください。

## ほとんどのチームが過小評価する移行コスト

3つのコストが必ず同じ順番で効いてきます。

**履歴は一緒に移りません。** 候補者、job、応募のレコードはレポートと監査のために SuccessFactors に残り、新しい recruiting 活動は新プラットフォームで動きます。誰も採用業務をしていないシステムに払い続けるか、エクスポートとレポートの作り直しに予算を出すかのどちらかです。契約前に決めてください。4か月目ではなく。

**段階的ロールアウト中はキャリアサイトが分断されます。** recruiting プラットフォームの併存は可能で、フェーズ2が明示的にサポートします。ただしサイト構成、ナビゲーション、ブランディング、求人配信を一体として設計しない限り、候補者にはつなぎ目が見えます。ガード: キャリアサイトのオーナーを、最初に終わったワークストリームではなく、プログラム初日に個人名で割り当ててください。

**サービス費がライセンス費を追い越します。** SmartRecruiters は設定・統合・移行を $10,000〜$100,000 超で別見積もり、Greenhouse は $15,000〜$150,000 超、Workday の導入は年間サブスクリプションの1〜2倍に達します。サービス費の行を、ライセンス交渉より先に予算化してください。値引きが最後に回る行だからです。

移行の形は意図して選んでください。ビッグバンは最速で最も危険です。国、地域、事業部ごとの段階的ロールアウトは大半のグローバルチームにとって現実的な経路であり、フェーズ2の並行稼働サポートはまさにそのために存在します。限定移行——新規 requisition のみ、あるいは特定の採用領域のみ——は最もリスクの低い入口で、設定を大きくカスタマイズしている場合の正解です。

## 残留が正しいとき

次の3つがすべて当てはまるなら、まだ動かないでください。recruiter が不満を言っていない、SuccessFactors Recruiting の設定が重いカスタムビジネスルールと統合を抱えている、契約更新が2年より先である。Core Stability Phase は実在する製品状態であってカウントダウンではなく、提供終了日が発表されていないシステムから逃れるために2026年の変革予算を燃やすのは、トリガーのない支出です。ガード: 次回更新に再評価の確定日を置き、SAP が提供終了日を公表した瞬間を第2のトリガーにしてください。待つことはレビューカレンダーを必要とする決定であり、放置とは別物です。

## 結論

Employee Central を運用していて、上記の条件で決めきれないなら、デフォルトは **SmartRecruiters** です。どちらにせよ移行コストは払うことになり、SAP がツールに資金を投じ、Employee Central への入社データ受け渡しを製品として出荷し、並行稼働での切り替えをサポートする移行先はここだけです。同じデータを第三者に移すということは、同じ請求書を払ったうえで受け渡しを自分で作るということです。

例外は2つ、名指しで挙げます。欠陥が recruiter の UX ではなく面接の質とソース帰属にあるなら **Greenhouse** を選んでください。ATS は入れ替えたいが SAP の人事コアは残したく、集中リスクが購買部門の明言された反対理由であるなら **iCIMS** を選んでください。

**Workday** はそもそも ATS の決定ではありません。recruiting を巻き込む HCM の決定であり、その大きな評価がすでに開いているのでない限り、誤った答えです。

そして率直に言っておくべき反対論。強制されるプラットフォーム変更は、ベンダーから得られる最も安い出口です。移行予算がすでに承認されているからです。SuccessFactors Recruiting への不満が実は SAP への不満だったのなら、今後3年がその窓であり、それを過ぎれば SmartRecruiters から再移行して二重に払うことになります。ベンダーが選んだ後継製品からではなく、[本当に必要な recruiting スタック](/ja/learn/recruiting-tech-stack/)から始めてください。
