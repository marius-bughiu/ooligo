When a CRM import loses a leading zero, the first decision is who needs access to what. Use Claude chat to reason about two sample rows. Choose Claude Code if the fix belongs in a repository you already work in. Choose Cursor if you want to inspect and edit the proposed changes alongside the code in its editor.

## Where the work happens

- **Claude chat.** Paste the field definition and a fictional CSV excerpt into a conversation. Ask which transformation could turn two accounts into one. This gives the person who owns the import a hypothesis they can check without granting access to the repository. [Claude plans and features](https://claude.com/pricing)
- **Claude Code.** Open the approved repository in your terminal or a supported IDE. Ask the agent to trace how the identifier travels from the CSV parser to the CRM lookup, change the relevant code and run the existing test suite. Review its commands and diff. [Claude Code overview](https://code.claude.com/docs/en/overview)
- **Cursor.** Open the same repository in Cursor. Follow the agent's edits in the editor and keep the parser and its tests open together while reviewing the change. Cursor's agent can search files, edit them and run commands. The available models and their usage charges depend on your plan. [Cursor Agent](https://cursor.com/docs/agent/overview) · [Models and pricing](https://cursor.com/docs/models-and-pricing)

## Try the same CRM import in each tool

These fictional rows represent different accounts. The import contract treats `external_id` as text, including leading zeros.

```csv
external_id,account
0071,North Mill
71,South Mill
```

Converting the IDs to integers would turn both into `71`. The import must preserve each ID when parsing the CSV **and** when looking up the account. In chat, ask for a field mapping and an explanation of where the collision can occur. With either coding agent, ask for a failing test that reproduces the collision before accepting a patch.

Use an empty local store with CRM writes disabled. After one import, expect `0071 → North Mill` and `71 → South Mill`. Import the same rows again. The two mappings should stay intact and the second run should create zero accounts. Use those outcomes to judge the patch. This exercise gives you an acceptance test to run in your own project. For a downloadable RevOps example, try the [Clay and Claude enrichment workflow](/en/workflows/lead-enrichment-clay-claude/).

## What one person would pay

Individual USD web prices checked November 2, 2026, before taxes. **Claude Free** covers chat with limits. **Pro** includes chat and Claude Code at $20 billed monthly or $200 billed annually. Max is $100 per month and Ultra is $200. Sign into Claude Code with the subscription account to use its allowance. An Anthropic API key can route the session to separately metered API usage. [Claude pricing](https://claude.com/pricing) · [Claude Code subscription billing](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-max-or-ultra-plan)

**Cursor Free** includes limited usage. For a new individual subscription, **Plus** costs $8 per month and excludes third-party models. To choose a Claude model in Cursor, **Premium** starts at $30 per month, with third-party model usage charged separately at API list price against prepaid credit. An existing $20 Cursor Pro account follows the legacy terms. [Cursor pricing](https://cursor.com/pricing) · [Model charges](https://cursor.com/docs/models-and-pricing) · [Legacy plans](https://cursor.com/docs/account/pricing/legacy-cursor-plans)

If mapping errors only need an explanation, start with [Claude](/en/tools/claude/) chat. If you already pay for Claude Pro, try Claude Code on the import before adding another bill. Add [Cursor](/en/tools/cursor/) if your team values reviewing edits inside Cursor enough to cover its subscription and the usage of your chosen model.
