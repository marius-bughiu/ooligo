## 概要

Octave は GTM コンテキストエンジンです。何を売り、誰に売るのかをバージョン管理された構造化モデルとして持ち、テーブル、エージェント、アシスタントはそれぞれがポジショニングのコピーを抱える代わりに、実行時にこのモデルを読み込みます。ライブラリには型付きのオブジェクト（提供製品、ペルソナ、ユースケース、セグメント、導入事例の顧客、競合、プルーフポイント）が格納され、Motions（戦略モデルとして旧来の Playbooks を置き換えたもの）がそれらをセールスプレイに結び付けます。このライブラリの上に、シーケンス作成、クオリフィケーション、エンリッチメント、商談準備、コンテンツ、プロスペクティングを担うマネージドエージェントが載っています。

解決する課題は具体的です。Clay のテーブルを 12 本ほど運用しているチームには、たいてい同じ数のプロンプトがあり、それぞれのテーブルを作った人が書いた、少しずつ異なる ICP と価値提案の説明が入っています。ポジショニングが変わっても、それらをすべて更新する人はいません。Octave はそのコンテキストを 1 か所に集め、すべての呼び出し元に配信します。

同社は 2025 年 5 月に Bonfire Ventures がリードする $5.5M のシードラウンドを調達し、累計調達額は $8.4M となり、独立企業のままです。顧客として Airbyte、WorkSpan、Cortex、Descope、Harmonic Security が名前を挙げられています。サイトには SOC 2 Type II のバッジが掲示され、Octave は顧客データでモデルを学習しないと明記しています。同名の Sierra Wireless の IoT プラットフォームとは無関係です。そちらは 2025 年 3 月にサービスを終了しています。

## スタックへの組み込み方

- **Clay の中で。** 2025 年 9 月の提携以降、Octave のエージェントは Clay のネイティブなエンリッチメントになっています。エンリッチメント列を追加して Octave を選び、エージェントの「Use in Clay」ボタンから取得した API キーを貼り付けます。よくあるパターンは、まず Qualify エージェントを実行し、そのスコアで Sequence エージェントの実行を絞り込むことです。たとえば 10 点満点で 7 点以上の行だけに実行します。
- **MCP 経由で。** MCP サーバーと Claude Code プラグインは 2026 年 2 月 6 日にリリースされました。Octave のドキュメントはクライアントとして Claude Desktop、Claude Code、Cursor、VS Code、Zed、Windsurf を挙げており、サーバーはナレッジベース検索、ライブラリの編集、リサーチとエンリッチメント、メールと商談準備資料の生成、CRM の参照、パイプラインの指標、通話の文字起こし検索を公開しています。担当者は Claude に商談準備を依頼し、アウトバウンドのテーブルと同じペルソナとプルーフポイントに基づいた回答を得られます。
- **API 経由で。** 同じエージェントを [Cargo](/ja/tools/cargo/)、[n8n](/ja/tools/n8n/)、Make から呼び出せます。データは Snowflake、Databricks、BigQuery、クラウドストレージにエクスポートできます。

## 価格の実態

Octave は価格を公開していません。現在の価格ページに載っているのは Octave Ultra という単一プランだけで、年額固定のプラットフォーム利用料に従量課金のクレジットを加えた形であり、クレジットを前払いでコミットすると割引があります。ユーザー数無制限、マネージドエージェント無制限、SSO/SCIM、RBAC、専任の CSM が含まれます。クレジットの一括購入、GTM エンジニアリングのサービス、ウェアハウスコネクタは有料の追加オプションです。

参考までに、第三者のレビューは 2025 年時点のセルフサーブ型の階層を記録しています。Core は 4,000 クレジットで月額 $149、Boost は 20,000 クレジットで月額 $499、Turbo は 60,000 クレジットで月額 $999 でした。定価で年間 $1,800 から $12,000 です。これらの階層はすでに廃止されています。SSO と CSM が含まれる Ultra の契約は、旧価格帯の上限かそれ以上から始まるというのが私たちの推定です。これは見積もりではなく、交渉の基準値として扱ってください。

クレジットの消費量は、各エージェントが使うモデルの階層で決まります。高速なモデルは消費クレジットが少なく、コンテキストの大きいモデルは多くなり、Prospector は見つかった見込み客の分だけ課金します。シートは無料なので、請求額は人数ではなく、エージェントに流す行数に比例して増えます。

## 最適な対象

Series B から D の B2B 企業で、複数のペルソナや製品にまたがるアウトバウンドの施策を同時にいくつも回し、実行にはすでに Clay か Cargo を使っていて、ライブラリを所有できるプロダクトマーケターがいるチームの RevOps リーダーと GTM エンジニアです。テーブル、担当者、AI アシスタントの間でメッセージングが食い違っていることを具体的に指摘できる場合に、コストに見合う価値が出ます。

提供製品が 1 つでペルソナも 1 つなら見送ってください。手入れの行き届いたシステムプロンプトで同じことができます。ポジショニングの担当者がいない場合も見送ってください。エンジンは誰かが入れたものしか配信できません。

## 代替候補との比較

[Clay](/ja/tools/clay/) はこのセグメントの既定の選択肢であり、多くのチームにとってはテーブル間で共有するプロンプトブロックと Claygent で足ります。施策が 1 つか 2 つで、すべてのテーブルを 1 人が作っているなら Clay 単体を選んでください。[Cargo](/ja/tools/cargo/) はコンテキストをバージョン管理されたコードとして持ちたいチームに向いています。TypeScript の担当者がいて、ICP とメッセージングを、それを使う play と並べて git に置きたいなら Cargo を選んでください。最も成長が速い新規参入の [Unify](/ja/tools/unify/) は、シグナル、リサーチ、シーケンスをまとめてパッケージにしています。その上に構築するコンテキスト層ではなく、今月中にアウトバウンドを動かしたいなら Unify を選んでください。自前で済ませる道は、メッセージングを保持する [Claude](/ja/tools/claude/) のプロジェクトか共有ドキュメントです。これに依存するテーブルとアシスタントが数個を超えるまでは機能します。

## 注意点

- **ライブラリの質は担当者次第です。** 古くなったペルソナやプルーフポイントは、すべてのテーブルとアシスタントに一斉に広がるようになります。ガード: 契約前にライブラリの担当者を 1 人指名し、四半期ごとに見直し、MCP の `check_resource_drift` ツールを使って、ライブラリが最後に読み込んだ後に変更されたソースを検出してください。
- **Clay の中ではメーターが 2 つあります。** Octave の Clay 向けガイドによれば、エージェントの実行には Octave のクレジットが使われますが、その列の Clay 側のコストについてガイドは何も書いていないため、同じ実行が Clay のプランでも計測される可能性があります。ガード: トライアル中に代表的な 100 行をエンドツーエンドで実行し、クレジットのコミット量を決める前に両方のメーターを確認してください。
- **不透明な価格と、モデル次第の消費量。** 公開レートがないため、同じワークロードでも各エージェントが使うモデルの階層によってコストが大きく変わります。ガード: パイロットではモデルの階層を固定し、1,000 行あたりのクレジットを記録し、クレジット単価、コミット割引、繰り越し条件を書面で受け取ってください。
- **小規模なベンダーで、製品も変化し続けています。** シード段階の企業でありながら、すでに Playbooks を Motions に置き換え、旧 Playbook のツールを非推奨にしています。ガード: 元となるポジショニング文書は自社のリポジトリかウェアハウスに保管し、ウェアハウスへのエクスポートを使い、統合は非推奨のものではなく現行の MCP と API のツールに対して構築してください。
