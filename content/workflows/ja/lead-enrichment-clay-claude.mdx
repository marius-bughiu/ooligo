このダウンロード可能な [Claude](/ja/tools/claude/) スキルは、提供された企業情報の根拠から ICP スコアと確認用のメール冒頭文を作成します。まず同梱の20行の合成データで試し、その後、同じ根拠チェックを [Clay](/ja/tools/clay/) のテーブルに適用します。バンドルにはローカル検証プログラム、採点ルール、プロンプト、期待される出力が含まれます。

**[バンドルをダウンロード](/artifacts/lead-enrichment-clay-claude.zip)**、または[セットアップガイドを確認](/artifacts/lead-enrichment-clay-claude/README.md)してください。サンプルは Python で動作し、ネットワークにはアクセスしません。Clay アカウント、API キー、有料モデル呼び出しは不要です。

**テスト状況：**オフラインサンプルが検証するのは、提供されたテストデータと決定的な採点処理です。Claude の実際の実行、Clay 連携の動作、実在企業に関する情報の正確さ、返信率の向上を示すものではありません。このワークフローは引き続き `human_tested: false` です。

## 利用に適した場面

企業に関する根拠をすでに持っていて、どの行を営業担当者に渡すかを一貫した検証可能なルールで決めたい場合に選んでください。RevOps 担当者が採点基準を管理し、営業担当者が冒頭文を確認してからシーケンサーに渡します。抽出した事実と元の文章を保存すれば、調査をやり直さずにスコアを検討できます。

連絡先データベース、検証済みメールアドレス、自動 Web 調査、無人の CRM 同期が必要な場合は対象外です。これらの機能は実装していません。対象アカウントが少なければ、資料を読んで手動でメモするほうが準備は少なく済みます。継続的なデータ拡充には既存のプロバイダーを使い、同じ根拠ルールで出力を評価してください。[データ拡充戦略のガイド](/ja/learn/data-enrichment-strategies/)でも選び方を説明しています。

## ダウンロードに含まれるもの

バンドルの場所は `apps/web/public/artifacts/lead-enrichment-clay-claude/` です。各ファイルの役割は次のとおりです。

- `README.md` はセットアップとテスト範囲を説明し、`SKILL.md` は Claude Code に手順を渡します。
- `references/1-icp-rubric.md`、`references/2-opener-style-guide.md`、`references/3-source-quality-matrix.md` は、調整する運用ルールです。
- `pipeline.py` は抽出結果の根拠を検証してスコアを計算します。`rubric.example.json` は実行可能なサンプル採点基準です。
- `prompts/extract.md`、`prompts/opener.md`、`extraction.schema.json` は、モデルへの手動の受け渡しを定義します。
- `examples/leads.jsonl`、`examples/extractions.jsonl`、`examples/expected-output.jsonl` は、合成入力、抽出候補、期待される結果です。

スキルをインストールする前にファイルを読んでください。参照文書は指示であり、Python 検証プログラムが強制するのはコードに実装されたチェックだけです。

## まずサンプルを実行する

ダウンロードを展開し、`pipeline.py` があるディレクトリでターミナルを開いて実行します。

```bash
python3 pipeline.py demo
python3 pipeline.py validate --leads examples/leads.jsonl --extractions examples/extractions.jsonl --rubric rubric.example.json --as-of 2026-11-01
```

日付を固定することでサンプルを再現できます。実データには実際の評価日を使ってください。デモは結果を `examples/expected-output.jsonl` と比較します。入力や採点基準を変えると期待される結果も変わるため、独自の実験は別に保存してください。

各リードには `source_id`、`url`、`text`、`checked_at` を持つ情報源文書を渡します。各抽出候補には `row_id`、`industry`、`headcount`、`region`、`value_prop` と各フィールドの根拠となる引用を含めます。検証プログラムは、引用が提供文書に存在するかを確認します。URL にアクセスしたり、企業の事業内容を独自に確認したりはしません。

サンプル基準では `B2B SaaS` に4点、従業員数50〜500人の範囲内に3点、`US` または `CA` に3点を付けます。閾値は7です。架空の `ledgerleaf.example`、行 `demo-01` は `B2B SaaS`、従業員数120人、`US` なので10点になります。これは計算方法の例であり、貴社の ICP に対する推奨基準ではありません。

企業属性の根拠が欠けると `needs_review` となり、スコアは null になります。ほかに `ready_for_review`、`below_threshold`、`unreachable`、`invalid_evidence` があります。すべての結果は `review_required=true` を保持します。オフラインの冒頭文は提供された製品説明を引用します。これは振り分け処理の例であり、モデル生成によるパーソナライズの性能測定ではありません。

## Claude Code でスキルを使う

展開したバンドルを `~/.claude/skills/lead-enrichment/` にコピーし、その直下に `SKILL.md` を置きます。ローカルの Claude Code セッションで `/lead-enrichment` を呼び出します。この配置は [Claude Code のスキル文書](https://code.claude.com/docs/en/skills)に従っています。

実際のリードを評価する前に、文章の採点基準と `rubric.example.json` の両方を調整してください。情報源文書と抽出プロンプトを Claude に渡し、抽出候補を保存して検証プログラムを実行してから、冒頭文を依頼します。モデルは事実の候補を提案し、ローカルのチェックが設定済みルールを根拠が満たすか判断します。引用の照合に合格しても、人による解釈は必要です。引用された従業員数が、見込み客ではなくその顧客を指している場合があります。

## Clay への適用を明示的に行う

Clay の [Use AI 文書](https://university.clay.com/docs/use-ai-integration-overview)は、プロンプトと構造化出力を説明しています。コンテンツ変換と Web 調査は別のモードです。ローカルの `SKILL.md` ディレクトリを Clay の列としてインポートする仕組みではありません。

行の識別子と提供する元の文章を含む小規模なテストテーブルを作成します。`prompts/extract.md` をその列に合わせ、`extraction.schema.json` を出力形式として使います。アカウントで利用できる Claude モデルを選び、モデル識別子を記録し、設定中は自動実行を無効にしてください。抽出候補を文書に記載された JSONL 形式でエクスポートし、ローカルで検証します。

チェックに合格して閾値に達した行だけを `prompts/opener.md` に渡します。下書き、引用、確認結果をまとめて保存してください。[HubSpot](/ja/tools/hubspot/) などの CRM へのエクスポートは確認後に行います。このダウンロードには CRM コネクターも送信処理も含まれません。初期設定には推定30-60分を見込み、その後は実際の確認時間を測定してください。この見積もりには無人連携の構築を含みません。

## 仮定を置き換えられる費用計算

オフラインデモの有料 API 呼び出しは0回です。実運用には Clay 利用料、独自キーを使う場合のモデルアカウント料金、外部データ、確認作業という別々の費用があります。Clay の説明では、[個人の API キーでも Actions を消費し、モデル使用料はプロバイダーが請求します](https://university.clay.com/docs/ai-tokens)。テーブルを実行する前にアカウントの料金を確認してください。

実測値を使って計算します。

```text
model_cost = input_tokens / 1000000 * input_rate
           + output_tokens / 1000000 * output_rate
run_cost = model_cost + data_cost + platform_cost
review_hours = rows_reviewed * seconds_per_review / 3600
```

総処理費用を1行あたり $0.02 とする明示的な仮定では、20行は $0.40、100000行は実行ごとに $2000 です。週次実行4回では $8000 になり、この仮定から除外した費用は別途加算します。これは計算例であり、Clay や Anthropic の料金の提示ではありません。受け入れた1行あたりの実費を出すときは、失敗した試行や再実行も含めてください。

## 失敗の確認と受け入れテスト

- **根拠のない事実：**元の引用を保持し、根拠の欠落や不一致は却下します。スコアを推測で埋めないでください。
- **古い根拠：**`checked_at` と評価日を比較します。サンプルの30日という上限は変更可能なルールであり、事実の現在性を証明しません。
- **誤解を招く引用：**各引用が何を説明しているかを確認します。文字列の一致は真実を証明せず、プロバイダー間の矛盾も解消しません。
- **想定外の費用：**自動実行を止め、固定した行数で開始し、拡張する前に請求を確認します。
- **意図しない連絡：**`review_required=true` を維持し、送信はこのワークフローの外で扱います。

最初の実データ20行の試行では、検証失敗、確認中に見つかった誤情報、採用した下書き、確認時間、総費用を記録してください。成功とは、採用した各スコアと冒頭文を根拠から説明でき、実費を示せることです。合成デモでは営業成果の向上は証明できません。対象を増やす前に、同種のアカウントを手動で確認する労力と比較してください。
