## 概要

BigQuery は Google Cloud のサーバーレスなデータウェアハウスです。データを読み込んで SQL を実行し、ストレージとコンピュートを別々に支払います。サイズを決めるべきクラスタはありません。このページでは、GTM データの背後にあるウェアハウスとしての BigQuery と、2026年に変わった部分である Conversational Analytics を扱います。Google は2026年7月1日に一般提供(GA)を発表しました。データチームは BigQuery Studio でデータエージェントを作成し、選んだテーブル、ビュー、グラフ、UDF に加えて、検証済みクエリと書面の指示に基づかせます。そのうえでビジネスユーザーが自然言語で質問すると、チャート、生成された SQL、エージェントが使ったコンテキストの引用を添えた回答が返ります。deep-dive モードは「なぜこの指標が動いたのか」という質問に、複数ステップの計画とダウンロード可能なレポートで答えます。

エージェントは Gemini Enterprise(2026年10月14日から GA)、Data Studio、または Conversational Analytics API(2026年6月23日に GA)経由で自社アプリに公開できます。すべてのクエリは質問したユーザーの IAM 権限のもとで実行され、ログに記録されます。エージェントは読み取り専用で、DML の実行、データの書き込み、リモート関数の呼び出しはできません。これとは別に、`bigquery.googleapis.com/mcp` にある Google マネージドの MCP サーバーを使うと、[Claude](/ja/tools/claude/) やその他の MCP クライアントがデータセットの一覧取得や SQL の実行を行えます。デフォルトでは結果は3,000行まで、クエリのタイムアウトは3分です。

## RevOps・CS のスタックに入る理由

- **Google のマーケティングデータがネイティブに集まります。** GA4 のエクスポートと Google Ads 向けの Data Transfer Service により、広告データと Web データがサードパーティのパイプラインなしで BigQuery に入ります。[Fivetran](/ja/tools/fivetran/) で CRM と請求データを加えれば、マーケティングオペレーションは広告費とパイプラインを1か所で突き合わせられます。
- **Ops は BI ライセンスなしで質問できます。** RevOps リーダーが「今四半期に製品利用が落ちたアカウントから来ている $50,000 超のオープン商談はどれか」と尋ねると、アナリストにレビューを依頼できる SQL が返ってきます。質問するために Looker や Tableau のライセンスは必要ありません。
- **出力がスタックの他の部分に流れます。** BigQuery で作ったセグメントは [Hightouch](/ja/tools/hightouch/) 経由で Salesforce や HubSpot に同期されます。[Looker](/ja/tools/looker/)、[Hex](/ja/tools/hex/)、[Sigma](/ja/tools/sigma/) などの BI ツールは同じテーブルを照会します。

## 価格の実態

コンピュートの課金方法は2つです。オンデマンドはスキャンした TiB あたり $6.25 で、毎月最初の 1 TiB は無料です。キャパシティ料金はエディションごとのスロット時間単位で、従量課金の場合 Standard が $0.04、Enterprise が $0.06、Enterprise Plus が $0.10 です。1年および3年のコミットメントで Enterprise は $0.048 まで下がります。アクティブな論理ストレージは米国リージョンで1 GiB あたり月額約 $0.023 で、最初の 10 GiB は無料です。

エージェントはこれとは別に課金されます。Google の Data Cloud エージェント料金では、Conversational Analytics Agent に入力トークン100万あたり $3、出力トークン100万あたり $20 がかかります。すべての Data Cloud エージェントは2026年12月31日まで無料トライアル中で、トークン課金はその後に始まります。各回答が実行する SQL は通常の BigQuery コンピュートとして課金されます。

1問あたり入力30,000トークン、出力3,000トークンとした当社の試算では、エージェントのトークン費用は1問あたり約 $0.15 です。40人の Ops チームが営業日ごとに1,000問を投げると、2027年1月以降はクエリのコンピュートを除いてトークンだけで月額約 $3,150 になります。オンデマンド課金で1問あたり 20 GB をスキャンするチームなら、1問ごとにさらに約 $0.12 が加わります。当社の数字で予算を組むのではなく、無料トライアル期間中に自社のトークン数を計測してください。

## 最適な対象

すでに Google Cloud を使っている、または GA4 と Google Ads のデータがすでに BigQuery に入っている企業の RevOps、マーケティングオペレーション、CS オペレーションのリーダーで、20〜200人のビジネスユーザーに既存の IAM のもとでパイプライン、広告費、アカウントヘルスについて質問させたい、しかも全員に BI ライセンスを買いたくない方に向いています。

ウェアハウスがすでに Snowflake か Databricks なら見送ってください。エージェントのためにデータを移す価値はほとんどありません。フォーキャストやクォータの変更のように、ユーザーが数字を書き戻す必要がある場合も見送ってください。データエージェントは読み取り専用なので、その用途には Sigma のようなライトバックツールが必要です。

## 代替との比較

**[Snowflake](/ja/tools/snowflake/)** はシェアで首位の独立系ウェアハウスで、そのエージェント層である CoWork が同じ役割を果たします。AWS や Azure でのマルチクラウドが必要なら Snowflake を選んでください。Google Cloud を使っている、あるいはマーケティングデータの大半が Google の製品から来ているなら BigQuery を選んでください。

**Databricks** はもう一方のリーダーです。ビジネスユーザー向けエージェントは Genie で、DBU で課金されます。データチームがすでに ML 用に Databricks のレイクハウスを運用しているなら Databricks を選んでください。BigQuery は Databricks Unity Catalog のテーブルをレイクハウスのソースとして照会できますが、両者は自由に組み合わせられる関係ではありません。

**ClickHouse** は最も急成長している新興勢力です。Bloomberg によると、2026年1月に評価額150億ドルで4億ドルを調達しました。イベントデータに対する1秒未満の製品分析なら ClickHouse を選んでください。Conversational Analytics に匹敵するビジネスユーザー向けエージェントはありません。

「パイプライン」の定義について誰も合意していないせいでどれも合わないなら、まずモデルを直してください。[data warehouse vs CDP](/ja/learn/data-warehouse-vs-cdp/) と [reverse ETL](/ja/learn/reverse-etl/) を参照してください。

## 注意点

- **無料トライアルがエージェントの本当のコストを隠します。** トークン課金は2027年1月1日に始まり、それ以前に計測したパイロットではクエリのコンピュートしか見えません。*対策:* トライアル期間中に、代表的な1週間の1問あたり入力・出力トークン数を記録してください。100万あたり $3 と $20 を掛け、その金額の承認をロールアウト前に得てください。
- **コスト上限はオンデマンド課金でしか機能しません。** `big_query_max_billed_bytes` の上限とユーザーごとの1日あたりクエリクォータはスロット予約には適用されず、エージェント単位のクォータやラベルもサポートされていません。*対策:* エージェントはオンデマンド課金の専用プロジェクトで実行してください。そこでクエリごとのバイト上限と「Query usage per day per user」クォータを設定してください。
- **回答の質は、その根拠となる情報の質で決まります。** 列名が分かりにくい Fivetran の生テーブルからは、自信満々の誤った SQL が生まれます。*対策:* エージェントは生テーブルではなく整備済みのビューに向けてください。中核となる20〜30の指標に検証済みクエリを追加し、既知の質問セットを毎月再実行してください。
- **MCP サーバーは書き込みができます。** `execute_sql` ツールは `execute_sql_readonly` と違って DML と DDL を受け付けます。*対策:* MCP で接続する ID には、整備済みデータセットに対する BigQuery Data Viewer と BigQuery Job User だけを付与し、書き込みが権限レイヤーで失敗するようにしてください。
