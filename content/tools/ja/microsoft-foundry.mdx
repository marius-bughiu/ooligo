## 概要

Microsoft Foundry は、自社の Azure サブスクリプションの中でモデルを呼び出し、エージェントを構築するための Azure のプラットフォームです。Azure AI Studio から Azure AI Foundry へと名前を変え、2026 年の初めに「Microsoft Foundry」という名前に切り替わりました。オペレーション部門の購買担当者にとって重要な層は 2 つです。**Foundry Models** はカタログです。OpenAI の GPT-5.6 ファミリー（Sol、Terra、Luna。2026 年 7 月 9 日から一般提供）、Claude（2026 年 6 月に一般提供。推論は Anthropic がデータ処理者として運用）、Microsoft 独自の MAI モデル、Grok、Llama、DeepSeek、そして多数のオープンウェイトモデルが揃っています。**Foundry Agent Service** はエージェント層で、現在は 3 つの形態をカバーしています。

- **プロンプトエージェント**：Microsoft が代わりに実行する宣言型のエージェント（モデル、指示、ツール）です。2026 年 3 月 16 日から一般提供されています。
- **ホステッドエージェント**：自社のコード（Microsoft Agent Framework、LangGraph、その他のオープンソースフレームワーク）を、セッション状態とファイルシステムを備えた Foundry 管理の隔離コンテナで実行します。2026 年 7 月 9 日から一般提供されています。
- **Workflows と Routines**：複数ステップのエージェントとスケジュール実行のエージェントです。Routines は 2026 年 9 月 24 日に一般提供になりました。

その周りには次のものがあります。**Toolboxes**（多数のエージェントが共有する、ツール、MCP サーバー、コネクタをまとめたガバナンス付きのバンドル。GA ですが、Skills と Tool Search はまだプレビュー）、**Foundry IQ**（SharePoint、OneLake、Azure AI Search、Web を対象とするマネージドのナレッジベース。ナレッジベースは GA、サーバーレス層はプレビュー）、**Memory**（セッション、ユーザー、手続きのメモリ。まだプレビュー）、**ブラウザー自動化**ツール（2026 年 10 月 19 日に GA）、そして **bring-your-own AI gateway**（2026 年 4 月に GA）です。後者により、エージェントは Azure API Management やサードパーティのゲートウェイの背後にあるモデルを呼び出せます。最も新しい要素である **Copilot harness** は、スキルとサブエージェントを備えたマネージドのエージェントループで、2026 年 10 月 28 日にパブリックプレビューに入りました。

## オペレーションチームがここにたどり着く理由

きっかけは予想どおりです。チームが最初のエージェントを [Copilot Studio](/ja/tools/microsoft-copilot-studio/) で構築し、それがうまく動き、今になってクレジットの請求額か機能の上限が痛手になっている、という状況です。契約受付エージェントには独自の抽出コードが必要です。パイプライン整備エージェントは月に 3,000 回実行され、アクションごとの Copilot Credits が積み上がります。採用チームはスクリーニングの評価基準に Claude を使いたいのに、スタックの残りは Microsoft です。エンジニアが所有者になったとき、こうしたエージェントの移行先になるのが Foundry です。

AWS に乗り換えずに Microsoft にとどまる理由は、配布とガバナンスです。**2026 年 6 月 10 日**から、Foundry のエージェントを [Microsoft 365 Copilot](/ja/tools/microsoft-365-copilot/) と [Microsoft Teams](/ja/tools/microsoft-teams/) に直接公開できるようになりました。そのため、コードファーストのエージェントが、従業員がすでに仕事をしている場所に、同じ Entra の ID の下で表示されます。すべてのエージェントに Entra Agent ID が付与され、[Microsoft Agent 365](/ja/tools/microsoft-agent-365/) に登録されます。つまりセキュリティ部門は、Copilot Studio のエージェントに使っているのと同じ Conditional Access、Purview、Defender のツールで Foundry のエージェントをレビューできます。支出は既存の Microsoft Azure Consumption Commitment（MACC）から消化され、Claude の利用分も含まれます。これが調達を通る決め手になることがよくあります。

## 価格の実態

席単位の価格はありません。プロンプトエージェントとワークフローエージェントには**ランタイム料金がかかりません**。支払うのはモデルのトークンと、エージェントが呼び出すツールの料金です。以下はすべて US East 2 における Azure の定価で、2026 年 11 月 4 日に Azure Retail Prices API と照合しました。

- **GPT-5.6 Terra：Global Standard で入力 100 万トークンあたり $2、出力 100 万トークンあたり $12** です。GPT-5.6 Sol は $4/$20、GPT-5.6 Luna は $0.20/$1.20 です。これらは短いコンテキストの料金で、長いコンテキストのプロンプトはさらに高くなります。
- **Data Zone のデプロイは 10% 高くなります。** 推論を EU または US のデータゾーン内にとどめると、Terra は $2.20/$13.20 になります。Batch は Global Standard から 50% 引きです。
- **Claude** は、Anthropic が公開しているトークン料金に基づき、Azure の請求書上で Claude Consumption Units として課金され、MACC に算入されます。データ処理者は Microsoft ではなく Anthropic です。
- **ホステッドエージェント：** コンテナのコンピューティングは vCPU 時間あたり $0.0994、GiB 時間あたり $0.0118 です。
- **Memory：** 保存された短期イベント 1,000 件あたり $0.25、長期メモリ 1,000 件あたり月 $0.25、取得 1,000 回あたり $0.50 です。
- **ツールは別途課金されます：** Grounding with Bing、Foundry IQ（Azure AI Search として）、ファイル検索のストレージ、コードインタープリターのセッション、Logic Apps コネクタ、ブラウザー自動化（Playwright Workspaces として）は、それぞれ独自のメーターを持ちます。
- **Copilot harness：** プレビュー期間中は 2026 年 12 月 1 日まで無料で、その後はサンドボックスに同じく vCPU 時間あたり $0.0994、GiB 時間あたり $0.0118 がかかります。

試算の目安です。社内の RevOps エージェントが**月 3,000 セッション**を処理し、各セッションが GPT-5.6 Terra で入力約 20,000、出力約 1,500 トークン、EU のデータゾーンに固定した場合。トークン：入力約 $132 と出力約 $59 で、合計約 $191 です。プロンプトエージェントなら、これが請求額のほぼすべてです。セッションごとに 1 vCPU と 2 GiB を 5 分間確保するホステッドエージェントなら、コンピューティングとして約 $31 が加わります。Memory とグラウンディングは、この量なら合わせて $15 未満に収まります。**合計：月約 $200〜$240、年約 $2,400〜$2,900 です。** 同じワークロードを、1 回の実行あたり 6 アクションと 1 回の生成回答を行う Copilot Studio の自律型エージェントで動かすと約 96,000 クレジットとなり、キャパシティパックで月 $800 になります。Azure の請求額は小さいほうの数字です。本当のコストは、エージェントを構築し保守するエンジニアです。

## 最適な用途

**Microsoft 365 と Azure を使う企業のプラットフォームチームまたは RevOps エンジニアリングチーム**で、Copilot Studio のローコードの上限やアクション単位のクレジットを超えてしまい、Entra の ID と Agent 365 のガバナンスの下で Teams と Microsoft 365 Copilot に届けるエージェントを必要としているチームに最適です。ワークロードが大量かつバックオフィス型（抽出、分類、ルーティング、エンリッチメント）で、消化すべき Azure のコミットメントがすでにある場合は、文句なしに Foundry が勝ちます。

## 向いていないケース

構築を担うエンジニアがいない 10〜50 人規模のオペレーションチームには向きません。[Copilot Studio](/ja/tools/microsoft-copilot-studio/) にとどまるか、[Dust](/ja/tools/dust/) や [Langdock](/ja/tools/langdock/) を購入してください。Foundry が提供するのはポータルと SDK であり、RevOps マネージャーが自力で設定できるアシスタントではありません。また、ID とデータが AWS や Google Workspace にある企業にとっても間違った買い物です。既存のクラウドがすでに販売しているものを手に入れるために、Entra、Azure サブスクリプション、2 つ目のクラウドの請求書を導入することになるからです。

## 代替ツールとの比較

- **[Amazon Bedrock](/ja/tools/amazon-bedrock/)**：ハイパースケーラーのエージェントプラットフォームにおける、もう一方のシェアリーダーです。ID、データ、クラウドのコミットメントが AWS にあるなら Bedrock と AgentCore を選んでください。それらが Entra と Azure にある場合、またはエージェントを Teams と Microsoft 365 Copilot の中に表示する必要がある場合は Foundry を選んでください。トークン価格は近く、決め手は ID プロバイダーとデータがすでにどこにあるかです。モデルの差も縮まりました。GPT-5.x は Bedrock で動き、Claude は Foundry で動きます。
- **Google Cloud の Agent Platform**：3 つ目のハイパースケーラーの選択肢です。データウェアハウスが BigQuery で、会社が Google Workspace で動いており、[Gemini](/ja/tools/gemini/) が第一候補のモデルである場合に選んでください。
- **[Copilot Studio](/ja/tools/microsoft-copilot-studio/)**：Foundry の上にある Microsoft 独自のローコード層です。エンジニアではなくメーカーがエージェントを所有し、クレジットが月に数パック以内に収まる程度の量であるうちは、エージェントをそこに置いておいてください。カスタムコード、Copilot Studio が公開していないモデル、または大量利用でのトークン単位の価格が必要になったら Foundry に移行してください。
- **Claude Platform と Claude Managed Agents**：エージェント機能で最も動きの速い新規参入者です。Foundry 上の Claude には、Anthropic 自身のプラットフォームにあるコード実行、Agent Skills、Files API、バッチがありません。これらの機能が設計を左右するなら Anthropic を直接選び、要件が 1 本の Azure の請求書と Entra で統制された配布であるなら Foundry を選んでください。

## 注意点

- **Foundry 上の Claude は Claude API の完全版ではなく、Microsoft はその処理者ではありません。** 推論を運用し、データ処理者かつ SLA の提供者となるのは Anthropic です。また、ホスト版にはコード実行、Agent Skills、Files API、バッチがありません。**対策：** 個人データを Claude に送る前に、別個の処理者としての Anthropic の規約をプライバシー担当の弁護士にレビューしてもらってください。さらに、採用を決める前に、設計に必要な Claude の機能をすべて Microsoft の Claude 機能リストと照合してください。
- **データレジデンシーはデフォルトではなく、デプロイの種類です。** Global Standard は最も安く、リクエストを任意のリージョンに振り分ける可能性があります。**対策：** EU のデータや規制対象データには Data Zone または Regional の SKU だけをデプロイし、10% の割増を予算に組み込み、該当するエージェントを抱えるサブスクリプションで Global Standard のデプロイを拒否する Azure Policy で強制してください。
- **1 つのエージェントの中に GA とプレビューが混在しています。** ホステッドエージェントと Toolboxes は GA ですが、Memory、Toolbox の Skills、Tool Search、サーバーレスの Foundry IQ、Copilot harness はまだプレビューで、GA の約束もありません。**対策：** エージェントごとに依存関係リストを作り、各機能に GA かプレビューかを記録してください。プレビューの機能は、GA になるまで顧客向けやコンプライアンスに関わるものには使わないでください。
- **請求が 6 つのメーターに分かれて届きます。** トークン、ホステッドのコンピューティング、メモリ、Bing のグラウンディング、AI Search、Playwright がそれぞれ別々に課金されるため、1 つのエージェントにいくらかかっているかを示す画面がありません。**対策：** 本番のエージェントはそれぞれ専用のリソースグループに置いてエージェント名のタグを付け、エージェントごとに予測の 120% で Azure Cost Management の予算アラートを設定してください。
- **古いチュートリアルは廃止された API を教えています。** Assistants API は 2026 年 8 月 26 日に提供を終了し、Prompt flow は 2027 年 4 月 20 日に廃止されます。**対策：** 構築は Responses API と Foundry Agent Service だけで行い、Prompt flow のパイプラインは機能を追加する前に Agent Service のワークフローへ移行してください。
