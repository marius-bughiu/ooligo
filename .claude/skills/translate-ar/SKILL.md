# translate-ar

Translate one item from `ar_TRANSLATION_QUEUE.md` into Modern Standard Arabic, then commit and push to `main`. Fully autonomous — invoking this skill is the user's consent for that single page.

## How this skill is wired

- **Source of work**: `ar_TRANSLATION_QUEUE.md` at the repo root (regenerated by `npm run queue:translations`).
- **Staleness signal**: each translated MDX carries `source_sha256` — SHA-256 of the EN source's body. When the EN body changes, the hash drifts and the queue marks the page stale.
- **Autonomy**: this skill commits and pushes to `main` without asking. Do not invoke it if you don't want that to happen.
- **Direction**: `ar` is the only RTL locale. The page wrapper sets `dir="rtl"` automatically based on `locales.json` — you don't need to add direction markers to MDX bodies. Markdown content flows RTL by default once the wrapper is set.

## The autonomous one-page workflow

Execute these steps in order. Stop at the first failure (don't push broken builds).

1. **Read the queue.** Read `ar_TRANSLATION_QUEUE.md`. If the body says "Queue empty — all content translated and current.", print one line ("AR queue is empty.") and exit.

2. **Pick the next item.** Take the **first** unchecked checklist item under the **first non-empty** collection section. Note `source` and `target` paths from the item's bullet lines, and whether the status is `missing` or `stale`.

3. **Read the EN source.** Read the full file at `source`. Use `gray-matter` semantics in your head: everything between the two `---` fences is frontmatter; everything after is the body.

4. **Translate the body** into Modern Standard Arabic, applying the rules in this skill (glossary + register sections below). Translate the markdown body only. Frontmatter values are not translated except where noted in step 5.

5. **Compute the EN body hash.** Run `npm run hash:en --workspace=packages/pipeline -- <source>` and capture stdout. The single line printed is the SHA-256 of the EN file's body. You will paste this into the target's frontmatter in the next step.

6. **Write the target MDX** at `target`. Frontmatter rules:
   - Copy these fields verbatim from EN: `slug`, `canonical_slug`, `verticals`, and **all entity-specific fields** (`name`, `category`, `subcategories`, `pricing_model`, `pricing_starts_at`, `pricing_url`, `website`, `ai_native`, `mcp_available`, `api_available`, `integrations`, `ooligo_score`, `ooligo_score_breakdown`, `last_reviewed`, `last_refreshed`, `affiliate_link`, etc.). These are structural data, not translatable display strings.
   - Set `locale: ar`.
   - Set `ai_generated: true`, `ai_translated: true`.
   - Set `translated_from: en/<basename of source>.mdx`.
   - Set `translated_at` to now in ISO-8601 UTC with seconds precision (e.g. `"2026-05-02T22:58:47Z"`).
   - Set `translation_model: claude-opus-4-7`.
   - Set `source_sha256: "<hash from step 5>"`.
   - If the target already exists (stale case), overwrite it.

7. **Validate the build.** Run `npm run validate` and `npm run build`. If either fails, fix the translation file and retry. Never proceed with a failing build.

8. **Regenerate the queue.** Run `npm run queue:translations --workspace=packages/pipeline -- --locale=ar` (the workspace form is required — npm doesn't forward `--` args through the root passthrough). Confirm the item you just translated no longer appears in `ar_TRANSLATION_QUEUE.md`.

9. **Commit and push.** Stage exactly: the new/updated target file, `ar_TRANSLATION_QUEUE.md`. Commit with message `content(<collection>/ar): translate <slug>` (e.g. `content(tools/ar): translate claude-skills`). Include the `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>` trailer. Then `git push origin main`.

10. **Report.** One sentence: which slug was translated, status before (missing/stale), commit SHA.

## Translation rules

### Never translate (proper nouns + industry English)

```
Clay, Apollo, HubSpot, Salesforce, Claude, GPT, Cursor, n8n, MCP,
Anthropic, OpenAI, Google, Microsoft, GitHub, Slack, Zapier, Outreach,
Salesloft, Gong, Chorus, Default, ZoomInfo, Apollo, Lemlist, Smartlead,
Instantly, Lusha, RegieAI, Common Room, Pavilion, Gainsight, Reforge,
Maven, MasterClass, AppSumo, Levels.fyi, Wirecutter,

RevOps, GTM, ICP, TCV, ARR, MRR, NRR, GRR, SDR, BDR, AE, CSM, TA, RAG,
LLM, API, SaaS, CRM, MCP, RPA, ETL, ELT, BI, KPI, OKR, NPS, CSAT, QBR,

ooligo
```

### Fixed translations (Latin script standard for tech in MSA writing)

```
lead       → lead   (or "عميل محتمل" in formal context)
pipeline   → pipeline   (or "خط الأنابيب")
outbound   → outbound   (or "صادر")
inbound    → inbound   (or "وارد")
stack      → stack
workflow   → سير العمل   (or "workflow")
prompt     → prompt   (Latin)
agent      → وكيل
skill      → skill   (when referring to Claude Skills specifically)
```

Brand names always in Latin script (Claude, Apollo, GitHub, HubSpot). Mixing Latin script into Arabic prose is standard in MSA tech writing.

### Regional register — Modern Standard Arabic (الفصحى الحديثة)

- Use **Modern Standard Arabic (الفصحى الحديثة)** — not regional dialects (Egyptian, Gulf, Levantine, Maghrebi). MSA is the cross-regional written register for B2B / professional writing.
- Avoid Classical/Quranic-style flourishes — keep it modern and direct.
- Tech terms commonly stay in Latin script in MSA tech writing (Claude, MCP, GitHub, API). Arabic translations are also acceptable when the term has a widely-used Arabic form (وكيل for "agent", سير العمل for "workflow").
- **Numerals**: Western Arabic digits (0-9) are acceptable for tech metrics, prices, and version numbers. Arabic-Indic digits (٠-٩) are also valid — pick whichever is more common in the surrounding context. Be consistent within a single file.
- **Direction**: write Arabic text naturally; the page wrapper handles RTL via `dir="rtl"`. Don't insert Unicode RLM/LRM markers into MDX bodies. Code blocks, URLs, and Latin-script terms render LTR within the RTL flow automatically (browser bidi).
- Audience: Arabic-speaking B2B operators across MENA — Egypt, KSA, UAE, Jordan, Lebanon, Morocco, Tunisia, Algeria.
- Keep the original voice: confident, opinionated, structured. We rank, we recommend, we say what's bad. Don't soften into G2-style hedging — Arabic professional writing tends to hedge more than English; resist that pull.

### Quality bar

**Translate; don't re-author.** The AR variant says the same things the EN variant says — same opinions, same recommendations, same product judgments. If the EN entry says "Apollo is the right pick under $10M ARR," the AR entry says the same. Never inject locale-specific opinions or restructure the argument.

If you spot a factual error in the EN source while translating, **stop and surface it** in your final report — don't silently "fix" it in the translation. The fix belongs in the EN source as a separate change.
