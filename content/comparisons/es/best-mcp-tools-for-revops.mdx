Las herramientas MCP-native (o MCP-ready) en las que un equipo de RevOps debería estandarizar en 2026. Cinco picks, ranqueados por dónde MCP realmente crea leverage hoy — no donde podría hacerlo en dos años.

## 1. Claude — el assistant MCP-first

Claude es el assistant construido para MCP. Soporte de cliente nativo en Claude.ai, Claude Code y la app de escritorio. El lugar correcto para correr cualquier Skill de RevOps que necesite data con grounding. Score ooligo: 9.5.

**Lo que reemplaza:** ChatGPT ad-hoc con data del CRM copiada y pegada, el tiempo de analista que solía irse en "resume la actividad de deals de Q4".

**Por dónde empezar:** instala el MCP server de HubSpot o Salesforce. Construye un Skill que jale un registro de deal + las últimas tres calls + los últimos cinco emails y escriba una narrativa de forecast. El unlock es inmediato.

## 2. n8n — el runtime de workflow MCP-native

n8n tiene soporte MCP de primera clase — tanto como cliente como servidor. Corre agentes de IA dentro de workflows que llaman herramientas MCP, expone tus flujos de n8n como endpoints MCP. La capa de orchestration. Score ooligo: 9.0.

**Lo que reemplaza:** Zapier (que está años atrás en MCP), servidores Python custom, el gap entre agentes LLM y tus sistemas operativos.

**Por dónde empezar:** reconstruye un cron job nocturno en n8n con un workflow expuesto por MCP que Claude pueda triggear. Una vez que el loop se cierra, verás los siguientes 10 automations obvios.

**[Reseña completa de n8n →](/es/tools/n8n/)**

## 3. Cursor — el cliente MCP del lado developer

Cursor es el IDE para construir MCP servers y consumirlos. Para GTM engineers y líderes técnicos de RevOps, es donde el trabajo MCP realmente pasa. Score ooligo: 9.3.

**Lo que reemplaza:** escribir servers de herramientas internas en VS Code con Copilot, el ciclo de build de varias semanas para integraciones custom de RevOps.

**Por dónde empezar:** en Cursor, pídele a Claude que haga scaffolding de un MCP server para la herramienta interna que más dolor de copy-paste te da. El primer server toma 2 horas; el segundo toma 30 minutos.

**[Reseña completa de Cursor →](/es/tools/cursor/)**

## 4. HubSpot — CRM MCP-ready

HubSpot ha shipeado integración MCP real vía Breeze. Lee deals, contacts, companies; escribe notas; triggea workflows. El CRM correcto si quieres una capa MCP usable sin construirla tú mismo. Score ooligo: 8.8.

**Lo que reemplaza:** el cliente custom de la API de HubSpot que cada equipo de RevOps escribe y luego mantiene mal.

**Por dónde empezar:** conecta el MCP server de HubSpot a Claude. Pregunta "qué está en riesgo esta semana?" y mira lo que pasa.

**[Reseña completa de HubSpot →](/es/tools/hubspot/)**

## 5. Salesforce — MCP vía Agentforce

La historia de MCP de Salesforce corre por Agentforce. Funcional, menos elegante que la de HubSpot, pero workable para la población gigante de equipos residentes en Salesforce. Score ooligo: 8.5.

**Lo que reemplaza:** el pegamento casero de Salesforce-a-LLM que cada enterprise ha estado construyendo durante dos años.

**Por dónde empezar:** si estás en Salesforce y tienes tiempo de admin, levanta la capa MCP de Agentforce para queries de solo lectura primero. Mete escrituras una vez que los patrones de lectura estén claros.

**[Reseña completa de Salesforce →](/es/tools/salesforce/)**

## Lo que no está en esta lista (y por qué)

- **Herramientas sin MCP** — capaces pero resbalando. Esperamos que esta lista se vea muy diferente en 12 meses a medida que más vendors shipeen.
- **Solo MCP servers in-house custom** — decente si eres una shop de Cursor + Claude Code, pero la mayoría de los equipos deberían comprar lo que puedan y construir solo lo que deban.
- **ChatGPT** — tiene function calling pero está atrás de Claude en ergonomía MCP-native.

## El stack mínimo viable de MCP para RevOps

Si quieres empezar con tres:

1. Claude (assistant MCP-first)
2. n8n (runtime MCP-native)
3. HubSpot o Salesforce (CRM MCP-ready)

Agrega Cursor el día que contrates a alguien que va a construir MCP servers custom. El compounding empieza en el segundo server, no en el primero.
