**2026年5月1日**、Microsoft は Agent 365 を一般提供に切り替えました。価格は**年払いで1ユーザーあたり月額 15.00 ドル**です。これによって、シート ライセンスが決してカバーしてこなかったもの、つまり自律的に動くソフトウェアのためのレジストリ、ID、監査証跡に値段が付きました。価格で最も重要なのは単位です。Agent 365 は**エージェント単位ではなく、人間のユーザー単位**でライセンスされます。40体目のエージェントは無料です。201人目の従業員は月額 15 ドルです。

これは多くの ops 組織の予算の立て方をひっくり返します。彼らはエージェントを数え、シートを交渉しています。請求は人員数に比例し、リスクはエージェント数に比例する。異なる2本の曲線であり、請求書に現れるのは片方だけです。

このスタックはたった1つのルールを軸に組まれています。**実システムに書き込めるエージェントは、自社が発行した ID と自社が設定した支出上限のもとで動く。** 以下の要素は、このルールを執行するか、正直にその外側にあるかのどちらかです。

## 構成

- **Microsoft Entra Agent ID が ID レイヤーであり、ここが飛ばされがちな層です。** 親子関係を持つ blueprint からエージェント ID を発行するため、ポリシーは1体ずつではなくエージェントのファミリー単位で適用できます。OAuth 2.0、MCP、A2A に対応します。Microsoft 外で構築したエージェントは Entra Auth SDK のサイドカーまたはワークロード ID フェデレーションで登録します。Microsoft は **AWS Bedrock と n8n** を名指ししています。Agent ID はすべての Entra 顧客が利用できます。落とし穴は Microsoft 自身のドキュメントにある1行です。Entra の*セキュリティ*機能をエージェントに拡張すること、つまりエージェント向け Conditional Access、Identity Protection のリスク検出、ID ガバナンスには Agent 365 ライセンスが必要です。Agent 365 のない ID は名札であって、鍵ではありません。
- **Agent 365 がコントロール プレーンです。** 役割は3つ。観測 (エージェント レジストリ、レジストリ同期、Microsoft 365 管理センターの Agent Map)、統制 (ライフサイクル、アクセス レビュー)、保護 (アクセスは Entra、データは Purview、脅威は Defender) です。Microsoft 365 E7 に含まれ、E5、A5、Business Premium、あるいは Defender Suite と Purview Suite の組み合わせへのアドオンとして販売されます。まだ E5 環境でないなら、アドオンより先に前提条件の価格を見積もってください。
- **[n8n](/ja/tools/n8n/) がアクション レイヤーであり、ここで Microsoft が agent factory として掲載している唯一のコンポーネントです。** n8n 上で構築したエージェントには自動的に Entra Agent ID が付与され、管理センターに現れ、Agent 365 の可観測性を継承します。自前の ID 実装は不要です。n8n は承認ゲートも担います。モデルの判断と CRM への書き込みの間に立つ、人間の Yes か No です。ただしパートナー一覧の条件はよく読んでください。n8n の Agent 365 トリガー ノードは **early preview であり、Microsoft の Frontier プログラムへの登録が必要**です。最も安価で信頼できるアクション レイヤーだから今日 n8n の上に作る、というのは正しい。preview のインテグレーションの上にコンプライアンスの論拠を組み立てるのは正しくありません。
- **[Glean](/ja/tools/glean/) が検索・取得レイヤーであり、自らを統制します。** Glean は Agent 365 のパートナー一覧に載っていないため、そのエージェントは Microsoft のレジストリには入りません。だからこそ Glean 自身の制御が重要になります。Glean の agent access policy は実行時に2か所で走ります。**実行前**にツールの ID と入力引数を検査し、**実行後**に構造化されたレスポンス ペイロードを検査します。アクションは3つ。**Block** は呼び出しを止め、**Filter** は結果配列から該当項目だけを取り除き、**Flag for review** は通したうえで記録します。適用範囲はユーザー グループ単位、エージェントまたはエージェント フォルダー単位、ツール単位で指定します。これは本物のポリシー エンジンであり、「このエージェントは社外ドメインにメールを送れるのか」という問いに、検索製品が通常まったく答えられない形で答えます。
- **[Claude](/ja/tools/claude/) または [ChatGPT](/ja/tools/chatgpt/) が人間の操作面です。** 従業員が実際に使うのはこの層であり、Microsoft のコントロール プレーンからは見えない層でもあります。どちらも Agent 365 のパートナー一覧にはありません。制御は各社の管理コンソールにあり、そこで設定するか、まったく設定しないかのどちらかです。

### 名前の付いた受け渡し

1. **誰かが n8n でワークフロー エージェントを作る → Entra が ID を発行し、Agent 365 が登録する。** チケットも手動プロビジョニングも不要です。そこで生まれたからレジストリにいます。
2. **エージェントがトークンを要求する → エージェント向け Conditional Access が評価する。** 人間を統制するのと同じポリシー エンジンです。この段階が Agent 365 ライセンスを必要とします。
3. **エージェントが Glean に問い合わせる → アクセス ポリシーが2回発火する。** 1回目はツール呼び出しと引数に対して、2回目は返ってくるペイロードに対して。エージェントが本来取得を許されていた結果セットからも、財務文書は除外されます。
4. **エージェントが書き込みを提案する → n8n が承認ゲートで止める → Agent 365 が操作を記録し、Purview が記録を保持する。** ゲートは自社のもの、ログは Microsoft のもの、どちらもモデル ベンダーのものではありません。
5. **人が Claude や ChatGPT Work を操作する → その支出はそのベンダーのメーターに乗る。** それを止める上限は Anthropic か OpenAI のコンソールで設定します。Agent 365 は止めませんし、見えませんし、報告もしません。

受け渡し5がこのスタックの正直な穴です。取り繕わず、担当者を割り当ててください。

## コストを決める分岐

アシスタント層はシート課金と従量課金が分かれる場所であり、2社は正反対の側を選んでいます。

**Claude Enterprise は 2026年2月12日からセルフサーブで購入できます。** 課金は年払いの1ユーザー月額固定シート料金に、**標準 API レートで課金される全トークン**が加わる形です。最低 20 シート。セルフサーブは前払いクレジットを購入して消費し、営業経由は月次後払いです。Anthropic はこのモデルを公開していますが、シート単価そのものは公開していません。公開しているのは制御のほうです。**管理者は組織レベルとユーザー個人レベルの両方で支出上限を設定でき**、メンバーごとの当月累計支出としきい値アラートを確認できます。SSO、ドメイン キャプチャ、SCIM、監査ログ、Compliance API、カスタム保持期間、既定でのトレーニング オプトアウトが含まれます。

**ChatGPT Business は利用分をシートに含める方式で、月次請求なら1ユーザー月額 25.00 ドル**、最低2ユーザー、年払いはこれより安くなります。Enterprise は見積のみで、Enterprise Compliance API が加わります。タイムスタンプ付きの会話、アップロードされたファイル、ワークスペースの GPT 設定、メモリが対象です。さらに Enterprise と Edu ではアプリとコネクタが**既定で無効**になっています。指示を受けて完成ファイルを返すエージェント ChatGPT Work は **2026年7月9日**に登場しました。

**選び方:** 利用量を予測できないなら、利用分込みのシートを買ってください。上限を設定しないまま従量プランに入るのが、パイロットが予算事故に変わる典型的な経路です。利用量を予測でき、支出を人単位で可視化したいなら、従量プランのほうが情報量は明確に多い。ただしそれは、最初の請求書が来てからではなく最初の1週間で誰かが上限を設定する場合に限ります。一般原則は [AI のシート課金と従量課金](/ja/learn/seat-based-vs-usage-based-ai-pricing/) にあります。

## コストの実態

すでに Microsoft 365 E5 をライセンス済みで、およそ30体のエージェントを動かす200人規模の組織の場合:

- **Agent 365:** 15 ドル × 200 ユーザー = **年間 36,000 ドル**。エージェントが5体でも50体でも変わりません。
- **ChatGPT Business:** 25 ドル × 200 = 月次レートで**年間 60,000 ドル**、利用分込み。
- **Claude Enterprise:** 見積のみのシート料金 × 200 に、**加えて**別途予測が必要な API レートの利用分。まず利用分から見積もってください。動くのはそちらです。
- **[n8n](/ja/tools/n8n/) Pro:** 年払いで **月額 50 ユーロ**、10,000 実行分。ステップ単位ではなく実行単位の課金です。Business は月額 667 ユーロ、超過は 300,000 実行の追加ブロックごとに 4,000 ユーロ。
- **Glean:** 自社の価格ページに価格の掲載はなく、デモ申し込みだけが表示されます。第三者のトラッカーは年間で数万ドル台のエンタープライズ最低契約額を報告していますが、見つけた数字はすべて「報告値」であって「公開値」ではないものとして扱い、設計の前に見積を取ってください。

公開されていて根拠を示せる金額でおよそ**年間 96,000 ドル**、加えて見積のみの2行。上のすべてを合計した額を超える可能性が最も高いのは Glean の見積です。

## バリエーションと差し替えの判断

- **ナレッジがすでに Microsoft 365 にあるなら Glean を外す。** 答えが SharePoint、Teams、Outlook にあるなら、検索・取得に二重で払っています。Microsoft がうまくインデックスできないシステム、たとえば Salesforce、Jira、wiki、データ ウェアハウスに相当量のコーパスがある場合、そしてエージェントのツール呼び出しに読み書きのポリシーが必要で CRM ではそれを表現できない場合は、Glean を残してください。
- **ロールアウトが Frontier preview ではなく一般提供のインテグレーションを前提とするなら、n8n を Microsoft ネイティブの agent factory に差し替える。** 現時点でパートナー一覧に agent factory として載っているのは Kore と Kasisto です。ルールはこうです。範囲とコストなら n8n、購買部門が書面で GA のインテグレーションを求めるならネイティブ経路。
- **Claude と ChatGPT を1四半期並走させ、その後どちらかを切る。** アシスタント契約2本はパイロットとしては妥当で、恒常状態としては擁護できません。レビュー日は更新が近づいてからではなく、署名時に決めてください。

## このスタックが置き換えないもの

- **AI ポリシーではありません。** 決定を執行しますが、決定はしません。どのエージェントがどのシステムに書き込んでよいかは、まず文書化されたルールです。[RevOps チームの AI ポリシー](/ja/learn/ai-policy-for-revops-teams/) を参照してください。
- **エージェント自体を作るプラットフォームではありません。** エンジニアなしでエージェントを作る少人数チームが必要なのは [AI agent ops stack](/ja/stacks/ai-agent-ops-stack/) です。価格は10分の1で、ここにあるガバナンスは一切ありません。
- **シャドー AI は統制できません。** 従業員が個人のブラウザー タブで開いたものは、ここにあるすべての層の外側です。
- **エージェントを正確にはしません。** ID、ログ、上限は誤答が引き起こせる被害を限定します。誤答の頻度は下げません。

## 注意点とそれぞれの防御策

- **Agent 365 なしの Agent ID は名前を与えるだけで、執行はしません。** エージェント向けの Conditional Access と Identity Protection はライセンスの向こう側にあります。**防御策:** ID レイヤーを統制手段として社内に発表する前に、少なくともライセンスの前提条件、すなわち E5、A5、Business Premium、または Defender と Purview Suite の組み合わせを確認してください。
- **n8n のインテグレーションは early preview かつ Frontier 限定です。** preview の機能はパイロットとロールアウトの間に形が変わることがあります。**防御策:** コンプライアンスの説明は Agent 365 の GA 機能だけを根拠に書き、n8n のレジストリ対応は「なくても進めた加速要因」として扱ってください。
- **最も使われる AI 製品2つが Microsoft のレジストリの外にあります。** Claude と ChatGPT はパートナー一覧にありません。**防御策:** それぞれの監査エクスポート、つまり Anthropic の Compliance API と OpenAI の Enterprise Compliance API を設定し、両方を Agent 365 のログと同じレビューに載せてください。レビューは1つ、ソースは3つ。
- **ユーザー単位課金はエージェントの増殖を隠します。** エージェントが増えても請求は動かないため、30体目の重複エージェントを誰も請求してくれません。**防御策:** 毎月 Agent 365 のレジストリをオーナー一覧と突き合わせ、名前の付いたオーナーがいないものは廃止してください。書き込み権限が残っているものには [CRM エージェント アクセス監査](/ja/workflows/crm-agent-access-audit-skill/) を実行します。
- **支出上限を「無制限」にしても課金は続きます。** Anthropic のドキュメントは明示しています。上限が無制限でも消費は課金されます。**防御策:** 初日に組織上限とユーザー単位の上限を設定し、しきい値アラートを人間が読むチャンネルに送ってください。

## 適合ルール

**正しい選択となる条件:** すでに Microsoft 365 E5 以上を使っており、従業員が100人から2,000人の範囲にあり、エージェントが複数の場所で作られていて、CISO、監査人、取締役会の誰かが「特定のシステムへの特定の書き込みを誰が承認したのか」と尋ねる見込みがあること。その答えが「聞いて回らないと分かりません」でなくなった瞬間に、このスタックはコストを回収します。

**誤った選択となる条件:** 50人未満の場合。E5 という前提条件だけで管理対象のリスクを上回り、エージェントごとに名前の付いたオーナーを置けば無料で同じ仕事が済みます。Microsoft ではなく Google Workspace を使っている場合も誤りです。コントロール プレーンは Entra テナントを前提としており、Vertex AI の登録経路はエージェントを管理センターで*可視化*するだけで、残りの Microsoft 資産を買う理由にはなりません。そしてまだどのエージェントもどこにも書き込んでいない場合も誤りです。統制すべきは2体目のエージェントであって、1体目ではありません。

**1つだけやるなら:** アシスタント プランの支出上限を設定してください。10分で終わり、費用はかからず、悪い1週間が悪い1四半期になるのを防ぐ、このスタック唯一の制御です。
