## 概要

Lovable は、プロンプトからアプリを生成するビルダーです。チャットでアプリを説明すると、フロントエンドに React と Tailwind、データ・認証・ファイルストレージに Supabase ベースのバックエンドを使ったフルスタックの Web アプリケーションを書き、そのままホスティングします。コードは製品の中に閉じ込められません。GitHub リポジトリに同期されるため、エンジニアはプルリクエストをレビューし、自分のエディタで開発を続けられます。この「出口」があることが、アプリがベンダー独自の形式で存在する [Retool](/ja/tools/retool/) のような従来型ローコードのキャンバスとの最大の違いです。

売上で見ると、社内アプリ領域で最も急成長している新興ベンダーでもあります。ストックホルムを拠点に、オープンソースの GPT Engineer プロジェクトから Anton Osika と Fabian Hedin が 2023 年に創業しました。2026 年 8 月 12 日に Menlo Ventures がリードする $400M のシリーズ C を評価額 $13.3B で調達しており（TechCrunch）、これは評価額 $6.6B での $330M のシリーズ B から 8 か月後のことです。共同創業者の Fabian Hedin は 2026 年 9 月 24 日、年換算売上が $600M を超えたと述べました。2025 年 11 月に公表した $200M の約 3 倍です。Lovable によれば、作成されたプロジェクトは 6,000 万件を超え、Fortune 500 企業のほぼ 3 分の 2 で従業員が利用しています。

## オペレーションチームがここに行き着く理由

オペレーション担当者がすでに使っているからです。多くの場合、IT が把握する前に。典型的な依頼 ── パートナーポータル、レビューキュー付きのインテークフォーム、CRM データを使ったコミッションダッシュボード ── は、エンジニアリングが優先順位を上げるには小さすぎ、スプレッドシートで回すには具体的すぎます。Lovable はこのギャップを午後のうちに埋めます。シリーズ C の発表ではコネクタとして Salesforce、Google Workspace、Microsoft 365、Stripe が挙げられ、Lovable Cloud は Supabase アカウントを別途用意しなくても各アプリにデータベース、認証、ストレージを提供します。

Enterprise プランにはガバナンス層が揃っています。SSO/SAML、SCIM プロビジョニング、監査ログ、誰が公開でき誰が結果を閲覧できるかを制限する公開コントロール、そしてワークスペース内のすべてのアプリをリスク順に一覧表示する Security Insights です。Lovable は SOC 2 Type II、ISO 27001、AIUC-1 の認証取得を公表しています。

## 購入に値するユースケース

RevOps や CS のリーダーが、いくつかのテーブルを読むだけの顧客・パートナー向けアプリを必要としているケースです。更新見積もりの依頼ポータル、Salesforce に書き込むパートナー案件登録フォーム、案件種別ごとに依頼を振り分ける法務インテークページなどが該当します。いずれも本番データウェアハウスに対する行レベルの権限は不要ですが、完成品に見える必要があります。Lovable で構築し、初日から GitHub に同期し、アプリがパイロットを超えて使われ続けるならリポジトリをエンジニアに引き継いでください。

## 料金

Free は 1 日 5 クレジット、月の上限は 30 クレジットです。Pro は月額 $25（年額 $250）で月 100 クレジットから始まり、上位の Pro 階層は 200 クレジットで $50、400 で $100、800 で $200 です（No Code MBA、lovable.dev と照合済み）。Business は月額 $50 からで、SSO、学習へのデータ利用のオプトアウト、ロールベースのアクセス、社内公開が加わります。Enterprise は見積もりのみです。

課金単位はクレジットで、消費量はタスクによって変わります。Lovable 自身の例では、1 行のスタイル変更で 0.5 クレジット、画像付きのランディングページで 1.7 クレジットです。追加購入は Pro で 50 クレジットあたり $15（1 クレジット $0.30）、Business で 50 クレジットあたり $30（1 クレジット $0.60）です。ホスティングとアプリ内 AI は、月次の付与分がある Cloud と AI の別残高から消費され、付与分を超えると従量課金になります。社内アプリを 2〜3 本作る小規模なオペレーションチームの実勢は月 $50-200 です。毎日反復するチームは $100-200 の Pro 階層に収まるか、SSO のために Business 料金を払うことになります。

## 最適な対象

従業員 20〜500 人規模の企業で、エンジニアでない人が構築でき、後からエンジニアが GitHub 経由で引き継げる、単体で完成度の高いアプリ ── ポータル、インテークフォーム、軽量なダッシュボード ── を必要としている Ops、RevOps、CS のリーダー。

## 代替ツールと選ぶべき場面

- **[Retool](/ja/tools/retool/)** ── エンジニアが構築する社内ツール領域のリーダーで、2025 年 10 月時点で ARR $120M を公表しています。構築者が SQL を書き、アプリがクエリ単位の権限を持つ本番データベース上で動く場合に選んでください。
- **Microsoft Power Apps** ── M365 ライセンスに同梱される、もう一方のシェアリーダーです。アプリが SharePoint や Dataverse 上のフォームで、IT が構築を担う場合に選んでください。
- **[Superblocks](/ja/tools/superblocks/)** ── 評価の理由がガバナンスである場合に選んでください。Lovable のプロトタイプを取り込み、行レベルの権限管理を備えた統制下の接続上で再ホスティングします。
- **[Airtable](/ja/tools/airtable/)** ──「アプリ」がビューと自動化を備えた共有テーブルで、独自 UI が誰にも必要ない場合に選んでください。

## 注意点

- **2026 年の Lovable 自身のセキュリティ実績。** 2026 年 2 月 3 日から 4 月 20 日まで、バックエンドの不具合により、公開プロジェクトのチャット履歴とソースコードが認証済みの Lovable ユーザーなら誰でも閲覧できる状態になっていました。HackerOne 経由の報告は、Lovable が対応する前に「意図された動作」として閉じられていました（Lovable、2026 年 4 月 22 日）。Lovable は不具合を修正し、過去の公開プロジェクトを非公開に切り替えました。対策：ワークスペース全体で非公開プロジェクトを必須にし、API キーはプロンプトやコードではなく Cloud の secrets に保管し、一度でもチャットに現れた認証情報はすべてローテーションしてください。
- **生成されたアプリのセキュリティは、プロンプトで求めた範囲にとどまります。** 2025 年 3 月、ある研究者が Supabase テーブルにアクセスポリシーがなく、データが公開状態で読み取れる Lovable 製アプリを 170 件以上発見しました（CVE-2025-48757）。対策：公開のたびに Lovable のセキュリティスキャンを実行し、顧客データを持つテーブルについては本番公開前にエンジニアが row-level security のポリシーをレビューしてください。
- **クレジット消費は予測しにくいです。** チャットでバグ修正を繰り返すと試行ごとにクレジットを消費し、Business の追加購入単価は Pro の 2 倍です。対策：Pro の 1 席で請求サイクル 1 回分のパイロットを行い、リリースした機能ごとのクレジット消費を記録してから階層を決めてください。行き詰まった修正はプロンプトを繰り返さず、GitHub とエンジニアに回してください。
- **アプリはデフォルトで Lovable のホスティング上に置かれます。** 対策：本番利用の前に GitHub を接続し、コードと履歴が Lovable の外にも存在する状態にしてください。また、移行する場合に Supabase または Cloud のデータエクスポートを誰が所有するかを確認してください。
