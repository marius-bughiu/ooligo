## O que é

Claude Managed Agents é o runtime hospedado da Anthropic para agentes de longa duração, parte da Claude Platform (a API). Você define um **agente** (modelo, system prompt, ferramentas, servidores MCP e skills), um **ambiente** (o sandbox onde ele trabalha) e inicia uma **sessão**, que é uma instância em execução desse agente. A Anthropic roda o loop do agente, o contêiner e as chamadas de ferramenta; você envia turnos de usuário e recebe eventos por streaming. O lançamento em beta pública foi em 8 de abril de 2026, e todos os endpoints ainda exigem o header beta `managed-agents-2026-04-01`, que os SDKs configuram para você. O acesso vem ativado por padrão em todas as contas da API.

Cada sessão ganha um contêiner Linux novo, com linguagens comuns e gerenciadores de pacotes pré-instalados. O toolset nativo cobre `bash`, leitura, escrita e edição de arquivos, `glob`, `grep`, `web_fetch` e `web_search`, todos ativados por padrão, e cada ferramenta pode ter uma política de permissão que pausa para pedir aprovação. Servidores MCP remotos se conectam por HTTP em streaming. As credenciais ficam em **vaults**: tokens OAuth para servidores MCP com renovação automática, tokens bearer e variáveis de ambiente que o sandbox só enxerga como placeholders, trocados pelo segredo real na saída de rede. Desde maio de 2026, outcomes (uma rubrica contra a qual o agente se autoavalia), orquestração multiagente, memória e webhooks estão em beta pública; dreaming e os túneis MCP para servidores privados seguem em um research preview mais restrito. Em 12 de novembro de 2026, a Anthropic abriu uma beta privada do Managed Agents auto-hospedado, que roda o serviço inteiro na sua própria nuvem.

A pergunta que ele responde para um time de operações: *rodamos agentes headless (uma varredura noturna de higiene do CRM, uma triagem de contratos recebidos, um agente de resumo de candidatos) no runtime da Anthropic, ou continuamos hospedando o Agent SDK por conta própria no n8n ou em workers próprios?*

## Quanto custa na prática

A cobrança tem duas linhas. Tokens são cobrados nas tarifas padrão da API do Claude para o modelo escolhido, com os multiplicadores de prompt caching aplicados normalmente. O runtime custa **$0.08 por hora de sessão**, medido em milissegundos e cobrado só enquanto o status da sessão é `running`. O tempo em `idle`, esperando sua próxima mensagem ou a aprovação de uma ferramenta, não é cobrado, e o runtime de sessão substitui a cobrança separada por hora de contêiner de execução de código. Busca web dentro de uma sessão custa $10 a cada 1.000 buscas. Não há cobrança por usuário nem taxa de plataforma, e o uso conta para um compromisso de gasto já existente com a Anthropic.

O exemplo da própria Anthropic, uma sessão de uma hora com Opus 5.5, 50.000 tokens de entrada e 15.000 de saída, dá $0.58: $0.20 de entrada, $0.30 de saída e $0.08 de runtime. Com 40.000 desses tokens de entrada vindo do cache, cai para $0.428. A lição para o orçamento é que o runtime é a linha pequena. Uma sessão que rodasse de fato 24 horas por dia durante um mês somaria uns $58 de runtime; uma varredura noturna de 20 minutos soma menos de $1 por mês. O que precisa ser previsto e limitado são os tokens do modelo. Dois descontos não valem: não existe preço de Batch API para sessões, nem preço de nuvem parceira, porque o runtime hospedado não é vendido via Bedrock nem Vertex.

## Ideal para

- **Times de RevOps ou Legal Ops com um único engenheiro** que querem um agente que trabalhe uma hora em um sandbox, chame o CRM ou o CLM via MCP e devolva o resultado, sem montar antes uma frota de contêineres, uma fila de jobs e um cofre de segredos.
- **Times que já têm compromisso com a API do Claude** e estão construindo um agente dentro de uma ferramenta interna ou de um produto, onde a tarifa de runtime e o tracing do console substituem semanas de código de orquestração. Os clientes de lançamento da Anthropic (Notion, Rakuten, Asana, Sentry) relatam entregar em "semanas em vez de meses"; são números publicados pelo fornecedor.

## Alternativas, e quando escolhê-las

- **[Amazon Bedrock](/pt-BR/tools/amazon-bedrock/) com AgentCore**: um dos dois líderes em participação de mercado entre as plataformas de agentes em nuvem. Escolha quando identidade, dados e o compromisso de nuvem estão na AWS e o agente precisa rodar na sua própria conta. Lembre que o Claude no Bedrock não tem o runtime do Managed Agents.
- **[Microsoft Foundry](/pt-BR/tools/microsoft-foundry/) Agent Service**: o outro líder. Escolha quando você precisa de tenancy no Azure, identidades do Entra para agentes e modelos além do Claude.
- **Hospedar o Claude Agent SDK por conta própria** no [n8n](/pt-BR/tools/n8n/) ou em workers próprios: escolha quando você precisa hoje de retenção zero de dados, elegibilidade HIPAA ou garantia firme de duração de sessão. Sandbox, retries e segredos ficam com você, e você paga só tokens.
- **[Claude Cowork](/pt-BR/tools/claude-cowork/)**: escolha quando o usuário é uma pessoa na mesa, não um serviço. O Cowork é o agente de desktop cobrado por usuário; o Managed Agents é o runtime de API para trabalho headless.
- **[Hermes Agent](/pt-BR/tools/hermes-agent/)**: o entrante que mais cresce no lado auto-hospedado, com cerca de 263.000 estrelas no GitHub nove meses após o lançamento. Escolha para um agente residente no Slack ou no Telegram, sobre qualquer modelo, sem trabalho de integração com a API.

## Pontos de atenção

- **A saída de rede fica aberta até você fechar.** Um ambiente criado pela API sem configuração de rede fica em `unrestricted` por padrão (o formulário do console começa em Limited). **Proteção:** defina `networking` como `limited` com uma lista explícita de `allowed_hosts` em todo ambiente criado por código, e lembre que essa lista também rege `web_search` e `web_fetch`.
- **Não é elegível para ZDR nem para HIPAA.** A documentação da Anthropic diz que o runtime hospedado fica fora da retenção zero de dados e do HIPAA, em todas as subfuncionalidades. **Proteção:** mantenha PHI e qualquer coisa sob cláusula ZDR em um deploy auto-hospedado do Agent SDK, ou espere a beta privada auto-hospedada, que é a única variante coberta pelo ZDR.
- **É uma beta com header datado.** Endpoints, tipos de evento e padrões podem mudar, e a documentação não publica duração máxima de sessão nem limite de concorrência; os rate limits publicados são 300 requisições de criação e 1.200 de leitura por minuto por organização. **Proteção:** fixe as versões do SDK, grave as definições de agente e ambiente em arquivos aplicados com a CLI `ant` para que fiquem no git, e configure limites de gasto da organização antes da primeira execução agendada.
- **A memória persiste entre sessões.** Os memory stores passam de uma execução para a outra, então um dado errado salvo pelo agente continua guiando as execuções seguintes. **Proteção:** dê a cada agente de produção seu próprio memory store, revise o conteúdo pela API em uma frequência fixa e apague as entradas que nenhuma fonte revisada sustenta.
