1 人の担当者の過去 7 日間のコール、メール、[Salesforce](/ja/tools/salesforce/) アクティビティを取り込み、6 つの箇条書きシグナルレポートを出力する Claude スキルです。加速している案件、冷え込んでいる案件、担当者が行き詰まっている箇所、来週の具体的な 1 つの提案を提示します。マネージャーによる監視ではなく、金曜日の自己レビューを目的として設計されており、ブリーフは担当者自身がマネージャーより先に受け取る仕組みになっています。バンドルには動作する SKILL.md と 3 つのリファレンステンプレートが含まれており、チームが自社のクオリフィケーションフレームワーク、シグナル閾値、トーンに合わせて編集できます。

## 使用するタイミング

このスキルが対象とする具体的なケース：AE が金曜日にログオフする前に自分の 1 週間を 5 分でスキャンしたい場合です。10〜30 件のオープン案件があり、CRM はすでに知っていることを教えてくれるだけで、再度聞き直す時間がなかった [Gong](/ja/tools/gong/) コールがある状況です。ダッシュボードではなく、月曜日に行動すべき 3 つのことが必要です。スキルはまさにそれを生成します — ヒーティング 3 件、スタック 2 件（またはスタックがなければクーリング 2 件）、具体的な提案 1 件 — というフォーマットは意図的に短く設計されているため、担当者が実際に読みます。数千行のアクティビティエクスポートはざっと見て忘れられますが、6 つの箇条書きは行動につながります。

RevOps がチーム全体のために管理する週次ケイデンスとしても機能しますが、出力が最初に担当者の DM に届き、担当者がマネージャーに転送するかどうかを制御できる場合に限ります。プライバシーの姿勢が負荷を担う部分です — 「マネージャー自動 CC」に変わると、担当者は 1 週間以内に入力データを操作し始め、シグナルが崩壊します。

## 使用しないタイミング

クロスチームのパイプラインレビューにこのスキルを使用しないでください。20 人の担当者は 20 回の呼び出しを意味し、コストが急速に積み重なります。Salesforce ダッシュボードがこの作業を安価に実行でき、マネージャーの仕事は個々の週を深く見ることではなく横断的に見ることです。予測コールの準備にも使用しないでください — Salesforce レポートの方が数値のロールアップに優れており、スキルはドルを合計するように設計されていません。監視ツールとして使用しないでください（「Bob が今週何をしたか教えて」）。担当者が自分で実行せずにレポートがマネージャーに渡った瞬間、担当者が自分のアクティビティについて正直であり続けるための社会的な契約が失われます。アカウントレベルの深掘りにも使用しないでください — それは 1 つのアカウントを広く調査する `account-research` スキルが解決する別の問題です。

3 日未満のウィンドウで実行しないでください。データポイントが少なすぎてバケット化ルーブリックがきれいに機能せず、出力がノイズのように見えます。オープン案件が 5 件未満の担当者には実行しないでください — バケット化するのに十分なシグナルがありません。

## セットアップ

アーティファクトバンドルは `apps/web/public/artifacts/activity-summarizer-skill/` にあります。エントリーポイントである `SKILL.md` と `references/` 以下の 3 つの記入可能なリファレンスが含まれています。以下の順番で進めてください：

1. `apps/web/public/artifacts/activity-summarizer-skill/SKILL.md` を最初から最後まで読んでください。「Method」セクションには設計上の選択が記載されています（並列プルを使う理由、優先順位ルールの理由、300 秒コールフィルターの理由）。それらを流し読みすると、偽陽性が捕捉される箇所を見逃します。
2. `apps/web/public/artifacts/activity-summarizer-skill/references/qualification-framework.md` を編集します。MEDDPICC のデフォルトをチームの実際のフレームワーク（BANT、SPICED、自社独自のもの）に置き換え、重要なこととして Salesforce フィールド名（`Opportunity.Economic_Buyer__c` など）を CRM で実際に使用されているものに変更します。Salesforce レポートからチームのステージ平均滞在時間を取得してテーブルに入力してください。それらが行き詰まり検出に使われます。
3. `apps/web/public/artifacts/activity-summarizer-skill/references/signal-rubric.md` を編集します。デフォルト値（ヒーティングに 2 以上のマルチスレッドタッチ、クーリングに 10 日以上のノータッチ、スタックにステージ平均滞在時間の 1.5 倍）は適切な出発点です。数週間実行して過去のデータに照らし合わせて調整してください。`min_call_duration_seconds` はデフォルトで 300 に設定されており、Gong のボイスメールをフィルタリングします — チームが多くの 5 分未満の実際のコールを行う場合を除き、変更しないでください。
4. `apps/web/public/artifacts/activity-summarizer-skill/references/sample-output.md` を編集します。チームのトーンに条件付けるために、過去の優れたレポートを 1〜2 件（匿名化して）追加してください。リファレンスには、スキルが避けるべき「悪いサンプル」も含まれています — 両方を残してください。
5. 認証を設定します。Salesforce：担当者のユーザーの Activity、Opportunity、OpportunityHistory にスコープを絞った読み取り専用 OAuth。Gong：担当者が参加したコールとトランスクリプトを読み取るためにスコープを絞った API キー。両方とも MCP サーバーまたは直接 API コール — スキル自体はトランスポートに依存しません。
6. 実行をスケジュールします。デフォルトは金曜日 16:00 現地時間です。出力はチームの Slack またはメール連携を通じて担当者の DM に届きます。マネージャーへの自動 CC はスキル内で設定可能なオプションとして意図的に含まれていません。マネージャーが可視性を求める場合、担当者が転送します。

## スキルの実際の動作

2 つの API コールが並列で実行されます。ウィンドウ内の `Task`、`Event`、`OpportunityHistory` 行に対する Salesforce SOQL と、担当者のメールでフィルタリングされた Gong `/v2/calls`（Gong は Salesforce ユーザー ID ではなくメールでインデックスを作成します — 最初に変換しないとコールリストが空になります）。Salesforce フィルターは、`Description` が空の「Logged Email」タスクを明示的に除外します。それらは CRM の衛生ノイズであり、エンゲージメントではありません。返信がない状態でそれらが 10 件あっても、案件が盛り上がっているという意味ではありません。

各オープン案件は、ステージ、金額、ステージ滞在時間、意味のあるタッチ数、クオリフィケーションフレームワークの必須フィールドを持つレコードを取得します。各案件は `signal-rubric.md` の閾値に対してヒーティング、クーリング、スタックにバケット化されます。優先順位ルールが重複を解決します — クーリングはスタックに勝ち、スタックはヒーティングに勝ちます — これにより最も一般的な偽陽性が排除されます（手続き上の理由でステージが前進したが、その他のすべてのシグナルが死んでいる案件）。Closed Lost の遷移はヒーティングから明示的に除外されています。このルールがないと、金曜日の午後に不活性な案件をクローズしている担当者が輝かしいレポートを生成してしまいます。

レンダリングステップはヒーティング上位 3 件、スタック（またはスタックがなければクーリング）上位 2 件を選択し、1 つの提案を生成します。提案には 3 つのガードレールがあります — アカウント名、ステージ名、特定のブロッカーを必ず含む必要があります。ルーブリックが 3 つすべてを満たす提案を生成できない場合、スキルは「今週の提案なし — パイプラインはクリーンです」と書き、汎用的な「停滞したリードにフォローアップ」という行を埋め込みません。

## コストの実態

オープン案件 20 件の担当者の週次実行 1 回は、Sonnet で約 6,000 入力トークンと 800 出力トークン — 約 0.05 USD の実行コストです。スケーリングの計算：

- 1 担当者、週次：月 0.20 USD
- 20 担当者、週次：月 4 USD
- 100 担当者、週次：月 20 USD
- 100 担当者、日次：月 140 USD
- 200 担当者、日次：月 280 USD — この規模では Haiku（実行あたり 0.04 USD、月 112 USD）に切り替えるか、複数の担当者コンテキストを 1 つのプロンプトにバッチ処理してください

隠れたコストは Claude ではなく Salesforce と Gong の API クォータです。Salesforce の REST API にはオルグ単位の日次制限があります（Enterprise オルグでは通常 15K コール）。各担当者の実行はアクティビティ量に応じて 4〜8 コールを消費します。200 担当者の日次では Salesforce で 1,600 コール/日 — 予算内ですが、他の自動化も大量に実行している場合はオルグの使用状況を確認する価値があります。

時間コスト：CRM フィールド名がクリーンであれば初期セットアップに 30 分、適切なカスタムフィールド API 名を追跡する必要がある場合は 1 時間。週次の継続コスト：ゼロ — スケジュール実行されます。

## 成功の姿

動作するインストールは、担当者が 90 秒で読んで月曜日の朝の行動を少なくとも 1 つ変える出力を生成します。具体的には、4 週間の実行後：

- 担当者の「スタック」案件がマネージャーの停滞パイプラインレビューに現れる少なくとも 1 週間前にレポートに表示されます。そうでない場合、`qualification-framework.md` のステージ平均滞在時間の閾値が寛大すぎます — 厳しくしてください。
- 「1 つの提案」行が、担当者が実際に取る行動を週の 60% 以上で生成します。それ以下の場合、ルーブリックが汎用的な提案を生成しており、レンダリングガードが十分に厳格ではありません — スキルが名前付きアカウント、ステージ、ブロッカーのない提案を拒否しているか確認してください。
- クーリングバケットが、その後 Closed Lost になる案件を 70% 以上の確率でフラグします。精度がそれよりはるかに低い場合、クーリング閾値が過敏すぎます（偽陽性がシグナルを溺れさせています）。

これらは虚栄の指標ではありません — スキルが本来の目的を果たしているかのシグナルです。改善しなければ、スキルは金曜日の読み物を生成しているだけで、金曜日の意思決定につながっていません。

## 代替案との比較

**CRM ネイティブダイジェスト（Salesforce Einstein Activity Capture、Gong 独自の週次サマリー）と比較して。** これらは生のアクティビティ数とコールサマリーを提供しますが、2 つのストリームを統合したりクオリフィケーションフレームワークを適用したりしません。Einstein は「今週 47 通のメール」と教えてくれます。このスキルは「Acme が CTO が参加して価格を尋ねたため Proposal に移動した」と教えてくれます。抽象化のレイヤーが異なります。

**担当者が自分で書く手動サマリーと比較して。** 自分の金曜日のまとめを書く担当者は、このスキルより優れた戦略を生成します — 案件のコンテキストを知っているからです。しかし、担当者の 80% はまとめを書かず、書く担当者も四半期末にはスキップします。このスキルは週の 100% で 90% の品質のサマリーを生成します。これは週の 30% で 100% のサマリーを生成するより優れています。

**Gong 独自の週次サマリーメールと比較して。** Gong のサマリーはコールのみです。冷え込みシグナルを多く運ぶメールと CRM のアクティビティを見逃します。またクオリフィケーションフレームワークを適用しないため、「Economic Buyer が指名されていないため行き詰まっている」を浮かび上がらせることができません。有用な補完であり、代替品ではありません。

**現状（他の金曜日ごとのマネージャー 1 対 1）と比較して。** マネージャーの 1 対 1 は 2 週間遅れで問題を把握し、マネージャーの処理能力に依存します。このスキルは担当者の手に同じ週に問題を届け、行動をあるべき場所に留めます。

## 注意事項

- **プライバシーの姿勢：担当者向けのみ。** デフォルトの `recipient` は `dm` で、スキルはマネージャーチャンネルへの送信を拒否します。自動 CC は社会的な契約を「週次自己レビュー」から「週次密告レポート」に変えます — 担当者は 1 週間以内に入力データを操作します。ガード：スキルは受信者パラメーターのマネージャーチャンネル ID を拒否し、バンドルの `SKILL.md` はこれを設定不可としてドキュメント化しています。
- **Gong トランスクリプトの品質がシグナルの品質を左右します。** 国際コール、音声の問題、短いボイスメールはノイズの多いサマリーを生成し、質の悪い箇条書きに繋がります。ガード：`min_call_duration_seconds = 300` がボイスメールとテストコールをフィルタリングします。スキルは Gong のコールごとの `transcriptionConfidence` フィールドも読み取り、0.6 未満のものを除外します。
- **アクティビティ定義のドリフト。** 本文とリプライのない「Logged Email」はエンゲージメントではなく CRM の衛生管理です。それが 10 件あっても案件が盛り上がっているという意味ではありません。ガード：SOQL フィルターはタスクの `Description` が空でないことを要求し、`Subject` がチームの自動ログパターン（`/^(Email\: |Logged via )/`）に一致するタスクを明示的に無視します。
- **提案の疲弊。** 「来週の 1 つの提案」の行はルーブリックが緩いと汎用的な内容（「停滞したリードにフォローアップ」）に流れます。ガード：レンダリングステップはアカウント、ステージ、特定のブロッカーを名前で挙げていない提案を拒否します。ルーブリックがそれを生成できない場合、スキルは「今週の提案なし — パイプラインはクリーンです」と書きます。
- **ステージ変化をシグナルとして使うと嘘をつく場合があります。** Closed Lost に案件を移動した担当者はステージ変化として表示されますが、ヒーティングを促進すべきではありません。ガード：バケット化ルールはステージのロールバックと Closed Lost の遷移をクーリングの下で明示的に扱い、ヒーティングには決して入れません。
- **スキルはディールレビューの代わりではありません。** シグナルを表面化するのであり、戦略ではありません。スタックフラグは担当者に「Initech はステージ平均滞在時間を超えており Economic Buyer がいない」と伝えます。その 1 つの提案以上に何をすべきかは伝えません。トリアージとして扱ってください。コーチングではありません。
