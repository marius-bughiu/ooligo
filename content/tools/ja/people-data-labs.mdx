## 概要

People Data Labs（PDL）は、開発者向けを第一に設計された人物・企業データのプロバイダーです。同じデータグラフを 2 つの形で販売しています。1 つは REST API（人物・企業のエンリッチメント、検索、identify、さらに無料のクリーナーとオートコンプリートのエンドポイント）、もう 1 つは S3、GCS、Azure、Snowflake、Databricks に納品されるバルクの Data License フィードです。2026 年 10 月のリリースノート（v36.0）では、履歴書レコード 8 億 1,780 万件、企業レコード 7,690 万件、求人 5,110 万件を数え、その月に検出された転職は 610 万件でした。人物データセット全体は、9 月の重複排除で約 4,000 万件の重複プロフィールが削除された結果、24 億 2,000 万件となっています。PDL は独立系のベンチャー出資企業で、2026 年 4 月の v34.0 から 10 月の v36.0 まで、バージョン番号付きの月次リリースを出しています。

PDL ではないもの：プロスペクティングアプリでも、AI エージェント製品でもありません。営業担当がリストを作る UI も、シーケンサーも、公式の MCP サーバーもありません。PDL は、Clay をはじめとする他の製品の土台になる生データのレイヤーです。

## RevOps のスタックに入る理由

- **エンリッチメントのウォーターフォールの下にあります。** Clay には PDL との組み込み接続と自社の API キーを持ち込むオプションがあり、PDL は 2026 年に Clay の「OG Data Partner」賞を受賞しました。多くのチームは、気づかないうちに別のツールの中で PDL のデータに料金を払っています。
- **レコード単価が公開されています。** Pro は人物クレジット 350 件で月 $98 から、1 マッチあたり約 $0.28 で、年払いにすると 20% 安くなります。商談の前に試算できる数字を公開している人物データベンダーは多くありません。
- **課金はマッチに対してで、試行に対してではありません。** エンリッチメントは成功したマッチ 1 件につき 1 クレジットで、マッチしなければ無料です。ヒット率 60% の CRM バックフィルなら、支払うのは 60% の行分だけです。
- **フィルターに使える品質シグナルがあります。** PDLScores は 2026 年 7 月のリリース（v35.0）で一般提供になりました。`profile_score` はプロフィールが実在の人物らしいか、`activity_score` は更新が続いているかを示します。アウトバウンドの前にスコアの低いプロフィールを除外するほうが、バウンスを出すより安く済みます。
- **データウェアハウスへのネイティブ納品。** データチームにとっては、API を 1 行ずつ呼ぶより Snowflake や Databricks の共有のほうが優れています。また、IP と求人のデータセットは Enterprise 限定で、この方法でしか入手できません。

## 料金

2026-11-06 に peopledatalabs.com/pricing と PDL の課金ドキュメントで確認しました。

- **Free：** 月あたり人物クレジット最大 100 件、企業レコード最大 100 件。メール、電話番号、住所は伏せ字になるため、無料プランで確かめられるのはマッチ率であって、連絡が取れるかどうかではありません。
- **Pro（セルフサーブ）：** 人物データは 350 クレジットで月 $98 から、企業データは 1,000 レコードで月 $100 から。連絡先フィールドと CSV エンリッチメントは含まれ、プレミアムフィールドのバンドルはアドオンです。利用量が増えるとボリューム階層で 1 クレジットあたりの価格が下がりますが、各階層の料金は公開されていません。
- **Enterprise：** 個別の年間契約、すべての API、Data License フィード、追加のフィールドバンドル、SSO/SAML。
- **請求額を左右する課金ルール。** エンリッチメント：1 マッチにつき 1 クレジット。バルクエンリッチメント：1 回の呼び出しで最大 100 クレジット、1 マッチにつき 1。検索：返されたプロフィール 1 件につき 1 クレジット。Person Identify：マッチしない応答も含め、1 リクエストにつき 1 クレジット。
- **実際にかかる費用。** マッチ率 65% で CRM の連絡先 10,000 件をエンリッチすると 6,500 クレジットで、Pro の入門料金なら約 $1,800、年払いやボリューム階層ならそれ以下です。同じ予算を Search API に使うと、フィルターに合うかどうかに関係なく 6,500 件のプロフィールが返ってきます。検索とエンリッチメントは別々の費目として試算してください。

## 最適な利用者

- シリーズ A からエンタープライズまでの企業で、CRM、ウェアハウス、プロダクトのデータを既知のレコード単価でエンリッチしたい RevOps エンジニアとデータチーム
- 自社アプリに人物や企業のデータを組み込み、シート課金ではなくバルクライセンスと再配布条項が必要なプロダクトチーム
- Clay を多用する GTM チームで、大量のテーブルで Clay の行あたりクレジットコストを下げるために自前の PDL キーを持ち込みたいチーム
- リスト作成とシーケンス送信の UI が欲しい営業担当には向きません（[Apollo](/ja/tools/apollo/) を使ってください）。検証済みの携帯番号を大量に必要とする場合も向きません（[FullEnrich](/ja/tools/fullenrich/) のようなウォーターフォールを使ってください）。リアルタイムの転職 webhook やライブ再取得が必要な場合も向きません（[Crustdata](/ja/tools/crustdata/) を使ってください）

## 代替ツールと選び分けのルール

- **[ZoomInfo](/ja/tools/zoominfo/)** — カテゴリーのシェア首位で、インテントデータ、組織図、営業担当向け UI を備え、個別契約の中央値は年間約 $33,500 です（Vendr）。営業担当が主なユーザーなら ZoomInfo を選んでください。データを使うのがコードやウェアハウスで、シート課金が意味をなさないなら PDL を選んでください。
- **[Apollo](/ja/tools/apollo/)** — もう一方のシェア首位で、データベース、シーケンス、ダイヤラーを年払いで 1 シート月 $49 から提供します。プロスペクティングを人が行うなら Apollo、データだけが必要なら PDL です。
- **[Crustdata](/ja/tools/crustdata/)** — エージェント向けを第一に設計された後発のデータ API で、ライブエンドポイント、ソーシャル投稿、Watcher webhook、ホスト型 MCP サーバーを備えます。AI エージェントがデータを呼び出し、アウトバウンド時点の鮮度が重要なら Crustdata を選んでください。公開価格、SOC 2、成熟したバルクライセンスが欲しいなら PDL を選んでください。
- **Coresignal** — セルフサーブで月 $49 から、従業員と企業の大規模な履歴データセットを持ちます。人員数や職歴の履歴の深さが用途なら Coresignal、幅広いエンリッチメントと ID 解決が必要なら PDL です。
- **[Clay](/ja/tools/clay/)** — この分野で最も急成長しているプラットフォーム（2026 年 9 月に評価額 71 億ドルで 1 億 1,500 万ドルのシリーズ D を調達）で、競合というより上に載るレイヤーです。Clay は PDL を数十の他プロバイダーとともにウォーターフォールで実行します。人がテーブル上でエンリッチメントのロジックを設計し、CRM 同期が欲しいなら Clay を選んでください。1 つのプロバイダーでほとんどの行をカバーでき、コードを書けるなら PDL を直接購入してください。

## 注意点

- **検索は返されたプロフィールごとに課金されます。** 条件の緩い Search API のクエリが 5,000 件のプロフィールを返すと、ICP に合うかどうかに関係なく 5,000 クレジットかかります。対策：すべてのクエリをまず無料のサンドボックスで試し、すべてのリクエストに `size` の上限を設定し、メール、ドメイン、プロフィール URL が分かっている場合は既知の識別子に対するエンリッチメントを使ってください。
- **クレジットで鮮度は買えません。** PDL はデータセットを月次リリースで再構築するため、レコードが転職から数週間遅れることがあります。対策：`activity_score` とレコードの転職タイムスタンプでフィルターし、シーケンスに入れる前にすべてのメールを検証ツールで再確認してください。
- **データブローカーとしてのリスクはあなたに及びます。** PDL は登録済みのデータブローカーで、カリフォルニア州の Delete Act により、ブローカーは 2026 年 8 月から州の DROP プラットフォーム経由の削除要求を処理する義務を負います。あなたが保持するデータのコピーもこの義務を引き継ぎます。対策：PDL の無料の Subject Request API を自社の削除フローに組み込み、保存したレコードの横に PDL のレコード ID を保持して、PDL が削除したときに同じものを消去できるようにしてください。
- **フィールドのスキーマは予定どおりに変わります。** v36.0 で `funding_details.investing_companies` と `affiliated_profiles` が非推奨になり、2027-02-16 に削除されます。対策：クライアントで API のバージョンを固定し、changelog を購読し、PDL のフィールドを使うすべてのパイプラインに月次のスキーマ差分チェックを追加してください。
- **公式の MCP サーバーはありません。** npm や GitHub にコミュニティ製のラッパーはありますが、PDL 製のものはありません。対策：エージェントが PDL のデータを必要とする場合は、サードパーティのサーバーに本番キーを渡すのではなく、権限を絞ったキーとクレジット上限を設定したうえで、自社のツール定義から API を呼び出してください。
