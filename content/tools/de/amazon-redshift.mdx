## Was es ist

Amazon Redshift ist das Cloud Data Warehouse von AWS und wird in zwei Varianten verkauft. **Provisionierte** Cluster laufen auf RA3-Nodes, die Sie selbst dimensionieren und stundenweise bezahlen; Speicher wird separat als Redshift Managed Storage abgerechnet. **Redshift Serverless** rechnet Rechenleistung in Redshift Processing Units (RPUs) nur ab, solange Abfragen laufen, mit einer Basiskapazität, die Sie zwischen 4 und 512 RPUs festlegen (in einigen Regionen bis 1.024). Beide fragen das Warehouse ab und über Spectrum auch Daten in S3. Seit dem 31. August 2026 liest und schreibt Redshift zudem Apache-Iceberg-v3-Tabellen. Das zählt, wenn Ihr Data Lake der Langzeitspeicher ist und das Warehouse nur eine von mehreren Engines.

Die Änderung von 2026, die für Ops-Teams zählt, ist der Zugriff durch Agents. Am 27. August 2026 hat AWS Redshift in das **Agent Toolkit for AWS** integriert: den AWS MCP Server plus eine Reihe von Redshift-Skills (SQL-Syntax, Metadaten-Erkundung, Datenladen, Materialized Views, Migrations-Playbooks), gebündelt als Plugin `aws-data-analytics` für Claude Code, Kiro und Cursor. Es funktioniert mit provisionierten Clustern und Serverless-Workgroups und kostet nichts extra. Daneben veröffentlicht AWS einen Open-Source-MCP-Server für Redshift, der SQL im Read-only-Modus ausführt und schädliche Anweisungen per Validierung abfängt. In der Konsole ist Amazon Q generative SQL im Query Editor v2 seit September 2024 GA und übersetzt Fragen in natürlicher Sprache in SQL, sobald ein Admin die Funktion aktiviert.

## Warum Ops-Teams hier landen

Kaum jemand wählt Redshift für RevOps. Man erbt es: Die Entwicklung hat sich vor Jahren auf AWS festgelegt, und die Produktdaten liegen schon dort. Die eigentliche Frage lautet: *Wir sind auf Redshift, nicht auf Snowflake. Funktionieren die warehouse-nativen GTM- und Provisions-Tools trotzdem, und können Agents es sicher abfragen?*

Meistens ja. [Hightouch](/de/tools/hightouch/) synchronisiert aus Redshift, [Fivetran](/de/tools/fivetran/) lädt hinein, [Sigma](/de/tools/sigma/) fragt es live ab, und sowohl [Everstage](/de/tools/everstage/) als auch [Fullcast](/de/tools/fullcast/) führen es als nativen Connector. Zero-ETL-Integrationen, seit Dezember 2024 GA, replizieren Salesforce und andere SaaS-Anwendungen ohne Pipeline-Tool nach Redshift. Sie werden über AWS Glue abgerechnet, sodass ein Team mit wenigen Quellen Fivetran womöglich gar nicht braucht. Ein konkreter Einsatz: Ein CS-Team fragt Claude Code über den MCP Server, welche Verlängerungen über 50.000 $ sinkende wöchentlich aktive Nutzer zeigen, und bekommt die Antwort direkt aus Produkttelemetrie und Salesforce-Daten im selben Warehouse.

## Preisrealität

Es gibt keinen Preis pro Nutzer. Listenpreise in US East (N. Virginia):

- **Serverless:** 0,375 $ pro RPU-Stunde, sekundengenau abgerechnet mit 60 Sekunden Minimum; die Untergrenze von 4 RPUs kostet also 1,50 $ pro aktiver Stunde. Neue Serverless-Nutzer erhalten 300 $ Guthaben, das nach 90 Tagen verfällt. Serverless Reservations senken den Satz um bis zu 24 % bei einem Jahr Laufzeit und um bis zu 45 % bei drei Jahren.
- **Provisioniert:** ra3.xlplus für 1,086 $ pro Node-Stunde und ra3.4xlarge für 3,26 $, plus Managed Storage für 0,024 $ pro GB und Monat. Jeder Cluster erhält pro Tag eine kostenlose Stunde Concurrency Scaling, ansparbar bis 30 Stunden.
- **Spectrum:** 5 $ pro in S3 gescanntem TB.

Eine Beispielrechnung: ein RevOps-Warehouse auf Serverless mit 8 RPUs Basis, an jedem Werktag etwa vier Stunden aktiv, mit 500 GB Daten. Rechenleistung rund 264 $ im Monat (3 $ pro Stunde × 4 Stunden × 22 Tage), Speicher rund 12 $. **Etwa 280 $ im Monat, rund 3.300 $ im Jahr.** Dieselbe Last auf zwei rund um die Uhr laufenden ra3.xlplus-Nodes kostet on demand etwa 1.590 $ im Monat. Deshalb gehören kleine Ops-Workloads auf Serverless.

## Am besten für

Eine **RevOps- oder CS-Analytics-Leitung in einem Unternehmen, dessen Produktdaten bereits in AWS liegen**, die warehouse-native Aktivierungs-, Provisions- und BI-Tools darauf betreiben will, ohne Migrationsprojekt. Es passt auch für Teams, die Kundendaten für die Security-Prüfung in einem AWS-Konto und einer Region halten müssen und die Coding-Agents das Warehouse unter IAM abfragen lassen wollen statt über einen Drittanbieterdienst.

## Nicht für

Ein Unternehmen, das sein erstes Warehouse ohne AWS-Bindung auswählt. Snowflake und BigQuery haben die größeren GTM-Ökosysteme und eigene Conversational-Analytics-Schichten. Die KI-Geschichte von Redshift ist vor allem Agent-Zugriff über MCP, kein Chat-Produkt für Fachanwender. Wenn die Hauptfrage lautet „brauchen wir überhaupt ein Warehouse oder ein CDP?“, beginnen Sie mit [Data Warehouse vs. CDP](/de/learn/data-warehouse-vs-cdp/).

## Im Vergleich zu den Alternativen

- **[Snowflake](/de/tools/snowflake/)**: Marktanteilsführer im GTM-Umfeld und Standardziel jedes Reverse-ETL- und Provisionsanbieters. Wählen Sie es, wenn Sie an keine Cloud gebunden sind und einen Chat im Stil von CoWork für Fachanwender auf dem Warehouse wollen.
- **[Google BigQuery](/de/tools/google-bigquery/)**: der andere Marktanteilsführer. Wählen Sie es, wenn das Unternehmen auf Google Cloud oder Workspace läuft und Sie On-Demand-Preise pro TiB ganz ohne Cluster wollen.
- **[Databricks](/de/tools/databricks/)**: der am schnellsten wachsende Anbieter: Presseberichte vom August 2026 bezifferten die Run Rate des Data-Warehousing-Geschäfts auf über 1,5 Mrd. $, ein Plus von mehr als 100 % gegenüber dem Vorjahr. Wählen Sie es, wenn Data Science und ML bereits auf dem Lakehouse laufen und Sie Genie auf denselben Daten wollen.
- **Bleiben Sie bei Redshift**, wenn die Daten schon dort liegen. Ein funktionierendes Warehouse für einen etwas besseren GTM-Connector zu migrieren, ist selten ein Quartal Engineering-Zeit wert.

## Stolpersteine

- **Serverless schlägt standardmäßig eine große Basiskapazität vor.** Die Konsole setzt 128 RPUs an, also 48 $ pro Stunde, solange Abfragen laufen. **Absicherung:** Setzen Sie die Basis für Ops-Workloads auf 8 RPUs und legen Sie ein tägliches Nutzungslimit für RPU-Stunden mit Alarm vor Erreichen fest.
- **BI-Tools und Syncs halten Serverless wach.** Ein Dashboard, das alle fünf Minuten aktualisiert, oder ein stündlicher Reverse-ETL-Sync verursacht den ganzen Tag Rechenkosten. **Absicherung:** Bündeln Sie Syncs in wenigen Batch-Fenstern, materialisieren Sie die Modelle, die Sigma liest, und prüfen Sie im ersten Monat wöchentlich die RPU-Nutzung pro Workgroup.
- **Schreibzugriff für Agents ist nur eine IAM-Policy entfernt.** Der AWS MCP Server führt authentifizierte AWS-API-Aufrufe als der Nutzer aus, den er erhält. **Absicherung:** Geben Sie Agents eine eigene IAM-Rolle und einen eigenen Datenbanknutzer mit reinen SELECT-Rechten auf den modellierten Schemas, und nutzen Sie für Ad-hoc-Fragen den Read-only-Modus des Open-Source-MCP-Servers für Redshift.
- **Python-UDFs sind abgeschaltet.** Der Support endete nach dem 30. Juni 2026, und ältere dbt-Pakete und Tutorials nutzen sie noch. **Absicherung:** Durchsuchen Sie Ihre Modelle nach `LANGUAGE plpythonu` und portieren Sie diese Funktionen auf Lambda-UDFs, bevor Sie sich auf ein Paket verlassen, das sie mitbringt.
- **Writeback-Tools wollen größere Nodes.** Sigma empfiehlt für seine Input Tables auf Redshift ra3.4xlarge oder größer. **Absicherung:** Testen Sie Writeback im Trial auf Serverless oder Ihrer tatsächlichen Node-Größe, bevor Sie eine App darauf aufbauen.
