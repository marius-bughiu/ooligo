リーガルインテークとは、法的業務の依頼が法務チームのキューに入るプロセスです——フォーム、ルーティングロジック、トリアージの判断、そしてレビュアーへのアサインが含まれます。社内チームにとって、インテークは法務部門への入り口です；ファームにとっては案件への入り口です。不適切なインテークは騒がしいキュー、SLA の未達成、そして法務がボトルネックだという認識を生みます。優れたインテークは、法務を利用可能で予測可能で関与しやすいサービスのように感じさせます。

## 優れたインテークが収集すること

毎回、3つのこと：

1. **識別情報。** 誰が依頼しているか、どのビジネスユニットか、フォローアップの連絡先は誰か。
2. **分類。** どのタイプの依頼か——契約レビュー、アドバイス質問、雇用案件、規制質問、IP 出願。ルーティングを左右します。
3. **コンテキスト。** 取引は何か、緊急度は、リスクは、関わる金額は。優先度付けとトリアージ層を左右します。

[契約レビュー](/ja/learn/contract-review-sop/)インテークの場合は特に：相手方当事者、契約タイプ、すでに締結されている適用テンプレートや NDA も収集します。

## インテークフォーム

フォームは Legal Ops における最も重要な単一のアーティファクトです。[契約レビュー SOP](/ja/learn/contract-review-sop/)、トリアージロジック、SLA の期待値を依頼の瞬間にエンコードします。機能する社内インテークフォームは 8〜15フィールドを持ち、依頼者が 90秒以内に記入でき、適切なレビュアーに自動ルーティングされます。

一般的なフォームセクション：

- **依頼について。** タイプ、緊急度、ビジネスユニット、オーナー。
- **取引について。** 相手方、金額、期間、関連する合意書。
- **文書について。** 添付ファイル、ディールルームへのリンク、以前のバージョン。
- **承認が必要な時期。** 具体的な日付またはビジネスイベント。

## インテークルーティングロジック

ルーティングの意思決定ツリーはフォームの回答をレビュアーアサインメントにマッピングします。機能するルーティングルールセットは以下をカバーします：

- **契約タイプ → レビュアー層。** NDA / 標準 MSA → 自動承認またはパラリーガル；ベンダー MSA → 社内弁護士；パートナーシップ / 戦略的 → シニア社内 ＋ GC レビュー。
- **金額閾値 → 承認マトリクス。** X ドル以上は VP 承認が必要；Y ドル以上は GC 承認が必要。
- **緊急度 → SLA。** 標準依頼は 2営業日；緊急フラグ付き依頼は当日；「緊急」依頼は即時ページング。
- **相手方リスク層 → デューデリジェンス。** 既知の低リスク相手方は[ベンダーデューデリジェンス](/ja/learn/vendor-due-diligence-workflow/)を迂回；未知または高リスクはフルデューデリジェンスをトリガー。

## 運用化の方法

1. **1つのインテークポータル、1つのフォーム。** チャネルの規律が重要です。依頼がメール、Slack、Teams、廊下の会話、ポータル経由で並行して来ると、キューは管理不能になります。すべてを1つのポータルに誘導してください。
2. **フォームを [CLM](/ja/learn/contract-lifecycle-management/) に配置する。** [Ironclad](/ja/tools/ironclad/) と [Agiloft](/ja/tools/agiloft/) はいずれもダウンストリームの契約ワークフローと統合したインテークフォームビルダーを提供しています。別のツールでフォームを構築すると、引き継ぎ時の損失が生じます。
3. **AI で自動分類する。** フォーム依頼者が間違った契約タイプやベンダーリスク層を選択した場合、[Claude](/ja/tools/claude/) が送信時に再分類してルーティングを修正します。誤ルーティングを 40〜60% 削減します。
4. **可能な限りセルフサービス化する。** 「法律的な質問」の驚くほど大きな割合が、既存のテンプレート、[ナレッジベース](/ja/learn/legal-knowledge-management/)の記事、または以前に決定されたポジションへのリンクで回答できます。法務時間をキューに入れる前にそれらの回答を提示するようにインテークを構築してください。
5. **SLA を公開する。** インテークが「標準的な NDA レビューは 24時間以内に完了します」と確認すると、依頼者は安心し、GC のメール量が減少します。

## よくある落とし穴

- **フォームが長すぎる。** フィールドを追加するごとに送信率が下がります。15フィールドが実質的な上限であり、8フィールドの方が優れています。
- **SLA が表示されない。** いつ回答が来るかが分からないと、依頼者がステータスを追いかけます。
- **ステータスの可視性がない。** 送信後、依頼者は依頼がどこにあるか確認できません。ポータルにステータスを組み込んでください。
- **類似の依頼に複数のインテークフォーム。** 「契約レビュー」と「ベンダー契約レビュー」は条件ロジックを持つ1つのフォームであるべきで、2つの別々のパスではありません。
- **インテークフォームを静的なものとして扱う。** フォームは SOP をエンコードしています；両者は一緒に進化すべきです。実際の依頼パターンに対して四半期ごとにフォームをオーディットしてください。
