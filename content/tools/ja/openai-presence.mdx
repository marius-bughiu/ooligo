## 概要

OpenAI Presence は、音声とチャットのエージェントを本番運用に乗せるための OpenAI のマネージドプラットフォームで、2026年7月22日にローンチされました。モデルでもセルフサーブのビルダーでもありません。導入型のプロダクトです。OpenAI の Forward Deployed Engineers（FDEs）または選ばれたグローバルなシステムインテグレーターが、請求トラブルの解決、保険金請求の対応、社員の IT チケットのクローズといった特定の業務を一緒に定義し、その業務に必要なシステムを接続し、ポリシーとエスカレーションルールを組み込み、エージェントをテストして本番に投入します。OpenAI のローンチ記事は、カスタマーサポート、アウトバウンド営業、高リスクな社内ワークフローを対応範囲として挙げています。

このプラットフォームは、本来なら自社で組み上げる要素をまとめたものです。標準業務手順とポリシー、ガードレール、API に対して権限を絞った「承認済みアクション」、リリース前に実行するシミュレーションと評価器、そしてローンチ後の改善ループです。改善ループでは [Codex](/ja/tools/openai-codex/) が Presence プラグインを使って本番セッションとエスカレーションを分析し、変更案を出します。チームはその案を本番バージョンと比較テストしてから、段階的なロールアウトを承認します。

[ChatGPT](/ja/tools/chatgpt/) の中で作るエージェントとは別のプロダクトです。OpenAI のヘルプセンターは線引きを明確にしています。ChatGPT Workspace Agents は ChatGPT と Slack のワークスペース内で作成・共有されます。Presence のエージェントは OpenAI またはパートナーと一緒に定義・導入され、そのインターフェースから作られることはありません。

## 現時点のエビデンス

OpenAI 自身の英語の電話サポート窓口が Presence で稼働しています。OpenAI によると、この窓口は受電した問い合わせの 75% を人の手を介さずに解決しており、Codex による改善ループで人への引き継ぎが 10 日間で 15 ポイント減りました。どちらも自己申告の数字で、OpenAI は「解決」の定義を公開していません。

名前の挙がった顧客はまだ初期段階です。BBVA はデザインパートナーとしてメキシコでの日常的な銀行業務向け音声サポートを検討しており、SoftBank は日本語での顧客対話をテストし、IAG は荒天時などの需要急増時のサポートを検討しています。ローンチ時点で本格的な本番導入と説明された顧客はありません。

## 価格の実態

公開価格も、公表された課金単位も、最低契約額の記載もありません。OpenAI のヘルプセンターによると、価格、モデル、チャネル、キャパシティ、データの取り扱いは導入ごとに決まり、利用可否は「ワークフローの適合性、導入準備の状況、提供可能なデリバリーキャパシティ」次第です。これは文字どおりに受け取ってください。限定 GA の間、あなたが申し込んでいるのはライセンスの購入ではなく FDE の工数です。

以下は見積もられた金額ではなく、ooligo の計画用の目安です。最も近い成果報酬型の競合である Sierra と同様に予算を組んでください。Sierra の契約は年額 $150K〜$350K+ の範囲に収まります。これに加えて、セキュリティ・プライバシー・法務レビューの社内コストと、自社チームが担うシステム連携作業のコストがかかります。問い合わせ量が年間 6 桁ドルの契約を支えられないなら、現時点で Presence は適していません。

## 最適なケース

請求、保険金請求、アカウント対応など、大量かつポリシーの多い音声・チャットのジャーニーを抱え、すでに OpenAI とエンタープライズ契約の関係があり、構築を OpenAI のエンジニア自身に任せたいエンタープライズのサポート・CX リーダーに向いています。OpenAI 主導のデリバリーが決め手になる、アウトバウンドやリード選別の音声エージェントを試験導入する RevOps チームにも合います。

今四半期中に営業サイクルなしで始める必要がある場合、CCaaS の置き換えを求めている場合（Presence はルーティング、ワークフォースマネジメント、品質管理について説明していません）、あるいはエージェントのコードを自社で保有したい場合は見送ってください。その場合は OpenAI API の上に直接構築します。OpenAI は音声の顧客向けに API の提供を続けるとしています。

## 代替ツールとの比較

確立された 2 つの選択肢は、成果報酬型の専業ベンダーで大規模な音声の本番導入実績を持つ [Sierra](/ja/tools/sierra/) と、サービスデスクがすでに Salesforce 上にある場合の標準である [Salesforce Agentforce](/ja/tools/salesforce-agentforce/) です。最も成長の速い新興勢力は [Decagon](/ja/tools/decagon/) です。名前の出ている本番導入事例が多いベンダーと、何を「解決」とみなすかを定義した契約が欲しいなら Sierra か Decagon を選んでください。モデルの選択より CRM への集約を重視するなら Agentforce です。電話中心のコンタクトセンターなら、[Parloa](/ja/tools/parloa/) と [PolyAI](/ja/tools/polyai/) が Presence では文書化されていない電話まわりの深さを提供します。OpenAI のモデルを使い、成果の責任を OpenAI の FDEs に負わせたく、デリバリーキャパシティの空きを待てるなら Presence を選んでください。

## 注意点

- **実績の根拠は OpenAI 自身の電話窓口です。** 自社のサポートを自動化するベンダーには戦うべきレガシーシステムがなく、モデルも完全に管理できます。対策：パイロット契約で、現行ツールに基づく自己解決率と正確性のベースラインを設定し、「解決」を再オープン率と再問い合わせ率で定義し、四半期を通してベースラインを上回ることを拡大の条件にしてください。
- **条件はすべて導入ごとなので、標準がありません。** データ保持、保存リージョン、モデル構成、価格が隣の顧客と異なる可能性があります。対策：セキュリティ承認の前に、保持期間、マスキング、リージョン、モデル変更の事前通知を導入ドキュメントに明記させ、モデル変更の前には通知と自社の評価スイートの再実行を必須にしてください。
- **デリバリーキャパシティがボトルネックで、ロックインがそれに続きます。** OpenAI の FDEs が Presence 内で構築したエージェントは、自社が保有するポータブルなコードではありません。対策：初日から SOP、ポリシールール、テストシナリオ、評価基準を自社のリポジトリで管理し、Sierra、Decagon、API での自社構築に移行する際にゼロからやり直さず再利用できるようにしてください。
