[iManage](/ja/tools/imanage/) と [NetDocuments](/ja/tools/netdocuments/) は、リーガル文書管理の複占を構成する2社です。Am Law 200 の法律事務所はほぼ例外なく、どちらか一方に成果物を保管しています。20年にわたり、この選択は導入形態とメタデータ設計で決まってきました。2026年に決め手となるのは別の点です。どちらなら AI が実際に読むことを許されるのか、そしてその権限は発注書の上でいくらになるのか。

両社はこの1年、同じ主張を展開してきました。リーガル AI は DMS という権限の境界を通らなければならない、という主張です。[Harvey](/ja/tools/harvey/)、[Legora](/ja/tools/legora/)、[Litera](/ja/tools/litera/)、[Definely](/ja/tools/definely/)、[DraftWise](/ja/tools/draftwise/) はいずれもリポジトリを置き換えるのではなくインデックスするからです。両社ともそれを証明するために MCP サーバーを出荷しました。機能比較表が役に立たなくなるのは、まさにここからです。

## 同等に見えて同等ではない

「MCP 対応」は今や両社に当てはまります。だからこそ差別化要因ではなくなりました。それに代わって効いてくるのが権限の問題です。どのライセンス階層がエージェント接続を含むのか、そして誰がそのシートを保有しなければならないのか。

iManage は 2026年5月14日に MCP Server を提供開始として発表しました。単一の接続がベンダーごとの API 連携を置き換え、Harvey、Legora、ChatGPT、Claude、Microsoft Copilot、あるいは事務所自前のエージェントがそれを呼び出せます。アクセスは認証され、権限に従い、ログに残り、ベンダーのインデックスへ一括エクスポートされるものは何もありません。配布は Anthropic のパートナーエコシステム経由です。発表文は AI 階層に一切触れていません。ただし MCP Server が公開するのは Insight+ であり、Insight+ は iManage Work とは別ライセンスです。つまり価格ページが黙っていても、権限そのものは実在します。

NetDocuments は同じ機能を、名前を共有する2つの製品に分けています。**ndConnect Standard** は全顧客に提供される手動版です。人がピッカーで文書を選び、承認済みのパートナーアプリに読み込ませます。**ndConnect Enterprise** は MCP 階層で、認証済みユーザーに代わってエージェントが検索・取得できるようにするものですが、利用できるのは ndMAX Enterprise の契約者に限られます。入手可能な最新の独立系セットアップ資料（2026年7月18日付）によれば、さらに組織が限定プレビューへの承認を受けている必要があり、接続する各ユーザーが自分自身の有効な AI 300 サブスクリプションを保有している必要がありました。

この最後の条件が、この比較のすべてです。NetDocuments 側では、実際に AI を使う弁護士の人数が課金単位になります。iManage 側ではモジュールライセンスです。この2つの形は同じ人員規模でもまったく違う値段になり、どちらが安いかは両社に見積もりを取るまでどちらのベンダーも教えてくれません。

## iManage が勝つ場面

- **オンプレミスまたはハイブリッドの資産を抱えている。** iManage の顧客基盤の78%が iManage Cloud 上で稼働しています。裏を返せば、残り22%を今も販売・サポートしているということです。NetDocuments はサーバールーム版を一度も販売していません。オンプレミスからの脱却が今期の予算に入っていないなら、これは一行で終わる判断であり、以下の内容は関係ありません。
- **倫理的隔壁が明文化された調達要件になっている。** クライアント単位・案件単位の need-to-know 制御は Security Policy Manager にあります。AI アシスタントは誰が何を読んでよいかの並行モデルを別途持つのではなく、その隔壁をそのまま継承します。
- **既存プレイヤーとしての実績がセキュリティ委員会向けの論拠になる。** 4,000組織・100万人超の専門職が利用し、Am Law 100 の79%、Global 100 の83%、Fortune 100 の40%を含みます。同業他社の採用状況を判断基準に置く委員会に対しては、この数字が議論を終わらせます。
- **エージェント接続は一般提供であり、承認待ちではない。** iManage の MCP Server は5月から提供開始として発表されています。NetDocuments の同等機能は2か月後の時点でもプレビュー承認の先にありました。パイロットに日程が入っているなら、一般提供は申請フォームに勝ります。
- **AI の動作が監査面に現れる。** Threat Manager はユーザー活動レポートに AI エージェントの活動を直接表示するようになりました。アシスタントが実際に何を読んだのかと初めて問われたときに効きます。

## NetDocuments が勝つ場面

- **導入費用が3分の1から5分の1で済む。** 数字は後述します。小規模から中堅の規模では、これがシート単価の差を大きく上回ります。この比較で最も見積もりを誤られやすい項目です。
- **AI ツールを1つずつ許可できる。** 管理者は Security Center から AI ツールを個別に許可します。つまり MCP を有効にするのはツール単位の判断であって、包括的な認証情報の発行ではありません。「API を有効にしました」と言うよりも、リスク委員会に対してはるかに良い回答になります。
- **DMS 本体の価格が安い。** ユーザーあたり月額およそ40〜65ドルで、同等のリーガル向け構成における iManage の50〜75ドルに対する数字です。
- **選んだ覚えがないのに、すでに顧客かもしれない。** NetDocuments は2026年1月12日、OpenText から eDOCS の買収を現金1億6,300万ドルで完了しました。2022年の Worldox 買収に続くものです。どちらかの製品を使っているなら、移行の道筋はすでに NetDocuments との会話になっています。ただし両者は正反対の約束を背負っており、その点が重要です（末尾のガードを参照）。
- **コネクタプログラムのパートナーの広さ。** Harvey、Legora、Thomson Reuters、Vincent by Clio はいずれも ndConnect 経由で接続し、Claude、ChatGPT、Perplexity、Copilot Studio は MCP 経由で接続します。

## 価格の実態

両社とも何一つ価格を公表しておらず、AI の価格も公表していません。これは明言する価値があります。逆のことが広く繰り返されているからです。NetDocuments 自身の ndMAX 製品ページは構造化データに `Custom Pricing` を返しますし、ndMAX に紐づいて出回っているユーザーあたり月額15〜25ドルという数字は、リセラー、コンサルタント、比較サイトが出所であって、NetDocuments ではありません。交渉のアンカーとして使うのはよいとして、料金表として予算を組んではいけません。iManage に至っては一切何も公表していません。

2026年8月時点のリセラーおよびコンサルタントの報告が裏づけている範囲は以下のとおりです。

- **DMS のライセンス。** iManage はおよそ10シートの最低数量でユーザーあたり月額50〜75ドル、NetDocuments はリーガル向け構成で40〜65ドル、エントリー版は20ドル近辺で提示されます。ライセンス行では NetDocuments 有利に15〜20%の差、と考えてください。
- **導入費用、ここに本当の差がある。** iManage は10〜25ユーザーで約1万〜1万5,000ドル、25〜50ユーザーで1万5,000〜2万5,000ドル、51シート超で2万5,000ドル以上です。NetDocuments は中小事務所で1,000〜5,000ドル、エンタープライズ移行で5,000〜2万ドル以上が一般的です。15シートなら3〜5倍の比率になり、しかも全額が初年度に発生します。
- **15シートでの試算例。** iManage の現実的な初年度は総額でおよそ2万2,000〜2万7,000ドル、うちライセンスは約1万1,700ドルです。つまり導入費用が初年度請求額のほぼ半分を占めます。同じ事務所が NetDocuments を使えば、ライセンス行はより低く、セットアップはその一部で済みます。

AI 階層はどちらも非公表ですが見積もり自体は取れます。両社にユーザー単位の独立した行として、**実際に接続する人数**で見積もらせてください。総人員数ではありません。ベンダーが2社しかいない市場では、相見積もりが唯一存在する価格圧力です。

## コンテキストレイヤーの問題

2026年5月14日、iManage の MCP Server が出たまさに同じ日に、NetDocuments は Context Graph を発表しました。既存の権限と倫理的隔壁を尊重しながら、数億件のレコードにわたって各案件・文書・コミュニケーションがどうつながっているかを継続的に地図化するものです。プライベートプレビューはその日に開始し、より広い展開は「今後数か月のうちに」とされています。iManage は ConnectLive 2026 を、自社の方向性をコンテンツ・関係性・リアルタイム活動の上に載る context fabric として提示することに費やしました。

2社が同じ日に同じアーキテクチャの物語を語り、どちらも一部はプレビュー段階です。これはどちらかを選ぶ理由にはなりません。必要な DMS と、今四半期に実際に有効化できる AI 階層を買ってください。コンテキストレイヤーは更新交渉で持ち出す材料として取っておきましょう。

## 結論

- **iManage を選ぶべき場面。** 今期に移行しないオンプレミスまたはハイブリッドの資産がある場合。Security Policy Manager の案件単位の倫理的隔壁が、好みではなく明文化された調達要件である場合。セキュリティ委員会が Am Law 規模の同業他社の採用実績を名指しで求める場合。あるいは AI パイロットに日程があり、エージェント接続が承認待ちではなく一般提供である必要がある場合。
- **NetDocuments を選ぶべき場面。** 引き継ぐオンプレミス資産がなくゼロから始める場合。制約になっているのがシート単価ではなく導入予算である場合。Security Center によるツール単位のオプトインが、リスク委員会の聞きたいガバナンスの話である場合。あるいはすでに eDOCS か Worldox を運用しており、移行の会話がどのみち発生する場合。
- **どちらも選ばないべき場面。** 案件数が少なく、すでに Microsoft E3 または E5 を支払っており、案件単位の need-to-know アクセスの証明を誰からも求められていないなら、SharePoint で足ります。引き換えに失うのはリーガルのメタデータモデルと倫理的隔壁の強制です。また、本当の課題が保管ではなく DMS・メール・イントラネット・クライアントポータルを横断する検索であるなら、この判断をやり直すのではなく、残すほうの DMS の隣に [DeepJudge](/ja/tools/deepjudge/) を置いてください。

どうしても決められないときの既定の選択は **NetDocuments** です。決められないという状況は、定義上、オンプレミス資産も倫理的隔壁の要求も答えを強制していない状況です。その2つを除けば、導入費用の差が決め手になります。初年度に一括で発生する3〜5倍の差は、契約期間に薄く広がる15〜20%のライセンス差より重く効きます。これを逆転させる条件は具体的で、当てはまるかどうかはすぐ分かります。廃止できないオンプレミス環境があるか、外部弁護士ガイドラインが案件単位の隔壁強制を明示しているか、のどちらかです。

どちらの交渉にも持ち込むべきガードが2つあります。1つ目。AI の権限を発注書に独立した行として、シートの算定基準まで明記させてください。MCP が動くかどうかを決める言葉は「ndMAX Enterprise」と「Insight+」であり、そのどちらも DMS の見積書には既定では載りません。2つ目。Worldox か eDOCS を運用しているなら、サポート期限を更新契約書に入れてください。Worldox のオンプレミス版は2026年12月31日にサポート終了を迎える一方、eDOCS のオンプレミス版については終了予定なしと NetDocuments は表明しています。プレスリリースの約束は契約条項ではありませんし、Worldox の日程がもう一方の結末の見本です。
