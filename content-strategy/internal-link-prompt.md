# Internal cross-link audit

Per-entity inbound/outbound count audit; surface entries below the link-budget floor; auto-insert links where topical confidence is high. Scheduled weekly (Sunday 03:00 local). The link-budget rules live in [../ARCHITECTURE.md](../ARCHITECTURE.md); this routine operationalizes them.

## Step 1 — Build the graph (EN as canonical)

Walk `content/<entity>/en/*.mdx`. For each entry:

1. Read frontmatter to identify `slug`, `canonical_slug`, `verticals`, and any relationship fields (`integrations` for tools, `tool_a`/`tool_b`/`tools` for comparisons, `tools_used` for workflows, `related_tools`/`related_workflows` for learn, `tools`/`related_workflows` for stacks).
2. Read the body for outbound internal links: `[text](/learn/<slug>)`, `[text](/tools/<slug>)`, etc. Also count references that the schema implies (e.g. a comparison page implicitly links to its `tool_a` and `tool_b` entries).
3. Tally inbound: for every other entry that mentions this slug in its body or relationship fields.

The graph is EN-only. The 5 translated locales mirror EN's link structure — any insertion in EN is mirrored across all 6 locales.

## Step 2 — Identify under-linked entries

The link-budget targets in ARCHITECTURE.md (re-state here for clarity; the contract is in the architecture doc):

- Every tool entry: ≥ 3 outbound links to related tools, comparisons, or workflows; ≥ 2 inbound from comparisons or stacks that reference it.
- Every comparison: ≥ 2 outbound (to the constituent tools' entries); ≥ 1 inbound from a related learn or workflow page.
- Every workflow: ≥ 2 outbound (to constituent tools); ≥ 1 inbound from a related stack or learn page.
- Every learn entry: ≥ 2 outbound (to related tools/workflows/learn); ≥ 1 inbound.
- Every stack: ≥ 2 outbound to each constituent tool's entry; ≥ 1 inbound from a learn or workflow page.

(If ARCHITECTURE.md disagrees with the above, ARCHITECTURE.md wins; flag the inconsistency in the commit message.)

Flag entries below floor. Categorize the gap:

- **Outbound under floor** — auto-insertable if a high-confidence target exists.
- **Inbound under floor** — usually not auto-fixable from this entry's side; it's the OTHER entries that need to link IN. Add the entry's slug to a backlog list for the next freshness sweep on the relevant cluster.

## Step 3 — Auto-insert high-confidence outbound links

For an entry with an outbound gap, look for high-confidence link targets:

- **High confidence** (auto-insert) — a slug that:
  1. Shares ≥ 2 verticals with this entry, AND
  2. Is named in this entry's relationship fields (e.g. tool listed in `integrations`, workflow listed in `related_workflows`), OR
  3. The slug's `name`/`title` appears verbatim in the body and is not yet linked.

- **Medium confidence** (queue for human review) — shares ≥ 1 vertical and matches by category but isn't already referenced in the body.

- **Low confidence** (skip) — no vertical overlap, no body mention, no relationship-field link.

For high-confidence auto-insertions:

1. Pick the best anchor — natural prose, not "click here" or the raw slug. Prefer the target's `name`/`title` (e.g. "Apollo", "the Spellbook vs Harvey comparison") in context.
2. Edit the EN MDX body to insert the link at the natural mention point. If the target slug's name doesn't appear in the body, insert as a sentence at the end of the most relevant section — never force an unnatural anchor.
3. **Mirror the insertion to all 5 non-EN locale files.** Find the equivalent sentence in each translated file (the translations preserve EN's sentence structure) and insert the link with the same anchor text (or the locale's translated equivalent if the anchor was prose like "see the comparison" — the link target stays the same, only the anchor prose translates).
4. Cap auto-insertions at **3 new links per entry per run** to prevent runaway changes. If an entry needs more than 3 links to clear the floor, do the top 3 and note the remaining in the medium-confidence queue.

## Step 4 — Queue medium-confidence candidates

Append to a new file `content-strategy/link-audit-queue.md` (create if missing):

```markdown
# Link-audit queue (manual review)

Generated by ooligo-internal-links. Each entry below is a medium-confidence link candidate that the auto-pass didn't insert. Resolve by either (a) inserting the link manually in an authoring run, (b) marking as `→ rejected: <reason>` to skip in future audits, or (c) clearing the line entirely if the relationship is no longer relevant.

## YYYY-MM-DD

- [source-slug] → [target-slug]: shares vertical revops, target's name "Apollo" not in body
- [source-slug] → [target-slug]: ...
```

The next run appends a new dated section; old sections stay until manually cleared.

## Step 5 — Validate

Run `npm run validate:config` after any auto-inserts. If validation fails, revert all auto-inserts in this run (don't commit a half-broken state) and log the failure.

## Step 6 — Commit

If auto-inserts were made, commit:

```
chore: internal-link pass YYYY-MM-DD — N links inserted across M entries

Auto-inserted (high confidence): N
Queued for review (medium confidence): K
Below floor with no candidate: J
```

Stage:
- The 6-locale set of MDX files for every modified entry
- `content-strategy/link-audit-queue.md`

Include the `Co-Authored-By` trailer. Push to `origin main`.

If no auto-inserts (everything passed floor, or all candidates were medium-confidence-only), commit just the queue file if it changed, or exit cleanly if it didn't.

## Guardrails

- Never link to the same target twice in one entry's body — dedupe before insert.
- Never insert ≥3 outbound to the same target across the catalog (anti-spam against any single target).
- Never insert into the `last_updated` frontmatter date — it only bumps on actual content refresh.
- Auto-insertion is opt-out via a `no_auto_links: true` frontmatter field (rare, e.g. for legal-ops entries where every claim is hedged).

## Autonomous mode

Run end-to-end. Be conservative — a wrong auto-insertion is harder to clean up than a missed one. When in doubt, queue for medium confidence rather than auto-insert.
