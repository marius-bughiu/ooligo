## Was es ist

Claude Managed Agents ist die gehostete Runtime von Anthropic für lang laufende Agents und Teil der Claude Platform (der API). Sie definieren einen **Agent** (Modell, System-Prompt, Tools, MCP-Server und Skills), eine **Umgebung** (die Sandbox, in der er arbeitet) und starten eine **Session**, also eine laufende Instanz dieses Agents. Anthropic betreibt die Agent-Schleife, den Container und die Tool-Aufrufe; Sie senden Nutzereingaben und erhalten Events per Stream. Der Start in der öffentlichen Beta war am 8. April 2026, und alle Endpunkte verlangen weiterhin den Beta-Header `managed-agents-2026-04-01`, den die SDKs automatisch setzen. Der Zugang ist für alle API-Konten standardmäßig freigeschaltet.

Jede Session erhält einen eigenen, frischen Linux-Container mit gängigen Sprachen und vorinstallierten Paketmanagern. Das eingebaute Toolset umfasst `bash`, Lesen, Schreiben und Bearbeiten von Dateien, `glob`, `grep`, `web_fetch` und `web_search`, alle standardmäßig aktiv, und jedes Tool kann eine Berechtigungsrichtlinie erhalten, die vor der Ausführung auf Freigabe wartet. Remote-MCP-Server werden per Streamable HTTP angebunden. Zugangsdaten liegen in **Vaults**: OAuth-Tokens für MCP-Server mit automatischer Erneuerung, Bearer-Tokens und Umgebungsvariablen, die die Sandbox nur als Platzhalter sieht und die erst beim ausgehenden Netzwerkverkehr durch das echte Secret ersetzt werden. Seit Mai 2026 sind Outcomes (eine Bewertungsrubrik, an der sich der Agent selbst misst), Multi-Agent-Orchestrierung, Memory und Webhooks in der öffentlichen Beta; Dreaming und MCP-Tunnel zu privaten Servern bleiben in einer engeren Research Preview. Am 12. November 2026 hat Anthropic eine private Beta für selbst gehostete Managed Agents geöffnet, die den gesamten Dienst in Ihrer eigenen Cloud betreibt.

Die Frage, die es für ein Ops-Team beantwortet: *Betreiben wir Headless-Agents (einen nächtlichen CRM-Hygiene-Durchlauf, eine Triage eingehender Verträge, einen Agent für Kandidaten-Zusammenfassungen) auf der Runtime von Anthropic, oder hosten wir das Agent SDK weiter selbst auf n8n oder eigenen Workern?*

## Was es in der Praxis kostet

Die Abrechnung hat zwei Posten. Tokens werden zu den Standardpreisen der Claude API für das gewählte Modell berechnet, die Multiplikatoren für Prompt Caching gelten wie gewohnt. Die Runtime kostet **$0.08 pro Session-Stunde**, auf die Millisekunde gemessen und nur berechnet, solange der Session-Status `running` ist. Zeit im Status `idle`, also beim Warten auf Ihre nächste Nachricht oder eine Tool-Freigabe, wird nicht berechnet, und die Session-Runtime ersetzt die separate Abrechnung pro Container-Stunde für Code-Ausführung. Websuche innerhalb einer Session kostet $10 pro 1.000 Suchen. Es gibt keine Gebühr pro Nutzer und keine Plattformgebühr, und die Nutzung wird auf ein bestehendes Anthropic-Commitment angerechnet.

Das Rechenbeispiel von Anthropic, eine einstündige Opus-5.5-Session mit 50.000 Input- und 15.000 Output-Tokens, ergibt $0.58: $0.20 Input, $0.30 Output, $0.08 Runtime. Kommen 40.000 dieser Input-Tokens aus dem Cache, sinkt der Betrag auf $0.428. Für die Budgetplanung heißt das: Die Runtime ist der kleine Posten. Eine Session, die einen Monat lang tatsächlich rund um die Uhr liefe, käme auf etwa $58 Runtime; ein nächtlicher Durchlauf von 20 Minuten kostet unter $1 im Monat. Prognostizieren und deckeln müssen Sie die Modell-Tokens. Zwei Rabatte gelten nicht: Für Sessions gibt es keine Batch-API-Preise, und auch keine Partner-Cloud-Preise, weil die gehostete Runtime weder über Bedrock noch über Vertex verkauft wird.

## Am besten geeignet für

- **RevOps- oder Legal-Ops-Teams mit einem einzigen Engineer**, die einen Agent wollen, der eine Stunde in einer Sandbox arbeitet, das CRM oder CLM per MCP aufruft und Ergebnisse zurückmeldet, ohne vorher eine Container-Flotte, eine Job-Queue und einen Secret-Store aufzubauen.
- **Teams mit bestehendem Claude-API-Commitment**, die einen Agent in ein internes Tool oder ein Produkt einbauen und bei denen Runtime-Gebühr und Console-Tracing wochenlangen Orchestrierungscode ersetzen. Die Launch-Kunden von Anthropic (Notion, Rakuten, Asana, Sentry) berichten von einem Go-live in „Wochen statt Monaten“; das sind vom Anbieter veröffentlichte Angaben.

## Alternativen und wann Sie sie wählen sollten

- **[Amazon Bedrock](/de/tools/amazon-bedrock/) mit AgentCore**: einer der beiden Marktanteilsführer unter den Cloud-Agent-Plattformen. Wählen Sie es, wenn Identitäten, Daten und das Cloud-Commitment in AWS liegen und der Agent in Ihrem eigenen Konto laufen muss. Beachten Sie, dass Claude auf Bedrock die Managed-Agents-Runtime nicht enthält.
- **[Microsoft Foundry](/de/tools/microsoft-foundry/) Agent Service**: der andere Marktführer. Wählen Sie es, wenn Sie Azure-Tenancy, Entra-Identitäten für Agents und Modelle neben Claude brauchen.
- **Das Claude Agent SDK selbst hosten** auf [n8n](/de/tools/n8n/) oder eigenen Workern: Wählen Sie das, wenn Sie heute Zero Data Retention, HIPAA-Eignung oder eine feste Garantie für die Session-Dauer brauchen. Sandbox, Retries und Secrets liegen dann bei Ihnen, und Sie zahlen nur Tokens.
- **[Claude Cowork](/de/tools/claude-cowork/)**: Wählen Sie es, wenn der Nutzer ein Mensch am Schreibtisch ist und kein Dienst. Cowork ist der pro Nutzer bepreiste Desktop-Agent; Managed Agents ist die API-Runtime für Headless-Arbeit.
- **[Hermes Agent](/de/tools/hermes-agent/)**: der am schnellsten wachsende Neueinsteiger auf der Self-Hosting-Seite, mit rund 263.000 GitHub-Sternen neun Monate nach dem Release. Wählen Sie ihn für einen dauerhaft laufenden Agent in Slack oder Telegram auf beliebigem Modell, ohne API-Integrationsaufwand.

## Worauf Sie achten sollten

- **Ausgehender Netzwerkverkehr ist offen, bis Sie ihn schließen.** Eine per API ohne Netzwerkeinstellung angelegte Umgebung steht standardmäßig auf `unrestricted` (das Console-Formular startet auf Limited). **Absicherung:** Setzen Sie `networking` in jeder per Code angelegten Umgebung auf `limited` mit einer expliziten `allowed_hosts`-Liste, und denken Sie daran, dass diese Liste auch für `web_search` und `web_fetch` gilt.
- **Nicht ZDR- und nicht HIPAA-fähig.** Laut Anthropic-Dokumentation fällt die gehostete Runtime mit allen Teilfunktionen nicht unter Zero Data Retention und nicht unter HIPAA. **Absicherung:** Halten Sie PHI und alles unter einer ZDR-Klausel auf einem selbst gehosteten Agent-SDK-Deployment, oder warten Sie auf die selbst gehostete private Beta, die einzige Variante, die ZDR abdeckt.
- **Es ist eine Beta mit datiertem Header.** Endpunkte, Event-Typen und Standardwerte können sich ändern, und die Dokumentation nennt weder eine maximale Session-Dauer noch ein Concurrency-Limit; die veröffentlichten Rate Limits liegen bei 300 Create- und 1.200 Read-Requests pro Minute und Organisation. **Absicherung:** Pinnen Sie SDK-Versionen, schreiben Sie Agent- und Umgebungsdefinitionen in Dateien, die Sie mit der `ant`-CLI anwenden, damit sie in git liegen, und setzen Sie Ausgabenlimits der Organisation vor dem ersten geplanten Lauf.
- **Memory bleibt zwischen Sessions bestehen.** Memory Stores werden von Lauf zu Lauf übernommen, sodass eine falsche Angabe, die der Agent speichert, auch spätere Läufe beeinflusst. **Absicherung:** Geben Sie jedem Produktiv-Agent einen eigenen Memory Store, prüfen Sie dessen Inhalt in festem Rhythmus über die API und löschen Sie Einträge, die keine geprüfte Quelle stützt.
