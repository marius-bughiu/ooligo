Le GTM Engineering est le versant technique de la fonction go-to-market — les personnes qui écrivent du code pour construire, intégrer et opérer les systèmes générateurs de revenus. À partir de 2024-2026, il est apparu comme un intitulé de poste distinct dans les entreprises B2B SaaS IA-native, à l'intersection du RevOps, du génie logiciel et du génie des données.

## Ce que fait un GTM Engineer

Le travail, en termes concrets :

1. **Construit des agents IA et des Skills** qui automatisent la recherche, la rédaction, le scoring et le triage. Skills Claude, agents n8n, serveurs MCP câblés aux données internes.
2. **Écrit des intégrations** entre les outils GTM qui n'ont pas de connexions natives — pousser les données Salesforce dans Snowflake, synchroniser Linear vers HubSpot, exposer le data warehouse à Cursor pour des requêtes en temps réel.
3. **Maintient le pipeline de données** entre les systèmes opérationnels et l'entrepôt analytique — pour que le reporting, les prévisions et le scoring ML tournent tous sur la même source de vérité.
4. **Construit des outils internes** que les équipes AE/SDR/CSM utilisent directement — tableaux de bord, applications de recherche de leads, générateurs de deal rooms, automatisations de préparation aux QBR.
5. **Détient l'infrastructure IA** — quels modèles l'équipe utilise, quels serveurs MCP sont déployés, ce que contient la bibliothèque de Skills, quelle est la politique de versionnage des prompts.

## GTM Engineer vs RevOps Engineer vs Sales Engineer

| Intitulé | Rattachement | Travail principal |
|---|---|---|
| GTM Engineer | Leader RevOps ou CRO | Construit des IA/agents/intégrations sur l'ensemble du stack GTM |
| RevOps Engineer | Leader RevOps | Construit des workflows dans le CRM + outils adjacents (souvent no-code ou low-code) |
| Sales Engineer | Leader commercial | Support technique pré-vente aux AEs (démos, POC, cadrage d'intégration) |

Les frontières s'estompent dans les petites entreprises. Dans une organisation de 50 personnes, une seule personne peut faire les trois. À 50 M€+ ARR, ils se séparent.

## Pourquoi le rôle a émergé en 2024-2026

Trois forces ont convergé :

1. **Les outils IA sont devenus scriptables au niveau workflow.** Claude + MCP, les nœuds agents IA de n8n, le mode agent de Cursor — construire un agent qui fait un travail significatif ne nécessite plus une équipe ML spécialisée.
2. **Le transfert RevOps vers l'ingénierie s'est cassé.** Les équipes d'ingénierie ont cessé d'avoir de la capacité pour les « demandes RevOps » une fois qu'elles ont priorisé la vélocité produit. Quelqu'un dans l'organisation GTM devait écrire le code.
3. **Le vibe coding a abaissé la barrière.** Un développeur non traditionnel peut livrer des automatisations de qualité production avec Claude Code ou Cursor en quelques heures. Le plafond de compétences pour « ops engineer » a considérablement baissé.

## Signal de recrutement

Cherchez : un ingénieur logiciel qui a pivoté vers le GTM, ou une personne RevOps qui a appris à coder. Les deux profils fonctionnent. N'embauchez pas un ingénieur logiciel pur qui n'a jamais vu un CRM — ils écriront du code élégant qui résout les mauvais problèmes.
