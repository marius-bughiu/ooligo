## 概要

Chameleon はプロダクトアダプションのプラットフォームです。Tours、Tooltips、Microsurveys、Launchers、Banners、Checklists、そしてアプリ内検索ウィジェットの HelpBar を、コードを書かずに構築してターゲティングできます。デジタルアダプション領域における、デザイン重視の選択肢です。[Pendo](/ja/tools/pendo/) がアナリティクス優先に寄り、Whatfix がエンタープライズの DAP 導入を狙うのに対して、Chameleon の差別化要因は、ウィジェットが本当に自社プロダクトらしく見えることにあります。CSS は完全にカスタマイズ可能で、有料プランでは「made with」の強制表示もなく、このカテゴリーで最もピクセル単位の制御に近い体験を提供します。現在はその builder の上に AI エージェント（Copilot、Ranger）を重ねています。

## Customer Success スタックで採用される理由

- **CS が他の手段では触れない in-product レイヤーを押さえている。** CSM は health score や playbook のために [Gainsight](/ja/tools/gainsight/)、Vitally、[Catalyst](/ja/tools/catalyst/) で作業しますが、これらのツールは顧客のアプリ内に tooltip を表示することはできません。Chameleon は、CS の「feature の adoption を促進する」という目標を、ユーザーが本当に必要なタイミングで目にする形に変える表面です。
- **Microsurveys が health のシグナルを供給する。** アプリ内の NPS、CSAT、CES サーベイは実際の利用イベントをトリガーに発火し、CS プラットフォームへ戻ります。adoption のシグナルと sentiment のシグナルが、CSM が既に作業している同じ場所に集まります。
- **デザイン品質が社内の摩擦を下げる。** プロダクトチームやブランドチームは、後付け感のある adoption ツールを日常的に却下します。Chameleon の CSS 制御こそが、より安価なツールが却下される審査を生き残る理由です。
- **ノーコードのターゲティング。** CS と product ops はエンジニアリングのチケットなしで体験を構築・セグメントできるため、onboarding フローのイテレーションはスプリントではなく当日の変更で済みます。

## Pricing

カスタムかつ非公開です。Chameleon はプランページでの定価掲載をやめており、価格は Monthly Tracked Users（MTUs）に応じてスケールします。

- **Startup** — 年額契約で約 279 USD/月、最大 2,000 MTUs。Tours と Tooltips が無制限、Microsurveys 5 個、Launcher 1 個、カスタム CSS、Copilot エージェント
- **Growth** — 概ね約 1,000 USD/月から（第三者データでは年間契約が 12k USD 以上）。体験が無制限、A/B testing、AI Interactive Demos、governance スイート
- **Enterprise** — カスタム。シート無制限、ロール/権限、ローカリゼーション、redlining

最大の注意点は Startup から Growth への崖です。価格の跳ね上がりはおよそ 3〜4 倍で、ほとんどのチームは Startup の 2,000 MTUs と Launcher 1 個という上限をすぐに超えてしまいます。

## 適しているチーム

ブランドとデザインの基準が高く、汎用的な見た目のオーバーレイなら却下されるような、従業員 50〜500 人規模の SaaS 企業の CS・プロダクトチーム。そして、アプリ内の onboarding と adoption をエンジニアリングではなく CS と product ops が共同で所有しているチームです。

## 注意点

- **MTU 課金は、高トラフィック・freemium・PLG のプロダクトに不利。** 大きな無料枠は売上を増やさずに MTUs だけを膨らませます。契約前にアクティブな無料ユーザー数に対して MTU 数を確認し、Startup の見せ球ではなく Growth ティアの数字でモデリングして備えてください。
- **これは記録のシステムではなくプレゼンテーションレイヤー。** Chameleon はガイダンスを表示しサーベイ回答を収集しますが、health scoring や playbook のオーケストレーションで Gainsight/Vitally/Catalyst を置き換えるものではありません。サーベイと adoption のイベントを初日から CS プラットフォームへ接続し、シグナルが孤立しないようにして備えてください。
- **現時点で MCP サーバーはない。** CS-ops の自動化を MCP のエージェント型 tooling で回している場合、頼れるのは REST/JS API と webhook です。動きはしますが、ネイティブな MCP 連携よりも繋ぎ込みの手間が増えます。コミットする前に、API が自社のイベントモデルをカバーするか確認してください。
- **より安価でアナリティクスに厚い代替がある。** adoption のアナリティクスを主価値、アプリ内ガイダンスを副次的に求めるなら Pendo の方が強い選択肢です。デザインの忠実度が決め手なら Chameleon が勝ちます。
