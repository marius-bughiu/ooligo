## 概要

Twilio Segment はパッケージ型のカスタマーデータプラットフォームです。Web アプリ、モバイルアプリ、バックエンドに SDK を組み込み、`track` と `identify` を呼び出すと、Segment がそのイベントを収集し、匿名時とログイン後のアクティビティを 1 つのプロファイルにつなぎ合わせ、そのストリームを必要とするツールへ転送します。製品は 4 つのレイヤーで構成されています。700 を超える既成の宛先へ流すイベントパイプラインである Connections、不正な形式のイベントをブロックするトラッキングプランの強制機能である Protocols、アイデンティティ解決とプロファイルを担う Unify、そしてそのプロファイルの上に構築するオーディエンスとジャーニーの Engage です。Twilio は 2020 年に約 32 億ドル相当の株式で Segment を買収し、業績不振を受けて 2024 年初頭に戦略的見直しの対象としましたが、2024 年 3 月に保持を決め、Thomas Wyatt を Segment のプレジデントに任命しました。2026 年 5 月の SIGNAL で、Twilio は Segment を新しい Conversation Memory レイヤーのデータソースとして打ち出しました。これは、Twilio 内での Segment の将来が、マーケティング予算を奪い合う単体の CDP ではなく、コミュニケーション製品のための配管であることを示しています。

## RevOps スタックに入ってくる理由

RevOps や CS チームが購入するプロダクトシグナル系のツール、つまり [Pocus](/ja/tools/pocus/)、[Vitally](/ja/tools/vitally/)、[Common Room](/ja/tools/common-room/)、[Amplitude](/ja/tools/amplitude/)、[Mixpanel](/ja/tools/mixpanel/) は、いずれもクリーンなプロダクトイベントのストリームがすでに存在することを前提にしています。チーム内にウェアハウスのモデルを管理する人がいない場合、Segment はそこへ至る最短の道です。1 回の計装ですべての宛先にデータが流れるため、来四半期に Vitally を追加するのは Segment の UI でトグルを切り替えるだけで済み、2 つ目のエンジニアリングプロジェクトにはなりません。過小評価されているのが Protocols です。合意済みの名前が `Account Created` のときに `Signed Up` を拒否するトラッキングプランがあるかどうかで、CSM が信頼するヘルススコアになるか、無視することを覚えてしまうヘルススコアになるかが分かれます。

Segment はリバース ETL とウェアハウス接続型のオーディエンスビルダーも備えています。2024 年 8 月から Snowflake と Databricks 向けに一般提供されている Linked Audiences と Data Graph を使えば、アカウント、サブスクリプション、請求書といったウェアハウスのエンティティテーブルから、先に Segment へコピーすることなくオーディエンスを構築できます。これで [Hightouch](/ja/tools/hightouch/) との差は縮まりますが、どちらの機能も Business ティアが必要で、Data Graph は Engage にバンドルされています。

## 価格の実態

プランは 3 つあり、公開価格があるのは最初の 2 つだけです。Free は 1,000 monthly tracked users（MTU）までをカバーします。6 か月の期間内に 1 回超過すると Segment はアカウントをロックしますが、データは流れ続けます。2 回目の超過でデータが止まります。Twilio の請求ドキュメントによると、Team は 10,000 MTU で月額基本料金 120ドル、その上に段階的な超過料金がかかります。Twilio の価格ページにはもはや Team が一切掲載されておらず、Customer Data Pipeline プランと Customer Data Platform プランだけが表示されています。どちらも見積もりのみで、シートは無制限です。

Business については購買データがその空白を埋めます。Vendr は 616 件の購買にわたる年間契約の中央値を 55,600ドル、レンジを 14,825ドルから 198,000ドル、平均値引きを 17% と報告しています。読み方はこうです。tracked users が数十万人規模で Unify を有効にしている B2B SaaS 企業なら、年間 40,000ドルから 80,000ドルのどこかに着地します。メーターの単位はイベントではなく人なので、一度もログインしない匿名訪問者もカウントされます。

## こんなチームに向いています

データチームもモデル化されたウェアハウスもなく、プロダクトイベントを CS プラットフォーム、PQL ツール、CRM へ数週間で流す必要がある、従業員およそ 20 から 300 人規模の PLG SaaS 企業の RevOps またはグロースのリードです。この場合、Segment の価値実現までの速さはどのコンポーザブルな代替製品にも勝ります。

dbt モデルを備えた Snowflake や Databricks をすでに運用し、SQL を書ける人がいるなら買うべきではありません。顧客データの 2 つ目のコピーと 2 つ目のアイデンティティグラフを保持するために Segment に支払い、さらにその 2 つを突き合わせるためにもう一度支払うことになります。

## 代替製品との比較

[Salesforce](/ja/tools/salesforce/) Data Cloud と Adobe Real-Time CDP は、エンタープライズでの導入規模が最も大きい 2 つの CDP です。Salesforce が記録システムで、中間ベンダーを挟まずに Agentforce と Marketing Cloud の中でプロファイルを使いたいなら Data Cloud を選んでください。マーケティング組織がすでに Adobe Experience Platform を運用しているなら Adobe です。自社アプリからプロダクトイベントを取り出して多数のミッドマーケット向けツールへ届けることが目的なら、両者よりも Segment を選んでください。どちらのスイートもその用途を中心に作られていません。

Hightouch は最も成長の速い新規参入です。Gartner の 2026 年 CDP Magic Quadrant で Leader に選ばれ、Twilio は 2 年連続で Niche Player でした。ウェアハウスが真実の源であり、アイデンティティを 2 か所で保守することを拒むなら Hightouch を選んでください。アクティベートの元になるウェアハウスがないなら Segment です。

RudderStack は最も近い同種の競合で、SDK ベースのイベント収集を行い、生のイベントを自社のウェアハウスに格納します。課金は人ではなくイベント単位で、月 250,000 イベントまで無料、100 万イベントからは月額 265ドルです。匿名訪問者が多く、訪問者あたりのイベント数が少ないなら RudderStack を選んでください。その場合、人単位のメーターのほうが高くつくからです。

どれも合わない場合、問題はたいてい CDP ではなく計装にあります。誰も合意していないイベントスキーマを直せるプラットフォームはないので、まずトラッキングプランを書いてください。

## Watch-out

- **MTU メーターは匿名トラフィックにも課金します。** `userId` を持たないユニークな `anonymousId` はすべてカウントされます。ログイン前は各ソースが独自の匿名 ID を発行するため、2 つのソースのうち 1 つでしかログインしないユーザーも 2 MTU として請求されます。*ガード:* すべてのソースで、認証フローが許す限り早い段階で `identify` を呼び出してください。そして年間ボリュームをコミットする前に、最初の丸 1 か月が終わった時点でワークスペースの使用状況にある MTU の内訳を確認してください。
- **単体の CDP 機能に対する Twilio のコミットメントにはむらがあります。** Engage Premier（マルチチャネルのキャンペーン送信、購読管理）は 2025 年 12 月 15 日にサポート終了を迎えました。Gartner の 2026 年のレポートは、B2B 向けのアカウント階層管理が限定的であると指摘しています。*ガード:* Segment は Connections、Protocols、Unify のために買い、キャンペーンの実行は HubSpot、Braze、Customer.io のように独立して入れ替えられる専用ツールに置いてください。
- **ワークスペースのデータに対応する Segment の MCP サーバーはありません。** Twilio のホスト型 MCP サーバーはパブリックベータで、Segment のドキュメントをインデックスしており、読み取り専用です。プロファイルを照会したり、オーディエンスを構築したりすることはできません。*ガード:* 顧客プロファイルへのエージェントのアクセスが要件なら、自社のサービスアカウントのもとでウェアハウスか Profile API を経由させ、その構築費用を評価に織り込んでください。
- **Team プランはドキュメントには存在しますが、価格ページにはありません。** *ガード:* プラン名、MTU の上限、1,000 MTU あたりの超過単価、スループットの上限を発注書に記載させてください。Twilio のドキュメントはスループットを有料 MTU あたりの API コール数として説明しており、Business の上限は個別設定です。
- **UI で構築する Engage オーディエンスと Unify ルールが増えるほど、離脱コストも増えます。** *ガード:* 初日からウェアハウスの宛先を有効にし、生のイベント履歴を自社が所有するストアに置いてください。そうすれば Segment からの移行は SDK の向き先を変えるだけで済み、何年分ものデータを失うことはありません。
