## Was es ist

Microsoft Entra Agent ID ist der Teil von Entra ID, der einem KI-Agent eine eigene Identität gibt, statt ihn die eines Menschen ausleihen zu lassen. Die Dokumentation von Microsoft beschreibt es als allgemein verfügbar. Es fügt dem Verzeichnis vier Objekttypen hinzu: einen **Agent Identity Blueprint** (die Vorlage, aus der eine Familie von Agents erstellt wird), den Principal des Blueprints in jedem Tenant, die **Agent-Identität** selbst und einen optionalen **Agent-User**, ein Benutzerkonto für Agents, die sich bei Systemen anmelden müssen, die nur Benutzer akzeptieren. Jede Agent-Identität kann einen **Sponsor** tragen – einen namentlich benannten Menschen, der für ihren Lebenszyklus und ihren Zugriff verantwortlich ist –, getrennt von ihren technischen Ownern.

Auf diese Identitäten wendet Entra die Kontrollen an, die Sie bereits für Menschen betreiben: Conditional Access für Agents, ID-Protection-Risikoerkennungen für Agents, Access Packages und Sponsor-Lifecycle-Workflows in ID Governance sowie eine Standard-Inaktivitätsrichtlinie, die ruhende Agent-Identitäten findet, die Verantwortlichen benachrichtigt und die Identitäten deaktiviert.

Agent ID ist die Identitätsschicht, nicht das Inventar. Seit dem **1. Mai 2026** liegt die Agent-Registry in [Microsoft Agent 365](/de/tools/microsoft-agent-365/), und die Registry-Blades im Entra Admin Center wurden eingestellt. Entra stellt die Identität aus und sichert sie ab; Agent 365 listet und steuert den Agent.

## Warum Ops-Teams hier landen

Die Frage kommt meist als drei Fragen auf einmal: Brauchen unsere Ops-Agents eigene Entra-Identitäten, welche Lizenz ist dafür nötig, und was passiert mit den Copilot-Studio-Agents, die Microsoft gerade migriert?

Die erste Antwort lautet ja, sobald ein Agent unbeaufsichtigt in ein System of Record schreibt. Ein Agent, der mit dem Token seines Erstellers läuft, erscheint in den Logs als diese Person, erbt alles, worauf diese Person zugreifen kann, und hört auf zu funktionieren – oder funktioniert weiter –, wenn diese Person das Unternehmen verlässt. Eine Agent-Identität gibt Ihnen ein separates Audit-Subjekt, einen Sponsor, der dafür geradesteht, und ein Ziel für Richtlinien.

Die dritte Antwort wird bereits für Sie entschieden. Die Message-Center-Mitteilung **MC1478488** (24. September 2026) besagt, dass [Copilot Studio](/de/tools/microsoft-copilot-studio/)-Agents, die vor Mai 2026 erstellt wurden, möglicherweise noch mit Legacy-Identitäten aus App-Registrierungen laufen; die Self-Service-Migration startete am **24. August 2026** in Power Platform Advisor, und die automatische Migration von Agents ohne Agent ID begann im **September 2026**. Die Migration wandelt die Identität an Ort und Stelle um, sodass der Agent seine Client-ID behält und Connectors weiterhin aufgelöst werden. [Microsoft Foundry](/de/tools/microsoft-foundry/)-Agents erhalten automatisch eine Agent ID. Agents, die außerhalb von Microsoft gebaut werden – [n8n](/de/tools/n8n/), [Amazon Bedrock](/de/tools/amazon-bedrock/), alles in einem Container –, erhalten eine über den Entra Auth SDK Sidecar oder über Workload Identity Federation, die ein AWS- oder Google-Cloud-Token austauscht, ohne ein Secret zu speichern.

## Preisrealität

Die Produktseite von Microsoft verkauft Agent ID auf zwei Wegen:

- **Microsoft Agent 365 für $15.00 pro User und Monat**, jährlich bezahlt.
- **Microsoft 365 E7 für $99.00 pro User und Monat** ($90.45 ohne Teams), das Agent 365 und die Microsoft Entra Suite bündelt.

Bezahlt wird für die Kontrollen. Microsoft Learn gibt an, dass Conditional Access für Agents und ID Governance für Agents jeweils entweder E7 erfordern oder eine Agent-365-Lizenz in Kombination mit mindestens Entra ID P1 oder Microsoft 365 E3. Die Mitteilung **MC1395007** hat zwischen Juli und August 2026 zwei Service-Pläne – Entra Conditional Access for Agents und Entra ID Protection for Agents – zu Agent 365 und E7 hinzugefügt und erklärt, dass Tenants, die diese Funktionen ohne eine dieser Lizenzen nutzen, eine kaufen müssen, um sie zu behalten.

Die Einheit ist der Mensch, nicht der Agent. Für einen **E3-Betrieb mit 200 Mitarbeitenden** kommen durch Agent 365 $15 × 200 = **$36,000 pro Jahr** hinzu. Für Agents, die im Namen eines angemeldeten Users handeln, zählt auch die eigene Lizenz des Users: Conditional Access wird gegen das Token des Users ausgewertet und erfordert E3, ID Protection erfordert E5, und ID Governance für diese Agents erfordert Entra ID Governance oder die Entra Suite. Ein Betrieb, der das Add-on überspringt und direkt auf E7 wechselt, zahlt $99 × 200 = **$237,600 pro Jahr**, was nur sinnvoll ist, wenn Sie auch alles andere wollen, was E7 enthält.

## Am besten geeignet für

Eine IT- oder Identity-Leitung in einem **Microsoft-365-Tenant ab E3**, deren Ops-Teams bereits Agents in Copilot Studio, Foundry oder n8n betreiben. Der Fall, in dem es klar gewinnt: Ein RevOps- oder Legal-Ops-Agent schreibt ohne Menschen in der Session ins CRM oder ins Vertragsrepository, und eine Compliance-Prüfung fragt, welche Identität jede Änderung vorgenommen hat, wer sie sponsert und welche Richtlinie sie aus einem nicht verwalteten Netzwerk blockiert.

## Nicht geeignet für

Ein Team auf Google Workspace oder eines, dessen Identity Provider Okta ist. Sie würden Entra einführen, um Agents zu steuern, deren User sich anderswo authentifizieren. Es ist auch nicht die Antwort für Agents, die SaaS-APIs mit statischen Keys aufrufen: Die eigene Dokumentation von Microsoft sagt, dass ein API-Key die Entra-Authentifizierung vollständig umgeht, sodass keine Conditional-Access-Richtlinie greift.

## Im Vergleich zu den Alternativen

- **[Okta](/de/tools/okta/)** – der andere Marktanteilsführer bei Workforce Identity. Agent SSO wurde am 24. August 2026 innerhalb der Core-SSO-Pläne ohne Aufpreis allgemein verfügbar und stellt kurzlebige Tokens über Cross App Access aus; Okta for AI Agents ist ein separates Abonnement nur auf Angebotsbasis. Wählen Sie Okta, wenn Ihre Mitarbeitenden sich bereits über Okta anmelden und die relevanten Agents auf SaaS außerhalb von Microsoft zugreifen. Wählen Sie Entra Agent ID, wenn die Agents in Copilot Studio oder Foundry gebaut werden, denn sie erhalten eine Entra-Identität, ganz gleich, welchen IdP Sie bevorzugen.
- **[Rippling](/de/tools/rippling/) AI Governance** – der sich am schnellsten bewegende Neueinsteiger, im August 2026 gestartet mit einem MCP-Gateway und Agent-Identität auf Basis eines HRIS. Wählen Sie es, wenn Rippling das System of Record ist und Sie den Agent-Zugriff an den Beschäftigungsstatus koppeln wollen, ohne separaten Identity-Anbieter.
- **[Zenity](/de/tools/zenity/), [Runlayer](/de/tools/runlayer/), [Obot](/de/tools/obot/)** – keine Identity Provider; sie prüfen, was ein Agent beim Tool-Aufruf tut. Ergänzen Sie eines davon, wenn das Risiko ein per Prompt Injection manipulierter Agent ist, der legitime Berechtigungen missbraucht – etwas, das eine Identität nicht verhindern kann.

## Worauf Sie achten sollten

- **Eine Berechtigungsänderung kann diesen Monat Agents lahmlegen.** Die Mitteilung **MC1506728** besagt, dass Entra ab dem 4. November 2026 aufgehört hat, `AgentIdentity.CreateAsManager` automatisch an Agent-Blueprint-Principals zu vergeben, mit Rollout bis Ende November. Agents, die ihre eigenen untergeordneten Identitäten ohne explizite Admin-Freigabe erstellen, scheitern jetzt mit einem 403. **Absicherung:** Filtern Sie die Entra-Audit-Logs nach „Add Service Principal“-Ereignissen mit einem Anwendungsakteur und einer Agent-Identität als Ziel, und erteilen Sie die Graph-Berechtigung jedem Blueprint, der sie noch benötigt.
- **On-Behalf-Of-Agents entgehen agentbezogenen Richtlinien.** Eine Conditional-Access-Richtlinie, die auf eine Agent-Identität zielt, deckt keine Anfragen ab, die dieser Agent im Namen eines Users stellt; diese folgen den Richtlinien des Users, und ID Protection rechnet das Risiko dem User zu. **Absicherung:** Schreiben Sie separate Richtlinien für die drei Zugriffsmuster – autonome Agents, On-Behalf-Of-Flows und Agent-User – und testen Sie jede im Report-Only-Modus, bevor Sie sie erzwingen.
- **Zwei Identitätstypen, bis die Migration abgeschlossen ist.** Copilot-Studio-Agents, die noch auf App-Registrierungen laufen, werden von Richtlinien für Agent-Identitäten nicht erfasst. **Absicherung:** Führen Sie die Empfehlung in Power Platform Advisor aus, migrieren Sie zuerst einen kleinen Batch nicht kritischer Agents, validieren Sie Channels und Connectors, und nutzen Sie das Rollback pro Agent für alles, was bricht.
- **Eine Richtlinie auf einem Blueprint erreicht auch später erstellte Agents.** Das ist der Sinn von Blueprints – und zugleich ein Weg, versehentlich eine ganze Familie zu blockieren. **Absicherung:** Beschränken Sie neue Richtlinien zunächst auf eine einzelne Agent-Identität und weiten Sie sie erst nach einer Woche sauberer Sign-in-Logs auf den Blueprint aus.

Verwandt: Der [Enterprise-AI-Rollout-Stack](/de/stacks/enterprise-ai-rollout-stack/) nutzt Agent ID als Identitätsebene, und der [Agent-Access-Governance-Stack](/de/stacks/agent-access-governance-stack/) legt fest, welche Agents in die Revenue-Systeme schreiben dürfen und bis zu welcher Obergrenze.
