採用担当者が職務に関する記述を確認するときは、その判断の根拠となる原文までたどれることが重要です。このワークフローは、利用が許可された抜粋を職務上の基準に沿って整理します。確認カードにはレコード ID、引用文、出典が残ります。

## 架空の3件で試す

[一式をダウンロード](/artifacts/candidate-sourcing-claude-skill.zip)して展開し、そのフォルダーで `python3 prepare_review.py examples/brief.json` を実行します。必要なのは Python 3 です。サンプルファイルは英語です。[入力例](/artifacts/candidate-sourcing-claude-skill/examples/brief.json)と[期待される出力](/artifacts/candidate-sourcing-claude-skill/examples/expected-review.json)を見比べてください。

想定する職種は倉庫のデータ分析責任者です。出荷イベントの重複を検出する SQL の使用例を確認します。C-01 には、出荷 ID とイベント種別で集計したという W-01 の引用があり、カードには `verify_quote` と表示されます。誤検出をどう検証したかは別途確認が必要です。`hold` の C-02 は保留件数だけに反映されます。引用のない C-03 は `request_evidence` として残ります。2枚のカードは入力順に並びます。

## 許可を得たエクスポートで使う

1. 職務上の作業を明文化し、何を根拠として確認するか採用チームで合意します。[構造化面接のガイド](/ja/learn/structured-interviewing/)は追加質問を作る際に使えます。
2. 出典の利用権限と連絡制限を担当者が確認します。仮名の ID を付け、各レコードに確認または保留の区分を指定します。区分がない場合や未知の値の場合は処理が止まります。[確認リスト](/artifacts/candidate-sourcing-claude-skill/references/2-fairness-checklist.md)に沿って点検してください。
3. [カードのひな型](/artifacts/candidate-sourcing-claude-skill/references/3-shortlist-format.md)を使って引用を照合します。[Claude](/ja/tools/claude/)でメモの下書きを作る場合は、その用途で許可されたカードだけを渡します。次の対応や連絡の可否は採用担当者が別途判断します。

[Juicebox](/ja/tools/juicebox/)などにあるプロフィールを使うには、正式に許可されたエクスポートか、自社で用意したコネクターが必要です。付属のプログラムはローカルファイルを処理します。外部検索、ATS の更新、メッセージ送信には別の仕組みが必要です。

## 結果を確認する

公開した検証には架空のレコードを使いました。自社で試すときは、出典まで確認できた引用数、修正したメモ、確認にかかった時間を記録してください。実際の採用結果や作業時間の削減効果は測定していません。
