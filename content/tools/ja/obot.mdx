## 何をするものか

Obot は自社でホストするコントロールプレーンで、AI クライアントとその接続先すべての間に立ちます。接続先とは MCP サーバー、それらのサーバーが必要とする認証情報、そして今ではモデル自体です。Go で書かれ、`github.com/obot-platform/obot` で MIT ライセンスとして公開され、GitHub のスター数は 983 です。3 つの部品が仕事を担います。管理者がキュレーションし社員が閲覧する MCP Catalog、下流のすべてのサーバーに対して OAuth を仲介するゲートウェイ、そしてツール呼び出しごとにユーザー、エージェント、サーバー、引数、結果を記録する監査ログです。

注目すべき理由は認証モデルにあります。Obot はすべての MCP サーバーの前に単一の ID レイヤーを置き、Google、GitHub、Okta、Auth0、JumpCloud、Entra に対してトークンを仲介し、スコープの適用とローテーションを引き受けます。トークンがゲートウェイの外に出ることはない、というのが Obot の明示する保証です。アクセス制御はサーバー単位ではなくツール単位で効きます。どのユーザー、グループ、エージェントが、どのサーバーのどのツールを呼べるかを、コードとしてのポリシーで定義します。

Obot AI は 2025 年 9 月 23 日に発表された $35M のシードラウンドを調達しました。リードは Mayfield と Nexus Venture Partners の共同です。創業チームは SUSE に買収された Rancher Labs と、Citrix に買収された Cloud.com を築いた面々で、CEO は Sheng Liang です。MCP Gateway は 2025 年 8 月に提供が始まり、同社は Apache-2.0 のエージェントフレームワーク Nanobot も公開しています。

## このページが解く分岐

このページが存在する理由となる問いは「ゲートウェイを自社でホストするか、マネージドの tool-auth を使うか」です。[Composio](/ja/tools/composio/) と [Arcade](/ja/tools/arcade-dev/) はどちらも自社インフラであなたの OAuth トークンを保持し、その見返りにカタログを渡します。Composio は 2026 年 5 月 21 日、攻撃者がまさにその種の保管庫から約 5,241 件の API キーと 5,001 件の GitHub OAuth トークンを持ち出したと公表しました。Obot はこの取引を反転させます。認証情報の経路にベンダーが存在しないため、ベンダーから抜き取られるものがありません。同時に、1,000 件規模の既製カタログも存在しません。Obot はあなたが持ち込む MCP サーバーを統治するのであって、供給はしません。

2026 年 6 月 18 日にリリースされた v0.23.0 は、Obot を両者から分ける部品を加えました。LLM ゲートウェイです。Obot は OpenAI および Anthropic 互換のモデルエンドポイントを提供するようになり、[Claude](/ja/tools/claude/) Code は Obot のトークンで認証し、モデルをネイティブ名で呼び出し、そのユーザーに許可されたモデルだけを見ます。Composio と Arcade はツール呼び出しを統治します。Obot はツール呼び出しとモデル呼び出しを 1 つのポリシーと 1 本の監査証跡で統治します。それはコンプライアンス審査担当者が実際に要求する成果物です。

同じリリースで、共有 MCP サーバーは Git で管理されるカタログエントリに移りました。新しいサーバーはコードレビューを通って入り、シークレットは Obot 内に保存せず外部管理のものを参照します。エディションも 1 つのビルドに統合されました。オープンソースのイメージにライセンスキーを加えると enterprise 機能が有効になるため、別のイメージを配り直すのではなく、その場でアップグレードできます。

## 価格の実態

Obot Community は MIT ライセンスの無償セルフホストです。Obot Cloud はホスト型で、無料で試せます。Obot Enterprise はライセンスキーで、Okta と Microsoft Entra の ID 連携、高度なガバナンス、商用サポートが加わります。この エディションの価格は公開されていません。`obot.ai/pricing` は 404 を返し、enterprise の窓口はデモ申し込みです。

無償ライセンスの読み方を間違えないでください。Obot 自身のインストールガイドによれば、本番環境には PostgreSQL 17 以上、Obot と Obot が動かすすべての MCP サーバーを収容できる本番品質の Kubernetes クラスター、S3 互換のオブジェクトストレージ、TLS 証明書、クラウド KMS キー (AWS、Google、Azure のいずれか)、そしてバックアップ戦略が必要です。この文書化された要件からの当社の見積もりでは、控えめな AWS 構成 (マネージド Kubernetes、PostgreSQL 用の RDS、バケット 1 つ、KMS キー 1 つ) で、MCP サーバー自体を除いて月あたり $400-700 前後に着地します。ライセンスは $0 ですが、アップグレード経路を引き受けるプラットフォームエンジニアは無償ではありません。

## 最適な相手

すでに Kubernetes を運用しており、セキュリティレビューがマネージドの tool-auth を差し止めた企業のプラットフォームエンジニア、または IT エンジニアです。Obot が明確に勝つ限定条件は次のとおりです。40 人が Claude Code と [Cursor](/ja/tools/cursor/) から [Salesforce](/ja/tools/salesforce/) と [Slack](/ja/tools/slack/) の MCP サーバーに接続し、法務が書き込みごとに担当した人間の名前が残るツール単位の監査証跡を求め、同じポリシーでその人たちが呼べるモデルまで制御する必要がある場合です。

## 向かない相手

Kubernetes の運用実績がない 5 人規模のチームです。単一コンテナの Docker イメージは評価用の経路であって配備ではなく、本番で動かすことはホストの Docker ソケットをエージェントのコントロールプレーンにマウントすることを意味します。初日から広さが欲しい場合も Obot は誤った選択です。今週中に 1,000 件の SaaS アプリへ認証付きで書き込むのが目的なら、それを出荷するのは Composio であって Obot ではありません。

## 代替候補との比較

- **Docker MCP Gateway** — このカテゴリで最も広く行き渡っており、オープンソースで、Docker Desktop の MCP Toolkit に同梱され、一般提供は 2025 年後半です。各 MCP サーバーを権限とネットワークアクセスを絞ったコンテナとして実行します。要件が開発者向けの安全なローカル実行であり、全社的なガバナンス要請がないなら、これを選んでください。「どの人間がこれを承認したのか」には全社規模で答えません。
- **[Composio](/ja/tools/composio/)** — 約 1,000 件という最大のマネージドカタログを持ち、認証付きツール呼び出しの単価はこのセグメント最安の $0.0003 です。認証情報の保管より書き込みが動くまでの速さが重いとき、そして誰もトークンを自社で持てとは言っていないときに選んでください。
- **[Arcade](/ja/tools/arcade-dev/)** — 最も成長の速い新規参入で、2026 年 6 月に $60M のシリーズ A、2026 年 8 月 5 日に Smithery を買収しています。既存の IdP に対して、呼び出し時にユーザー単位で認可します。インフラを自前で運用せずにユーザー単位の OAuth が欲しく、認証情報の経路に第三者が入ることを許容できるなら、これを選んでください。

どれも合わないなら、エージェントに必要な MCP サーバーを素のコンテナとして既存の API ゲートウェイの背後で動かし、監査イベントはすでに費用を払っている SIEM に書き出してください。サーバーが 5 台程度以下でチームが 1 つなら、コントロールプレーンは過剰です。

## 注意点

- **ライセンスは無償でも、配備は無償ではありません。** 本番要件には Kubernetes クラスター、PostgreSQL 17 以上、オブジェクトストレージ、KMS、バックアップが並び、クラスターは Obot に加えてホストするすべての MCP サーバーの分まで見積もる必要があります。対策として、パイロットの前にプラットフォームエンジニアを予算に入れ、`/var/run/docker.sock` をマウントする単一コンテナの Docker イメージは評価用ハードウェアだけに留めてください。ここでの現実的な失敗はそのコンテナが本番へ流れ込むことであって、Kubernetes の請求額ではありません。
- **enterprise の SSO はライセンスキーの向こう側にあります。** Okta と Microsoft Entra の連携は Enterprise で提供され、オープンソースのビルドがカバーするのは Google、GitHub、Auth0、JumpCloud です。対策として、パイロットの第 1 週より前にセキュリティレビューがどの IdP を必須とするかを確定し、その時点で enterprise の見積もりを取ってください。パイロットで価値が証明された後に要件を知ると、更新交渉をテーブルの弱い側から始めることになります。
- **結局購入することになるエディションの価格が公開されていません。** 対策として、課金の基準がシート数、サーバー数、ツール呼び出し数のどれなのかを明記した書面の見積もりと、更新時の上限を最初の契約で確保してください。Obot が全社のエージェントの隘路になる前に取ることが肝心です。
- **1.0 未満のソフトウェアが速く動いています。** v0.23.0 は UI を再編し、共有サーバーの定義方法を変え、モデルエンドポイントを追加しました。すべて 2026 年 6 月 18 日の 1 回のリリースです。対策として、`:latest` ではなくイメージのダイジェストを固定し、アップグレードのたびにリリースノートを読み、PostgreSQL のリストアを事前に演習してください。ツールとモデルの両方の前段に立つゲートウェイは、倒れると全社のエージェントを道連れにします。
