Un Claude Skill que escanea cada call de CSM y picos de uso a través de tu base de clientes y saca a la luz señales concretas de expansion: nuevos use cases mencionados, equipos adicionales haciendo onboarding, preguntas de integración sobre features de tier premium y pedidos de capacidades que mapean a tus SKUs de upsell. Deja un digest semanal con una lista ranqueada por CSM.

## Qué necesitas

- Acceso a Gong para calls de CSM (separadas de calls de ventas)
- Gainsight para detección de anomalías de uso
- Claude Code o Claude.ai con el Skill instalado
- Una taxonomía de señales mapeando menciones a SKUs de upsell específicos
- Un destino de Slack o email para el digest semanal

## Setup

1. **Construye la taxonomía de señales.** Edita `references/expansion-signals.md` con cada SKU de upsell y las frases gatillo o patrones de uso que indican intent. Sé específico: no "más usuarios," sino "preguntó por pricing para 50+ seats" o "mencionó requirements de compliance."
2. **Instala el Skill.** Coloca `expansion-signals.skill` en `~/.claude/skills/`. Define `GONG_API_KEY` y `GAINSIGHT_TOKEN`.
3. **Ejecuta semanalmente.** `detect_expansion(window_days=7)`. El Skill escanea cada call de CSM en la ventana más cada pico de uso de más de 30% week-over-week, y luego mapea señales a SKUs y ranquea por potencial de tamaño de deal.
4. **Rutea el digest.** El output va a un canal de Slack `#csm-expansion` y un email a cada CSM con su lista personalizada. Top 3 por CSM, no 30.

## Cómo funciona

Para cada call de CSM, el Skill corre un prompt de extracción: "Encuentra cualquier mención de equipos adicionales, use cases más allá del scope actual, interés en features premium, o metas de negocio declaradas que impliquen expansion." Cada match se loguea con una cita y un score de confianza.

Para uso, jala eventos de uso de Gainsight y encuentra cuentas con picos anómalos — particularmente en features que están limitadas por tier. Una cuenta de tier free que está pegando contra un límite de feature enterprise-only es una señal. Un equipo que acaba de duplicar usuarios activos es una señal.

Claude después sintetiza por cuenta: combina señales de calls con señales de uso, scorea probabilidad de expansion, nombra el SKU más probable, y sugiere una línea de apertura para que el CSM use en la próxima conversación.

## A tener en cuenta

- **Fatiga de señales.** No saques 30 señales por CSM. Ranquea a 3. Cualquier cosa más se ignora.
- **Cobertura de calls de CSM.** Si los CSMs no están logueando calls, la mitad de conversación del set de señales está vacía. Audita la cobertura antes de depender de esto.
- **Señales mal clasificadas.** "Estamos pensando en irnos" puede sonar como "estamos pensando en expandir" para un prompt descuidado. Construye ejemplos negativos en el prompt del Skill.
