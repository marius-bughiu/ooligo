## 何をするツールか

Gorgias は、顧客がすでに何かを購入していることを前提としたヘルプデスクです。すべてのチケットは、注文、返金履歴、サブスクリプション、配送状況の隣に開きます。これらは Shopify、BigCommerce、Magento、WooCommerce、PrestaShop からリアルタイムで読み込まれます。担当者は — 人間でも AI でも — ストア管理画面に切り替えて結果を貼り戻すのではなく、会話の中で注文を返金し、サブスクリプションを編集します。

これがこの製品の主張のすべてであり、このカテゴリが一般的なサポートソフトウェアと別に存在する理由です。[Zendesk](/ja/tools/zendesk/) や [Intercom](/ja/tools/intercom/) の導入環境はアプリ経由でコマースデータに到達しますが、Gorgias はそれをチケットの背骨として扱います。その周囲には、email、チャット、SMS、WhatsApp、Instagram、Facebook を扱う 1 つの受信箱があり、さらに Voice と、購入後チケット向けの Support Agent と購入前の質問向けの Shopping Assistant に分かれる AI Agent があります。Gorgias は 300 以上の連携を掲げ、トップページでは Recharge、Klaviyo、Yotpo、Loop Returns、Bloomreach、Attentive を挙げています。

同社には Shopify が出資しています。2022 年 8 月に評価額 $710M で $30M のシリーズ C を調達し、2024 年 5 月には評価額 $530M で再度調達しました。累計調達額は $100M 超です。Sacra は ARR を 2022 年 $25M、2023 年 $51M、2024 年 $69M とし、前年比 34% の成長としています。

## Customer Success スタックで採用される理由

- **コマースの文脈そのものが製品であり、連携機能ではありません。** DTC ブランドでは、チケットの大半が注文状況、返品、交換、住所変更、サブスクリプションの編集です。いずれもストアに対する「参照 + 操作」です。Gorgias は参照と操作が同じ場所で起きるように作られており、それが自律的な解決を願望ではなく実行可能なものにしています。
- **課金の単位は人数ではなく件数です。** Gorgias の料金ページはこう明言しています。「Helpdesk scales from 50 to 5,000 tickets a month, never priced per agent」。第 4 四半期に向けて担当者を 3 倍にする季節性の高い DTC チームでも、ライセンス費用は 3 倍になりません。
- **AI Agent は成果に対して課金します。** 同じページにこうあります。「AI Agent on every plan, pay only when it resolves a conversation」。会話単位で課金する回避型ボットは失敗に対しても請求しますが、こちらは解決に対して請求します。
- **自社製の MCP サーバー。** Gorgias は自社の MCP サーバーを提供しており、`docs.gorgias.com` に文書化されています。チケットの作成・更新・削除、顧客レコード、タグ付けを [Claude](/ja/tools/claude/) や [ChatGPT](/ja/tools/chatgpt/) に公開します。API クライアントを自作せずに、サポートデータをヘルプデスクの外から照会できます。

## 料金

定価は公開されています。Starter は 50 チケットで月額 $10、Basic は 300 チケットで $60、Pro は 2,000 チケットで $360、Advanced は 5,000 チケットで $900、そして個別見積もりの Enterprise があります。年額契約でおよそ 16% 下がり、Basic $50、Pro $300、Advanced $750 になります。上限を超えたチケットは、Starter と Basic で 1 件 $0.40、Pro と Advanced で $0.36、Enterprise で $0.32 です。AI Agent は別建てで計測され、月額請求で自動解決 1 件あたり $1.00、年額請求で $0.90 です。

プランではなく実際の請求額をモデル化してください。月 3,000 チケットのブランドが Pro 年額なら、$300 に超過 1,000 チケット分の $0.36 を足して、自動化前の時点で $660 です。その 40% を AI Agent に流すと 1,200 件 × $0.90 で $1,080 が加わり、合計で月およそ $1,740 になります。自動化の項目がヘルプデスクの項目を上回り、エージェントの精度が上がるほど大きくなります。この逆転こそ、契約前にモデル化すべき最も重要な点です。

## 最適な利用者

Shopify、BigCommerce、Magento、WooCommerce 上で 2〜40 名の担当者を抱える EC・DTC の顧客体験責任者で、注文状況・返品・サブスクリプションのチケットがキューの大半を占め、現状のコストが担当者によるヘルプデスクとストア管理画面の間のデータ転記になっているケースです。B2B ソフトウェアのサポートには形が合いません。そこではチケットがエンジニアリングの作業になり、注文よりもアカウントが重要だからです。それは [DevRev](/ja/tools/devrev/) や [Pylon](/ja/tools/pylon/) の領域です。

## 注意点

- **2 つのメーターが成功とともに加速します。** チケット超過と AI 解決あたりの課金は、どちらも件数と同じ方向に動き、自動化だけではチケットのメーターは止まりません。ガード: 契約前に、AI Agent が解決した会話がプランのチケットも消費するのかどうかを Gorgias に書面で明示させ、現在の 2 倍の件数で 12 か月を、自動化率 25%、50%、70% の 3 通りでモデル化してください。単一の点ではなく傾きが見えます。
- **見出しの導入実績は、見た目より狭い数字です。** トップページには「We power customer conversations for 40% of Shopify brands」とあります。Sacra の数字は Shopify の*上位 1,500* 事業者の 40% であり、母数が異なり、はるかに小さいものです。ガード: 全体の数字は無視し、自社の注文件数、平均注文単価、カテゴリに近い参照顧客を 3 社出させたうえで、その担当チームに 3 か月目以降に実測の自動化率がどこで落ち着いたかを聞いてください。
- **ベンダーの成果数値は上限であって基準値ではありません。** Gorgias は「60% of inquiries resolved instantly」、Orthofeet は 2 か月未満で自動化率 56%、Pepper は AI 主導の販売接点で 19.2 倍の ROI を公表しています。いずれもポリシーページが整い、カタログが整理されたブランドでの最良ケースです。ガード: 有償パイロットを実施し、自社のチケットで測定した「24 時間以内に人間の返信なしで解決」を契約上の下限として定義し、更新価格をその達成に連動させてください。
- **評価額の調整は公開情報であり、契約条件に反映すべきです。** Gorgias は 2022 年の評価額 $710M から 2024 年には $530M になりました。成長は 34% で続いているため経営難の兆候ではありませんが、更新時の交渉力の所在は変わります。ガード: 再構築できないキューを移行する前に、更新時の値上げ上限と、チケット・マクロ・AI Agent の学習コンテンツを対象とする明示的なデータエクスポート条項を交渉してください。

## 代替候補と、そちらを選ぶ基準

[Zendesk](/ja/tools/zendesk/) と [Intercom](/ja/tools/intercom/) が比較対象になる 2 大既存プレイヤーで、いずれも AI エージェントを解決単位で計測するようになっているため、価格だけでは決着しません。サポートが B2C と B2B にまたがる場合、成熟した管理機能とレポーティングが必要な場合、あるいはストアが会話の中心でない場合は Zendesk を選んでください。プロダクト内メッセージングが主要チャネルで、買い手が買い物客ではなくソフトウェアの利用者である場合は Intercom を選んでください。チケットの大半が注文を見ないと答えられない場合は Gorgias を選んでください。

[Siena AI](https://www.siena.cx) は EC 向け CX 領域で最も成長の速い新規参入で、設計上は逆の賭けをしています。既存のヘルプデスクを置き換えるのではなく、その上に自律エージェントの層を載せる形です。ヘルプデスク自体には問題がなく自動化だけが足りない場合、あるいは年度途中でのプラットフォーム移行を避けたい場合は Siena を選んでください。両方を一度に置き換え、解決の責任を 1 社に持たせたい場合は Gorgias を選んでください。

[Gladly](/ja/tools/gladly/) と [Kustomer](/ja/tools/kustomer/) は、チケットではなく顧客を主たるオブジェクトとして扱います。担当者がおよそ 50 名を超え、リピート購入率が高く、音声の件数が多い場合に効いてきます。それ未満では、個別見積もりの価格と導入期間が見返りを上回ります。そして月 200 チケット未満なら、いずれもまだ答えではありません。共有受信箱と Shopify アプリの組み合わせのほうが、交渉できるどの解決単位のメーターよりも安く済みます。
