RPA と AI エージェントの違いは 1 点だけです。実行経路を誰がいつ選ぶか、です。RPA では人間が構築時に経路を選び、ソフトウェアはそれを永久に同じ形で再生します。AI エージェントでは、あなたが提示したゴールをもとに、モデルが実行時に経路を選びます。コストモデル、障害の出方、監査証跡、変更への耐性は、すべてこの 1 つの違いから導かれます。だからこそ「どちらが優れているか」は誤った問いであり、「このタスクに判断は含まれるか」が正しい問いになります。

AI エージェントは、賢くなった RPA ボット**ではありません**。そして RPA は時代遅れのエージェントでもありません。RPA はいかなる意味でも AI ではなく、古典的なロボットはモデルを一切含みません。それは、すでに保有しているアプリケーションの画面上の UI セレクタ、XPath、object ID に結びついたスクリプトであり、ベンダーが公開している範囲で API 呼び出しを加えたものです。指示した場所をクリックするだけです。一方エージェントには再生すべき固定経路がありません。つまり、想定していなかったケースを処理できる代わりに、承認していないことを実行することもできます。

## この 1 つの違いから何が導かれるか

**変更への耐性は逆方向に働きます。** RPA は画面が変わると壊れます。ベンダーがリリースを出し、クラス名が変わり、セレクタが解決しなくなり、ロボットは停止します。エージェントは同じ UI 変更を生き延びますが、代わりにドリフトします。モデルは新しい画面を読み、もっともらしい何かを判断し、誰もレビューしていない方向へ進み続けます。可視的に壊れるシステムと、不可視のまま曲がるシステムのどちらを取るか、という選択です。

**障害の出方は反転しており、QA の設計も反転します。** 壊れたロボットは例外を投げてキューに落ち、実行数がゼロになることであなたは気づきます。失敗しているエージェントは、完全で整った、自信に満ちた誤った結果を出し、成功として報告します。稼働監視は前者を捉え、後者には盲目です。プロセスを RPA からエージェントへ移しても監視をそのまま残したなら、それは移行ではなく、警報を外しただけです。

**課金単位はキャパシティから消費へ変わります。** RPA ロボットはキャパシティの席としてライセンスされます。作業者を借り、あとは好きなだけ動かせます。エージェントは消費した分だけ課金されるため、複雑化したタスクは誰がライセンスに触れなくても高くなります。予算のブレは、上限を設けない限りゼロから青天井へ変わります。

**監査証跡は作り直しになります。** RPA のスクリプトはそれ自体が監査証跡です。決定論的な再生とは、各実行で何が起きたかをコードが正確に記録しているということであり、規制対象のバックオフィス業務がこれに標準化した理由もそこにあります。エージェントの行動は、ベンダーが行動と並べて推論を記録している場合にのみ再構成できます。行動ログだけでは何が変わったかは分かっても、なぜ変わったかは分かりません。そして「モデルが判断しました」は監査に耐えません。

## コストの計算

Microsoft はこのトレードオフの両側を 1 つの価格表で公開しており、入手できる比較として最も明快です。2026-07-26 時点で確認: Power Automate Premium はユーザーあたり月額 $15 で attended デスクトップフローを含みます。Power Automate Process は unattended デスクトップフロー向けにボットあたり月額 $150、Power Automate Hosted Process は Microsoft 管理の VM 付きでボットあたり月額 $215 です。Copilot Studio は月額 $200 で 25,000 クレジットです。UiPath は Automation Cloud の入門ティアを月額 $25 からとして公開し、unattended ロボットは見積もり対応としています。

unattended ボットのライセンスは固定なので、1 実行あたりのコストは $150 を月間実行数で割った値にすぎません。

- 月 100 実行 → 1 実行あたり $1.50
- 月 1,000 実行 → 1 実行あたり $0.15
- 月 10,000 実行 → 1 実行あたり $0.015

したがって、実案件のサンプルでエージェントの実際の 1 実行あたりコストを測り、それを C とすると、月あたりおよそ `150 / C` 実行を超えたところでボットが勝ちます。1 実行 $0.15 のエージェントは月 1,000 実行で損益分岐し、$0.50 のエージェントは 300 実行で分岐します。その水準を下回れば固定のボットライセンスのほうが高くつき、エージェントの柔軟性はほぼ無償で手に入ります。大きく上回る領域では、同じ決定論的経路をモデルに月数千回も導出し直させることは、すでに下されている判断に実行ごとの料金を払う行為です。

## 判断の仕方

タスクを 2 つの軸で分類します。経路がどれだけ変動するか、そしてどれだけの頻度で走るかです。

- **変動が小さく、量が多い**(請求書入力、ステータス同期、レポート生成): RPA、もしくはより望ましくは API 連携。判断を含まないタスクに判断力を買ってはいけません。
- **変動が大きく、量は少ないか中程度**(例外処理、契約のトリアージ、インバウンドのリサーチ): エージェント。実際に攻めているコストは例外キューです。
- **変動が大きく、量も多い**: エージェントが判断し、ロボットまたは API が実行します。これが後述の組み合わせパターンです。
- **変動が小さく、量も少ない**: どちらも不要です。月に 20 回なら人間がやるほうがどちらのライセンスより安く済みます。

双方のベンダーが飛ばす選択肢があります。対象システムに文書化された API があるなら、UI 層は本来組めるはずの連携を迂回しているだけです。RPA が存在する理由の大半は、企業向けソフトウェアが API なしで出荷されてきたことにあります。フォームに入力させるロボットを借りる前に、そしてより高いコストで同じことをするモデルを借りる前に、API の有無を確認してください。

## 競合するより組み合わさる

2026 年の両陣営のベンダーの立場は、置き換えではなく組み合わせです。UiPath は自社プラットフォームを、Maestro というオーケストレーション層が調整するエージェント、ロボット、人という構成として示し、Agent Builder と Autopilot を併せ、役割分担を「エージェントが考え、ロボットが実行し、人が導く」とまとめています。Automation Anywhere はゴール駆動のエージェント、RPA ボット、API、人間による承認を一体でオーケストレーションする Agentic Process Automation システムを販売しており、2026 年の Gartner Magic Quadrant for RPA でも Leader を維持しました。

これはマーケティングではなく設計パターンとして読んでください。モデルは個々のケースに何をすべきかを判断するのが得意で、同じキー操作を 10,000 回確実に繰り返すのは不得手です。ロボットはその逆です。判断はエージェントに、反復はロボットか API に置き、その間に承認ゲートを挟んでください。

## ベンダーへの診断質問

これらは、本物のエージェントと、前面に言語モデルを置いた RPA 製品とを切り分けます。[Ops 向け AI エージェント](/ja/learn/ai-agent-for-ops/) にある質問群とは別物で、あちらは自律性一般を、こちらは移行判断を試します。

1. **実行経路は構築時に固定されますか、実行時に選ばれますか。** これがすべてです。残りは細部です。
2. **同じ入力を 2 回流したとき、同じ経路になりますか。** 経路が同一なら、買っているのは RPA です。それ自体は妥当な買い物です、RPA の価格であれば。
3. **UI を操作しますか、API を叩きますか。** UI 駆動の製品は、モデルが何をしようと RPA の破損プロファイルを継承します。
4. **課金単位はボット、実行、トークンのどれですか。** 複雑化したプロセスをどの予算が吸収するかが、この答えで決まります。
5. **対象アプリが UI 変更を出したとき、何が壊れ、誰が直しますか。**「何も壊れません」は回答ではありません。画面が一致しなくなったときモデルが何をするのかを聞いてください。

## よくある失敗

**動いている RPA を、RPA が古く聞こえるという理由で置き換える。** 安定した大量・無判断のプロセスを 3 年間走らせてきたロボットは技術的負債ではありません。移行して得られるのは変動と、より高い 1 実行あたりコストです。

*ガード:* 移行するのは、正常系ではなく例外キューに工数が吸われているプロセスだけにしてください。例外が全体の 5% 未満なら、そのロボットは触らないことです。

**エージェントの柔軟性を無料と見なす。** 柔軟性は実行ごとに課金され、複雑なケースは単純なケースより高くつきます。つまり請求額は、エージェントを導入した理由そのものであるケースに正比例して増えます。

*ガード:* 本番投入前にプラットフォーム側でタスクあたりのコスト上限を固定で設定し、30 日後に実トラフィックで 1 実行あたりコストを測り直してください。デモのサンプルで測ってはいけません。

**切り替え後も RPA 時代の監視を続ける。** 実行数と稼働率のダッシュボードは、ハルシネーションを起こしているエージェントを完全に健全と報告します。

*ガード:* 稼働監視を出力のサンプリングレビューに置き換えてください。完了実行のうち一定割合を毎週人間が読み、加えて、エージェントの処理を人間が取り消した頻度を数える差し戻し率を計測します。

**規制対象プロセスで決定論的な監査証跡を失う。** NYC LL 144、EU AI Act、社内 SOX 統制の対象となる Legal Ops や TA のプロセスでは、何をなぜ決めたのかを示す必要があります。

*ガード:* 切り替え前に、参照した入力、適用した規則、エスカレーションした内容を含む構造化された決定記録を要求してください。そして規制対象の区間には決定論的なロボットを残し、その周囲の受付とトリアージをエージェントに担わせてください。
