モダンな AI-native B2B SaaS スタートアップが、Salesforce や HubSpot にデフォルトで頼る代わりに Series A や B で採用するスタックです。各レイヤーは API-first で AI を前提としており、チームの GTM engineers が out-of-the-box で動かすのと同じくらい自分たちでカスタマイズすることを想定しています。ポイントは単一のツールが単体で勝つことではなく、ツール間を流れるデータが、2 人の RevOps チームでも午後のうちに自分たちのモーションに合わせて曲げられる CRM を生み出すことです。

## 各ピースの噛み合い方

- **[Attio](/ja/tools/attio/) は CRM の基盤です。** API-first で、Notion 風のカスタマイズ可能なデータモデル、高速な UI を備えます。他のすべてのツールが読み書きする信頼できる情報源のデータベースです。Plus は $29/user/mo、Pro は $69/user/mo（年額）で、Pro には現在 **Call Intelligence** が同梱されます。これは Zoom、Google Meet、Teams の通話をレコードに直接文字起こしするネイティブレコーダーです。これは Fathom の役割と重なり、スタックの形を変えます（詳しくは後述）。
- **[Clay](/ja/tools/clay/) はデータ + AI のワークベンチです。** [アウトバウンドスタック](/ja/stacks/ai-outbound-prospecting-stack/) と同じ役割（リスト構築、エンリッチメント、スコアリング）を、CRM の宛先を HubSpot や Salesforce ではなく Attio にして担います。Clay の **2026 年 3 月の価格改定** は課金を Data Credits と Actions の 2 つのメーターに分割し、lookup あたりのコストを 50-90% 削減しました。セルフサーブのチームは Launch（$185/mo）か Growth（$495/mo）に落ち着きます。
- **[Claude](/ja/tools/claude/) は横断的な AI サーフェスです。** リード要約、アカウントリサーチ、商談ステージの検証、[QBR プレップ](/ja/workflows/qbr-prep-skill/)、[アクティビティ要約](/ja/workflows/activity-summarizer-skill/)、さらに Attio の API に対して構築するカスタム Skills。他のツールの出力を読み取り、人が書くのではなく編集するドラフトに変えます。
- **[n8n](/ja/tools/n8n/) は連携レイヤーです。** フォーム入力からの webhook → Clay エンリッチメント → Attio へのインサート → Slack 通知。ツール間のフローはすべて、ハードコードされたベンダーコネクタではなく n8n を通ります。Cloud Starter は $20/mo、Pro は $50/mo で、セルフホスティングはソフトウェアコストをほぼゼロに落とし、それを ops 時間と引き換えにします。
- **[Slack](/ja/tools/slack/) は運用サーフェスです。** リードルーティング、ディールアラート、チャーンリスクの警告、競合インテリジェンス。ほとんどの rep は CRM の UI よりも Slack 通知から作業します。
- **[Fathom](/ja/tools/fathom/) は外部ミーティングを録画して要約します。** Attio のミーティングレコードに自動で添付され、トランスクリプトは下流の合成のために Claude が利用できます。CRM sync を備えるのは Business ティア（$25-34/user/mo）です。

## これをスタックにするハンドオフ

価値は 6 つのロゴではなく、そのチェーンにあります。フォーム入力が n8n の webhook に届き、それが Clay のエンリッチメント実行をトリガーし、完成した行を Attio に書き込み、ルーティングしたリードを Slack に投稿します。1 つのイベント、4 つのツール、ループに人は不在です。rep が通話に出ると、Fathom（または Attio Call Intelligence）がそれを取り込み、トランスクリプトを Attio のレコードに載せます。Claude はそのトランスクリプトとアカウントのアクティビティを読み、フォローアップ、QBR デック、ステージ検証ノートをレコードに書き戻します。各矢印は次のアクションをトリガーするイベントであり、だからこそスタックは単に共存するのではなく複利的に効いてきます。

## なぜこの組み合わせなのか

Salesforce と HubSpot は、すでに 1 つ運用している組織にとっては優れた CRM です。2026 年にゼロから始める AI-native チームにとっては、どちらも重く感じられます。機能が多すぎ、サーフェスが多すぎ、単純なことをするのに設定が多すぎるのです。Attio はモデルを反転させます。クリーンなデータモデルを出荷し、すべてを API で公開し、チームをプラットフォームに合わせるのではなく、チームが自分たちのモーションに合う workflow を構築できるようにします。

トレードオフは、あらゆる連携がベンダーサポート付きのコネクタではなく自前の構築になることです。n8n は、大きなエンジニアリング組織を持たないチームにとってこれを扱いやすくする接着剤です。エンジニアリングが厚いチームは、Attio の API に対する自前コードで同じ形を得られます。いずれにせよ、このスタックは CRM を一度設定して終わりの製品購入ではなく、進化するコードベースとして扱うことを前提とします。

## コスト

10-25 seats の GTM チームで、年間おおよそ **$18K-$45K オールインで** 見積もってください。Attio の seats（Plus $29 / Pro $69 ユーザーあたり月額）と Clay（セルフサーブで $2.2K-6K、契約が ~$30K/年 の中央値で走る Enterprise ではそれ以上）が 2 つの最大のレバーです。Claude Team（$25/seat/mo、最低 5 seats）、Fathom（$15-34/user/mo）、Slack（$8.75-15/user/mo）、n8n（$20-50/mo クラウド、またはセルフホスト）はそれぞれ年間数千を足します。レンジが広いのは、Attio と Fathom が seats でスケールする一方、Clay がデータと actions のボリュームでスケールするからです。コミットする前に、この 2 つの Clay メーターを実際のリストサイズに対してモデリングしてください。さもないとこの項目に驚かされます。

## Fathom vs Attio Call Intelligence の判断

Attio の 2026 年の Call Intelligence は Fathom と直接重なります。通話に出る全員がすでに Attio の seat で、Pro の seat あたりコストが許容できるなら、ネイティブ録画はツールを 1 つ減らし、キャプチャを CRM 内に保ちます。CRM 外のユーザー（創業者、CS、パートナー）に録画が必要なとき、ライトユーザー向けに無料の個人ティアが欲しいとき、あるいは要約の品質やプレイリスト・検索の UX が統合よりも重要なときは、Fathom を残してください。名前を挙げられる理由なしに、同じ seats に対して両方を払わないでください。

## よくあるバリエーション

- **アウトバウンド重視のモーション。** [Apollo](/ja/tools/apollo/) と [Outreach](/ja/tools/outreach/) を追加します。全体像は [アウトバウンドスタック](/ja/stacks/ai-outbound-prospecting-stack/) を参照してください。トリガーは、アウトバウンドのボリュームが Clay-から-Attio で手動処理できる範囲を超えたとき。
- **高いディール価値の sales-led。** conversation intelligence のために [Gong](/ja/tools/gong/) を追加します。Fathom と Attio Call Intelligence はトランザクショナルなモーションに対応し、Gong がその価格に見合うのは Enterprise のディール複雑性とコーチングのスケールにおいてのみです。
- **n8n よりコードを好むエンジニアリングチーム。** n8n を、Attio の API に対する TypeScript/Python の自前オートメーションに置き換えます。同じ形、より多くの制御、より多くのメンテナンス。
- **Enterprise スケールで Attio を卒業する。** ops の複雑性が Attio のデータモデルを超えたとき（マルチビジネスユニット、多通貨、複雑な CPQ）、[Salesforce](/ja/tools/salesforce/) への移行が典型的な道です。永遠の選択ではなく Series D のイベントとして計画してください。

## このスタックが正しい選択になるとき、ならないとき

Series A-B の AI-native 企業の創業者または RevOps リーダーで、CRM をゼロから始め、admin にチケットを切るより workflow を構築するのを楽しむ人が少なくとも 1 人いるとき、これを選んでください。それがこのスタックの重心です。

以下のいずれかが当てはまるなら見送ってください。すでに Salesforce や HubSpot を動く process とともに運用しているなら、リップ・アンド・リプレースが割に合うことはめったにありません。代わりに、今あるものの上に Clay と Claude を重ねてください。チームの誰も n8n と API の接着剤を所有しないなら、自前構築の前提が崩れ、HubSpot のようなオールインワンの方が役立ちます。そして初日から CPQ、多通貨、重いテリトリー管理が必要なら、Attio は誤った基盤です。最終的にたどり着く場所から始めてください。

## このスタックが置き換えないもの

- 複雑な価格設定のための CPQ — Attio はそれを装いません。
- ABM プラットフォーム — そのモーションは [ABM スタック](/ja/stacks/abm-revenue-stack/) を参照してください。
- スケールでの customer success プラットフォーム — [customer success 拡張スタック](/ja/stacks/customer-success-expansion-stack/) を参照してください。
- 高ボリュームのナーチャー向けの marketing automation プラットフォーム（Marketo、HubSpot Marketing）— Attio はセールス側であり、GTM 全体ではありません。
