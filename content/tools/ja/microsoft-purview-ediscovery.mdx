## 概要

Microsoft Purview eDiscovery は、Microsoft 365 に組み込まれた特定・保全・収集・レビュー・エクスポートのためのツール群です。Exchange Online、SharePoint、OneDrive、Teams、Microsoft 365 Groups、Viva Engage をデータが置かれている場所のまま検索し、それらのロケーションに hold をかけ、第三者プラットフォームへ事前にコピーすることなく結果をエクスポートします。多くの企業法務チームにとって、これはすでに購入済みの eDiscovery です。

2025年8月31日、Microsoft はクラシック版のすべての体験、つまりクラシック Content Search、クラシック eDiscovery (Standard)、クラシック eDiscovery (Premium) を廃止しました。置き換えたのは Purview ポータル上の単一の Cases 一覧で、標準の挙動と premium の挙動が並んで存在し、別製品ではなく設定によって分かれています。用語も一緒に変わりました。custodian は data source になり、case が組織化の単位になりました。collection は検索内の Statistics になり、job は process になり、advanced indexing は custodian ごとに実行する再インデックスではなく、検索・add-to-review-set・エクスポートのたびに just-in-time で走ります。

runbook に「custodian を追加し、collection を実行し、job を確認する」と書いてあるなら、それはもう存在しない製品を説明しています。

## 単一の Cases 一覧が隠しているライセンスの線

一覧は 1 つ、製品は 2 つです。検索、KeyQL クエリ、statistics と sample、hold、search-and-delete、ロールベースの権限、case 管理、検索結果のエクスポートは E3 に含まれます。これをレビュープラットフォームにしている部分はすべて premium の壁の向こう側です。review set、advanced indexing、analytics（近似重複検出、email threading、themes）、OCR、復号、conversation threading、タグ付け、外部データのインポート、ゲストレビュアーのアクセス、Security Copilot、Graph の app-only 認証がそれにあたります。

購入側が読み違えるのはこの壁です。premium 機能のライセンスは**分析する側の人間ではなく、データを分析される側の人間**に対して必要になります。ある従業員のメールを review set に取り込むには、その従業員自身が Office 365 E5 または Microsoft 365 E5 を持っている必要があります。E1/E3 の場合は Microsoft Purview Suite（旧 Microsoft 365 E5 Compliance）または Microsoft 365 eDiscovery and Audit アドオンのライセンスが必要です。E3 テナントで法務チーム全員にライセンスが割り当たっていても、case を開き、検索を実行し、hold をかけたうえで、肝心の custodian に対する review set は作れません。

## 価格

- **Microsoft 365 E3 — 1 ユーザーあたり月額 39 ドル**、年間契約・年払い。検索、hold、エクスポートを買えます。
- **Microsoft 365 E5 — 1 ユーザーあたり月額 60 ドル**、同条件。そのユーザーのデータに対する premium 機能を買えます。
- **Microsoft Purview Suite — 1 ユーザーあたり月額 12 ドル**を E1/E3 に追加し、全員を引き上げる代わりに一部の人だけ premium の挙動を有効にします。2,000 席の E3 テナントで恒常的な custodian が 60 人なら年間およそ 8,600 ドルで、テナント全体を E5 に上げる 1 ユーザーあたり月額 21 ドルの差額、年間およそ 504,000 ドルと比較することになります。
- **従量課金 — 1 GB あたり月額 20 ドル**。Microsoft 365 以外の AI アプリケーションデータ（Copilot in Fabric、Security Copilot、接続済みおよびクラウドの AI アプリ）を review set に追加、またはエクスポートした場合に発生します。このメーターには Azure サブスクリプションの紐付けが必要で、24 時間ごとに課金計算され、**クローズ済み**の case でも回り続けます。メーターから外れるのは case を削除したときだけです。Microsoft 365 のデータと Microsoft 365 Copilot のデータはサブスクリプションに含まれ、計測されません。
- **Graph の eDiscovery API** は E3 テナントにも開放されており、月 50 GB のエクスポートが無償枠として含まれます。課金対象はエクスポート呼び出しだけです。

## in-place の discovery で足りなくなる地点

Purview が収集・保全できるのは Microsoft が保持しているデータです。その先の上限は具体的です。review set からの 1 回のエクスポートは 500 万ドキュメントまたは 500 GB のいずれか小さい方が上限、テナント全体では premium 機能ありで 1 日 5 TB、なしで 2 TB。メールボックスのエクスポートは 1 メールボックスあたり毎時 2 GB で進み、7 日を過ぎても終わらない process はキャンセルされます。advanced indexing は毎時 2 GB が上限、150 MB を超えるファイルはインデックスされず、OCR は 24 MB で止まります。

スループットの数字の裏には、さらに硬い壁が 2 つあります。

**Microsoft 365 以外のデータ。** Slack、Bloomberg、モバイルメッセージのアーカイブが eDiscovery に届くのは、有償のサードパーティコネクタ（17a-4 の DataParser など）を通した場合だけです。これらはアイテムをメールとして Exchange のメールボックスに書き込み、Purview がネイティブコンテンツとして扱えるようにします。review set への外部データインポートは収集ではなく手動アップロードです。フォレンジックイメージやデバイス収集には経路自体がありません。

**プロダクション。** Bates 番号付与も、墨消しツールも、privilege log の生成もありません。弁護士・依頼者間秘匿特権の検出は、こちらが渡した弁護士リストと突き合わせて特権の可能性が高い文書にフラグを立てるだけで、特権レビューの代替にはならないと Microsoft 自身のドキュメントが明記しています。案件がプロダクションに達した時点で、エクスポートはレビュープラットフォームへ出ていきます。

## こんなチームに向く

証拠が Microsoft 365 に置かれている E5 組織の企業法務オペレーションと訴訟サポートです。労務関連の請求、社内調査、召喚状や規制当局への対応、中規模の民事案件の初期評価が対象になります。収集と絞り込みのレイヤーであって、プロダクションを出す土台ではありません。

## 代替候補

- **[Relativity](/ja/tools/relativity/)** — 外部法律事務所が案件を回している場合、データがすでにそこにある場合、あるいは数百万ドキュメント規模でプロダクション、Bates、privilege log が必要な場合。
- **[Everlaw](/ja/tools/everlaw/)** — レビューチームが現行世代の UI と、ホスティングパートナーを挟まずに見積もれる GB 単価のホスティングを求める場合。
- **[DISCO](/ja/tools/disco/)** — 案件単位で課金されるクラウドネイティブなレビューと、Relativity の導入サイクルより短い「収集から first-pass coding まで」の経路が欲しい場合。

案件が Microsoft 365 から出ず、収集量が数百 GB 前半にとどまり、データを外に出すよりその場で保全するほうが有利なときは、この 3 つより Purview を選んでください。

## 注意点

- **premium ライセンスはレビュアーではなく custodian に付いてくる。** ガード：case で premium 機能を有効にする前に、case のメンバーではなく data source 側のライセンスを確認し、eDiscovery and Audit アドオンのライセンスをプールとして確保して、review set が失敗してからではなく収集の前に割り当てます。
- **case をクローズしても従量課金のメーターは止まらない。** ガード：エクスポートしてから削除する手順を案件クローズの明示的なステップにするか、Microsoft が公開している `ItemClass` の KeyQL フィルターで Microsoft 365 以外の AI データを検索時点で除外します。
- **hold 通知と受領確認のトラッキングは無くなった。** 現在のフローはトリガーイベント、case、検索、hold、レビュー、エクスポートの順で、custodian communications と Communications library は廃止されたクラシック版に属していました。ガード：通知と受領確認は [Exterro](/ja/tools/exterro/) や Relativity Legal Hold のような専用の legal hold ツールで運用し、その受領確認の連鎖をシステム側の hold とは別に文書化します。
- **case のデータはテナントと一緒に移動しない。** ガード：Advanced Data Residency による移設や商用から GCC への移行の前に、review set をエクスポートし、検索結果をダウンロードし、hold の構成メンバーを記録しておきます。移設前に作成された case は移行先テナントからは到達できず、in-place の移行経路は存在しません。

関連する読みもの：discovery のライフサイクル上の位置づけは [EDRM モデル](/ja/learn/edrm-model/)、システム側の hold の周辺で何が必要かは [legal hold のプロセス](/ja/learn/legal-hold-process/) を参照してください。
