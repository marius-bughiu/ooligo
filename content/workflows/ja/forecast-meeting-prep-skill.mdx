営業マネージャーが週次の予測会議を準備するには、どの商談が動き、担当者に何を聞くべきかを把握する必要があります。このダウンロードは、1人の担当者について日付の異なる CSV スナップショット2件を比較します。カテゴリ別の金額、変更した商談 ID、各変化に対応する質問を含む Markdown のブリーフィングを出力します。まず架空の例で、データからどこまで判断できるか確認してください。[パッケージ一式をダウンロード](/artifacts/forecast-meeting-prep-skill.zip)。

## 架空の例を実行する

ZIP を1つのディレクトリに展開します。`forecast.py` があるディレクトリでターミナルを開いてください。実行には Python 3.9 以降と標準ライブラリを使います。サンプルで使うベンダーアカウント、API 呼び出し、モデルトークンはいずれも0です。

```sh
python3 forecast.py demo
```

デモは `examples/pipeline-2026-10-16.csv` と `examples/pipeline-2026-10-23.csv` を読み、ブリーフィングを生成して、同梱された期待結果のテキストと比較します。一致するとレポートを表示します。入力検証やサンプルファイルでエラーが発生すると、終了コード2と診断内容を返します。実行前に結果を確認することもできます。[期待されるブリーフィング](/artifacts/forecast-meeting-prep-skill/examples/expected-briefing.md)。

各スナップショットには `REP-F01` の架空の商談が4件あります。2週間を通して異なる ID は5件です。commit は **30,000 USD から50,000 USD** に増え、best case は58,000 USD から30,000 USD に減り、upside は20,000 USD から32,000 USD に増えます。オープンなパイプライン全体の増加は4,000 USD です。commit の20,000 USD の変化にはカテゴリ間の移動が含まれます。

Pine Mill（`D-101`）は best case から commit に移り、金額は48,000 USD から50,000 USD に増え、クローズ日は11月6日から11月20日に変わります。修正後の日付を誰が確認したか質問してください。Cedar Loom（`D-102`）は commit を離れますが、今回のエクスポートには残っています。Maple Ferry（`D-104`）は今回のファイルにありません。受注または失注と評価する前に CRM の状態と抽出範囲を確認してください。Fern Desk は変わらず、Amber Finch は今回のファイルに初めて現れます。

## 許可された自社のエクスポートを比較する

同じ担当者のオープンなパイプライン全体を含むスナップショット2件を使ってください。両方の日付で商談 ID を維持します。アカウントの表示名が変わっても ID で照合します。両方に同じフィルタ、通貨、[予測カテゴリの定義](/ja/learn/forecast-categories-explained/)を適用してください。気づかないうちにフィルタが変わると実際のパイプライン移動に見えるため、抽出担当者が調査する必要があります。

```sh
python3 forecast.py compare prior.csv current.csv
```

`README.md` に8列の仕様があります。プログラムは列順の入れ替えに対応し、欠落、追加、重複のあるヘッダーを拒否します。各ファイルの全行で担当者と日付が同じであること、両ファイルの担当者が同じであること、今回のスナップショットが前回の1〜10日後であることを確認します。この期間は週次会議用のサンプル方針です。1週抜けた場合は、比較可能な新しい組み合わせを用意してください。

カテゴリには `commit`、`best_case`、`upside` のいずれかを使います。小数点以下2桁までの0以上の USD 金額と ISO 形式のクローズ日を渡してください。プログラムはセント単位の整数を合計して金額を正確に保持します。ID の重複、非対応通貨、不正な行、空のスナップショット、無効な日付があると比較を停止します。空のエクスポートからは担当者も日付も確定できないため、別途原因を確認してください。

## 担当者とブリーフィングを確認する

カテゴリ別の金額を読んでから、変更した各 ID を2つのレコードに照合します。新しい ID には登場理由を尋ね、消えた ID には状態と抽出範囲の確認を促します。カテゴリ、金額、クローズ日、アカウント名の変化に応じて固定の質問を選びます。変化のない件数は動きの少ない週の照合に使えます。出力には観測した項目と質問が含まれます。顧客側の事情は担当者が補い、提出する予測はマネージャーが判断します。

`references/01-briefing-format.md` で出力の各節を確認できます。`references/02-question-library.md` は項目の変化に応じた質問の選び方を説明します。`references/03-deal-deepdive-template.md` は、会議後に確認した背景、担当者、次回確認日を記録するワークシートです。このシートを編集しても計算済みの合計は保持されます。プログラムは英語のブリーフィングを出力します。

アシスタントからプログラムを呼び出す場合は、[Claude](/ja/tools/claude/) 用の `SKILL.md` が同梱されています。展開した一式をプロジェクト内の `.claude/skills/forecast-meeting-prep/` にコピーし、許可された入力パスを指定して `/forecast-meeting-prep` を呼び出してください。実際の商談を渡す前に処理環境を確認します。架空の例全体はローカルの Python コマンドだけで実行できます。[Claude Code のスキル設定](https://code.claude.com/docs/en/skills)。

## Salesforce 接続は別に実装する

[Salesforce](/ja/tools/salesforce/) アダプターでは、要求元を認証し、パイプラインの読み取りやエクスポートの前に、その人の担当者、レコード、項目に対する権限を適用する必要があります。サービスアカウントは自身の権限で動きます。要求元マネージャーのアクセスをアダプターで明示的に検証し、本番エクスポートを有効にする前に、許可される利用者と拒否される利用者の両方を試してください。スナップショットのスケジュール、保存先のアクセス、保持期間の責任者も決めます。CSV の `rep_id` は提供されたデータ内の整合性を確認するものです。ファイルの読み取りだけで、誰が元のデータを抽出したかは確認できません。[Salesforce のアクセスガイド](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html)。

## このサンプルが適する場合

2つのエクスポート間の変化を継続的に話し合うなら、このワークフローを選んでください。商談が少なく、マネージャーがすでに全変更を追える場合は、表計算のピボットと手書きメモが比較の基準になります。より広い確認には[パイプラインレビュープロンプト集](/ja/workflows/pipeline-review-prompt-pack/)、承認済みの予測にコメントを書く場合は[予測ナラティブのワークフロー](/ja/workflows/forecast-narrative-skill/)を使ってください。予測精度、確率の推定、顧客との通話内容の解釈には、この2ファイル以外の根拠が必要です。

試行では、入力の修正、マネージャーが採用した質問、未解明の変化、準備と確認に費やした時間を記録してください。本番エクスポート、保存、アシスタントの費用は別に記録します。削減効果を示す前に、同じ会議範囲で現行の手順と比較してください。
