Un Claude Skill qui ingère les dix derniers appels Gong d'un AE et produit une note de coaching dans une forme fixe trois-choses-qui-marchent / deux-choses-à-resserrer / un-exercice-spécifique. Conçu pour les managers qui souhaitent un coaching hebdomadaire constant mais n'ont pas dix heures par semaine à consacrer à réécouter des appels. Le skill rédige le brouillon ; le manager édite, contextualise avec le signal hors-appel, et livre lors du prochain one-on-one. L'envoi automatique est explicitement hors périmètre.

## Quand utiliser

Vous êtes un manager commercial avec 4 à 10 AE en direct report. Vous voulez que chaque commercial reçoive la même profondeur de coaching chaque semaine, pas seulement les plus bruyants avec des deals compliqués. Vous avez Gong, votre équipe a une rubrique d'appel, et vous pouvez dégager trente minutes par semaine par commercial pour réviser et éditer le brouillon. Le skill compresse la boucle « écouter dix appels + prendre des notes + structurer le feedback » de ~3 heures par commercial à ~30 minutes.

Utilisez-le hebdomadairement. Quotidien, c'est trop (aucun commercial ne change de comportement en 24 heures). Mensuel, c'est trop rare (les appels cités sont périmés et les patterns plus difficiles à mémoriser). La livraison le vendredi après-midi est le bon moment — l'AE a le week-end pour absorber sans que ça empiète sur sa journée de vente.

## Quand NE PAS utiliser

- **Plans d'amélioration des performances, processus RH formels, décisions de rémunération, ou documents de licenciement.** C'est une note de coaching, pas un dossier personnel. Les PIP nécessitent l'implication des RH, une reconnaissance signée, et un niveau de défendabilité que ce Skill n'est pas conçu pour atteindre. Le fichier `references/03-escalation-criteria.md` du bundle d'artefact définit les signaux binaires qui sortent un commercial entièrement du chemin de coaching.
- **Un commercial que vous ne managez pas directement.** Le Skill vérifie le manager-of-record dans Gong et refuse s'il n'y a pas de correspondance. Une sortie par le mauvais manager exposerait un contenu d'appel que l'invocateur ne devrait pas voir — le mode d'échec à impact le plus élevé que ce Skill pourrait permettre s'il n'était pas sécurisé.
- **De tout nouveaux commerciaux en rampe pendant leurs 30 premiers jours.** Le coaching en rampe est sa propre conversation : shadowing, jeux de rôle, scoring de certification. Une note hebdomadaire scorée sur une rubrique à partir de dix appels minces produit du bruit. Attendez que le commercial ait trois semaines de volume réel d'appels clients.
- **Une semaine avec moins de trois appels utilisables.** Le Skill renvoie `Insufficient call data` plutôt que de rembourrer. Deux appels n'établissent pas un pattern ; prétendre le contraire est du biais rétrospectif recyclé en markdown.

## Configuration

1. **Déposez le bundle.** Le Skill complet se trouve dans `apps/web/public/artifacts/ae-rep-coaching-skill/SKILL.md` avec trois modèles de référence. Copiez le répertoire dans `~/.claude/skills/ae-rep-coaching/` (ou le `.claude/skills/` au niveau de votre projet d'équipe) pour que Claude Code le détecte.
2. **Authentifiez Gong.** Clé API avec accès en lecture aux appels et transcriptions de l'AE. Le Skill respecte le modèle de permission de Gong ; si les appels de l'AE sont restreints, le Skill ne peut pas les voir, ce qui est le comportement correct.
3. **Remplacez les modèles par vos vrais artefacts.** Le bundle est livré avec trois fichiers de référence génériques. Chacun est générique jusqu'à ce que vous le remplissiez avec le contenu réel de votre équipe :
   - `references/01-coaching-rubric-template.md` — votre rubrique par type d'appel (découverte, démo, négociation, closing). Le pilote est livré avec cinq critères par type comme forme de départ.
   - `references/02-coaching-note-format.md` — la forme Markdown exacte qu'utilise chaque note hebdomadaire. Le format fixe est délibéré pour que l'AE repère ce qui a changé d'une semaine sur l'autre.
   - `references/03-escalation-criteria.md` — les signaux binaires qui amènent le Skill à refuser d'écrire une note de coaching et à faire remonter un flag de conversation sur la performance à la place.
4. **Définissez l'ID du commercial et la plage de dates.** Par défaut, les dix derniers appels ou les quatorze derniers jours, selon ce qui est le plus court. Limitez la fenêtre à trente jours ; des appels plus anciens reflètent une version différente du commercial.
5. **Décidez de la cadence et du canal de livraison.** Hebdomadaire, vendredi après-midi, dans le prochain 1:1 ou en DM que l'AE peut lire avant le 1:1. Obtenez l'accord de l'AE sur le canal avant que la première note n'arrive à froid.

## Ce que le skill fait réellement

Six étapes, dans l'ordre, sans parallélisation :

1. **Vérifiez le manager-of-record.** Refus ferme si l'utilisateur invocateur n'est pas le manager direct du commercial dans Gong.
2. **Extrayez les appels récents** filtrés par durée (≥5 min), nombre de participants (≤5 externes) et qualité audio. Arrêtez si moins de trois appels utilisables.
3. **Classifiez chaque appel** comme découverte / démo / négociation / closing. La classification par appel (pas une hypothèse globale) est le choix d'ingénierie qui prévient le mode d'échec précoce le plus bruyant : appliquer une rubrique de découverte à un appel de négociation.
4. **Scorez par rapport à la section de rubrique correspondante** avec une citation de transcription par score. Pas de score sans citation — ce garde exclut les retours intuitifs déguisés en analyse.
5. **Effectuez la vérification d'escalade** par rapport à `03-escalation-criteria.md`. Si un critère se déclenche (représentation erronée des tarifs, ton hostile, promesses de deal parallèle, etc.) le Skill s'arrête et renvoie le bloc d'escalade au lieu de la note de coaching.
6. **Agrégez en trois / deux / un** avec un rendu à format fixe. Les patterns nécessitent ≥2 appels de support chacun ; le Skill renvoie un seul « à resserrer » au lieu de deux quand un seul est supporté. Ne rembourre jamais.

L'exercice en fin de note est la sortie la plus importante. « Améliorer la découverte » est inutile. « Sur vos trois prochains appels de découverte, posez la question budgétaire avant la vingtième minute » est actionnable, observable dans Gong la semaine suivante, et auditable. Le Skill est fortement incité à rendre l'exercice concret et mesurable.

## Réalité des coûts

Par note de coaching (un commercial, dix appels, ~10 000 tokens de transcription par appel après filtrage, Claude Sonnet 4.5) :

- ~120 000 tokens d'entrée (transcriptions + rubrique + format + référence d'escalade) → ~0,36 USD aux tarifs Sonnet actuels.
- ~2 000 tokens de sortie (la note elle-même) → ~0,03 USD.
- **~0,40 USD par commercial par semaine, 1,60 USD par commercial par mois.**

Pour un manager de huit commerciaux, c'est ~13 USD/mois en coût de tokens.

Temps économisé par manager par semaine : environ 2,5 heures par commercial se compressent à 30 minutes (révision + édition). Pour huit commerciaux, c'est ~16 heures récupérées par semaine. Le plancher réaliste est plus proche de ~10 heures récupérées une fois que vous comptez le temps de 1:1 supplémentaire passé à discuter de la note avec chaque commercial — ce qui est précisément le but.

Le coût Gong n'est pas incrémental ; si vous avez déjà Gong (la dépendance dure du Skill) l'accès API est inclus.

## Métrique de succès

Suivez un seul chiffre pendant un trimestre : **pourcentage de 1:1 hebdomadaires où l'AE fait référence spontanément à l'exercice de la semaine précédente.** Si ce chiffre n'est pas au-dessus de 50 % à la semaine 6, les exercices ne sont pas assez spécifiques — revenez resserrer le libellé dans `02-coaching-note-format.md` pour que « exercice » ne puisse pas se réduire à « conseil général ».

Signaux secondaires (plus lents, plus bruités) : évolution du taux de closing sur le type d'appel spécifique sur lequel le commercial est coaché, temps de rampe pour les nouveaux commerciaux une fois la boucle établie, qualité des 1:1 évaluée par le manager.

## Par rapport aux alternatives

- **Notes rédigées manuellement par le manager from scratch.** Meilleure fidélité si le manager le fait vraiment. Le problème est la cohérence : sous pression, les notes rédigées par le manager sautent une semaine, se réduisent à « bon travail, continuez », ou sont rédigées pour le commercial avec le deal problématique pendant que les performeurs constants ne sont pas coachés. Le Skill ne produit pas de meilleures notes qu'un excellent manager avec un temps infini ; il produit de meilleures notes que ce même manager sous une charge réaliste.
- **Scorecards intégrées et fonctionnalités de coaching de Gong.** Gong score les appels individuels par rapport à une rubrique et fait remonter les tendances agrégées. Utile, complémentaire, et moins cher que ce skill si vous avez seulement besoin du scoring. Ce qu'il ne fait pas bien, c'est de synthétiser à travers les appels dans la forme trois / deux / un avec un exercice spécifique. Vous pouvez empiler : utilisez les scorecards Gong pour le scoring par appel, utilisez ce Skill pour la synthèse hebdomadaire.
- **Membrain, Spekit ou autres plateformes dédiées au coaching commercial.** Configuration plus lourde, licence supplémentaire, capacités plus larges (bibliothèques de compétences, parcours d'apprentissage). La bonne réponse pour les grandes organisations commerciales enterprise avec des effectifs enablement dédiés. La mauvaise réponse pour un seul manager commercial qui veut juste des notes hebdomadaires qui ne mangent pas le vendredi.
- **Statu quo.** « Je m'occuperai du coaching après la revue de pipeline. » La revue de pipeline n'est jamais terminée.

## Points de vigilance

- **Amplification des biais.** Le scoring de rubrique sur les transcriptions peut encoder les biais du reviewer — les commerciaux verbeux scorent plus haut sur « rapport », les locuteurs non natifs de la langue scorent moins bien sur « flux de découverte », les commerciaux avec des clients plus bruyants scorent plus haut sur « demander une réaction » même quand le commercial n'a rien fait. Garde : chaque score nécessite une citation de transcription, pas un ressenti ; la rubrique est revue trimestriellement avec toute l'équipe plutôt qu'entretenue par un seul manager en isolation ; le Skill avertit quand la rubrique a plus de 90 jours. Voir `apps/web/public/artifacts/ae-rep-coaching-skill/references/01-coaching-rubric-template.md`.
- **Fuite de données par le mauvais manager.** Un manager extrait une note de coaching sur un commercial qu'il ne manage pas et se retrouve à lire du contenu d'appel qu'il ne devrait pas voir. Garde : l'étape 1 du Skill vérifie le manager-of-record par rapport au modèle de permission de Gong avant que toute transcription ne soit chargée. Refus ferme sur non-correspondance — pas de sortie partielle, pas de suggestion de contournement.
- **Rubrique périmée.** Une rubrique rédigée il y a 18 mois pour la découverte cold outbound appliquée aux démos inbound product-led d'aujourd'hui produit des retours non pertinents que l'AE arrête tranquillement de lire. Garde : chaque fichier de rubrique porte une date `last_edited` ; le Skill préfixe un avertissement à la note de coaching quand la section de rubrique correspondante a plus de 90 jours, et une revue trimestrielle de la rubrique fait partie du plan de déploiement, pas en option.
- **Calibration du ton.** Les notes de coaching qui ressemblent à un avertissement écrit sont ignorées ou font monter la tension dans la relation. Garde : le Skill impose une voix de « pair de confiance » dans `02-coaching-note-format.md`, la vérification d'escalade à l'étape 5 sort les signaux de conversation sur la performance entièrement du chemin de coaching, et le plan de déploiement prévoit de tester le ton avec l'un de vos meilleurs AE avant d'en envoyer un à froid.
- **Dépendance au manager-of-record.** C'est un outil pour le manager, pas un remplacement. La sortie est un brouillon. Le manager édite, contextualise avec les observations hors-appel (historique des 1:1, stade de rampe, contexte de deal que l'appel n'a pas montré), et livre en personne. L'envoi automatique n'est intentionnellement pas dans le bundle.

## Stack

- **Gong** — source d'appels, couche de transcription, vérification du manager-of-record, scorecards par appel optionnelles comme couche complémentaire
- **Claude (Sonnet 4.5 ou supérieur)** — scoring de rubrique, vérification d'escalade, synthèse dans la forme trois / deux / un
- **Rubrique de coaching, format de note, critères d'escalade** — les trois fichiers de référence dans `apps/web/public/artifacts/ae-rep-coaching-skill/references/` qui transforment un générique « scorez cette transcription » en une boucle de coaching que votre équipe possède vraiment
