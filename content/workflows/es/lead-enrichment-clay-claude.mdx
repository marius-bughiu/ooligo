Un Claude Skill que aumenta una tabla de Clay con tres columnas de IA: resumen de empresa, score de fit de ICP con justificación, y un opener personalizado para email frío. Conéctalo a cualquier tabla de Clay que tenga una columna `domain`, ejecuta, empuja a HubSpot.

## Qué necesitas

- Cuenta de Clay (plan Starter o superior)
- API key de Claude (o Claude.ai con el Skill importado)
- Una tabla de Clay con una columna `domain` poblada
- Un documento de rúbrica de ICP (opcional pero altamente recomendado)
- HubSpot (o cualquier CRM con el que Clay haga sync) como destino

## Setup

1. **Agrega el Skill.** Pon `lead-enrichment.skill` en tu proyecto de Claude.ai, o en `~/.claude/skills/` para Claude Code. El Skill expone tres funciones invocables: `summarize_company`, `score_icp_fit`, `write_opener`.
2. **Conecta tres columnas de IA en Clay** referenciando el Skill:
   - `summary` — input: `domain`. Output: resumen de empresa de 2 oraciones.
   - `icp_fit_score` — input: `domain` + rúbrica de ICP. Output: score 1-10 + justificación de 1 línea.
   - `opener` — input: `domain` + `summary` + noticias recientes. Output: opener de email frío de un párrafo, menos de 50 palabras.
3. **Configura el destino.** En Clay, configura la tabla para empujar filas enriquecidas a HubSpot vía la integración nativa. Mapea `summary` → propiedad custom, `icp_fit_score` → propiedad custom, `opener` → variable de sequence de first-touch.
4. **Ejecuta sobre una muestra de 20 filas.** Revisa la precisión. Ajusta la rúbrica de ICP si los scores no se sienten bien.
5. **Ejecuta a escala.** Cadencia recomendada: semanal para leads recién importados, diaria para segmentos de alta prioridad.

## Cómo funciona

El Skill toma un domain y ejecuta tres sub-tareas en secuencia:

1. Trae la homepage + página about de la empresa (Claude con tool de web fetch, o columna HTTP de Clay upstream).
2. Extrae: industria, señales de tamaño (employee count de fuentes públicas), value proposition, noticias recientes.
3. Genera los tres outputs en una única respuesta estructurada.

Para el scoring de fit de ICP, el Skill acepta una rúbrica opcional — pasa los criterios de "cliente ideal" de tu equipo como texto — y devuelve tanto un score 1-10 como la justificación, para que los reps puedan verificar o sobrescribir.

## A tener en cuenta

- **Calidad de los datos fuente.** Domains que no resuelven, parked domains o sitios con contenido pobre producen outputs más débiles. Corre la columna de validación de domain de Clay upstream.
- **Costo.** Cada fila dispara ~3 llamadas a Claude. Con el pricing de Sonnet, menos de un centavo por fila, pero a 100K filas el presupuesto importa. Usa la Anthropic Batch API para runs de enriquecimiento no urgentes (~50% de descuento).
- **La rúbrica de ICP es el punto de apalancamiento.** Una rúbrica vaga ("buen fit B2B SaaS") produce scores vagos. Rúbrica precisa → scores precisos. Itera la rúbrica mensualmente.
- **Variabilidad del opener.** La columna de opener necesita guardrails — establece un largo máximo, exige una referencia a algo específico (un lanzamiento de producto reciente, una contratación pública), y prohíbe los superlativos. Sin guardrails, los openers derivan hacia adulación genérica.

## Stack

- **Clay** — enriquecimiento + sustrato de orquestación
- **Claude** — inferencia de columnas de IA; el Skill es la interfaz reutilizable
- **HubSpot** — CRM destino (Salesforce, Attio, etc. funcionan igual)
