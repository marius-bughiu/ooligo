人身傷害案件のファイル — 診療記録、請求明細、休業損害の資料、警察報告書、事務所の案件メモ — を、和解のためのデマンドレター（demand letter）の初稿に変換する Claude Skill です。各エントリの背後にファイルのページ引用を付けた日付入りの医療クロノロジーを構築し、請求書から特別損害（special damages）を項目化し、事務所の乗数 playbook から一般損害（general damages）のレンジを算出し、事務所のテンプレートからレターを組み立てます。ドラフト内のすべての数値はソースページに遡れます。記録が裏付けない主張はすべて、レターに書かれるのではなく「データ不足」の下にリスト化されます。弁護士が編集し署名します。この skill は最終的なデマンド金額を決して設定せず、決して送信しません。

**弁護士のレビューは必須です。** この skill はドラフトを作成します。法律業務を行うものではありません。算出する一般損害のレンジは、事務所独自の playbook 上の計算であり、法的評価ではありません。弁護士がデマンド金額を設定し、引用された各事実を記録と照合して確認し、送付されるレターに責任を負います。

## 使うとき

- パラリーガルがデマンドパッケージを組み立て、6〜12 ページのレターが記録レビューに加えて 3〜6 時間の作成を要する、原告側の人身傷害事務所。ボトルネックは最初のドラフトであって、法的判断ではありません。
- 事務所が書面化されたデマンドレターのテンプレートと損害算定の方法論（傷害の重症度別の乗数バンド、または日額）を持っている。skill は事務所の方法を軸にドラフトを構造化します。方法を発明することはしません。
- 記録がすでに収集され、テキストに変換されている（OCR 済み PDF、または記録取得のエクスポート）。skill は存在する記録からドラフトを作成します。欠落した請求書を追いかけることはしません。

## 使わないとき

- **デマンド金額の設定。** skill は乗数 playbook からレンジを出力します。金額は弁護士が設定します。数値は、法廷地、アジャスター、責任の強さ、skill がモデル化しない保険のポリシー限度を勘案する戦略的判断です。
- **責任が争われる、または比較過失の複雑さがある案件。** 責任そのものが争点である場合、デマンドレターは弁護士が起草する弁論文書です。skill は、作業が因果関係の議論ではなく記録の組み立てである、責任が明確な軟部組織から中程度の案件向けです。
- **訴訟書面。** デマンドレターは訴訟前のものです。訴状、申立て、ディスカバリ応答は独自のルールを持つ裁判所文書であり、対象外です。
- **医学的意見。** skill は記録が述べる内容（診断、治療、医療提供者の所見）を要約します。医療提供者が書いた範囲を超えて、予後、因果関係、後遺障害を推論することはしません。それらは医学的意見であり、主治医または依頼した専門家から得られます。
- **契約上処理できない PHI を含む記録。** 保護対象の医療情報（PHI）がこの skill を通過します。記録を入れる前に、Claude のデプロイメントと依頼者との契約条件がそれをカバーすることを確認してください（注意点を参照）。

## セットアップ

1. **バンドルを配置する。** `apps/web/public/artifacts/demand-letter-drafter-claude-skill/SKILL.md` を `references/` フォルダとともに Claude Code の skills ディレクトリに置きます。
2. **事務所のデマンドテンプレートを作成する。** `references/1-demand-letter-template.md` のスケルトンを、事務所の実際のレター — セクション順、boilerplate、デマンドと期限の段落、署名ブロック — で置き換えます。skill はこのテンプレートに組み立てます。これは skill の声ではなく事務所の声です。
3. **損害 playbook をコード化する。** `references/2-damages-playbook.md` を事務所の方法論で埋めます。傷害の重症度別の乗数バンド（一般的なレンジは特別損害の 1.5〜5 倍。重度または醜状を残す傷害はより高くなります）、事務所が日額を使う場合はその日額、事務所が追跡する法廷地固有の上限やルール。このファイルがなければ skill は一般損害のレンジの根拠を持たず、生成を拒否します。
4. **クロノロジーのスキーマを定義する。** `references/3-medical-chronology-schema.md` が列（診療日、医療提供者、治療、請求額、ファイルページ）と引用フォーマットを定義します。弁護士が同じページ参照に対して検証できるよう、事務所が使う引用フォーマットを維持してください。
5. **クローズ済みの 3 件でドライランする。** デマンドが分かっている解決済みの 3 ファイルで skill を実行します。特別損害の合計を実際の特別損害と、クロノロジーをパラリーガルのものと、一般損害のレンジを事務所が請求した額と比較します。レンジが過去のデマンドを囲むまで playbook のバンドを調整します。

## skill が行うこと

7 ステップ。医療クロノロジーは損害計算の前に構築されます。特別損害の各ドルと傷害ナラティブの各行がクロノロジーのエントリを引用し、クロノロジーの各エントリがファイルのページを引用するためです。

1. **記録セットをインデックスする。** 記録、請求書、賃金資料、警察報告書、案件メモを取り込みます。後の各引用が特定の文書とページに解決するよう、ページインデックスを構築します。読み取れないファイル（OCR 失敗、画像のみ）はリスト化され、黙ってスキップされることはありません。
2. **日付入りの医療クロノロジーを構築する。** 診療日ごとに 1 行。医療提供者、主訴、治療、請求額、それが来たファイルページ。治療の中断はフラグされます（救急受診と最初のフォローアップの間の 6 週間の中断は、アジャスターが利用する事実です。弁護士はレターが出る前に知るべきで、後ではありません）。
3. **特別損害を項目化する。** 医療請求を医療提供者ごとに合計し、文書化された休業損害を加え、自己負担費用を加えます。各行はその請求書のページを引用します。skill は、記録で参照されているがファイルにない請求書、および照合できない先取特権（リーエン）や残高をフラグします。これらは推測として合計に入るのではなく、「送付前に確認」として弁護士に渡されます。
4. **責任と事実のナラティブをドラフトする。** 警察報告書と案件メモから、どう起きたかのセクションをドラフトします。報告書が裏付けない記述はフラグされ、書かれません。報告書と依頼者の説明が異なる場合、skill は一方を選ぶのではなく対立を提示します。
5. **傷害と治療のナラティブをドラフトする。** クロノロジーに基づきます — 診断、治療経過、医療提供者の所見、記録が述べる現在の状態。医療提供者が書いた場合を除き、予後や後遺障害の表現はありません。事務所が後遺障害の主張を望む場合、それは主治医の陳述を要するものとしてフラグされます。
6. **一般損害のレンジを算出する。** playbook の乗数バンドを特別損害に適用します（または playbook に従い日額法）。出力はバンドを示したレンジです — 「$Z の特別損害の 2.5〜4 倍で $X〜$Y」 — 明示的に出発点としてラベル付けされます。skill はレンジ内の一点を選びません。
7. **ドラフトとレビューチェックリストを組み立てる。** 事務所のテンプレートを埋めます。応答期限の行は弁護士が設定するプレースホルダとして残します。対になったレビューチェックリストを生成します。各数値とそのソース引用、フラグされた各中断、各「データ不足」項目、そして弁護士が設定する応答期限の行。レターはドラフトです。チェックリストは、弁護士がファイルを読み直す代わりに数分で検証する方法です。

## コストの実態

- **LLM トークン** — 完全な案件ファイルは入力 40〜120k トークン（記録、請求書、報告書）、出力 4〜8k（クロノロジー + ドラフト）です。Claude Sonnet のレートではデマンド 1 件あたり約 $0.30〜0.90、重い記録セットで Opus を使うと $1.50〜4 です。相殺する作成時間に対してセントからドルの範囲です。
- **パラリーガル / 弁護士の時間** — 利得です。デマンドパッケージは一般にパラリーガルの作成 3〜6 時間と言われます。skill はクロノロジーと最初のドラフトを数分で生成します。パラリーガルが検証して欠落を埋め、弁護士が編集して金額を設定します。現実的な節約は作成の半分であり、レビューの半分ではありません — デマンド 1 件あたり 2〜4 時間と考えてください。
- **セットアップ時間** — 45 分に、事務所のテンプレートと playbook の作成（各案件にわたって元が取れる 1〜2 時間の一度きりの作業）を加えたものです。

## 成功指標

- **ドラフトから弁護士までの時間** — 「記録収集済み」から「弁護士の机にドラフト」までの実時間。1〜2 日（パラリーガルのキュー内）から当日に落ちるはずです。
- **特別損害の照合率** — skill の特別損害合計が、修正なしで検証済み合計と一致するデマンドの割合。90% 超を目指します。ミスは記録インデックスまたは請求書パースのギャップを示すものであって、ドラフトを放棄する理由ではありません。
- **弁護士の編集深度** — ドラフトのどれだけが署名済みレターまで残るか。追跡してください。ナラティブが全面的に書き直されている場合、必要なのは skill ではなくテンプレートまたは案件選定基準の引き締めです。

## 代替案との比較

- **[EvenUp](/ja/tools/evenup/) Express Demands や類似のマネージドサービスとの比較。** EvenUp は AI 作成と人間のドラフターを組み合わせ、完成したパッケージを納品します。宣伝されるターンアラウンドは 1〜24 時間ですが、事務所は実際には数日の納品を報告しています。トレードオフはコントロールとデータ所在地です。マネージドサービスはあなたの PHI を保持し playbook を所有します。この skill はあなた自身の Claude 上で、あなたのテンプレートとあなたの損害算定法で動き、ドラフトは決してあなたの環境を離れません。完成したパッケージを返してほしく、データとターンアラウンドの条件に納得できるときはマネージドサービスを使ってください。ドラフトを社内で、今日、自分の方法論で欲しいときは skill を使ってください。
- **[Eve](/ja/tools/eve-legal/) やフルケースワークアップのプラットフォームとの比較。** Eve と訴訟 AI プラットフォームはデマンドだけでなく案件全体を扱います。事務所が案件評価、治療中断の分析、訴訟準備をスイートとして望むなら、それはプラットフォームの購入です。skill はそのパイプラインの 1 ステップ — デマンドのドラフト — であり、プラットフォーム購入の準備ができていない事務所向けです。
- **ゼロから起草するパラリーガルとの比較。** 現状維持です。事務所の声と判断を生み出しますが、最も遅い道であり、誰が起草したかで最も差が出る道です。skill は最初のドラフトと引用の規律を標準化します。パラリーガルの判断は検証とエッジケースに移ります。

## 注意点

- **ハルシネーションによる医療事実や数値。** 捏造された診断や水増しされた請求書を含むデマンドレターは、アジャスターが突く信用の喪失であり、書面に至れば制裁のリスクです。*ガード：* 各クロノロジーエントリ、各特別損害の行、各事実主張はファイルのページを引用します。skill が引用できないものは「データ不足」リストに行き、決してレターには入りません。弁護士は引用されたページに対して検証します。
- **乗数レンジを評価額として読むこと。** 一般損害のバンドは事務所の playbook 上の計算であり、法廷地、アジャスターの履歴、責任の強さ、ポリシー限度に対して盲目です。*ガード：* 出力は常にバンドを示したラベル付きレンジであり、単一の数値ではありません。弁護士がデマンドを設定します。
- **PHI の露出。** skill は診療記録 — 保護対象の医療情報 — を処理します。*ガード：* 記録を入れる前に、Claude のデプロイメントのデータ条件（ゼロ保持 / 学習なしの姿勢、およびコンプライアンスプログラムが要求する場合の BAA）と、依頼者との契約条件が AI 処理をカバーすることを確認してください。事務所の HIPAA プログラムを満たすデプロイメントで動かしてください。消費者向けエンドポイントは決して使わないでください。
- **埋もれた治療中断と責任の対立。** きれいに読めるが治療中断や報告書対依頼者の対立を省いたドラフトは、弁護士がアジャスターに不意を突かれる準備を整えてしまいます。*ガード：* 中断と対立はナラティブで滑らかにされるのではなく、レビューチェックリストに明示的なフラグとして提示されます。
- **欠落した請求書をゼロとして数えること。** 医療提供者の請求書が参照されているがファイルにない場合、存在するものだけを合計すると特別損害とデマンドを過小評価します。*ガード：* 参照されているが欠落した請求書は「送付前に確認」とフラグされ、推測されるのではなく合計から除外されます。パラリーガルがデマンド確定前にそれらを取得します。
- **古い、または法廷地が誤った playbook。** 損害の上限、報酬ルール、訴訟前通知の要件は法廷地ごとに異なり、変化します。*ガード：* playbook ファイルは skill がバンドのために引用する唯一のソースです。案件ごとに現行ルールと照合してレビューし、上限と通知要件は skill が主張するものではなく弁護士が確認したものとして扱ってください。
