## What it is

Octave is a GTM context engine: a versioned, structured model of what you sell and who you sell it to, which your tables, agents and assistants read at runtime instead of each carrying its own copy of the positioning. The library holds typed objects (offerings, personas, use cases, segments, reference customers, competitors and proof points), and Motions (which replaced the older Playbooks as the strategy model) tie them to a sales play. On top of that library sit managed agents for sequencing, qualification, enrichment, call prep, content and prospecting.

The problem it solves is specific. A team running a dozen Clay tables usually has a dozen prompts, each with a slightly different description of the ICP and the value proposition, written by whoever built that table. When positioning changes, nobody updates all of them. Octave moves that context into one place and serves it to every caller.

The company raised a $5.5M seed led by Bonfire Ventures in May 2025, bringing total funding to $8.4M, and remains independent. Named customers include Airbyte, WorkSpan, Cortex, Descope and Harmonic Security. The site shows SOC 2 Type II badges and states that Octave does not train models on customer data. Not to be confused with the unrelated Sierra Wireless IoT platform of the same name, which shut down in March 2025.

## How it plugs into your stack

- **Inside Clay.** Octave agents have been a native Clay enrichment since the September 2025 partnership. You add an enrichment column, pick Octave, and paste the API key from the agent's "Use in Clay" button. The common pattern is to run the Qualify agent first and gate the Sequence agent on its score, for example only on rows scoring 7 or higher out of 10.
- **Over MCP.** The MCP server and Claude Code plugin launched on 6 February 2026. Octave's docs list Claude Desktop, Claude Code, Cursor, VS Code, Zed and Windsurf as clients, and the server exposes knowledge-base search, library edits, research and enrichment, email and call-prep generation, CRM lookups, pipeline metrics and call-transcript search. A rep can ask Claude for call prep and get an answer grounded in the same personas and proof points the outbound tables use.
- **Over the API.** The same agents are callable from [Cargo](/en/tools/cargo/), [n8n](/en/tools/n8n/) and Make. Data can be exported to Snowflake, Databricks, BigQuery and cloud storage.

## Pricing reality

Octave publishes no prices. The current pricing page lists a single plan, Octave Ultra, priced as a flat annual platform subscription plus metered usage credits, with a discount for committing credits up front. It includes unlimited users and unlimited managed agents, SSO/SCIM, RBAC and a dedicated CSM. Bulk credits, GTM engineering services and a warehouse connector are paid add-ons.

For a reference point, independent reviews recorded earlier self-serve tiers in 2025: Core at $149/month for 4,000 credits, Boost at $499/month for 20,000 and Turbo at $999/month for 60,000. That is $1,800 to $12,000 a year at list. Those tiers are gone. Our estimate is that an Ultra contract, which bundles SSO and a CSM, starts at or above the top of that old range. Treat this as a negotiating anchor, not a quote.

Credit burn depends on the model tier each agent uses. Faster models cost fewer credits, larger-context models cost more, and Prospector charges only for prospects found. Because seats are free, your bill scales with how many rows you push through agents, not with headcount.

## Best for

RevOps leaders and GTM engineers at Series B through D B2B companies that run several outbound motions at once across multiple personas or products, already use Clay or Cargo for execution, and have a product marketer who can own the library. It earns its cost when inconsistent messaging across tables, reps and AI assistants is a problem you can point to.

Skip it if you have one offering and one persona, since a well-kept system prompt does the same job. Skip it too if nobody owns positioning, because the engine only serves what someone puts into it.

## Versus the alternatives

[Clay](/en/tools/clay/) is the segment default, and for many teams a shared prompt block across tables plus Claygent is enough. Pick Clay alone when you run one or two motions and one person builds all the tables. [Cargo](/en/tools/cargo/) suits teams that would rather keep context as versioned code: pick it when you have a TypeScript owner and want ICP and messaging in git next to the plays that use them. [Unify](/en/tools/unify/), the fastest-growing entrant, packages signals, research and sequencing together: take it when you want outbound running this month rather than a context layer to build on. The do-it-yourself path is a [Claude](/en/tools/claude/) project or a shared doc holding the messaging. It works until more than a few tables and assistants depend on it.

## Watch-outs

- **The library is only as good as its owner.** Stale personas or proof points now spread to every table and assistant at once. Guard: name one owner for the library before signing, review it each quarter, and use the MCP `check_resource_drift` tool to flag sources that changed since the library last read them.
- **Two meters inside Clay.** Octave's Clay guide says Octave credits pay for agent runs, and the guide does not say what the Clay side of the column costs, so your Clay plan may meter the same run as well. Guard: during the trial, run 100 representative rows end to end and read both meters before you size the credit commit.
- **Opaque pricing, model-dependent burn.** With no public rates, the same workload can cost very different amounts depending on which model tier each agent uses. Guard: fix the model tier for the pilot, record credits per 1,000 rows, and get the per-credit rate, the commit discount and the rollover terms in writing.
- **Small vendor, moving product.** A seed-stage company has already replaced Playbooks with Motions and deprecated the old Playbook tools. Guard: keep the source positioning documents in your own repo or warehouse, use the warehouse export, and build integrations against the current MCP and API tools, not deprecated ones.
