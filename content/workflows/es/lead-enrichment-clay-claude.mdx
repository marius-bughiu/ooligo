Usa este skill descargable de [Claude](/es/tools/claude/) para convertir evidencia empresarial proporcionada en un score ICP y un borrador de apertura que puedas revisar. Empieza con el ejemplo sintético de 20 filas incluido y adapta las mismas comprobaciones a tu tabla de [Clay](/es/tools/clay/). El paquete contiene un validador local, reglas de puntuación, prompts y resultados esperados.

**[Descarga el paquete completo](/artifacts/lead-enrichment-clay-claude.zip)** o [lee la guía de instalación](/artifacts/lead-enrichment-clay-claude/README.md). El ejemplo se ejecuta con Python sin hacer solicitudes de red. No necesita una cuenta de Clay, una API key ni llamadas de pago a un modelo.

**Estado de las pruebas:** el ejemplo sin conexión comprueba datos sintéticos y puntuación determinista. No demuestra una ejecución real de Claude, una integración funcional con Clay, exactitud sobre empresas reales ni mejoras en las respuestas comerciales. El workflow conserva `human_tested: false`.

## Cuándo usarlo

Elige este workflow cuando ya tengas evidencia sobre empresas y necesites una regla consistente e inspeccionable para decidir qué filas merecen atención comercial. Un operador de RevOps define la rúbrica; un representante revisa cada apertura antes de pasarla a un secuenciador. Conserva el texto fuente junto a los hechos extraídos para cuestionar un score sin reconstruir la investigación.

No lo uses si necesitas una base de contactos, emails verificados, investigación web automática o sincronización CRM desatendida. Nada de eso está implementado aquí. Para unas pocas cuentas, leer las fuentes y escribir notas manualmente exige menos preparación. Para enriquecimiento continuo, usa tu proveedor actual y evalúa sus resultados con las mismas reglas. La [guía de estrategias de enriquecimiento](/es/learn/data-enrichment-strategies/) desarrolla esa decisión.

## Qué descargas

El paquete está en `apps/web/public/artifacts/lead-enrichment-clay-claude/`. Cada archivo tiene una función:

- `README.md` explica la instalación y el alcance de las pruebas; `SKILL.md` entrega el procedimiento a Claude Code.
- `references/1-icp-rubric.md`, `references/2-opener-style-guide.md` y `references/3-source-quality-matrix.md` contienen las políticas que adaptas.
- `pipeline.py` valida la evidencia de las extracciones y calcula los scores. `rubric.example.json` contiene los criterios ejecutables del ejemplo.
- `prompts/extract.md`, `prompts/opener.md` y `extraction.schema.json` definen el intercambio manual con el modelo.
- `examples/leads.jsonl`, `examples/extractions.jsonl` y `examples/expected-output.jsonl` contienen entradas sintéticas, extracciones propuestas y resultados esperados.

Lee los archivos antes de instalar el skill. Los documentos de referencia son instrucciones; el validador de Python solo aplica las comprobaciones implementadas en su código.

## Ejecuta primero el ejemplo

Descomprime la descarga, abre una terminal en el directorio que contiene `pipeline.py` y ejecuta:

```bash
python3 pipeline.py demo
python3 pipeline.py validate --leads examples/leads.jsonl --extractions examples/extractions.jsonl --rubric rubric.example.json --as-of 2026-11-01
```

La fecha fija permite reproducir el ejemplo. Para datos reales, usa la fecha real de evaluación. La demo compara sus resultados con `examples/expected-output.jsonl`; cambiar una entrada o la rúbrica cambia el resultado esperado, así que conserva tus experimentos por separado.

Cada lead aporta documentos fuente con `source_id`, `url`, `text` y `checked_at`. Cada extracción propuesta incluye `row_id`, `industry`, `headcount`, `region` y `value_prop`, con citas de evidencia asociadas a los campos. El validador comprueba esas citas contra los documentos proporcionados. No visita las URL ni confirma por su cuenta la actividad de una empresa.

La rúbrica de ejemplo asigna 4 puntos a `B2B SaaS`, 3 a una plantilla de 50 a 500 personas inclusive y 3 a `US` o `CA`. El umbral es 7. La empresa ficticia `ledgerleaf.example`, fila `demo-01`, tiene `B2B SaaS`, 120 empleados y `US`, por lo que obtiene 10. Estos criterios ilustran la aritmética; no son una recomendación para tu ICP.

La falta de evidencia firmográfica produce `needs_review` y un score nulo. Otros resultados incluyen `ready_for_review`, `below_threshold`, `unreachable` e `invalid_evidence`. Todos conservan `review_required=true`. La apertura sin conexión cita el texto del producto proporcionado; demuestra la selección de filas, no un benchmark de personalización generada por un modelo.

## Usa el skill en Claude Code

Copia el paquete extraído en `~/.claude/skills/lead-enrichment/`, con `SKILL.md` directamente dentro de ese directorio. Invoca `/lead-enrichment` en una sesión local de Claude Code. La instalación sigue la [documentación de skills de Claude Code](https://code.claude.com/docs/en/skills).

Adapta tanto la rúbrica escrita como `rubric.example.json` antes de evaluar leads reales. Entrega a Claude los documentos fuente y el prompt de extracción, guarda el resultado propuesto y ejecuta el validador antes de pedir una apertura. El modelo propone hechos; las comprobaciones locales determinan si la evidencia cumple las reglas configuradas. Una cita que supera la comprobación sigue requiriendo interpretación humana: una plantilla citada puede corresponder a un cliente, no al prospecto.

## Adáptalo a Clay de forma explícita

La [documentación de Use AI de Clay](https://university.clay.com/docs/use-ai-integration-overview) describe prompts y salidas estructuradas. La transformación de contenido y la investigación web son modos separados. Un directorio local con `SKILL.md` no se importa como columna de Clay.

Crea una tabla pequeña de prueba con identificadores de fila y texto fuente. Adapta `prompts/extract.md` a esas columnas y usa `extraction.schema.json` como contrato de salida. Elige un modelo Claude disponible en tu cuenta, registra su identificador y mantén desactivadas las ejecuciones automáticas durante la configuración. Exporta las extracciones propuestas en el formato JSONL documentado y valídalas localmente.

Solo las filas que superen las comprobaciones y alcancen el umbral deben pasar a `prompts/opener.md`. Conserva juntos el borrador, la cita y la decisión de revisión. Exporta a [HubSpot](/es/tools/hubspot/) u otro CRM únicamente después de revisar; la descarga no incluye un conector CRM ni un paso de envío. Reserva unos 30-60 minutos estimados para la configuración inicial y mide después tu tiempo de revisión. Esta estimación excluye construir una integración desatendida.

## Aritmética de costos que puedes reemplazar

La demo sin conexión usa 0 llamadas API de pago. El uso real genera cargos separados: uso de Clay, tu cuenta del modelo si aportas tu propia key, datos de proveedores y tiempo de revisión. Clay documenta que [las API keys propias siguen consumiendo Actions y el proveedor factura el modelo](https://university.clay.com/docs/ai-tokens). Comprueba las tarifas de tu cuenta antes de ejecutar una tabla.

Usa datos medidos:

```text
model_cost = input_tokens / 1000000 * input_rate
           + output_tokens / 1000000 * output_rate
run_cost = model_cost + data_cost + platform_cost
review_hours = rows_reviewed * seconds_per_review / 3600
```

Con un costo de procesamiento total explícitamente hipotético de $0.02 por fila, 20 filas cuestan $0.40 y 100000 filas cuestan $2000 por ejecución. Cuatro ejecuciones semanales cuestan $8000, antes de costos excluidos de ese supuesto. Es aritmética, no una tarifa cotizada de Clay o Anthropic. Incluye intentos fallidos y repeticiones al calcular el costo real por fila aceptada.

## Comprobaciones de fallos y una prueba de aceptación útil

- **Hechos sin respaldo:** conserva la cita exacta; rechaza evidencia ausente o que no coincida en lugar de inventar un score.
- **Evidencia antigua:** compara `checked_at` con la fecha de evaluación. El límite de 30 días del ejemplo es una política configurable, no una prueba de vigencia.
- **Citas engañosas:** revisa qué describe cada cita. La coincidencia textual no establece la verdad ni resuelve discrepancias entre proveedores.
- **Gastos inesperados:** desactiva la ejecución automática, empieza con un límite fijo de filas y revisa la factura antes de ampliar.
- **Contacto accidental:** conserva `review_required=true` y mantén el envío fuera de este workflow.

En tu primer piloto real de 20 filas, registra fallos de validación, hechos incorrectos detectados, borradores aceptados, tiempo de revisión y gasto total. El éxito consiste en poder explicar cada score y apertura aceptados a partir de su evidencia y mostrar el costo real. Una demo sintética no demuestra mejoras comerciales. Compara ese esfuerzo con revisar manualmente cuentas similares antes de ampliar la ejecución.
