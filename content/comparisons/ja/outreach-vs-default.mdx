[Outreach](/ja/tools/outreach/) と [Default](/ja/tools/default/) は2026年、どちらも「レベニューチーム向けのエージェント」を売り出しており、初めて競合のように見えます。競合ではありません。Outreach はアウトバウンドの実行チャネル、つまりシーケンス、ダイヤラー、カンバセーションインテリジェンスであり、その上に今年エージェント層が乗りました。Default はそのエージェントが動くデータとオーケストレーションの層であり、今もメールを1通も送らず、電話を1本もかけません。2つのエージェントのデモが似て見えたので比較しているのなら、答えは「両者は同じ引き継ぎの反対側に立っている」です。

## 2026年に何が変わったか

2つの製品は4か月の間隔でそれぞれポジションを変えました。この組み合わせの古い枠組み、すなわちエンゲージメントプラットフォーム対ルーティングツールという説明は、もうどちらにも当てはまりません。

Outreach はサイトを outreach.io から outreach.ai へ移し、「レベニューチームのためのエージェンティック AI プラットフォーム」として再ローンチしました。新しい製品面は、Slack とモバイルで動く会話型エージェントの Outreach Omni、RevOps がビジュアルキャンバス上で独自エージェントを構築・スケジュールする Agent Studio、そして名前を持つ一連のエージェント、Meeting Prep Agent、Deal Agent（CRM のフィールド更新案を作成し、担当者が承認する）、AI Topics Explorer、Kaia のコーチングエージェントです。パッケージングも製品に合わせて変わり、Amplify の各プランはシートに加えて AI クレジットを計測します。Outreach は MCP サーバーも提供しており、2026年2月24日に一般提供が始まりました。MCP サーバーと MCP クライアントの両方として動作するため、外部のエージェントが Outreach のコンテキストを読み、その中で操作できます。このアクセスには Amplify アドオンを有効にしたライセンス済みシートが必要で、プラットフォーム標準ではなく有料プランの機能です。

Default は2026年6月16日、8VC がリードし Craft と Jack Altman が参加したシリーズ A を実施し、累計調達額は2,000万 USD になりました。これを元手に、インバウンドのオーケストレーションから「レベニューチームのための AI インフラ」へと立ち位置を移しています。製品は現在、リアルタイムの GTM データ層です。CRM、マーケティングオートメーション、フォーム、エンリッチメントのベンダーを、名寄せ済みのレベニューウェアハウスへ同期します。そこに Dot が乗ります。Dot はリクエストを計画し、サブエージェントに委任し、そのデータに対して並列で実行するエージェントです。ルーティング、ウォーターフォールのエンリッチメント、日程調整、ワークフローのオーケストレーションは、独立した機能ではなく Dot が呼び出すツールになりました。名前の挙がっている顧客には Perplexity、Owner、Cortex があります。

## Outreach が勝つところ

- **実行するのは2つのうちこちらだけです。** シーケンス、ダイヤラー、メールトラッキング、Kaia の通話録音が製品そのものです。Default には設計上、どのプランにも送信面がありません。課題が「担当者が十分な数のアカウントに触れていない」なら、Default はそれを解決しません。
- **営業組織の規模に耐えるシーケンスガバナンス。** 開封・クリック・返信による分岐ロジック、送信時間の A/B テスト、テリトリー再編を生き延びる共有シーケンスの権限設定。200人規模の営業組織が実際に買っているのはこれであり、オーケストレーションのキャンバス上で作り直せる機能ではなく、何年分ものエッジケースの蓄積です。
- **リードの段階だけでなく、商談と予測まで。** Deal Agent は CRM への更新案を書き戻して担当者の承認を受け、Meet・Deal・Forecast の各モジュールは、Outreach がすでに保有する活動データからパイプラインのビューを CRO に提供します。Default はリードとアカウントの層で止まります。
- **エンゲージメント履歴へのエージェントアクセス。** Outreach は MCP サーバーなので、Claude 上のエージェントや自社の社内ツールが、スタックのどこにも存在しない通話履歴やシーケンス履歴を照会できます。Default のデータ層は、自社コネクタが同期したものしか提供できません。

## Default が勝つところ

- **データ層がエンゲージメントツールの外にあります。** Outreach のエージェントは Outreach のデータの上で推論します。良質な一部ではありますが、あくまで一部です。Default の前提は、割り当ての判断をエージェントに任せる前に、CRM、マーケティングオートメーション、フォーム、エンリッチメントを横断するレコードが必要だという点にあります。複数ベンダーのエージェントを走らせるつもりなら、どのウェアハウスから読むかがアーキテクチャ上の問いであり、それをシーケンサーから買うのは最も後戻りしにくい選択です。
- **インバウンドリードへの反応速度。** ルーティングは設定可能なポリシー、つまりラウンドロビン、稼働可否、直近性、キャパシティで配分し、勤務時間、不在ブロック、カレンダーの空き、会議間のバッファを尊重するキューを通します。Outreach はリードをルーティングできません。
- **出荷済み機能としての巻き戻しやすさ。** ルーティングの判断はすべて記録され追跡でき、ルール変更はバージョン管理されワンクリックでロールバックできます。Dot はシステム全体を用意したうえで、公開前に人間の承認を待ちます。Outreach の承認モデルはフィールド単位で担当者が行い、Default はシステム単位で管理者が行います。担当の付け替えが起きるものについては、後者が欲しいはずです。
- **1人 RevOps チームにとっての構築時間。** Default なら午後1回で組めるルーティングフローが、もう一方の道では Salesforce の割り当てルールのプロジェクトに、日程調整ベンダーと各所の接着剤が加わります。この差が Default が買われる理由です。

## 価格、数字で

どちらも価格を公開していませんが、隠しているものが違います。

Outreach の価格ページは AI クレジットの付与量で Amplify の4段階を並べます。Essentials が10,000クレジット、Core が25,000、Plus が50,000、Pro が100,000です。モデルも明示されており、シート課金と AI クレジットで計測する従量課金の組み合わせで、プラットフォーム料金はありません。技術的な上限はプランとともに上がります。Essentials と Core は API 呼び出し250,000回、カスタムオブジェクト5個、ナレッジ500 MB。Plus は500,000回、10個、750 MB。Pro は1,000,000回、20個、1,500 MB。単価そのものは営業との会話です。

Default は価格ページ自体がありません。ルーティング、エンリッチメント、日程調整の各製品ページはすべて Request a Demo で終わります。販売形態はプラットフォーム料金に加えて、売上に貢献するユーザー分のシートを年間契約で購入する形で、編集者シートは無料です。

料率よりも課金の形が効きます。両者は違うものに値付けしているからです。Outreach は担当者ごとの課金です。25シートのチームなら、Meet、Deal、Forecast のアドオン前、シートだけでおおよそ年間30,000-48,000 USD の範囲に着地します（Outreach が年間契約で提示するシートあたり月100-160 USD のレンジからの推定です）。Default はプラットフォームに課金し、入口はおよそ年間6,000-9,000 USD です（推定）。SDR を10人増やすと Outreach の請求は約40%上がりますが、Default はほとんど動きません。その SDR はワークフローを編集するのではなく、ルーティングされたミーティングを消費する側だからです。CRM をもう1つ増やすと、非対称は逆向きになります。

## 両方を運用する

両方を本気で評価したチームはたいてい両方を導入します。その継ぎ目は、後から発見するのではなく設計する価値があります。Default はカレンダー招待までのすべてを持ちます。フォーム送信、エンリッチ、クオリファイ、ポリシーによるルーティング、予約です。Outreach は担当者がアカウントを持って以降のすべてを持ちます。シーケンス、架電、録音、コーチング、予測です。接合点は割り当てのイベントであり、失敗の形はオーナーシップの正となるシステムが2つ存在することです。Default のルーティングルールと Outreach のアカウント割り当てがずれていき、やがて担当者がすでに自分のものではないアカウントにシーケンスを流します。オーナーシップは CRM に固定し、両者がそれぞれ主張するのではなく、そこから読ませてください。

## 結論

- **Outreach を選ぶ**のは、ボトルネックがアウトバウンドの実行にある場合です。大規模な営業組織でのシーケンスガバナンス、架電量、通話コーチングなど。Default には送信するものが何もありません。
- **Default を選ぶ**のは、ボトルネックがインバウンドの転換にある場合、あるいは1社のベンダーの一部分ではなく、スタックを横断するレベニューデータをエージェントに読ませたい場合です。
- **どちらか1つしか買えず、正直に迷うなら、Outreach を買ってください。** 決め手になる問いは、パイプラインがどこから来るか、担当者からかフォームからか、です。この2つを比較するチームの多くは、いまだにパイプラインの大半を担当者経由で作っています。運用できないチャネルは、[Chili Piper](/ja/tools/chili-piper/) や Salesforce の割り当てルールで予算がつくまで凌げるルーティングよりも、埋め合わせが難しい穴です。
- **どちらも合わない**のは、本当に必要だったのが20人未満の担当者向けに価格が一段安いシーケンサーだった場合です。それは [Apollo](/ja/tools/apollo/) か [Salesloft](/ja/tools/salesloft/) の話であり、[Apollo vs Outreach](/ja/vs/apollo-vs-outreach/) のほうが近い比較になります。あるいは本当の穴がオーケストレーションではなくエンリッチメントのカバレッジなら、それは [Clay](/ja/tools/clay/) の領域です。

このページが防ぐために存在する誤解は、Outreach の2026年のエージェント層があればルーティングとデータの層は不要になる、というものです。そうはなりません。Agent Studio が自動化するのは Outreach のデータの内側の仕事であり、シーケンスに届かなかったリードについては何の見解も持ちません。
