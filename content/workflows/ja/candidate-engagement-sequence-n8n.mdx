パッシブ候補者と以前に不採用になった候補者に対してマルチタッチのアウトリーチシーケンスを実行する n8n フローです。前回の接触地点から再開し、次のメッセージをパーソナライズして、返信を適切なリクルーターにルーティングします。典型的な「1 回のアウトリーチ後は候補者のことを忘れる」パターンを、持続的なパイプライン構築に置き換えます。

## 必要なもの

- n8n セルフホストまたはクラウドアカウント
- 採用 CRM または ATS の API アクセス — [Gem](/ja/tools/gem/)、[Ashby](/ja/tools/ashby/)、[Greenhouse](/ja/tools/greenhouse/)、または [Lever](/ja/tools/lever/)
- メールインフラ — Gmail/Workspace、または専用のアウトリーチドメインと配信インフラ
- パーソナライズ用の [Claude](/ja/tools/claude/) API キー
- シーケンス状態追跡用の Postgres または同等のデータベース

## セットアップ

1. **シーケンスライブラリを定義する。** Postgres に 3〜5 個の名前付きシーケンスを作成します：「passive-engineer-3-touch」「previously-rejected-12mo-recheck」「talent-pool-quarterly-touchpoint」など。各シーケンスには、トリガー条件、メッセージテンプレート、インターバル、終了条件を定義します。
2. **n8n フローを構築する。** 8 つのノード：
   - Cron トリガー — 採用に適した送信時間に毎日実行
   - シーケンスクエリ — Postgres から次のタッチの期限が来た候補者を取得
   - ATS データエンリッチメント — Ashby から最新の候補者データを取得（最近のアクティビティ、現在のステータス、最後のインタラクション）
   - スキップ条件チェック — 最後のタッチ以降に返信した候補者、最近応募した候補者、明示的にオプトアウトした候補者を除外
   - Claude パーソナライズ — 候補者にパーソナライズされた次のメッセージ本文を生成
   - メール送信 — Gmail API またはアウトリーチプラットフォーム経由
   - シーケンス状態更新 — 最終タッチのタイムスタンプと次回予定タイムスタンプで Postgres を更新
   - 返信検出 — Gmail で返信を確認し、返信コンテキストと共に割り当てられたリクルーターの Slack にルーティング
3. **少数バッチでシーケンスをテストする。** シーケンスあたり 20〜30 人の候補者で実行し、コンテンツの品質とルーティングを確認します。シーケンスのインターバルとパーソナライズプロンプトを調整します。
4. **オプトアウトインフラを確立する。** すべてのメールにワンクリックの配信停止を含め、すべてのシーケンスでオプトアウトを尊重します。

## ルーティングの仕組み

| シーケンストリガー | ケイデンス | 終了条件 |
|---|---|---|
| パッシブ候補者がシグナルを示した（転職、資金調達ニュースで言及） | 21 日間で 3 タッチ | 返信、応募、オプトアウト |
| 12 ヶ月前に不採用、ロールは依然として関連性あり | 単発の再エンゲージメントタッチ | 返信、応募、オプトアウト |
| タレントプールメンバー、最近の接触なし | 関連コンテンツでの四半期タッチ | 応募、オプトアウト |
| 最終面接で不採用、高品質、関連ロールが開く | 単発のターゲットタッチ | 返信、応募、オプトアウト |

## 出力

タッチされた各候補者について：

- **送信済みメッセージ** — 候補者の実際のコンテキストを参照した適切な件名と本文を持つパーソナライズされたメール
- **シーケンス状態ログ** — タッチの記録（どのシーケンス、シーケンスの何番目のメッセージか、送信タイムスタンプ）
- **返信通知** — 候補者が返信した際に、返信コンテキストと推奨される次のアクションと共に割り当てられたリクルーターへの Slack 通知

## フローの位置付け

このフローは長期的な[タレントパイプライニング](/ja/learn/talent-pipelining/)の運用レイヤーです。なければ、一度タッチした候補者は通常永遠に沈黙します。あれば、パイプラインは何ヶ月も何年もわたって温かさを維持します — 適切なロールが開いたときにインバウンドの応募フローを生み出します。

成熟した採用組織は、以前にタッチした候補者の再エンゲージメントからシニア採用の 15〜30% が生まれていると報告しており、このような持続的エンゲージメントインフラのおかげです。

## 注意事項

- **配信可能性が重要です。** 単一ドメインからの一括アウトバウンドは配信可能性をすぐに低下させます。適切なアウトリーチインフラ（専用ドメイン、ウォームアップ、SPF/DKIM/DMARC）を使用してください。過少送信の方が配信可能性を損なうよりましです。
- **パーソナライズの品質が重要です。** 汎用的な AI パーソナライズアウトリーチは明らかに AI 生成と読まれます。パーソナライズには、パターンマッチしたフィラーではなく、実際の候補者固有のコンテキストが必要です。
- **オプトアウト処理は交渉の余地がありません。** すべてのメッセージにワンクリックの配信停止を含め、現在および将来のすべてのシーケンスでオプトアウトを尊重します。CAN-SPAM、CASL、GDPR はすべてこれを必要とします。
- **返信した候補者に自動送信しないでください。** 返信検出は非常に重要です — すでに返信した候補者に次のシーケンスメッセージを送ることは最悪の CX 失敗です。
- **高価値候補者へのリクルーターレビュー。** シニアロールまたは高優先度のタレントプールでは、リクルーターが自動送信ではなく各メッセージをレビューして承認します。
- **頻度の上限。** 同じ候補者が同時に複数のアクティブなシーケンスに現れてはなりません。シーケンス状態ロジックにキャップルールを設けてください。
