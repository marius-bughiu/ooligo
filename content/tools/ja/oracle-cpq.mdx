## 概要

Oracle CPQ は、Oracle が 2013 年に BigMachines として買収し、現在は Oracle Fusion Cloud Customer Experience の一部として販売している configure-price-quote 製品です。営業担当がルールに沿って製品を構成し、価格エンジンが価格表、値引き、承認ポリシーを適用し、見積から提案書が作られ、その先で受注につながります。管理者は Oracle 独自のスクリプト言語 BML ですべてを拡張でき、ヘルプサイトはいまも help.bigmachines.com にあります。

Gartner は 2026 年版 CPQ Applications の Magic Quadrant で Oracle を Leader に選出しました。レポートは 2026 年 1 月に公開され、16 社が評価対象です。Oracle の 2026 年 3 月 17 日の発表では 9 年連続とされています。リリースは A-D のラベル（26A、26B、26C）で四半期ごとに出ており、製品は Fusion に近づいています。Oracle のドキュメントは「Oracle CPQ running in Fusion」を 1 つのデプロイ形態として扱っており、コミュニティのスレッドでは 26C から Fusion インスタンス内で利用できると報告されています。

AI 機能は 2025-2026 年に加わりました。25C では見積支援の AI エージェントが追加されました。26B では Quote Generation Supervisor Agent が追加され、Oracle の readiness ノートによれば、CPQ のテンプレートとマスターデータをもとに構成、価格、ポリシーチェックをオーケストレーションして見積を組み立てます。あわせて、顧客の PDF から明細を抽出して Redwood の見積画面に取り込む AI 支援の製品追加機能も入りました。Oracle 自身の 26B のページがこのエージェントを 2 つの異なる名前で呼んでおり、それだけ新しい機能だということです。

## RevOps スタックに登場する理由

- **Salesforce CPQ からの移行候補リストに必ず入ります。** Salesforce は 2025 年 3 月に新規顧客への Salesforce CPQ の販売を終了しました。既存顧客は引き続き更新とサポートを受けられ、提供終了日は発表されていません。プラットフォームを移行するチームは Agentforce Revenue Management、[Conga CPQ](/ja/tools/conga-cpq/)、[DealHub](/ja/tools/dealhub/)、[Nue](/ja/tools/nue/)、Oracle を比較しています。Oracle の CX ブログもこうしたチームに直接訴求しています。
- **Salesforce から離れる必要はありません。** Oracle CPQ Connector for Salesforce は、CPQ の見積作成を Salesforce の商談の中に組み込む managed package です。7.x と古い 8.x は 22D 以降サポート対象外なので、新規導入では最新の version 8 リリースを使います。
- **Oracle ERP を使う企業にとってのネイティブな選択肢です。** 受注、価格、フルフィルメントがすでに Oracle Fusion で動いているなら、CPQ によって quote-to-order を 1 社のデータモデルとサポート契約の中に収められます。

## 実際の価格

Oracle は営業向けページで CPQ の価格を公開していません。ユーザー単位の月額で販売し、ユーザー数、モジュール、連携範囲で交渉します。リスティングサイトでは開始価格としてユーザーあたり月額 $240 が挙がっており（TrustRadius、ITQlick）、Standard エディションは $130 からと報告されています。$240 の場合、見積を作成するユーザーが 100 人なら、導入費用を除いてライセンスだけで年間 $288,000 になります。

導入は別建てで、しかも大きな費用です。ITQlick は小規模な導入で $25,000 から $75,000、エンタープライズ導入では $100,000 超と見積もっており、G2、TrustRadius、Gartner Peer Insights のレビューも、パートナー主導で BML を多用する長期プロジェクトだと一貫して述べています。稼働後の専任 CPQ 管理者も予算に入れてください。複数のレビュアーが、それは任意ではなく必須だと書いています。

## 最適なケース

構成可能な製品やサービスを階層的な価格で販売する企業のディールデスクと RevOps リーダー、とくにすでに Oracle Fusion ERP を使っている企業、または Agentforce Revenue Management に移らずにエンタープライズ級のエンジンがほしい Salesforce ユーザーに向いています。BML を習得する管理者がいるチームに合います。

シートと利用量のティアを販売する SaaS チームには不向きです。そうしたチームは DealHub や Nue のほうが早く稼働でき、カタログが定価の SKU 数点だけなら CPQ 自体が不要かもしれません。その線引きは [CPQ の定義](/ja/learn/cpq-configure-price-quote/) で説明しています。

## 代替ツールとの比較

**[Agentforce Revenue Management](/ja/tools/salesforce-revenue-cloud/)**（旧 Salesforce Revenue Cloud）は市場シェアでの既存大手です。Salesforce がシステム・オブ・レコードで、価格ロジックの深さより単一プラットフォームを優先するならこちらを選んでください。ERP が Oracle の場合や、見積エンジンを Salesforce のライセンス体系の外に置きたい場合は Oracle を選んでください。

**[Conga CPQ](/ja/tools/conga-cpq/)** はもう 1 つの重量級エンジンで、現在は PROS の価格最適化を備えています。難所が価格計算（リベート、チャネルプログラム、マージンガイダンス）にある場合や、組織の一部が Dynamics 365 を使っている場合は Conga を選んでください。難所が Oracle のバックオフィスシステムへの quote-to-order にある場合は Oracle を選んでください。

**[DealHub](/ja/tools/dealhub/)** は導入スピードと、サブスクリプション事業向けの購買者向け DealRoom で勝ります。**[Nue](/ja/tools/nue/)** は最も成長の速い新興勢で、Salesforce ネイティブの SaaS 企業向けに CPQ、請求、収益認識を 1 つのデータモデルで提供します。**[Tacton](/ja/tools/tacton/)** は、複雑さが価格ではなく CAD 出力を伴う受注設計（engineer-to-order）型の構成にある場合に勝ります。

どれも合わない場合、たいていは価格表の責任者が不在です。まず値引きポリシーを固めてください。その層は [ディールデスク向け価格設定スキル](/ja/workflows/deal-desk-pricing-skill/) で示しています。

## 注意点

- **BML は人員を確保すべきスキルです。** レビューでは、学習曲線が急で、スクリプトは保守しにくく、大規模な構成では遅くなると指摘されています。Oracle は入れ子ループなどの BML パターンを検出する Performance Reviewer を提供しています。*対策：* パートナーにすべての BML スクリプトの文書化と管理の引き継ぎを義務づけ、稼働前に Performance Reviewer を実行し、実際の最大規模の見積で負荷テストを行ってください。
- **四半期アップデートで機能が削除されます。** Direct Login と SOAP v1 Web サービスは 26A で削除され（SOAP のログイン API に依存する SSO が壊れる可能性があります）、Oracle Sales からのほぼリアルタイム同期は 26B で削除され、Proxy Login は 27A で削除されます。*対策：* 各リリースの非推奨通知を読む担当者を決め、アップデートのたびに事前にテスト環境で連携の回帰テストを行ってください。
- **Salesforce コネクタには最低バージョンがあります。** サポート対象外の managed package はいずれ接続できなくなります。*対策：* 評価段階で自社 org のパッケージバージョンを確認し、コネクタのアップグレードをリリースカレンダーに組み込み、Salesforce ユーザーが CPQ 内では制約が多いと感じる検索とレポートをテストしてください。
- **エージェントは登場したばかりで、Fusion 前提の設計です。** 26B のスーパーバイザーエージェントは今年出たばかりで、コミュニティの投稿では、CPQ が別インスタンスで動く一方でエージェントは Fusion 側で設定すると説明されています。*対策：* エージェントをビジネスケースに含める前に、自社のテナント構成と自社カタログで見積を生成するところを Oracle に実演してもらい、ライセンスと設定の要件を書面で受け取ってください。
- **Fusion への移行は文書が不足しています。** コミュニティのスレッドでは、スタンドアロンの CPQ から CPQ running in Fusion へのサポートされた移行手順を求める顧客の質問に、公開された回答がありません。*対策：* いま複数年契約を結ぶなら、どのデプロイ形態を使うのか、移行が必要になった場合に誰が費用を負担するのかを契約書に明記してください。

CPQ が請求、CLM、総勘定元帳とどう並ぶかは [quote-to-cash スタック](/ja/stacks/quote-to-cash-stack/) を参照してください。
