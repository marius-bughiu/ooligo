## 概要

Claudeforce は、Salesforce と Anthropic が2026年8月26日に拡大したパートナーシップに付けた名称で、実際には1つの製品を指します。**Salesforce in Claude** です。これは、営業担当者のアカウント、商談、パイプラインを、その担当者が既に持つ Salesforce 権限のまま [Claude](/ja/tools/claude/) の中に持ち込むプラグインです。37 個の既製セールススキル（朝のブリーフ、商談前の準備、日付入りの相互クロージングプランを含むディールレビュー、会議後のフォローアップ、パイプラインダッシュボード、フォーキャストのナラティブ）に加え、Salesforce と [Slack](/ja/tools/slack/) のコネクタが同梱されています。2026年9月15日にオープンベータとなり、2026年10月9日時点でもベータのままです。Claude のチャットと [Claude Cowork](/ja/tools/claude-cowork/) の Web 版とデスクトップ版で動作し、Claude Code では動きません。このページの機能に関する記述はすべてこのベータ時点のものであり、契約前に必ず再確認してください。

パートナーシップの残り2つの要素、つまり Slack のデフォルトモデルとしての Claude と、Agentforce のデフォルト推論モデルとしての Claude は、既にお持ちかもしれない製品の中身を変えるものです。別途購入するものではありません。

## ops スタックに載る理由

Reddit での疑問はもっともです。Salesforce のホスト型 MCP サーバーは Enterprise Edition 以上で2026年4月29日から GA になっており、どの管理者でも Claude のカスタムコネクタを `platform/sobject-reads` に向ければ半日で接続できます。では、プラグインは何を上乗せするのでしょうか。

- **接続ではなくスキル。** 素のコネクタが Claude に与えるのはレコードへの CRUD です。プラグインが与えるのは、明確な方針を持った営業手順です。商談前に何を読むか、ディールをどう採点するか、フォローアップでどの項目を更新すべきか。初回起動時のセットアップスキルが、担当者自身の担当顧客群からロール別の Artifact を作ります。本来なら RevOps チームが自前で構築・保守するはずの、数週間分のプロンプトとスキルのエンジニアリングです。
- **管理者の接続は1回、ID はユーザーごと。** 管理者は External Client App を介して Salesforce を一度接続し、Claude のグループ単位でプラグインを割り当てます。その後、各担当者が自分の Salesforce ログインでサインインします。読み取りはオブジェクト、項目レベル、共有のルールを継承します。Salesforce の表現では「あなたがレコードを見られないなら、MCP サーバーも見られない」です。
- **書き込み前の承認。** デフォルトでは Claude が変更を1件ずつ提案し、担当者が承認してから Salesforce に反映されます。記録システムは引き続き Salesforce です。

Anthropic は導入済み顧客として GitLab、Siemens、Legora を挙げ、社内で約7,000人の Salesforce 営業担当者が使っているとしています。いずれもベンダー発表の数値です。

## 価格の実態

Claudeforce としての価格はなく、Salesforce の Patrick Stokes 氏もローンチ時に、1枚の契約書では購入できないことを認めています。支払先は2社です。

- **Anthropic**：ユーザーごとに有料の Claude シート。Anthropic のガイドでは有料プランはすべて対象で、Team は定価 $25/シート/月（年払いで $20）です。日常的に多用すると、[Claude Cowork](/ja/tools/claude-cowork/) と同様に担当者はプレミアムシートや Max に寄っていきます。
- **Salesforce**：ベータには最新の Sales Cloud Enterprise エディションが必要で、定価は $175/ユーザー/月です。ホスト型 MCP のトラフィックは組織の既存の API リクエスト上限を消費します。現時点で Salesforce は MCP の呼び出し単価を公表していませんが、「Headless Platform Interaction」は既に価格未記載のまま料金表に載っており、課金開始の30日前に通知すると約束しています。

既に Sales Cloud Enterprise を持つ担当者 1 人あたりの実勢レンジは、**新規支出でユーザーあたり月 $20〜$125** で、すべて Claude 側の費用です。これに管理者の工数が加わります。Pro Suite を使っている場合は、エディションのアップグレード費用がそれ以外をすべて上回ります。

## 適しているのは

AE が既に Claude で仕事をしている Salesforce Enterprise 企業の RevOps リーダーで、RevOps がスキルを書いて保守しなくても、担当者が商談準備、ディールレビュー、CRM 更新を1つの画面で済ませられるようにしたい場合です。勝てる具体的なケースは、Claude Team または Enterprise を既に契約済みで Sales Cloud Enterprise を使う 20〜200 席の AE チームで、目的が自律的な営業ではなく、タブ切り替えを減らし商談項目の入力品質を上げることにある場合です。

## 適していないのは

自律的な業務や顧客対応の業務です。Salesforce 自身の位置づけでは、それは [Agentforce](/ja/tools/salesforce-agentforce/) の領域です。大量データ処理にも向きません。ホスト型 MCP は1回の呼び出しで1レコードしか作成しないため、「5,000件の商談を更新する」なら Flow か [n8n](/ja/tools/n8n/) のジョブで行うべきです。Enterprise Edition 未満のチームや、展開前に GA の署名済み契約が必要な組織にも適していません。

## 代替候補との比較

- **Salesforce ホスト型 MCP への無料カスタムコネクタ**：Reddit で指摘されている選択肢です。技術に強い RevOps 担当者が1人いて、読み取りか限られた書き込みだけで足り、公開するサーバー（`sobject-reads` か `sobject-mutations` か）を自分で厳密に選びたい場合に選んでください。37 個のスキルと管理されたセットアップは手放すことになります。
- **[Salesforce Agentforce](/ja/tools/salesforce-agentforce/)**：CRM 内の既存のエージェント層です。人間の承認を挟まずに動くエージェントや顧客対応のエージェントが必要な場合、また請求書2通ではなく Salesforce との1契約にまとめたい場合に選んでください。
- **[Microsoft 365 Copilot](/ja/tools/microsoft-365-copilot/) と Sales agent**：アシスタント側のもう一方の既存勢力です。営業担当者が Claude ではなく Outlook と Teams で仕事をしている場合に選んでください。なお、その Salesforce コネクタは読み取り専用で、書き戻しには別ライセンスの Sales agent が必要です。
- **[Day.ai](/ja/tools/day-ai/)**：最も勢いのある新規参入者で、2026年2月に Sequoia 主導で $20M のシリーズ A を調達した AI ネイティブ CRM です。営業担当者がおよそ50人未満で、既存 CRM に AI をかぶせるのではなく CRM ごと置き換える意思がある場合に選んでください。

## 注意点

- **2社のドキュメントが食い違っています。** 2026年9月中旬時点で、Salesforce の Winter '27 リリースノートはこのプラグインを読み取り専用で Claude Enterprise が必須と説明していましたが、Anthropic のガイドはすべての有料プランで承認付きの書き込みができると説明しています。対策：パイロットは Sandbox で読み取り専用として実施し、本番レコードで有効化する前に、書き込み対応とプラン要件を Salesforce のアカウントチームに書面で確認してください。
- **承認プロンプトは、情報に基づく承認とは限りません。** 汎用的な dispatch 呼び出しだけが表示されるプロンプトでは、担当者は何も確認できません。対策：パイロットユーザーには管理者プロファイルを使わせず、External Client App を担当者に必要なオブジェクトだけを含む権限セットに制限し、対象レコードと新しい値が表示されない書き込みは担当者に却下させてください。
- **監査証跡がつながりません。** Salesforce はホスト型 MCP の呼び出し（`API_CLIENT_CATEGORY = SALESFORCE_HOSTED_MCP`）をユーザー単位で記録しますが、Claude 側と共有される相関 ID はありません。そのためログが証明するのはどの ID が書き込んだかであり、誰が承認したかではありません。対策：Claude Enterprise では Compliance API のエクスポートを保管し、ベータ期間中は毎月サンプリングで Salesforce の API ログと突き合わせてください。
