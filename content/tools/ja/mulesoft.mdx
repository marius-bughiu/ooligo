## MuleSoft とは

MuleSoft は Salesforce の統合・API 管理プラットフォームです。Salesforce は 2018 年に約 65 億ドルで同社を買収しており、2026 年の Gartner iPaaS Magic Quadrant では [Workato](/ja/tools/workato/) や [Boomi](/ja/tools/boomi/) と並んで Leader に位置付けられています。中核製品の Anypoint Platform は、API 設計、統合を実行する Mule ランタイム、コネクタカタログ、API ポリシーを適用する Flex Gateway、そして Anypoint Code Builder をカバーします。Anypoint Code Builder では、MuleSoft Vibes（旧称 MuleSoft Dev Agent）が自然言語のプロンプトから Mule アプリ、DataWeave 変換、MUnit テストを生成します。

MuleSoft を他の 2 つの Leader と分けるのは、出発点の違いです。Workato はワークフローから、Boomi はアプリケーションとデータの統合から始まります。MuleSoft は API から始まります。「API 主導の接続性」モデルでは、各基幹システムをガバナンスの効いた再利用可能な API として公開し、その API の上にプロセスを組み立てます。最初の設計作業は増えますが、そのため購買担当は通常、オペレーションチームではなくエンタープライズアーキテクチャ部門になります。

## Agent Fabric：2026 年に変わった部分

Agent Fabric は 2025 年 9 月 25 日に、Salesforce に限らずどこで構築されたエージェントでも扱えるコントロールプレーンとして発表されました。機能は 5 つのグループに分かれます。エージェント、API、MCP ツールを 1 つのカタログで管理する Agent Registry、他プラットフォーム上のエージェントや MCP サーバーを検出する Agent Scanners（ドキュメントでは Amazon Bedrock と AgentCore、Google Vertex AI が挙げられ、製品ページには Microsoft、Claude、Databricks、Kong も記載されています）、マルチエージェントのオーケストレーションを担う Agent Broker、MCP と A2A のトラフィック向けに Flex Gateway 上に構築されたガバナンス層と Trusted Agent Identity、そしてエージェントのネットワークを可視化する Agent Visualizer です。MCP Bridge は、既存の Anypoint API を書き直すことなく MCP ツールとして公開します。

2026 年 10 月 27 日、Salesforce は本番運用向けの制御機能を追加しました。すでに一般提供されているのは、Agent Kill Switch、フェデレーテッド API ゲートウェイ向けのオープンポリシー、FinOps ダッシュボード、Model Wallet によるエージェント単位の支出上限、コスト最適化ポリシーです。まだ提供されていないのは Agent Evals と API Evals で、デプロイ前にテストシナリオを生成し、本番環境のエージェント、LLM、MCP サーバーを評価します。2026 年 11 月にベータ版となり、一般提供は 2027 年 1 月の予定です。評価の失敗を自動停止につなげるトリガー型 Kill Switch も同じく 2027 年 1 月の予定です。

## Agentforce を使っていても Agent Fabric は必要か

エージェントが 1 か所に収まらなくなったときだけ必要です。[Agentforce](/ja/tools/salesforce-agentforce/) は Salesforce 内で構築されたエージェントをすでに統制しています。Agent Fabric が費用に見合うのは、2 つ目のプラットフォームが現れたときです。たとえば [Amazon Bedrock](/ja/tools/amazon-bedrock/) 上のサポートエージェント、[Microsoft Copilot Studio](/ja/tools/microsoft-copilot-studio/) の社内アシスタント、MCP サーバーを [Claude](/ja/tools/claude/) につなぐエンジニアなどがいて、誰かが全体を通して「どんなエージェントが存在し、何にアクセスでき、いくらかかっているのか」に答えなければならない場合です。現時点ですべてのエージェントが Agentforce なら、スキャナーが見つけるものはありません。2 つ目のプラットフォームが登場した時点で再検討してください。

## 購入に値するユースケース

[Salesforce](/ja/tools/salesforce/) が基幹システムで、ERP が [NetSuite](/ja/tools/netsuite/) または SAP である Quote-to-Cash です。MuleSoft の API 主導モデルでは、「顧客」API と「受注」API を一度だけ公開し、それを CRM と ERP の同期、請求ポータル、そして受注履歴を読む必要がある更新エージェントで再利用します。初期設計の元が取れるのは 2 つ目、3 つ目の利用者からです。新しい統合やエージェントは、新たなポイントツーポイント接続を作る代わりに、独自のポリシーと監査証跡を持つガバナンスの効いた API を呼び出します。

## 料金

MuleSoft は 2026 年 9 月に料金体系を刷新しました。現在はすべてが Mule Credits を消費します。これは統合、API、自動化、エージェントで共有される単一の消費単位で、利用タイプごとに異なるクレジット単価が設定され、利用量が増えるほど単価が下がります。パッケージは **月額 2,000 ドル（年間請求）から** で、Govern APIs and AI、Manage Agents（Agent Fabric 全体）、Connect Apps、Process Documents、Access Everything の 5 種類です。購入方法は 3 つあります。Pre-Purchase（クレジットを前払い、最安単価、最低購入額なし）、Pre-Commit（**年間最低コミットメント 50,000 ドル**、使用量に応じて月次請求）、Unlimited（個別の固定価格、クレジット上限なし）です。30 日間の無料トライアルでポートフォリオ全体を試せます。

クレジット単価は公開されていないため、2,000 ドルという入口価格は実際の契約についてほとんど何も教えてくれません。第三者の取引データの方が参考になります。CostBench は 2026 年 4 月時点で検証済みの 74 件の購入をもとに、契約額の中央値を **年間 55,150 ドル** としています。アナリストが引用する Vendr の数字は **約 69,000 ドル** で、観測された契約は 10,000 ドル未満から 250,000 ドル超まで幅があります。最初の本番デプロイには 5 万ドル前後、Agent Fabric と複数の事業部門が対象に入れば 6 桁の予算を見込んでください。

## 最適な対象

Salesforce を中心に据えた企業のエンタープライズアーキテクトや統合責任者で、API 管理と統合を 1 社のベンダーで揃えたい人。さらに、複数のプラットフォームにまたがるエージェントをすでに運用している、あるいは今後運用する見込みがあり、共通のレジストリ、ポリシー層、支出上限が必要な組織に向いています。

## 代替候補と選ぶべき場面

- **[Workato](/ja/tools/workato/)**：要件が API プログラムではなく、オペレーションや IT の自動化チームが担うシステム横断のワークフローで、先に API 層を設計せずにエージェント向けツール（Workato One、Enterprise MCP）を使いたい場合に選びます。
- **[Boomi](/ja/tools/boomi/)**：2026 年で 12 回連続の Leader です。環境が Salesforce 中心ではなく、より低い入口価格でアプリケーションとデータの統合を行いたい場合に選びます。
- **[n8n](/ja/tools/n8n/)**：最も急成長している新興勢力です。セルフホストが可能で、エンジニアがいて、5 桁ドルの最低額なしにエージェントワークフローを組みたい場合に選びます。
- **[Zenity](/ja/tools/zenity/) または [Runlayer](/ja/tools/runlayer/)**：必要なのがエージェントの検出とセキュリティガバナンスだけで、そのために統合プラットフォームを買う理由がない場合に選びます。

## 注意点

- **クレジット単価が非公開のため、最初の見積もりを検証しにくい。** 対策：署名前に、消費するすべての利用タイプのクレジット単価表を注文書に明記させ、その単価表で取引量上位 5 件の統合と、想定されるエージェント・モデル呼び出し量のコストを算出してください。クレジットの上限に達したときに何が起きるか（超過料金、自動アップグレード、停止）も確認してください。
- **既存の vCore 顧客は異なる単位で更新することになる。** 対策：更新の少なくとも 2 四半期前に、現行の vCore 契約をクレジットに換算した対照表をアカウントチームに依頼し、並行して Workato か Boomi の見積もりを取り、換算を受け入れるのではなく交渉の対象にしてください。
- **Model Wallet の上限は MuleSoft の Model Proxy を通るトラフィックしか把握できない。** 自前のキーでモデルプロバイダーを呼び出すエージェントは予算から見えず、ドキュメントでも上限は概算と説明されています。対策：本番のモデルキーをすべてプロキシ経由にし、エージェントチームが持つ直接のプロバイダーキーを無効化したうえで、最初の 2 か月は FinOps ダッシュボードとプロバイダーの請求書を突き合わせてください。
- **Agent Evals は 2027 年 1 月までベータ版。** 対策：一般提供されるまでは、自動評価やトリガー型 Kill Switch を前提にしたリリースゲートを設計しないでください。それまでは手動の Kill Switch と人によるレビュー工程を Runbook に残しておきます。
