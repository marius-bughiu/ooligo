## What it is

Lovable is a prompt-to-app builder. You describe an app in chat, and it writes a full-stack web application — React and Tailwind on the front end, a Supabase-based backend for data, auth and file storage — then hosts it. The code is not locked inside the product: it syncs to a GitHub repository, so an engineer can review pull requests and keep building in their own editor. That exit is the main thing separating Lovable from classic low-code canvases like [Retool](/en/tools/retool/), where the app lives in the vendor's format.

It is also the fastest-growing entrant in the internal-app segment, measured by revenue. Stockholm-based and founded in 2023 by Anton Osika and Fabian Hedin out of the open-source GPT Engineer project, it raised a $400M Series C led by Menlo Ventures at a $13.3B valuation on 12 August 2026 (TechCrunch), eight months after a $330M Series B at $6.6B. Co-founder Fabian Hedin said on 24 September 2026 that annualised revenue had crossed $600M, roughly triple the $200M it reported in November 2025. Lovable says 60 million-plus projects have been created and that employees at nearly two-thirds of the Fortune 500 use it.

## Why ops teams end up here

Because ops people are already using it, usually before IT knows. The typical request — a partner portal, an intake form with a review queue, a commission dashboard over CRM data — is small enough that engineering will never prioritise it and specific enough that a spreadsheet stops working. Lovable closes that gap in an afternoon. The Series C release named Salesforce, Google Workspace, Microsoft 365 and Stripe as connectors, and Lovable Cloud gives each app a database, auth and storage without a separate Supabase account.

On Enterprise, the governance layer now exists: SSO/SAML, SCIM provisioning, audit logs, publishing controls that restrict who can ship and who can see the result, and Security Insights, which lists every app in the workspace ranked by risk. Lovable reports SOC 2 Type II, ISO 27001 and AIUC-1 certification.

## A use case worth buying it for

A RevOps or CS lead needs a customer- or partner-facing app that reads a handful of tables: a renewal-quote request portal, a partner deal-registration form that writes to Salesforce, a legal-intake page routing requests by matter type. None of these needs row-level permissions against a production warehouse; all of them need to look finished. Build it in Lovable, sync it to GitHub on day one, and hand the repository to an engineer if the app outlives its pilot.

## Pricing

Free gives 5 credits a day, capped at 30 a month. Pro starts at $25/month ($250/year) for 100 monthly credits, with larger Pro tiers at 200 credits for $50, 400 for $100 and 800 for $200 (No Code MBA, checked against lovable.dev). Business starts at $50/month and adds SSO, data-training opt-out, role-based access and internal publishing. Enterprise is quote-only.

Credits are the meter, and consumption varies by task: Lovable's own examples run from 0.5 credits for a one-line style change to 1.7 for a landing page with images. Top-ups cost $15 per 50 credits on Pro ($0.30/credit) and $30 per 50 on Business ($0.60/credit). Hosting and in-app AI draw on separate Cloud and AI balances with a monthly grant; beyond it, usage is billed. The real-world band for a small ops team building two or three internal apps is $50-200/month; a team iterating daily lands at the $100-200 Pro tier, or pays Business rates for SSO.

## Best for

Ops, RevOps and CS leads at 20-500-person companies who need a polished, standalone app — a portal, intake form or lightweight dashboard — that a non-engineer can build and an engineer can inherit from GitHub later.

## Alternatives, and when to pick them instead

- **[Retool](/en/tools/retool/)** — the segment leader for engineer-built internal tools, reporting $120M ARR in October 2025. Pick it when the builders write SQL and the app sits on production databases with per-query permissions.
- **Microsoft Power Apps** — the other market-share leader, bundled into M365 licensing. Pick it when the app is a form over SharePoint or Dataverse and IT owns the build.
- **[Superblocks](/en/tools/superblocks/)** — pick it when the reason you are evaluating is governance: it imports Lovable prototypes and re-hosts them against governed connections with row-level permissioning.
- **[Airtable](/en/tools/airtable/)** — pick it when the "app" is a shared table with views and automations, and nobody needs custom UI.

## Watch-outs

- **Lovable's own security record in 2026.** Between 3 February and 20 April 2026, a backend regression exposed chat histories and source code of public projects to any authenticated Lovable user; HackerOne reports were closed as intended behaviour before Lovable acted (Lovable, 22 April 2026). Lovable fixed the regression and converted historical public projects to private. Guard: require private projects workspace-wide, keep API keys in Cloud secrets rather than in prompts or code, and rotate any credential that ever appeared in a chat.
- **Generated apps inherit whatever security the prompt asked for.** In March 2025 a researcher found more than 170 Lovable-built apps whose Supabase tables lacked access policies, leaving data publicly readable (CVE-2025-48757). Guard: run Lovable's security scan before every publish, then have an engineer review row-level-security policies on any table holding customer data before the app goes live.
- **Credit burn is hard to forecast.** Iterating on a bug through chat spends credits on each attempt, and Business top-ups cost twice the Pro rate. Guard: pilot on one Pro seat for a full billing cycle, record credits per shipped feature, then size the tier; move stuck fixes to GitHub and an engineer instead of re-prompting.
- **Apps live on Lovable's hosting by default.** Guard: connect GitHub before the first production use so the code and history exist outside Lovable, and confirm who owns the Supabase or Cloud data export if you leave.
