## 概要

OpenCode は、どのモデルプロバイダーとも組み合わせて使える MIT ライセンスのコーディングエージェントです。タスクを説明すると、リポジトリを読み、ファイルを編集し、シェルコマンドを実行して結果を報告します。[Claude Code](/ja/tools/claude-code/) や [OpenAI Codex](/ja/tools/openai-codex/) と同じループです。違いは、エージェントが特定の AI ラボに縛られない点です。Anthropic、OpenAI、Google の API、[OpenRouter](/ja/tools/openrouter/)、[LiteLLM](/ja/tools/litellm/) のようなセルフホスト型ゲートウェイ、ローカルモデルなど、200 以上のプロバイダーに接続できます。

開発はプロジェクトの運営企業である Anomaly がオープンに進めています。GitHub リポジトリ（anomalyco/opencode）は、2026年11月22日に確認した時点でスター数約 228,000、コントリビューター 1,000 人超でした。ホームページの「22M+ developers every month」という数字はベンダー自身の発表で、監査されたものではありません。

2026年10月中旬に発表された OpenCode 2.0 では、クライアント/サーバー構成がデフォルトになりました。ローカルサーバーがエージェントのループを実行し、そこにクライアントが接続します。SSH 越しでも動くターミナル UI、macOS・Windows・Linux 向けデスクトップアプリ（まだベータ表記）、早期アクセス中のモバイルアプリ、そして SDK です。2.0 ではバックグラウンドタスクと、スキルやプラグインのホットリロードも追加されました。

## ops チームが注目する理由

CRM 同期スクリプトや独自の MCP サーバーを書く RevOps や Legal Ops のエンジニアは、たいてい会社の AI ベンダーに付属するエージェントを使うことになります。OpenCode が選ばれる理由は 3 つあります。

- **単一ベンダーに縛られない。** 同じエージェント、同じ設定、同じスキルが Claude、GPT、Gemini、安価なオープンモデルのいずれでも動きます。会社が主要な AI 契約を切り替えても、エンジニアリングのワークフローは変わりません。
- **既存のシートが使える。** ChatGPT Plus / Pro のサブスクリプションや [GitHub Copilot](/ja/tools/github-copilot/) のシートでログインできるため、すでに支払っている費用の上にエージェントを載せられます。Claude Pro と Max のログインには対応していません。OpenCode は Anthropic からの法的要請を受けて 2026年初めにこれを削除したため、Claude モデルを使うには API キーか Console が必要です。
- **無料ツールでも中央でポリシーを管理できる。** 管理者はシステム設定ファイル（Linux は `/etc/opencode/opencode.json`、macOS は `/Library/Application Support/opencode/opencode.json` または MDM 経由、Windows は `%ProgramData%\opencode\opencode.json`）を配布でき、これはユーザー設定やプロジェクト設定より優先されます。プロバイダー、ツール、MCP サーバーを制限できます。

## 実際の価格

エージェント自体は無料です。料金はモデルに対して支払い、方法は次の 4 つです。

- **手持ちのアカウントを使う**：任意のプロバイダーの API キー、または ChatGPT か Copilot のログイン。追加費用は $0 です。
- **OpenCode Go**：厳選された 32 モデルのサブスクリプションで、大半はオープンウェイトモデル（Kimi、GLM、Qwen、DeepSeek）、加えていくつかのクローズドモデルです。Go は月額 $10、Go Plus は月額 $40、Go Teams はメンバー 1 人あたり月額 $20（最低 2 人）です。各プランの利用枠はモデルごとにドル建てで設定され、5 時間の枠内で使えるのは枠の 20% まで、1 週間では 50% までです。
- **Console（従量課金）**：トークン単位で課金されるプリペイドクレジットです。クレジット購入ごとに 4.6% + $0.31 の決済手数料がかかり、それ以外の上乗せはありません。ワークスペースにはメンバーごとの予算を設定できます。
- **Enterprise**：個別見積もりで、SSO（Okta、Entra ID、Google Workspace、任意の OIDC / SAML 2.0 プロバイダー）、SCIM、予算、ポリシー管理が加わります。

実際のコストはプランではなくモデルで決まります。Console では Claude Opus 5.5 が 100 万トークンあたり入力 $4 / 出力 $20、割引中の GLM 5.3 は $0.56 / $1.76 で、トークン単価は約 7〜11 分の 1 です。定型作業（リファクタリング、テスト修正、設定変更）をオープンモデルに回し、難しいタスクだけフロンティアモデルを使うチームが、OpenCode の節約効果の大半を得られます。すべてを Opus で動かすチームは、API を直接使った場合とほぼ同じ金額を払うことになります。

## 最適な用途

エンジニアリングのワークフローを単一の AI ラボに縛りたくない企業、あるいはすでに ChatGPT や Copilot のシートを払っていて、その上で使える有能なターミナルエージェントがほしい企業の RevOps エンジニア、GTM エンジニア、Legal Ops や採用 ops の技術担当者です。最も効果が出るのは、小規模な ops エンジニアリングチーム（2〜10 人）が管理された設定のもとで 1 つのエージェントに標準化し、プロバイダーのキーを会社が保持し、高価なモデルは本当に必要なタスクだけに使うケースです。Go Teams プランなら、超過利用を除いて 1 人あたり年間 $240 です。

## 向いていないケース

エージェントとモデルの両方について責任を負う単一の窓口と、チェーン全体をカバーする署名済み DPA を求めるチームには向きません。自前のキーを使う場合、OpenCode はクライアントにすぎず、データは各プロバイダーがそれぞれの規約に基づいて保持します。エンジニアにとってはすっきりしていますが、購買部門にとっては扱いにくい構成です。また、diff をレビューしない人にも向きません。デフォルトの権限では、エージェントは確認なしに操作を実行します（後述）。エンジニアでない人には、より制約の強いツールが必要です。

## 代替ツールとの比較

- **[Claude Code](/ja/tools/claude-code/)**：売上で最大のコーディングエージェントで、月額 $20 からの Claude プランに含まれます。どのみち Claude を使うつもりで、routines、Code Review、単一のベンダー契約がほしいなら Claude Code を選んでください。OpenCode は Claude のサブスクリプションを使えないため、OpenCode 経由で Claude を使うと API 料金がかかります。
- **[GitHub Copilot](/ja/tools/github-copilot/)**：シート数で最大の導入実績があり、ユーザー 1 人あたり月額 $19（Business）または $39（Enterprise）です。GitHub Enterprise の中で多数の開発者にインライン補完を提供したい場合に選んでください。両方を使うチームも多く、Copilot のシートで OpenCode にログインしています。
- **[OpenAI Codex](/ja/tools/openai-codex/)**：最も急成長している新規参入者で、ChatGPT プランに含まれます。会社が ChatGPT Business に標準化していて、OpenAI 純正のエージェントと管理・コンプライアンス機能を求める場合に選んでください。エンジニアが OpenCode の UI を好むなら、同じ ChatGPT ログインがそちらでも使えます。
- **[Cursor](/ja/tools/cursor/)**：ターミナルから任せるより、IDE の中で編集を視覚的に操作したいエンジニアにはこちらを選んでください。

## 標準化しても安全か

2026年10月17日、OpenCode は、攻撃者が夜間に旧システムに侵入し、OpenCode Console のワークスペースに保存されていたプロバイダーの API キーに到達したと公表しました。影響を受けたのは Console ユーザーの 1.4% です。TechCrunch は、個人アカウントで数百ドル、一部では $1,000 を超える請求が発生したと報じました。Anthropic と Google は漏えいしたキーをブロックし、OpenAI はアクセスを復旧して API 顧客に返金し、OpenCode は返金を進めていると述べました。共同創業者は、オープンソースの CLI とアプリは影響を受けていないとしています。2026年11月22日時点で、OpenCode は侵入経路もキーの保存方法も公表していません。

私たちの見解：管理された設定のもとでなら、ローカルのエージェントは標準として妥当です。一方、会社のプロバイダーキーを Console に保存するのは、原因分析レポートが出るまでは避けるべきです。

## 注意点

- **デフォルトのポリシーはほぼすべてを許可する。** V2 の権限モデルでは、すべてのエージェントが「すべて許可」のルールから始まります。確認が入るのは `.env` ファイルの読み取りだけで、プロジェクトフォルダー外の編集も確認なしで進みます。対策：システムレベルの `opencode.json` を配布し、`shell`、`external_directory`、CRM に書き込む MCP ツールに `ask` か `deny` を設定してください。管理設定のポリシーアクションにはバージョン 2.2.3 以降が必要なので、最低バージョンを強制してください。
- **ホスト型のキー保管が攻撃対象になる。** 10月の侵害で狙われたのはノート PC ではなく、Console に置かれたキーでした。対策：プロバイダーのキーは自社のシークレットマネージャーか LiteLLM のようなゲートウェイの背後に置き、エンジニアごとにプロバイダー側で月次の支出上限を設けたスコープ付きキーを発行し、退職時には SCIM でキーを失効させてください。
- **無料モデルと一部の有料モデルはデータを保持または学習に使う。** 保持期間はモデルによって異なります。Go で提供されるオープンモデルの大半はゼロリテンションですが、OpenAI、Anthropic、xAI のモデルは 30 日、Google は最長 55 日保持し、一部の無料モデルはプロンプトを学習に使う場合があります。対策：`OPENCODE_DISABLE_FREE_MODELS=1` を設定するか管理設定で無料枠をブロックし、自社の DPA がカバーするプロバイダーだけを許可してください。
- **2.0 以降のリリースの不安定さ。** Hacker News のローンチスレッドでは、npm パッケージでまだ 2.0 がインストールされず、postinstall エラーが出るという報告がありました。対策：インストールスクリプトでバージョンを固定し、新しいリリースは 1 人のエンジニアが 1 週間使ってからチーム全体を更新し、プラグインは各自にインストールさせずポリシーで許可してください。
