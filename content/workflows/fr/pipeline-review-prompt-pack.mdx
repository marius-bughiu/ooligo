Un pack de douze prompts éprouvés pour les questions auxquelles une revue de pipeline doit réellement répondre. Collez un export de deals, collez un prompt, obtenez une réponse structurée dans le vocabulaire de votre équipe. Pas d'agent, pas d'API, pas d'intégrations. Juste les prompts, classés par fréquence d'utilisation.

## Ce dont vous aurez besoin

- [Claude](/fr/tools/claude/).ai (niveau Sonnet ou Opus)
- Un CSV ou tableau markdown de votre pipeline ouvert avec nom du deal, montant, étape, jours dans l'étape, propriétaire et dernière activité
- Votre fiche de synthèse de méthodologie commerciale, collée une fois en tête du projet

## Setup

1. **Créez un projet Claude.** Nommez-le « pipeline-review ». Déposez le doc de méthodologie comme connaissance du projet. Désormais chaque prompt du pack commence avec le bon contexte.
2. **Importez les prompts.** Copiez chacun des douze prompts comme prompt sauvegardé dans le projet. Étiquetez-les par cas d'usage : revue hebdomadaire, préparation pour le board, analyse approfondie, escalade.
3. **Collez le pipeline.** La plupart des prompts attendent le tableau inline. Deux d'entre eux attendent l'historique complet d'un seul deal. Le pack indique lequel est lequel.
4. **Exécutez les trois les plus utilisés en premier.** « Trouve les commits à risque », « classe les deals par crédibilité de la close date » et « rédige le talk-track manager ». Ces trois couvrent 80 % de l'usage hebdomadaire.

## Comment ça fonctionne

Les douze prompts sont organisés en trois niveaux. Le niveau un est portfolio : classement, segmentation, détection de glissement. Le niveau deux est deal unique : diagnostic de deal bloqué, analyse des gaps MEDDPICC, proposition de prochaines étapes. Le niveau trois est préparation de réunion : talk-tracks manager, one-pagers exécutifs et le prompt « quoi demander au rep » que les managers adorent.

Chaque prompt est structuré de la même façon : rôle, contexte, format d'input, format d'output, une liste explicite de choses à éviter. La section « choses à éviter » est la héros méconnu. Elle bannit les formulations d'entreprise vagues, empêche Claude d'inventer des données absentes du tableau, et force des chiffres précis plutôt que du langage vague.

## Points de vigilance

- **Garbage in, garbage out.** Si votre export de pipeline manque de dates de dernière activité, le prompt de risque va deviner. Incluez toujours la colonne d'activité.
- **Inadéquation de méthodologie.** Un prompt MEDDPICC exécuté sur une équipe formée au BANT produit une sortie peu familière. Remplacez le doc de méthodologie, n'éditez pas les prompts.
- **Spécificités hallucinnées.** Claude inventera avec confiance le nom d'un champion si vous le lui permettez. Les prompts incluent des gardes « si un champ est manquant, dites-le ». Conservez-les.
- **Dérive de longueur.** La sortie s'allonge avec le temps à mesure que vous posez des questions de suivi. Réinitialisez la conversation entre les deals.

## Stack

- **Claude** — couche modèle, connaissance du projet, prompts sauvegardés
- **Export CSV** — données pipeline dans une forme lisible par Claude
- **Doc de méthodologie** — la lentille qui rend la sortie utile
