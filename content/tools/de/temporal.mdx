## Was es ist

Temporal ist eine Plattform für Durable Execution: Sie schreiben einen Workflow als gewöhnlichen Code in Go, Java, TypeScript, Python oder .NET, und Temporal protokolliert jeden Schritt, sodass der Workflow Abstürze, Deployments, Rate Limits und wochenlange Wartezeiten übersteht, ohne seine Position zu verlieren. Fällt ein Worker mittendrin aus, spielt ein anderer Worker die Historie ab und macht beim letzten abgeschlossenen Schritt weiter. Retries, Timeouts, Timer und Signale von Menschen oder anderen Systemen sind Primitive, kein Code, den Sie selbst schreiben müssen.

Der Server ist Open Source unter der MIT-Lizenz und lässt sich selbst hosten. Temporal Cloud ist der Managed Service, und damit verdient das Unternehmen sein Geld. Temporal nennt mehr als 4.000 Kunden, darunter OpenAI, Cursor, Netflix und JPMorgan Chase. Temporal ist auch Infrastruktur, auf der andere Anbieter aufbauen: Maestro, der Agent-Orchestrator von [UiPath](/de/tools/uipath/), läuft auf der Engine von Temporal.

Was es nicht ist: ein visuelles Automatisierungs-Tool. Es gibt keine Drag-and-Drop-Oberfläche, keine Bibliothek vorgefertigter SaaS-Konnektoren und keinen Formular-Builder für Fachanwender. Jeder Workflow ist Code, den ein Engineer schreibt, testet und deployt.

## Warum Ops-Verantwortliche jetzt darauf stoßen

Agent-Workflows laufen ihrer Natur nach lange. Ein Agent, der einen Account recherchiert, ein Angebot entwirft, zwei Tage auf die Freigabe einer Führungskraft wartet und dann das CRM aktualisiert, muss seinen Zustand über LLM-Timeouts, Tool-Fehler und eine menschliche Pause hinweg halten. Temporals Antwort: Die Agent-Schleife wird zum Workflow, und jeder Modell- und Tool-Aufruf wird zur Activity. Ein fehlgeschlagener Aufruf wiederholt sich selbst, ein abgeschlossener wird nie erneut ausgeführt und erneut abgerechnet. Die Integration mit dem OpenAI Agents SDK ist allgemein verfügbar, und seit Replay 2026 im Mai gibt es Serverless Workers, seit dem 3. August 2026 als Public Preview auf AWS Lambda, sodass Teams keine eigene Worker-Flotte mehr betreiben müssen.

Das Unternehmen ist gut finanziert und unabhängig: eine Series D über 300 Mio. $ im Februar 2026, dann eine Series E über 550 Mio. $ bei einer Bewertung von 12,55 Mrd. $ am 14. September 2026, angeführt unter anderem von Lightspeed. Im Oktober 2026 kaufte Temporal Oso, ein Start-up für Autorisierung. Das deutet darauf hin, dass Berechtigungen für Agents die nächste Schicht sind, die Temporal besetzen will.

## Ein Use Case, der den Kauf rechtfertigt

Eine Pipeline für eingehende Verträge in einem Legal-Ops-Team, das 50.000 Lieferantenverträge pro Jahr bearbeitet. Jeder Vertrag startet einen Workflow: Text extrahieren, [Claude](/de/tools/claude/) das Risiko Klausel für Klausel klassifizieren lassen, Verträge mit geringem Risiko automatisch freigeben und alles Nicht-Standardmäßige an einem Signal parken, das bis zu fünf Tage auf einen Anwalt wartet, mit einem Timer, der nach 48 Stunden eskaliert. Wenn der Modellanbieter um 3 Uhr nachts ein Rate Limit setzt, wiederholt sich die Activity mit Backoff, statt den Vertrag zu verlieren. Wenn das Team eine neue Version des Klassifikators ausrollt, laufen Verträge, die bereits in Bearbeitung sind, auf dem alten Code zu Ende. Diese Garantie ist der Kaufgrund.

## Preise

Temporal Cloud rechnet nach **Actions** ab: Jeder Workflow-Start, jeder Activity-Start oder -Retry, jeder Timer, jedes Signal, jede Query und jedes Update zählt als eine Action. Der Einstiegsplan hat keine Grundgebühr und berechnet 50 $ pro Million Actions plus Support in Höhe von 10 % der Nutzung; der frühere Essentials-Plan für 100 $ im Monat steht nicht mehr in der Preisliste. **Business** kostet den höheren Betrag aus 500 $ im Monat oder 10 % der Nutzung, enthält 2,5 Millionen Actions und senkt den Preis für Mehrverbrauch in Stufen von 50 $ auf 25 $ pro Million. **Enterprise** und die Premium-Stufe darüber sind Jahresverträge mit 10 Millionen inklusive Actions und 24/7-Support. Speicher wird separat pro GB-Stunde abgerechnet. Neue Konten erhalten 150 $ Guthaben, gültig für 90 Tage.

Realistische Spannen, zu Listenpreisen und ohne Speicher:

- **Pilot, 2 Mio. Actions pro Monat** (rund 50.000 Läufe mit je 40 Actions): etwa 110 $ im Monat im Einstiegsplan.
- **Produktivteam, 20 Mio. Actions pro Monat**: etwa 1.275 $ im Monat in Business.
- **Plattformmaßstab, 100 Mio. Actions pro Monat**: etwa 3.850 $ im Monat in Business, vor Rabatten für zugesagte Ausgaben.

Den Open-Source-Server selbst zu hosten kostet keine Lizenzgebühren, aber Datenbank, Visibility-Store und Upgrades betreiben Sie selbst. Planen Sie mindestens die Zeit eines Platform Engineers ein, bevor sich das rechnet.

## Am besten geeignet für

Ops-Teams mit Engineering-Rückhalt — ein RevOps-Engineering-Pod, ein Legal-Tech-Team, eine Plattformgruppe, die Recruiting unterstützt —, die Agent- oder Prozess-Workflows über Stunden oder Wochen laufen lassen müssen, mit Retries, menschlichen Pausen und Nebeneffekten, die genau einmal ausgeführt werden, und die diese Workflows als Code unter Versionskontrolle haben wollen.

## Alternativen und wann Sie sie stattdessen wählen

- **AWS Step Functions** — die Standardwahl unter den Managed Services für AWS-Teams, 25 $ pro Million State Transitions bei Standard-Workflows. Wählen Sie es, wenn ohnehin alles in AWS läuft und die Workflows kurze State Machines sind, die Sie gern in JSON statt in Code definieren.
- **Azure Durable Functions** — die Standardwahl für Azure-Teams, mit Durable Orchestrations als Code. Wählen Sie es, wenn das Team auf Azure und .NET setzt und keinen neuen Anbieter will.
- **Restate** — der sichtbarste neue Herausforderer, mit einer Series A über 20 Mio. $ am 30. September 2026 und Replit Agent als genanntem Nutzer. Wählen Sie es, wenn Sie Durable Execution als einzelnes, schlankes Binary wollen und einen deutlich kleineren Anbieter akzeptieren.
- **[Camunda](/de/tools/camunda/)** oder **[Appian](/de/tools/appian/)** — wählen Sie diese, wenn Fachbereiche den Prozess als Diagramm lesen, freigeben oder bearbeiten müssen oder eine Aufsichtsbehörde ein BPMN-Modell erwartet.
- **[n8n](/de/tools/n8n/)** — wählen Sie es, wenn der Workflow in Minuten durchläuft, vorgefertigte Konnektoren braucht und eine Person aus dem Ops-Team statt eines Engineers ihn verantwortet.

## Worauf Sie achten sollten

- **Die Zahl der Actions überrascht.** Retries, Timer, Signale, Queries aus der UI und jeder geplante Lauf (drei Actions) werden abgerechnet, und eine Retry-Schleife um eine instabile API kann die Kosten vervielfachen. Absicherung: Zählen Sie die Actions pro Lauf in einem Staging-Namespace, bevor Sie sich auf einen Plan festlegen, und begrenzen Sie die Retries bei jeder Activity, die eine kostenpflichtige API aufruft.
- **Determinismus ist Programmierdisziplin.** Workflow-Code muss sich identisch wieder abspielen lassen. Wer direkt im Workflow-Code die Uhrzeit abfragt, eine Zufallszahl erzeugt oder eine API aufruft, bricht ihn in Produktion. Absicherung: Halten Sie jeden Nebeneffekt in Activities, nehmen Sie die Replay-Tests des SDK in die CI auf und nutzen Sie die Versionierungs-APIs, bevor Sie einen laufenden Workflow ändern.
- **Es braucht dauerhaft Engineers.** Es gibt keine Oberfläche, mit der das Ops-Team selbst Workflows baut. Absicherung: Setzen Sie Temporal nur hinter Prozesse, die ein Engineering-Team bereits verantwortet, und lassen Sie einfache App-zu-App-Automatisierungen auf n8n oder einer iPaaS.
- **Serverless Workers sind noch in der Preview.** Absicherung: Betreiben Sie produktive Worker in eigenen Containern, bis Temporal die Lambda-Option als allgemein verfügbar kennzeichnet.
