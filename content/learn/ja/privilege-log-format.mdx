特権ログとは、ディスカバリーの提出物に添付される文書であり、[特権](/ja/learn/privilege-review/)を理由に差し控えられたすべての文書を列挙し、保護された内容を明かすことなく相手方代理人と裁判所が特権の主張を評価するのに十分な情報を提供するものです。連邦民事訴訟規則26(b)(5)(A)がこれを要求しており、ほとんどの州規則および国際的な同等規則も同様の義務を課しています。適切に作成された特権ログは異議申立てに耐えますが、不適切に作成された場合は申立実務や（最悪の場合）特権放棄の認定を引き起こします。

## 2つの特権ログフォーマット

### 文書別ログ

米国連邦訴訟のほとんどでデフォルトとなります。差し控えられた文書ごとに1行、相手方代理人が主張を評価できるメタデータとともに：

| フィールド | 必要な内容 |
|---|---|
| Bates番号 | 提出物における一意の識別子 |
| 日付 | 文書の日付または送信日付 |
| 作成者 | 作成した弁護士または当事者 |
| 受信者（To／Cc／Bcc） | 種類の指定を含むすべての受信者 |
| 文書の種類 | メール、メモ、契約書草案など |
| 主題 | 内容を明かさない一般的なトピック |
| 特権の根拠 | 弁護士・依頼人特権／ワークプロダクト／その他 |
| 特権の説明 | 保護される理由の簡単な説明 |

大規模な案件の特権ログには数千のエントリが含まれることがあります。特権のある会話の各メール（会話全体に1つではなく）に1エントリが必要です。

### カテゴリカルログ（「カテゴリ別」ログ）

裁判所命令または当事者合意により、大量ケースでますます使用されています。文書はカテゴリにグループ化され（例：「2024〜2025年のMatter Xに関するリード訴訟弁護士と一般弁護士間の通信」）、カテゴリごとに文書数を含む1つのログエントリが作成されます。

カテゴリカルログはログ生成コストを大幅に削減しますが、裁判所または相手方代理人の合意が必要であり、有意義な評価を支援するのに十分なカテゴリごとの詳細が求められます。

## 良い特権ログエントリの例

悪い例：`法的助言に関するメール。特権あり。`

より良い例：`マスターサービス契約第8.3条に基づく免責条項に関する主張の評価について、社外弁護士から一般弁護士へのメール。法的助言を求め提供する弁護士・依頼人特権のある通信。`

2番目のエントリは相手方代理人に対して：
- 通信が弁護士から依頼人へのものであることを示す（特権の要素）
- 主題が法的助言であることを示す（特権の要素）
- 内容を明かさずに具体的な主題を示す
- 主張の合理的な根拠を示す

## 特権ログに対する一般的な異議申立て

相手方代理人が典型的に異議を申し立てるのは：

- **曖昧な説明。** 主題なしの「法的助言に関して」
- **膨らんだログ。** 実際には特権がない文書がログに含まれている（ビジネス通信、事実のみの内容）
- **エントリの欠落。** ログにあるべき文書がない（不注意な提出または過少申告を示唆）
- **一貫しない扱い。** ある保管者のログでは差し控えられているが、別の保管者のものでは提出されている同じメール
- **不適切な「特権」の主張。** 適用法の下で実際には特権のない文書（社内のビジネスアドバイス、弁護士のカレンダーエントリ）

各異議申立ては申立て手続き、インカメラレビュー、または最終的な特権放棄の認定につながる可能性があります。

## 運用方法

1. **案件受任時に特権ログテンプレートを作成する。** レビュー開始前にフォーマット、フィールド、詳細度基準を定義します。審理中途のフォーマット変更はコストがかかります。
2. **レビューツールのメタデータから自動入力する。** [Relativity](/ja/tools/relativity/)、[Everlaw](/ja/tools/everlaw/)、[DISCO](/ja/tools/disco/)はすべて、レビュータグからBates、日付、当事者、文書タイプを自動入力します。レビュアーが主題と根拠を追加します。
3. **AI支援による主題生成。** LLMが墨消しされた文書の内容から主題の説明を草案し、弁護士が最終化します。大規模なコスト削減。
4. **可能な場合は相手方代理人とカテゴリカル合意を結ぶ。** 大量ケースでは、早期にカテゴリカルログ構造を提案します。カテゴリが十分に詳細であれば、ほとんどの相手方代理人は同意します。
5. **最終弁護士レビュー。** ログを提出する前に、弁護士が各エントリの十分性、一貫性、正確性をレビューします。最低10%のエントリをサンプリングし、新規の特権根拠のあるエントリは100%レビューします。
6. **各エントリの履歴の監査ログ。** 誰がいつ何を特権としてタグ付けし、誰がレビューし、誰が最終化したか。事後の異議申立てに対する防御に不可欠です。

## よくある落とし穴

- **定型文の説明。** 数千のエントリにわたる同一の説明は自動的に異議申立てを招きます。各エントリには文書固有の主題が必要です。
- **草案の不一貫な扱い。** 草案は最終版とは異なる特権分析を持つことが多いです。特権として表示された草案はそれ自体のメリットで評価されるようにしてください。
- **メタデータの無視。** 受信者を除外したログエントリは評価を不可能にします。相手方代理人は異議申立てします。
- **弁護士のCCによる過度の主張。** ビジネス通信にCCされた弁護士が自動的にその通信を特権化するわけではありません。過度の主張は異議申立てを招きます。
- **ワークプロダクトを別途忘れる。** ワークプロダクトと弁護士・依頼人特権は別個の法理であり、要件も別々です。ログはどちら（時に両方）が適用されるかを明示すべきです。
