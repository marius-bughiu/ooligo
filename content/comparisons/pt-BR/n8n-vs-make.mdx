n8n vs Make é o head-to-head apertado em automação de workflow mid-tier, e a escolha é mais gosto que categoria. n8n é open-source, developer-leaning e cada vez mais AI-native com nós nativos LangChain. Make (antigo Integromat) é visual-first, polido e ótimo em cenários complexos com branching. Os dois são dramaticamente mais baratos que o Zapier em volume. Escolher entre eles é principalmente sobre quão técnico o seu time de ops é.

## Onde n8n ganha

- **Open source e self-hostável.** O código do n8n está no GitHub e você pode rodar na sua própria infra. Make é fechado e cloud-only. Para times pesados em compliance, isso importa.
- **Code nodes e flexibilidade de developer.** Nós nativos JavaScript e Python, requests HTTP customizados e uma primitiva de workflow flexível que dobra para requisitos esquisitos.
- **Integrações de IA e LLM.** n8n entregou nós estilo LangChain cedo e vem empurrando workflows de IA agressivamente. Make tem features de IA mas com menos profundidade.

## Onde Make ganha

- **Construtor visual de workflow.** O scenario editor do Make é genuinamente mais polido que o canvas do n8n. Para branching complexo com iterators e aggregators, Make é uma experiência visual melhor.
- **Maturidade do módulo de operations.** Routers, iterators, aggregators e error handlers no Make são battle-tested em formas em que o n8n ainda está amadurecendo.
- **Preço para volume baixo-médio.** O preço operations-based do Make pode ser mais barato que n8n Cloud para workflows de volume médio que não justificam self-hosting.

## Quando usar os dois / Realidade de preço

Geralmente você não roda os dois — eles são substitutos. Preços: n8n Cloud Starter é US$ 24 por mês com 2.500 execuções; Pro é US$ 60 com 10K. Self-hosted é grátis. Make Core é US$ 10,59 por mês com 10K operações. Os dois são 5x a 50x mais baratos que o Zapier em escala.

## Veredito

- **Escolha n8n** se você tem um developer no loop, quer self-hosting, ou está construindo workflows AI-native.
- **Escolha Make** se o seu time é visual-first, os seus workflows são complexos mas no-code, e você não precisa de self-hosting.
- **Use os dois** raramente — escolha um e padronize.

O único erro a evitar: escolher baseado num único cenário complexo que você prototipou. A ferramenta certa é aquela que o seu time de ops vai operar por dois anos, não a que ganha uma demo.
