エージェンティック CLM とは、AI エージェントが契約に対する複数ステップの作業を自ら選んで実行する契約ライフサイクル管理プラットフォームのことです。次に何をするかを決め、ツールを呼び出し、レコードに書き戻します。ユーザーがパネルに入力した質問に答えるだけの仕組みとは別物です。境界線はモデルでも出力品質でもありません。次の一手を誰が決めるか、そこにあります。Anthropic のエンジニアリング上の定義もソフトウェア一般について同じ線を引いています。ワークフローはモデルとツールがあらかじめ定義されたコードパスを通る仕組みであり、エージェントはモデルが自分のプロセスとツール利用を自ら方向づける仕組みです。AI アシスタントを後付けした CLM は前者です。エージェンティック CLM は後者だと主張しています。

これに当たらないもの。第一に、リポジトリ上のチャットパネルです。「この MSA のうち Q4 に自動更新されるのはどれか」と尋ねて良い答えが返るのは検索・取得であり、「エージェンティック」という語がこの分野に現れる前から、まともな CLM はすべて備えていました。第二に、これらのプラットフォームが何年も抱えてきた条件付き承認ルーティングでもありません。*金額が $50K を超えたら GC に回す* は決定論的な分岐であり、名前を変えてもエージェントにはなりません。第三に、抽出でもありません。署名済み PDF を構造化フィールドに変えるのはエージェントが消費する入力であって、エージェンティックな振る舞いそのものではありません。この層については [契約データ抽出](/ja/learn/contract-data-extraction/) を参照してください。

## 2026 年にエージェントが実際に担っている範囲

この分野は 1 年のうちにライフサイクルの 4 つの段階へ固有名のついたエージェントを投入しました。その名前を見れば、各ベンダーがどこまでの範囲を引き受ける気があるかが分かります。

**インテーク。** Ironclad の Intake Agent は依頼を構造化された申請に変換します。Ironclad は平均申請時間が 50% 短縮したと報告しています。Docusign の AI 支援 Web Forms は署名側で同じ仕事をします。

**ドラフトとレッドライン。** Sirion の agentOS には Draft Agent、逸脱を論点単位で指摘する Issue Detection Agent、そしてその逸脱を説明付きで修正する Redline Agent が含まれます。Sirion は初稿・レッドライン・検索といった限定用途で 80〜90% の高速化を報告しています。Icertis が 2026 年 6 月に発表した Vera では Composer Agent、Playbook Creation Agent、Risk Review Agent、Redline Agent が名指しされ、契約の作成と交渉が 80% 以上速くなると主張しています。

**更新。** Ironclad の Renewal Agent は更新ブリーフ（主要条件、取引履歴、事業側の担当者、時期）を生成し、その下で Cost Savings Agent がボリュームディスカウント、リベート、バンドルの余地を洗い出します。

**署名後とアーカイブ。** Icertis の Vera Fulfillment Agent は義務履行を扱い、Ironclad の Archive Agent はアーカイブ用メタデータを抽出したうえで人に検証を促します。

これらの説明を丁寧に読むと、ひとつのパターンが浮かびます。ほとんどが、人が受け入れるための成果物を作っているのです。それ自体は実在する能力ですが、自ら動くエージェントとは同じではありません。

## 自律性のはしご

4 段階で整理します。各製品が 2026-08-20 時点で実際にどこにいるかも添えます。マーケティングはこれらを一緒くたにしますが、調達側が同じことをしてはいけません。

**レベル 0 — アシスタント。** ユーザーが尋ね、モデルがパネルで答え、書き込みは発生しません。Vera Copilot と AskSirion の会話インターフェースはここに属します。「CLM の AI」として実演されるものの大半も同様です。

**レベル 1 — 提案し、検証させる。** エージェントがレッドライン、ブリーフ、メタデータ一式を作り、人がそれを受け入れます。「ユーザーに検証を促す」と説明される Ironclad の Archive Agent は、この段階の正直な言い方です。出力が Word の変更履歴として届く Redline Agent も同じ段階です。

**レベル 2 — ワークフローを起動する。** エージェントがシステム・オブ・レコードで何かを開始します。承認を回す、更新ワークフローを開く、レコードの状態を変える、といった行為です。Ironclad の Assistant はここに届きます。会話からワークフローネイティブのエージェントを起動してワークフローを立ち上げるからです。一方で Renewal Agent が更新ワークフローを起こす能力は、2026-03-19 の発表時点ではまだ将来形で書かれていました。

**レベル 3 — 相手方に向き合う。** エージェントが修正版ドラフトを相手方に送り、返ってきたものに反応します。これを正面から掲げているのは Luminance だけです。ドラフトを相手方に送り、相手側の AI にリアルタイムで反応するエージェント間交渉を掲げ、人間の関与は必須のゲートではなく任意の品質レイヤーとして位置づけられています。

2026 年の予算で「エージェンティック CLM」と名のつく契約の多くが買っているのはレベル 1 です。それには支払う価値があります。ただしレベル 3 の価格で買う価値はなく、レビュー担当者を工程から外せるわけでもありません。

## 誰もスライドに書かない前提条件

契約データに対して動くエージェントは、そのデータの品質をそのまま引き継ぎます。そして企業の契約データはデモが思わせるより悪い状態にあります。Sirion と World Commerce &amp; Contracting が 2026-05-18 に公表した調査 *Trusted Contract Data*（対象 170 社、調査期間 2026-02-13〜2026-04-10）では、締結済み契約をすべて CLM だけに保管している組織は 27% にとどまります。共有ドライブは依然として主要な保管場所であり、北米の回答者の 71%、欧州の 78%、オセアニアの 71% が使っていました。連携面では 54% がシステム間の自動データ連携がまったくないと回答し、契約データを最新に保つ双方向同期を持つのは 9% だけです。

これを、同じ調査で契約業務に AI を実際に導入・展開中と答えた 42% と並べてみてください。この差がリスクのすべてです。資産の 3 分の 1 がファイル共有に眠っている状態でひとつのリポジトリだけを見張る義務管理エージェントは、義務を追跡しているのではなく、標本を追跡しています。まずシステム・オブ・レコードを直してください。その区別が何をもたらすかは [CLM と CMS の違い](/ja/learn/clm-vs-cms/) にあります。

## エージェントと看板の掛け替えを見分ける 5 つの質問

1. **何が実行の起点になりますか。** 答えが「ユーザーが頼んだとき」だけなら、資料に何と書いてあろうとレベル 0 か 1 です。イベント起点の例（T-90 の更新、インテークのキューに届いた相手方書式）をひとつ出させ、そのトリガーを誰が設定したのかまで聞いてください。
2. **1 回の実行のトレースを見せてください。** エージェントのステップ数は契約ごとに変わります。ワークフローは変わりません。異なる 2 件の契約に対する 2 回の実行がまったく同じ手順なら、それは言語モデルに文章を書かせている決定木です。
3. **何を、どのオブジェクトに書き込みますか。** Word ファイル上のレッドラインは文書成果物です。ステージの変更、承認の割り当て、義務レコードの作成はシステム・オブ・レコードへの書き込みです。ガバナンス上の答えが必要になるのは後者だけです。
4. **人によるゲートはどこにあり、条項単位で設定できますか。** Icertis 自身の説明は、エージェントが「必要に応じて」人を関与させるというものです。購買側の問いは *必要* を誰が定義するのか、そして全体一律ではなく条項の種類ごと・金額のしきい値ごとに設定できるのか、です。
5. **書き込みの主体は誰として記録され、1 回の実行を巻き戻せますか。** エージェントの書き込みがすべて接続を設定した連携ユーザー名義で残るなら、監査証跡はエージェントの判断をその場にいなかった人物に帰属させることになります。

## 注意点と、それぞれの対策

**パイロットがベンダーのきれいなコーパス上で走る。** 状態の良い MSA 50 件で示された抽出精度は、10 年分の共有ドライブ PDF に触れた瞬間に崩れます。*対策：* CLM の外にある最悪の契約 200 件でパイロットを回し、条項タイプ別にフィールド単位の精度を測ってから、レベル 2 の権限を与えてください。採点の仕方は [AI 契約レビューの精度は実際どの程度か](/ja/learn/ai-contract-review-accuracy/) にあります。

**発表文の「early access」が多くを背負っている。** Ironclad の Assistant と新しい 3 つのエージェントは early access で出ました。Docusign の Iris アシスタント、そのエージェント群、Agent Studio は 2026-05-21 の発表時点で米国の early access であり、ロールアウト開始は 2026 年 7 月でした。*対策：* 実演された自律レベルの、買おうとしている具体的なエージェント名を GA 日付とともに発注書へ書き込んでください。プラットフォーム名ではいけません。

**相手方との境界における自律性は、別のリスク階級です。** 責任制限の条件を譲ったレベル 3 のエージェントは、そのメールを保存している相手に対してあなたを拘束しています。*対策：* 相手方に向けた実行の前に、譲歩マトリクス（エージェントが単独で受け入れてよい条件、実行を停止させる条件）を文書化し、見たことのないプレイブック外条項に対する挙動を試験してください。

**アーキテクチャが変われば課金メーターも変わります。** シート課金は人が作業する前提ですが、エージェント課金はそうではありません。この分野のベンダーは価格を個別見積もりでしか出しません。*対策：* 実際の年間件数で契約 1 件あたりのエンドツーエンド費用を試算し、初回が却下されたときの再実行費用を書面で確認してください。

## どこから始めるか

信頼できるリポジトリと明文化されたプレイブックがあるなら、レベル 1 のレッドラインおよび更新エージェントが最も早く元を取ります。レビュー担当者はそのまま残り、エージェントが最初の 1 時間を消すからです。それがないなら、エージェントより先にシステム・オブ・レコードを買ってください。上の 27% という数字が、エージェンティックなパイロットの多くが行き詰まる理由です。土台となる分野と各段階のつながりは [契約ライフサイクル管理](/ja/learn/contract-lifecycle-management/) から始め、続いて [Ironclad](/ja/tools/ironclad/)、[Icertis](/ja/tools/icertis/)、[Sirion](/ja/tools/sirionlabs/)、[Luminance](/ja/tools/luminance/) の各ベンダーページを読んでください。
