Um gestor comercial que prepara a reunião semanal de forecast precisa saber quais oportunidades mudaram e o que perguntar ao representante. Este download compara dois snapshots CSV datados de um único representante. Ele produz um briefing em Markdown com totais por categoria, IDs de oportunidades alteradas e perguntas ligadas a cada mudança. Use primeiro o exemplo fictício para ver quais conclusões os dados sustentam. [Baixe o pacote completo](/artifacts/forecast-meeting-prep-skill.zip).

## Execute o exemplo fictício

Extraia o ZIP em um diretório. Abra um terminal no diretório que contém `forecast.py`. O programa requer Python 3.9 ou posterior e usa a biblioteca padrão. A amostra exige zero contas de fornecedores, chamadas de API ou tokens de modelos.

```sh
python3 forecast.py demo
```

A demo lê `examples/pipeline-2026-10-16.csv` e `examples/pipeline-2026-10-23.csv`, gera o briefing e compara o texto com o arquivo esperado incluído. Se corresponder, imprime o relatório. Um erro de validação ou dos arquivos de exemplo encerra com código 2 e um diagnóstico. Você pode inspecionar o resultado antes de executar. [Briefing esperado](/artifacts/forecast-meeting-prep-skill/examples/expected-briefing.md).

Cada snapshot tem quatro oportunidades fictícias de `REP-F01`. Nas duas semanas aparecem cinco IDs distintos. Commit sobe de **US$ 30 mil para US$ 50 mil**, best case cai de US$ 58 mil para US$ 30 mil e upside sobe de US$ 20 mil para US$ 32 mil. O pipeline aberto total cresce US$ 4 mil. O movimento maior de US$ 20 mil em commit inclui transferências entre categorias.

Pine Mill (`D-101`) passa de best case para commit, sobe de US$ 48 mil para US$ 50 mil e move o fechamento de 6 para 20 de novembro. Pergunte quem confirmou a data revisada. Cedar Loom (`D-102`) sai de commit e continua na exportação atual. Maple Ferry (`D-104`) desaparece. Confira seu status no CRM e o escopo da exportação antes de classificá-la como ganha ou perdida. Fern Desk permanece igual. Amber Finch aparece pela primeira vez no arquivo atual.

## Compare suas exportações autorizadas

Use dois snapshots completos do pipeline aberto do mesmo representante. Preserve os IDs estáveis das oportunidades entre as datas. Faça a correspondência por ID mesmo quando o nome exibido da conta mudar. Use os mesmos filtros, moeda e [definições das categorias de forecast](/pt-BR/learn/forecast-categories-explained/) nas duas extrações. Uma alteração silenciosa no filtro pode parecer movimento real e exige investigação pelo responsável pela exportação.

```sh
python3 forecast.py compare prior.csv current.csv
```

O `README.md` especifica oito colunas. O programa aceita colunas reordenadas e rejeita cabeçalhos ausentes, inesperados ou repetidos. Ele verifica que todas as linhas tenham o mesmo representante e data dentro do arquivo, que ambos os arquivos representem o mesmo representante e que o snapshot atual seja de 1 a 10 dias posterior ao anterior. Essa janela é uma política de exemplo para reuniões semanais. Uma semana pulada exige um novo par comparável.

Use `commit`, `best_case` ou `upside` como categoria. Forneça um valor não negativo em USD com até duas casas decimais e uma data ISO de fechamento. O programa soma centavos inteiros para preservar os valores exatos. IDs duplicados, moedas não aceitas, linhas malformadas, snapshots vazios e datas inválidas interrompem a comparação. Investigue uma exportação vazia separadamente, pois ela não estabelece representante nem data.

## Revise o briefing com o representante

Leia os totais por categoria e rastreie cada ID alterado nos dois registros. Um ID novo gera uma pergunta sobre a entrada. Um ID ausente gera uma verificação de status e escopo. Mudanças de categoria, valor, data ou nome de conta selecionam perguntas fixas. A contagem de registros iguais ajuda a conciliar uma semana sem novidades. O briefing contém campos observados e perguntas. O representante traz a explicação do cliente, e o gestor responde pelo forecast apresentado.

Use `references/01-briefing-format.md` para conferir as seções. `references/02-question-library.md` explica como os campos alterados selecionam perguntas. `references/03-deal-deepdive-template.md` oferece espaço para o gestor registrar contexto confirmado, responsável e data de acompanhamento após a reunião. Editar essa folha preserva os totais calculados. O programa gera o briefing em inglês.

Para usar um assistente com o programa, o pacote inclui `SKILL.md` para o [Claude](/pt-BR/tools/claude/). Copie o pacote extraído para `.claude/skills/forecast-meeting-prep/` dentro do projeto e invoque `/forecast-meeting-prep` com os caminhos aprovados. Confira o ambiente de processamento antes de fornecer oportunidades reais. O comando Python local basta para todo o exemplo fictício. [Configuração de skills do Claude Code](https://code.claude.com/docs/en/skills).

## A conexão com Salesforce exige implementação separada

Um adaptador do [Salesforce](/pt-BR/tools/salesforce/) precisa autenticar o solicitante e aplicar seus direitos sobre o representante, os registros e os campos antes de ler ou exportar dados. Uma conta de serviço tem permissões próprias. Verifique explicitamente o acesso do gestor solicitante no adaptador e teste um solicitante autorizado e outro negado antes de habilitar exportações reais. Atribua responsáveis pelo agendamento de snapshots, permissões de armazenamento e retenção. O `rep_id` no CSV verifica coerência dentro dos dados fornecidos. O leitor de arquivos não tem como identificar quem realizou a extração. [Orientação de acesso do Salesforce](https://developer.salesforce.com/docs/platform/lwc/guide/apex-security.html).

## Quando a amostra atende

Escolha este workflow para uma conversa repetível sobre mudanças entre duas exportações. Uma tabela dinâmica e notas manuais são uma referência razoável quando há poucas oportunidades e o gestor já rastreia cada mudança. Use o [pacote de prompts de revisão do pipeline](/pt-BR/workflows/pipeline-review-prompt-pack/) para uma revisão mais ampla ou o [workflow narrativo de forecast](/pt-BR/workflows/forecast-narrative-skill/) para redigir comentários sobre um forecast aprovado. Precisão de forecast, estimativas de probabilidade e interpretação de chamadas com clientes exigem evidências além desses arquivos.

Em um piloto, registre correções na origem, perguntas mantidas pelo gestor, movimentos sem explicação e minutos de preparo e revisão. Registre separadamente os custos reais de exportação, armazenamento e assistente. Compare o mesmo escopo de reunião com o processo atual antes de afirmar que houve economia.
